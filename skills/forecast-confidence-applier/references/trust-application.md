# Trust Application Rules

Правила маппинга trust-профилей из INDEX.md на конкретный запрос.

---

## Иерархия весов

| Trust level | Числовой вес | Роль в выводе |
|---|---|---|
| HIGH | 1.0 | Входит в filtered consensus с полным весом |
| MEDIUM | 0.5 | Входит в filtered consensus с половинным весом |
| LOW | 0.0 | Показывается в секции Outliers, в consensus не входит |
| IGNORE | 0.0 | Показывается с предупреждением «track record 0/N», в consensus не входит |
| Не аудирован | 0.0 | Показывается в отдельной секции, рекомендация прогнать через retrospective-forecast-audit |

---

## Nearest-Domain Matching

Источники в INDEX.md имеют trust-профили по субдоменам:
```
Stratfor: HIGH long-term-russia, MEDIUM middle-east, IGNORE eu-future
```

**Алгоритм выбора веса для конкретного запроса:**

1. Определи домен запроса (из Шага 1).
2. Найди в профиле источника субдомен, наиболее близкий к домену запроса.
3. Если точного совпадения нет — ищи более широкий субдомен.
4. Если не нашёл вообще → используй вес MEDIUM как дефолт (источник аудирован,
   но не по этому субдомену — его стоит показать, но не перевешивать).

**Примеры matching:**

| Запрос | Профиль источника | Применяемый вес |
|---|---|---|
| Прогноз по России 2026 | HIGH long-term-russia | 1.0 |
| Прогноз выборов в Германии | HIGH long-term-russia, IGNORE eu-future | 0.0 (IGNORE eu-future) |
| Прогноз по Ближнему Востоку | MEDIUM middle-east | 0.5 |
| Прогноз ставки ЦБ РФ | HIGH russia, MEDIUM ru-macro | 0.75 — возьми MAX из подходящих субдоменов |
| Прогноз по теме, которой нет в профиле | HIGH long-term-russia (нет нужного субдомена) | 0.5 (дефолт MEDIUM) |

**Правило MAX**: если для одного запроса подходят несколько субдоменов источника,
бери наибольший вес из них. Источник хорош там, где он хорош.

---

## Anti-pattern: Доверие «по ощущениям»

❌ **ЗАПРЕЩЕНО**: Назначать весовые коэффициенты на основе собственных представлений
о репутации источника, без опоры на INDEX.md.

**Почему это важно**: вся логика скилла построена на том, что trust calibrated
постфактум через ретроспективные аудиты — это и есть единственный надёжный сигнал.
Интуиция о репутации источника систематически ошибается (survivorship bias, медийная
видимость ≠ точность прогнозов).

Конкретные ошибки которых стоит избегать:
- Давать Goldman Sachs HIGH только потому что «это известный банк»
- Давать IGNORE региональному брокеру только потому что «он малоизвестен»
- Снижать вес источника потому что «он часто ошибается по ощущению»

Если источник не в INDEX → он **не аудирован**, вес 0, отдельная секция.

---

## Смешанные домены

Если запрос затрагивает несколько доменов (например, «курс рубля и санкции»):

1. Собери источники из обоих доменов.
2. Для каждого источника применяй вес по ближайшему субдомену из его профиля.
3. Если один источник присутствует в обоих доменах с разными весами — используй MAX.

---

## Что делать с IGNORE

IGNORE — это не «игнорировать молча». Это «у этого источника нулевой track record
в данном субдомене, но его прогноз может быть интересен как outlier».

Правильное поведение:
- Показать прогноз источника в секции Outliers
- Явно написать «track record: N/N промахов в субдомене X» (если эта информация
  есть в INDEX.md)
- Не включать в weighted median

Это помогает пользователю видеть, насколько outliers расходятся с weighted consensus.
