> Вынесено из SKILL.md дословно при дроблении 2026-08-12 (этап 3, подготовка Max → Pro).

## RECALIBRATE-mode (D7)

Запускается командой `macro-forecast-chain --mode RECALIBRATE [--strict]`.
**Никаких LLM-вызовов. Цель — <30 секунд.**

Порядок шагов:

1. Прочитать новые веса из `scenarios/{ref}.yaml` (SSOT), проверить sum ≈ 1.0
2. Coverage check: если `modal_scenario_id` изменился И coverage для нового
   modal == DERIVED → предупреждение «нужен FCA для нового modal» (не блокировать)
3. Пересчитать Layer 2 marginal в каждом forecast YAML с conditional блоком,
   **чей `source_matrix` указывает на эту матрицу** (спека §1.3). Прогнозы,
   привязанные к другим матрицам, пропускаются с записью в `skipped_files` —
   в живой библиотеке одновременно лежат файлы от трёх разных матриц.
   `expected_pl_pct` **НЕ считается** (D2).
4. Обновить modal/hedge-target ranking в `macro-scenarios-{date}.yaml`
5. Режимы:
   - `--strict`: stale marginals (расхождение >1%) → отказ с инструкцией ручного пересмотра
   - default (soft): stale → auto-recalculate с info-warning

**НЕ запускает FCA. НЕ пересчитывает Layer 1 marginal. НЕ меняет conditional values.**

**Источник весов — файл сайта.** Рядом с матрицей скрипт ищет `stress-weights-{имя матрицы}.json`
(схема `stress-weights@1`, веса задаёт владелец на странице «Стресс»). Файл есть и годен — веса берутся
из него, а не из матрицы: на дату срока сайта — веса срока; между двумя соседними сроками —
линейная интерполяция по числу дней; раньше первого и позже последнего срока — веса ближайшего срока.
Поэтому «вне дат матрицы» не бывает и h18-файлы пересчитываются. Скаляр (modal/hedge, `weights_snapshot`) —
веса сайта на дату, которую матрица называет h12 (без `p_by_horizon` — `matrix.date` + 12 месяцев).
Набор сценариев файла должен совпадать с набором матрицы. Файл есть, но не годен (схема, сумма ≠ 1,
битая дата, чужой набор сценариев) — отказ с кодом 1, а не тихий откат на матрицу. Файла нет — веса матрицы
и правила ниже (запрет интерполяции, пропуск h18-файлов). Аргументы: `--site-weights ПУТЬ` (явный файл;
нет файла — отказ), `--no-site-weights` (принудительно веса матрицы). Сводка печатает источник весов и
способ получения каждой даты; в результате — `weights_source` (`site` | `matrix`) и `weights_meta`,
в выходном артефакте — `run_metadata.weights_source` и `weights_source_meta`.

**Веса матрицы по горизонтам (MFC-5 шаг 2, 2026-08-06).** Матрицы с `p_by_horizon`
поддерживаются: каждая дата `marginal.values` агрегируется весами СВОЕГО
горизонта (hNN сопоставляются датам матрицы — `horizon_intermediate` +
`horizon`, порядково). Прогноз с горизонтом вне дат матрицы (h18-файлы)
пропускается целиком и громко — интерполяция весов запрещена. Дефекты формы
блока (частичный блок, разные наборы ключей, сумма ≠ 1 на любом горизонте) —
явный отказ, а не тихая деградация на скаляр. В выходной stress-артефакт
пишется `run_metadata.weights_by_horizon_snapshot`.

**Чего режим не делает молча (MFC-5, 2026-08-05):**

- **Не угадывает модальный сценарий.** При `method: modal|nonlinear` нужен
  однозначный лидер: либо назван в `marginal.modal_scenario_id`, либо один
  максимум по весам. При равных весах (Pure Shell 0.25×4 — то, что стоит во всех
  живых матрицах) горизонт пропускается: `max()` вернул бы первый ключ словаря, и
  значение прогноза определял бы порядок ключей в YAML.
- **Не переписывает файл, если числа не изменились.** `yaml.dump` нормализует
  форматирование и уносит комментарии — безусловная перезапись переформатировала
  бы библиотеку на каждом запуске.
- **Запись.** Зависимость — PyYAML. С `ruamel.yaml` изменённые файлы правятся точечно:
  числа заменяются на месте, комментарии, кавычки и формат остальных строк сохраняются
  (при правке нечисловых полей многострочные скаляры склеиваются в одну строку). Без него файлы
  переписываются целиком, в `warnings` попадает предупреждение. Запись атомарная с
  самопроверкой: перечитанное не совпало с расчётом — файл не тронут, ошибка в `errors`.
- **Не прячет пропуски.** Всё, что не тронуто (чужая матрица,
  непересчитываемый метод, неоднозначный modal), печатается строками `SKIP:` и
  возвращается в `skipped_files`.

CLI (`scripts/recalibrate.py`):

```bash
# Базовый запуск
python3 skills/macro-forecast-chain/scripts/recalibrate.py \
    --scenario scenarios/scenario-geopolitics-ru-west-2026-05-04.yaml \
    --forecasts-dir Claude-Memory/forecasts/ \
    --stress Claude-Memory/macro-chain/macro-scenarios-2026-05-04.yaml \
    --output macro-scenarios-updated.yaml

# Только конкретный scenario (без обновления forecasts)
python3 skills/macro-forecast-chain/scripts/recalibrate.py \
    --scenario scenarios/scenario-geopolitics-ru-west-2026-05-04.yaml

# --strict: отказ при stale marginals вместо auto-recalculate
python3 skills/macro-forecast-chain/scripts/recalibrate.py \
    --scenario scenarios/... --strict
```

Результат: JSON в stdout со списком `stale_recalculated`, `updated_files`,
`skipped_files`, `coverage_warning`. Пропуски дублируются в stderr строками
`SKIP:` — «пересчитано 4 из 31» и «пересчитано всё» обязаны читаться по-разному.
