## Категории staleness для вывода

```
FRESH       age ≤ порог × 0.75   (зелёный)
AGING       порог × 0.75 < age ≤ порог   (жёлтый, без предупреждения)
STALE       age > порог   (оранжевый, показать в report)
VERY_STALE  age > порог × 2   (красный, рекомендовать обязательное обновление)
```

## Источник статуса

Даты самого прогноза: возраст по `forecast.date` (таблица выше) и покрытие горизонтов.
Плюс пробой: прогноз (`forecast_file` фактора) с алертом `factor_breach` в последнем отчёте монитора
(`monitor-reports/`: последний полный + частичные новее него) — STALE независимо от даты, причина
«пробой по монитору от <дата отчёта>»; пробой по прежнему файлу темы новый прогноз не задевает.
Файла флагов устаревания нет — источник сам отчёт монитора.
Плюс расхождение со спотом (таблица ниже) — STALE независимо от даты.

## Расхождение со спотом

Центр ближайшего неистёкшего level-горизонта (`fca_stats[h].l1_weighted`, при пустом — `l1_unweighted`)
сравнивается со спотом последнего макроснимка. Расхождение больше порога — `STALE_VS_SPOT`: статус не лучше
STALE, причина «центр <x> против спота <y> (<дата>), расхождение <gap> > <порог>»; прогноз устарел по рынку,
даже если свежий по дате и пороги монитора ещё не проверялись.

| Фактор | Индикатор панели | Порог | Единица |
|--------|------------------|-------|---------|
| brent | Brent | 15 | % от спота |
| usdrub | USD/RUB | 7 | % от спота |
| cnyrub | CNY/RUB | 7 | % от спота |
| cbr_rate | Ключевая ставка ЦБ | 1.5 | п.п. |
| inflation_ru | Инфляция (г/г) | 1.5 | п.п. |

- **Спот** — `coverage_report.py --spot <Claude-Memory/macro-snapshots>`: самый свежий снимок из срезов
  macro-ru-watcher (`ru-*.md`, таблица `## Snapshot`, колонка «Текущее», первое число) и автосрезов сайта
  (`auto/ru-*.json`); при равной дате — JSON. Спот старше 10 дней — сигнал считается, пометка «спот от <дата>».
- **Центр** — из `fca_stats` во входе фактора или из его `forecast_file` (`--root <Claude-Memory>`).
- **Не считается** (`spot_check.status: n/a`, причина в `notes`): фактора нет в панели (xauusd, urals_discount,
  budget_deficit, sanctions, geopolitics, sector_*), прогноз событийный или без `fca_stats`, все горизонты истекли.
- **Переопределение** — `spot_gap_overrides: {фактор: число}` во входе, в единицах порога фактора
  (как `staleness_overrides` у возраста).

## Поведение при QUICK-REFRESH

В QUICK-REFRESH режиме показывать только STALE и VERY_STALE, включая STALE по расхождению
со спотом (`summary.stale_vs_spot`) — с центром, спотом и датой спота.
AGING — не показывать (не беспокоить пользователя).

В FULL режиме показывать все статусы включая AGING.

---

## Версионирование предыдущих run

Предыдущий run считается актуальным для diff если:
- Возраст < 180 дней (полгода)
- Портфель-снапшот тот же или отличается не более чем на 20% позиций

Если предыдущий run старше 180 дней или портфель сильно изменился —
показывать diff с пометкой «сравнение может быть неточным».

## Horizon coverage — отдельная ось staleness

Возраст прогноза (age) и покрытие горизонтов (horizon-coverage) — две независимые
оси. Прогноз может быть свежим по дате создания, но недостаточным по горизонту:
например, прогноз `usdrub` от 2026-04-28 с `horizon: 2026-09-01` — age = 6 дней
(FRESH), но не покрывает целевые `2026-12-31` и `2027-12-31`.

### Поле `chain_target_horizons` в SKILL.md → Шаг 2.1

Список дат, которые должна покрывать собираемая матрица. Умолчание:
```yaml
chain_target_horizons:
  - "2026-12-31"
  - "2027-12-31"
```

Есть `scenarios/horizons.json` — список равен всем датам его `horizon_ends`; другие даты пользователя: сказать о расхождении с файлом сроков и спросить, файл не менять (его меняет только сайт). Файла нет — может быть переопределён пользователем в запросе на запуск.

### Расчёт horizon-status

Для каждого прогноза:
1. Извлечь `forecast.horizon` (если поле строка) или `forecast.horizons` (если список).
2. Найти максимальную дату → `max_horizon`.
3. Если `max_horizon` ≥ max(chain_target_horizons) → `COVERS`.
4. Иначе → `INSUFFICIENT_HORIZON`, и зафиксировать gap:
   `gap_days = (max(chain_target_horizons) - max_horizon).days`.

### Действие при INSUFFICIENT_HORIZON

В Шаге 4 такой прогноз попадает в план как «extend» (расширить горизонт), не как
«rebuild целиком». Промпт в FCA для extend-операции:
```
Уже есть прогноз {factor} до {max_horizon}: {central_estimate}.
Расширь до {chain_target_horizons[-1]}.
Использовать существующий прогноз как базу до {max_horizon}.
```

Если age тоже за порогом (`STALE+SHORT`) — extend не помогает, нужен полный rebuild.

### Допустимый зазор (tolerance)

`max_horizon` ≥ `chain_target_horizons[i]` − 30 дней принимается как `COVERS`.
То есть прогноз до 2026-12-15 при цели 2026-12-31 — это COVERS, не
INSUFFICIENT_HORIZON. Это потому что macro-факторы плавно эволюционируют
и 2-недельный зазор на хвосте не критичен.

Зазор настраивается в `chain_config.horizon_tolerance_days` (default: 30).
