# Сплиты и корректировки количества

IntelInvest НЕ фиксирует сплиты отдельной операцией — qty в `trades_portfolio_*.xlsx`
остаётся **pre-split**, но в текущем портфеле уже **post-split**.

Если не применить коэффициенты, XIRR по сплитованным бумагам будет сломан:
cost basis посчитается на неверное количество, виртуальная стоимость будет
в N раз меньше реальной.

---

## Реестр сплитов

Действующий реестр = встроенный набор (`known_splits.BUILTIN`, четыре сплита ниже) ∪ файл
`Portfolio/known-splits.json`. При совпадении (тикер, дата) побеждает запись файла. Файла нет — работает
один встроенный набор. Файл невалидный (битый JSON, чужая `schema`, `ratio` ≤ 0 или = 1, кривая дата,
дубль) — сборка останавливается с понятным текстом и снапшот не пишется: откат на встроенный набор молча
не делается, потому что пропущенный сплит меняет количество бумаги в 10–100 раз.

Формат файла `known-splits@1`:

```json
{"schema": "known-splits@1",
 "splits":    [{"ticker": "PLZL", "date": "2025-03-27", "ratio": 10.0, "note": "…", "added_at": "…", "added_by": "site|claude|owner"}],
 "dismissed": [{"ticker": "XXXX", "date": "2026-10-01", "ratio": 10.0, "dismissed_at": "…", "note": "…"}]}
```

`date` — день возобновления торгов (первый день постсплитовых цен); `ratio` > 1 — прямой сплит
(1 акция → `ratio`), 0 < `ratio` < 1 — обратный. `dismissed` — подозрения, которые владелец признал не сплитом.

Файл правится только командой `scripts/known_splits.py` (запись атомарная, перед перезаписью копия в
`.backups/`, дубль отклоняется):

```
python3 known_splits.py add --file Portfolio/known-splits.json --ticker XXXX --date 2026-10-01 --ratio 10 --note "…" --by owner
python3 known_splits.py dismiss --file … --ticker XXXX --date 2026-10-01 --ratio 10
python3 known_splits.py list --file …
```

Файл реестра передаётся в `build_snapshot.py` (`--splits-file`, по умолчанию `{memory}/Portfolio/known-splits.json`
при наличии) и во все шаги расчёта; в пакет `--record` он копируется вместе со справочником типов, при
`--replay` берётся из пакета. В снапшоте — поле верхнего уровня `known_splits` (источник, файл, число сплитов).

### Предупреждение `split_suspected`

Проверка сборки: у активной акции или фонда с биржевой ценой (`current_price_source = moex_iss`) в прошлом и
текущем снапшоте цена изменилась в N раз (допуск ±7 %, в обе стороны; N — целое от 2 до 10 или круглая
кратность 20, 25, 50, 100 и т. п.) без записи сплита этого тикера в интервале (прошлый снапшот, дата сборки]
и без отклонённой записи. Подтверждение — дневные закрытия ISS: сплит виден как скачок между соседними
торговыми днями, его день и есть дата возобновления торгов; история получена, а скачка нет — цена менялась
постепенно, предупреждения нет; при сбое сети предупреждение выдаётся без даты. В `details` — готовая
запись `entry` в формате файла. Пока сплит не внесён, количество и стоимость бумаги в этой сборке неверны;
после подтверждения (`add`) снапшот пересобирается. Решение — владельца.

### Встроенный набор

Применяется в `scripts/portfolio_returns.py` → `split_factor()` внутри основного прохода `reconstruct_positions`.

| Тикер | Коэффициент | Дата возобновления торгов | Примечание |
|-------|-------------|--------------------------|------------|
| T     | 1:10        | 17.04.2026               | Т-Технологии, RUB-позиция |
| PLZL  | 1:10        | 27.03.2025               | Полюс |
| GMKN  | 1:100       | 04.04.2024               | Норникель |
| TRNFP | 1:100       | 21.02.2024               | Транснефть преф |

**Правила применения:**

1. Сплиты применяются **только к RUB-позициям**. Если тикер `T` встречается среди USD-бумаг (AT&T) — не применять. Признак RUB-позиции: `currency == "RUB"` в trades-записях.
2. `reconstruct_positions` умножает qty каждой сделки на `split_factor` (произведение `ratio` всех сплитов тикера в интервале `trade_date < split_date <= as_of`) до расчёта себестоимости, поэтому продажа после сплита списывает себестоимость по средней в постсплитовых единицах; несколько сплитов подряд перемножаются.
3. Сделка в день сплита и позже уже в постсплитовых единицах (множитель 1).
4. Cost basis в рублях **не меняется** — только qty растёт (цена одной бумаги падает).
5. Сплиты после прохода не применяются и снаружи `reconstruct_positions` повторно не применяются — double-apply ломает qty.

**Признак нового сплита:** видишь qty, расходящийся в 10× или 100× между trades и текущим портфелем Numbers.

При обнаружении нового сплита:
1. Возьми дату возобновления торгов из предупреждения `split_suspected` или из официального сообщения Мосбиржи / IR компании.
2. Внеси запись командой `known_splits.py add` (выше); код `portfolio_returns.py` не правится.
3. Пересобери снапшот.

## Операция «Корректировка» в IntelInvest

IntelInvest создаёт запись типа `Корректировка` при синхронизации остатков с отчётом брокера.

**Логика по знаку `amount`:**

| Знак amount | Действие | Что делать |
|-------------|----------|------------|
| `> 0` | Виртуальная покупка | qty+, cost_basis+ (по текущей WACC) |
| `< 0` | Виртуальная продажа | qty−, cost_basis− (по WACC) |
| `= 0` | Информационная запись | Игнорировать |

Корректировки включаются в `corrections_log` снапшота с полями `type: "correction"`, `ticker`, `date`, `amount`, `direction`.

## Валютные конверсии — исключение из cashflow

В IntelInvest обмен RUB↔USD/EUR/CNY фиксируется **парными строками**:
- Строка 1: продажа исходной валюты (минус)
- Строка 2: покупка целевой валюты (плюс)

Разница между курсом ЦБ РФ и курсом брокера на дату конвертации создаёт
ложный "депозит" или "вывод" в расчёте XIRR. `portfolio_returns.py` идентифицирует
такие пары и исключает их из cashflow-инварианта.

Количество исключённых конвертаций отражается в `corrections_log` с `type: "fx_conversion_excluded"`.

## Кросс-валютные позиции (TGLD, TLCB)

Некоторые фонды покупаются в USD, продаются/удерживаются в RUB. В IntelInvest
это могут быть записи с одним и тем же `name` но разными `currency`.

`merge_cross_currency_positions()` в `portfolio_returns.py` объединяет такие
записи по совпадению `name` в единую позицию (уже внутри `reconstruct_positions`).

**Не вызывать повторно снаружи pipeline** — double-apply.
