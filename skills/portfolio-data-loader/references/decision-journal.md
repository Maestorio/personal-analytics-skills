# Журнал решений и теневые базы (AIR-1) — как запускать и что показывать

План, решения владельца и правила разбора — `docs/investment/portfolio/air-1-decision-journal-plan.md`
(в репозитории; §7а — когда система спрашивает, §9 — что делать с данными).

## Когда

Журнал собирает сайт после «Сохранить»; на Маке — только по просьбе (расчёт детерминированный, без LLM): «обнови журнал решений», «покажи журнал решений», «как advisor попадал».

## Команда

```bash
python3 scripts/decision_journal_update.py --memory "{MEMORY_ROOT}" [--trades /path/trades_portfolio_*.xlsx]
```

- `--trades` — приложенная выгрузка IntelInvest; без флага берётся самая свежая
  `~/Downloads/trades_portfolio_*.xlsx` (каждая выгрузка содержит всю историю с 2019).
- `--dry-run` — посчитать и показать сводку, ничего не записывая.
- `--offline` — только кэш рядов (`~/.cache/claude-skills/market-series/`).
- Первый запуск на новой машине ≈ 2 мин (ряды ~70 облигаций из ISS), дальше — секунды из кэша.

## Что пишет (исключение D3, решение D-1)

`Portfolio/decision-journal/` — пересобирается целиком при каждом запуске:

| Файл | Что |
|---|---|
| `inputs.json` | факт B3 по датам снапшотов (с 2026-07-08), внешние потоки, дивиденды, история плана |
| `baselines.json` | ряды B0 / B1 / B2-live / B2-frozen, факт − база в п.п. годовых и ₽, ребалансы, флаги |
| `journal.json` | записи (вердикт × позиция × обзор), эпизоды, исходы (акции — против MCFTR; облигации — полная доходность против индекса корзины, USD/EUR без исхода), вопросы об отказах, смены плана, решения по бумаге (`decisions`, эпизоды решений), инциденты по месяцам |
| `report-{дата}.md` | короткий отчёт для человека |

Ручные входы (пишет **save-to-library**, Workflow P; скрипт только читает и проверяет валидатором до сборки —
ошибка: код 2, журнал не изменён): `refusals.yaml` (ответы об отказах), `incidents.yaml`, `theses.yaml`.
Без сделки вердикт — «отложено условием», «решил сам» (отметка или правка плана) или «проигнорировано»; вопрос
об отказе — только по последнему.

## Что показать пользователю

Выведи stdout скрипта как есть (3–5 строк + вопросы + напоминания). Не пересказывай отчёт и не
интерпретируй цифры: окно факта короткое, разница с базами — шум; это написано в самом отчёте.

- **Вопросы об отказах** в выводе data-loader НЕ задавай — их задаёт advisor в начале следующего
  обзора (один раз на эпизод). Здесь достаточно строки «вопросов: N, задаст обзор».
- **⚠ «выгрузка сделок кончается …»** — попроси приложить свежую выгрузку и перезапустить.
- **«Через N дн. — контрольная точка»** — предложи запустить разбор фразой из вывода.

## Чего не делать

- Не править файлы журнала руками и не «исправлять» цифры в чате — только перезапуск скрипта.
- Не делать из журнала рекомендаций: это зеркало, а не вход решений (R15).
