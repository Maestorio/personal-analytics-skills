# Парсинг Общий баланс.numbers (Apple Numbers)

Основной файл позиций пользователя. Ведётся в Apple Numbers, поэтому требует
библиотеку `numbers-parser`.

---

## Запуск парсера

```bash
pip install numbers-parser --break-system-packages -q
python3 scripts/parse_portfolio.py "/путь/к/Общий баланс.numbers" > /tmp/portfolio.json
```

Парсер также принимает `.xlsx` (export из Numbers) — тот же скрипт.

---

## Ключевые JSON-поля выхода

Используй эти поля напрямую — не вычисляй из raw-листов.

### `summary`
```json
{
  "Имеется (RUB)": 2150000.0,    ← ВЕСЬ портфель ВКЛЮЧАЯ ИИС-3, без заблокированных
  "ИИС": 125000.0,                ← ИИС-3 отдельно (с 2026-04-20); уже внутри «Имеется»
  "Пополнение (RUB)": 50000.0,   ← плановые пополнения, для анализа не нужно
  "Итого": 2200000.0             ← план на горизонт = Имеется + Пополнение
}
```

Семантика «Имеется» уточнена владельцем 2026-07-08: это стоимость всего
портфеля включая ИИС-3 и исключая заблокированные активы. Проверочный
инвариант: «Итого» = «Имеется» + «Пополнение» (ИИС отдельно не прибавляется).

### `metrics` — готовые агрегаты, использовать первыми

```json
{
  "total_current_rub_excl_iis": 2025000.0,    ← база для долей = Имеется − ИИС
  "total_current_rub_incl_iis": 2150000.0,    ← всё включая ИИС-3 = «Имеется» как есть
  "iis_balance_rub": 125000.0,                ← только ИИС-3
  "total_bonds_main_rub": 980000.0,           ← облигации на основных счетах
  "total_bonds_iis_rub": 95000.0,             ← облигации на ИИС-3
  "bonds_value_by_type_excl_iis": {           ← для анализа облигаций (без ИИС), группировка по «Тип» (5 корзин)
    "USD": 320000.0,
    "EUR": 180000.0,
    "CNY": 210000.0,
    "ОФЗ": 150000.0,
    "КОРП": 120000.0
  },
  "bonds_value_by_subtype_excl_iis": {        ← то же, но по плановой корзине «Тип/Подтип» (2026-08, до 9 корзин)
    "USD": 320000.0,
    "ОФЗ/>10": 100000.0,
    "ОФЗ/<10": 50000.0,
    "КОРП/AA+": 60000.0,
    "КОРП/A": 40000.0,
    "КОРП/B+": 20000.0
  },
  "active_stock_tickers": ["SBER", "GAZP", "LKOH", "PLZL"],
  "n_active_stocks": 4,
  "n_active_bonds": 12,
  "n_active_bonds_iis": 3,
  "iis_other_tickers": ["SBGB"],
  "stocks_with_action_notes": [
    {"ticker": "SBER", "name": "Сбербанк", "plan": "Сокращение", "status": null, "ie_note": null, "ai_note": null}
  ]
}
```

### `stocks` — акции
```json
[
  {
    "Тикер": "SBER",
    "Название": "Сбербанк",
    "Стоимость": 147825.0,
    "Доля Реальная": 0.023,
    "Доля актуальная": 0.022,
    "Доля Планируемая": 0.025,
    "IE New": 0.06,
    "IE Old": 0.05,
    "План": "Сокращение",
    "Статус": "",
    "IE": "",
    "AI": ""
  }
]
```

Позиция активна если `Стоимость > 0`.

Поля `IE New`, `IE Old` — веса Invest Era. Пустые ≠ "нет мнения".
Последние 4 колонки (с 2026-06): `План` (что буду делать), `Статус` (что сделал),
`IE` (комментарий Invest Era), `AI` (вывод ru-portfolio-advisor) — в `ie_actual`
маппятся в `user_plan` / `user_status` / `user_note_ie` / `user_note_ai`. Заполняются редко.

### `bonds` — все облигации (включая ИИС-3)
```json
[
  {
    "Тикер": "SU26243RMFS4",
    "Название": "ОФЗ 78729",
    "Текущая стоимость": 124000.0,
    "Тип": "ОФЗ",
    "Подтип": ">10",
    "Рейтинг": "AAA",
    "ИИС": 20,          ← количество на ИИС-3
    "Всего": 20,
    "Итого без ИИСа": 0.0,
    "Итого на ИИС": 124000.0,
    "Итоговая доля": 0.0
  }
]
```

`Подтип` (добавлена 2026-08-18, позиция 5 между `Тип` и `Рейтинг`) — плановая
корзина владельца: пусто для валютных строк (`USD`/`EUR`/`CNY`), `>10`/`<10`/
`Флоат` для ОФЗ (срок до погашения / плавающий купон), `AA+`/`A`/`B+` для КОРП
(кредитная лестница, см. `output-schema.md`). `Рейтинг` **никуда не делась** —
это отдельная, более детальная колонка (`AAA`…`B-`), обе сосуществуют.
Обогащённые строки несут ещё производные `plan_bucket_key`
(`"{Тип}/{Подтип}"` либо просто `"{Тип}"` для валютных) — см. контракт §4.1
`docs/investment/portfolio/bond-subtypes-plan.md`.

Подмножества:
- `bonds_main` — только основные счета (`Итого без ИИСа > 0`)
- `bonds_iis` — только ИИС-3 (`ИИС > 0`)

### `goals.bonds_breakdown` — план по подкорзинам («План по Облигациям»)

Отдельная таблица листа «Общий баланс» (не путать с `bonds` выше — это две
разные таблицы с непересекающимся набором колонок). Строки: `Тип`, `Подтип`,
`Доля План`, `План сумма`, `Нынешняя Сумма`, `Изменение` + строка `Итог`.
С 2026-08-18 — 9 плановых корзин (`ОФЗ` ×3 подтипа + `КОРП` ×3 подтипа + 3
валюты). Легаси-файлы (до 2026-08-18) несут в этой позиции колонку `Рейтинг`
вместо `Подтип` (переименование, не новая колонка — см. ловушку ниже) и только
6 корзин (`КОРП/AAA`, `КОРП/BBB`). Парсер принимает оба имени колонки
(`Подтип` приоритетно), сырые русские ключи не трогает.

> ⚠️ **Ловушка: `Подтип` в двух таблицах — разные события.** В «План по
> Облигациям» (`goals.bonds_breakdown`) колонка `Подтип` — **переименование**
> легаси-колонки `Рейтинг`, которой больше нет. В «Облигации» (`bonds`)
> колонка `Подтип` — **новая** колонка, добавленная рядом с сохранившимся
> `Рейтинг` (обе колонки живы). Общий нормализатор «Рейтинг → Подтип» на обе
> таблицы **неверен** — обрабатывать раздельно. Источник — `bond-subtypes-plan.md`
> §1.1–§1.2.

### `other_positions` — фонды и прочее
Включает TLCB, Рентал ПРО, TGLD, SBGB (на ИИС-3). Подмножество `iis_positions` — только ИИС.

### `errors_check`
```json
[
  {"Тип ошибки": "Есть в IntelInvest, нет в Акция", "Наличие": true}
]
```
Если `Наличие = true` — файл рассинхронизирован. Добавить в `data_quality_flags`.

## ИИС-3 — особенности с 2026-04-20

С 2026-04-20 ИИС-3 явно выделен в Numbers-файле:
- Отдельная строка `ИИС` в листе "Общий баланс"
- Строка `RUB/ИИС` в листе "Планы"
- Колонки `ИИС`/`Итого без ИИСа`/`Итого на ИИС` в таблице облигаций

**Для holdings-снапшота:**
- Позиции на ИИС-3 → `account: "iis_3"` в `holdings[]` (underscore, не `iis3` — сверено с `output-schema.md`)
- Остальные → `account: "main"`

**В `trades_portfolio_*.xlsx` ИИС-3 не отделён** — XIRR по ИИС-3 отдельно не считается (нет разбивки в trades).

При анализе игнорировать: `"Облигации: сводка"`, `"Импорт Акции"`, `"Импорт облигации"`, `"Ребаланс"`.

## Edge cases

- `Доля актуальная` и `Доля Планируемая` могут быть строкой `"--"` или пустыми — обрабатывать как `null`.
- `"Ренат ПРО"` в файле = опечатка для `"Рентал ПРО"` — принимать как есть.
- Фонд Финам «Алгоритм роста» (FINAMAR): его стоимость ВХОДИТ в «Имеется»,
  но ни в одной вкладке файла его нет (задаётся владельцем вручную, позиция
  видна только из трейдов). Без вычитания holdings он ошибочно проваливается
  в «кэш» — настоящий кэш считает `assemble_snapshot._build_cash`.
  Кэшем/ликвидностью FINAMAR не является ни в каком смысле.
- Если парсер упал → проверить `raw_sheets` в JSON, читать листы вручную через openpyxl. Не использовать данные из памяти модели.

## Что НЕ нужно вычислять вручную

Эти агрегаты уже есть в `metrics`:
- Общая стоимость счетов — `total_current_rub_excl_iis`
- Доли по типам облигаций — `bonds_value_by_type_excl_iis`
- Список активных тикеров — `active_stock_tickers`
- Позиции с action-пометками — `stocks_with_action_notes`

Не пересчитывай их из raw листов — используй готовые поля.
