# XIRR / TWR / ROI — методология и валидация

Этот файл описывает, что именно считается, почему именно так, и как проверить
корректность результатов.

---

## XIRR (Internal Rate of Return, money-weighted)

**Что измеряет:** реальная доходность с учётом timing пополнений и выводов.
Отвечает на вопрос «сколько % годовых на мои деньги с учётом того, когда я их вносил».

**Формула:** XIRR = r, при котором:
```
Σ CF_t / (1 + r)^((t - t0)/365) = 0
```

где `CF_t` — cashflow на дату `t`: пополнения отрицательные (вложил), выводы и
конечная рыночная стоимость — положительные.

**Реализация:** Newton-Raphson + bisection fallback (в `portfolio_returns.py`).

**Особенность при отрицательном XIRR total:** почти всегда следствие заблокированного
капитала (FinEx, иностранные акции оценены в 0). Это честная оценка. Для анализа
качества управления используй `restricted.xirr`.

---

## Modified Dietz TWR (time-weighted, одноинтервальный)

**Что измеряет:** доходность без влияния timing пополнений. Пригодна для
сравнения с фондами, бенчмарками (IMOEX, RGBITR), управляющими.

**Формула:**
```
TWR_dietz = (End_value - Start_value - Net_external_flows) /
            (Start_value + Σ CF_t * (D - d_t) / D)
```

где `D` — число дней в периоде, `d_t` — день поступления cashflow.

**Важное ограничение:** это упрощённая одноинтервальная версия. Точный TWR
требует ежемесячной переоценки по рыночным ценам — в скрипте не реализовано.
Для долгосрочных сравнений использовать с осторожностью.

---

## ROI (Return on Investment, simple)

```
ROI = (конечная_стоимость + выводы + дивиденды/купоны - покупки) /
      (начальная_стоимость + покупки - выводы)
```

Показывает суммарную прибыль относительно вложенного капитала без учёта времени.
Наименее информативная метрика из трёх, но простая для быстрой проверки.

## Per-type breakdown

Каждый подпортфель (stock, bond, fund, other) считается как **изолированная инвестиция**:

```
start:  −initial_cost_basis_by_type   (на start_date, обычно 01.03.2022)
inside: покупки −, продажи/купоны/дивиденды/амортизация +
end:    +market_value_by_type          (на as_of_date)
```

Это позволяет сравнить эффективность корзин между собой независимо от пополнений.

**Что показывает:** если `bond.xirr = 0.13` и `fund.xirr = 0.09` — прямые
облигации опережают фонды на этом горизонте. Если наоборот — повод обсудить
переход на пассивное управление облигационной частью.

## Per-security XIRR

**Использование:** запрос "какая доходность по тикеру X", сравнение бумаг
внутри корзины, поиск аутсайдеров.

**Скрипт:** `scripts/per_security_xirr.py`

```bash
# Один тикер
python3 scripts/per_security_xirr.py --trades /tmp/trades.xlsx --tickers SBER

# Несколько + текущая стоимость из common
python3 scripts/per_security_xirr.py --trades /tmp/trades.xlsx \
    --tickers TGLD,PLZL,SU26243RMFS4 --format json --no-cashflows
```

**Ключевые поля выхода на тикер:**
- `xirr_frac` — доля годовых (0.2337 = 23.37%), сопоставима с "Доходность, % год." в IntelInvest
- `qty_now` — текущее количество (0 = позиция закрыта)
- `pnl_rub` — суммарная прибыль (все притоки + терминал − все оттоки)
- `price_source` — откуда взята текущая цена

## Валидация против IntelInvest

На 9 бумагах пользователя расхождение XIRR с IntelInvest **≤ 0.25 п.п.**:

| Тип | Примеры | Сложность |
|-----|---------|-----------|
| RUB облигации | ОФЗ 78729, КОРП-AAA | Базовый |
| USD замещайки | ГазКЗ-27Д2, ГазКЗ-27Е3 | FX-конверсия номинала |
| CNY замещайки | ГазКЗ-27Д (CNY) | FX-конверсия CNY |
| Акция | SBER, PLZL | Дивиденды, сплиты |
| Закрытая позиция | qty=0 | Нет терминального cashflow |
| Кроссвалютный фонд | TGLD (USD→RUB) | merge_cross_currency |
| Сплит | PLZL 1:10 | split_factor (внутри reconstruct_positions) |

Если расхождение > 0.25 п.п. — проверь:
1. Сплиты — все ли учтены в KNOWN_SPLITS?
2. Double-apply — не вызывается ли merge/splits дважды?
3. Замещайки — правильно ли определена `nominal_currency`?
4. Конвертации — не попала ли RUB↔FX пара в cashflow?

## YTM для облигаций

**Источник по умолчанию:** MOEX ISS → `YIELD` поле через `moex_quotes.py`.

**Когда MOEX не вернул YIELD:**
1. Попробовать `YIELDATWAPRICE` (средневзвешенный за день)
2. History API: `https://iss.moex.com/iss/history/engines/stock/markets/bonds/securities/{ISIN}.xml?from=...&till=...`
3. Ручной расчёт по IRR:
   ```
   Вход: clean_price (% от номинала), купонный график (COUPONVALUE × даты),
         номинал, дата погашения, НКД (ACCRUEDINT)
   Метод: IRR на cash-flow до MATDATE или OFFERDATE
   Реализация: scipy.optimize.brentq или Newton
   ```
4. Если ничего не помогло → `ytm_pct: null, ytm_source: "unavailable"`, флаг в `data_quality_flags`

**Поле в снапшоте:** `"ytm_pct": 14.82, "ytm_source": "moex_iss"` (или `"calculated_irr"`, `"history_api"`, `"unavailable"`).

## Когда какую метрику использовать

| Вопрос | Метрика | Источник в снапшоте |
|--------|---------|---------------------|
| "Сколько я заработал на своих деньгах?" | `restricted.xirr` | `returns.restricted.xirr` |
| "Как портфель vs фонды/индексы?" | `restricted.twr_dietz_annualized` | `returns.restricted.twr_dietz_annualized` |
| "Что тянет вниз — акции или облигации?" | per-type XIRR | `returns.by_type.stock.xirr` и `returns.by_type.bond.xirr` |
| "Сколько я заработал на конкретной бумаге?" | per-security XIRR | `per_instrument_xirr.{ticker}.xirr` |
| "Полная доходность включая заблокированные?" | `total.xirr` | `returns.total.xirr` (обычно отрицательный) |

## Ограничения, которые нужно знать downstream-скиллам

1. **Cost basis на 28.02.2022** ≠ рыночная цена (биржа была закрыта). Приближение.
2. **TWR Dietz** — одноинтервальный, не точный. Для точного TWR нужны ежемесячные переоценки.
3. **FINAMAR** и позиции, введённые вручную в common.xlsx, не учитываются в trades-based расчётах.
4. **Заблокированные = 0 ₽** по умолчанию. `total.xirr` почти всегда отрицательный — это не ошибка.
5. **MOEX недоступен** → цены из `last_trade_price`. `price_sources_summary` в снапшоте покажет долю таких цен.
6. **Замещайки без MOEX** → `nominal_currency = "RUB"` (ошибочно). При `no_moex = true` не доверять стоимости FX-облигаций.
