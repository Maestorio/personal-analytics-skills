# Tier 1: Обязательные методы для hypothesis-stress-tester

Запускаются для любого прогноза без условий. Результаты идут в Events YAML stress-pair.

## 1.1 Pre-mortem (Gary Klein)

Установи фрейм: **«[Горизонт прогноза] наступил. Прогноз провалился. Это факт.»**

Вопрос не «может ли это случиться», а «это уже случилось — перечисли конкретные причины почему».

Генерируй 4–6 причин провала. Каждая — конкретная, не абстрактная («инфляция не снизилась из-за роста тарифов ЖКХ на 12%», не «макроэкономические риски»).

**Вывод:** нумерованный список причин провала → они становятся кандидатами для KAC и для секции `falsifiers` в Events YAML stress-pair (топ-3).

## 1.2 KAC lite (Key Assumptions Check)

Из прогноза и причин провала (pre-mortem) извлеки 3–5 структурных допущений. Для каждого:

| Допущение | Обоснованность | Чувствительность | Статус |
|---|---|---|---|
| [формулировка] | HIGH/MEDIUM/LOW | Критическая/Умеренная/Низкая | ⚠️ / ✓ |

⚠️ — допущение с LOW обоснованностью + Критической чувствительностью. Это главные риски прогноза. Они идут в секцию `assumptions` Events YAML stress-pair.

## 1.3 Devil's Advocate

Задача: **доказать, что прогноз заведомо неверен.** Не «что может пойти не так», а «вывод уже неверен — вот почему».

Сформулируй **1 сильный контраргумент** (не список рисков), опровергающий базовый тезис целиком.

Если контраргумент слабый — скажи это явно: «сильного контраргумента построить не удалось».

## 1.4 Reversibility check

Два вопроса:

1. Прогноз **path-dependent**? (результат зависит от последовательности событий, а не только от конечного состояния)
2. Есть ли **точка невозврата** — момент, после которого прогноз уже нельзя пересмотреть?

Если да — укажи конкретно что это за точка и когда она наступает. Это идёт в секцию `deadlines` Events YAML stress-pair.
