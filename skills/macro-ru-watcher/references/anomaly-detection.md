# Anomaly Detection: правила z-score и флагирования

## Базовая формула

Для каждого индикатора:

1. Собери исторические **weekly Δ** из последних 12 snapshot'ов:
   - Δ_t = (value_t − value_{t-1}) / value_{t-1} × 100% (для уровней: курсы, индексы, цены)
   - Δ_t = value_t − value_{t-1} (для процентных ставок и %-показателей: ставка ЦБ, инфляция, US 10Y)
2. Посчитай:
   - μ = mean(Δ_history)
   - σ = stdev(Δ_history)
3. **z-score текущего изменения:** `z = (Δ_current − μ) / σ`

## Флагирование

| Условие | Флаг |
|---|---|
| `\|z\| < 1.0` | Без флага (рутинный шум) |
| `1.0 ≤ \|z\| < 2.0` | ⚠️ (заметное отклонение) |
| `2.0 ≤ \|z\| < 3.0` | ⚠️⚠️ (сильное отклонение) |
| `\|z\| ≥ 3.0` | ⚠️⚠️⚠️ (экстремальное отклонение) |
| `\|z\| ≥ 3.0` И history < 8 недель | ❓ возможная аномалия — короткая история |

## Обработка короткой истории

| Доступно snapshot'ов | Что делаем |
|---|---|
| 0 (первый запуск) | Snapshot сохраняется без diff и без флагов. Заголовок отчёта — «Первый запуск, недостаточно данных для аномалий». |
| 1 | Считается только weekly Δ, БЕЗ флагов аномалий. Пометка: «Аномалии не флагуются: история <2 недель». |
| 2–7 | Δ + z-score на доступной выборке + пометка «короткое окно (N недель), пороги ориентировочные» рядом с каждым флагом. |
| 8–11 | Полноценный z-score с лёгкой пометкой «история <12 недель, пороги уточняются». |
| ≥ 12 | Полноценный режим, без пометок. |

## Специальные случаи

### Ключевая ставка ЦБ
Меняется только на заседаниях СД (8 раз в год). Между заседаниями Δ всегда = 0, поэтому формула z-score даст деление на ноль (σ = 0).
**Решение:** для ставки ЦБ z-score не считается. Вместо флагов — простой бинарный маркер:
- Без изменений: «—»
- Изменилась: ⚠️ + указание величины (`+1.0 п.п.` или `−2.0 п.п.`)

То же правило применяется к структурному балансу ликвидности, если он не двигался ≥4 недели подряд.

### Длинные выходные / праздники
Если weekly snapshot выпал на праздник, и часть рынков не торговала:
- Используется last available trading day за 5 рабочих дней до даты snapshot
- В отчёте пометка: «Brent: closing 23.04.2026 (праздник 24.04)»
- z-score считается без корректировки (выходной просто пропускается в истории)

### Outlier в истории
Если в истории 12 недель есть один экстремум (Δ > 5σ от остальной выборки) — НЕ исключаем его из расчёта. История есть история. Но в комментарии к z-score добавляется пометка: «σ inflated by [date]: Δ = X% (вероятно, событие)».

## Не делаем

❌ **Не строим прогноз волатильности.** σ — простой rolling stdev, не GARCH, не EWMA. Этот скилл не модельный, он observational.

❌ **Не корректируем σ на cross-asset correlation.** Если USD/RUB и CNY/RUB двигаются вместе, оба получают свой независимый z-score. Корреляция — observation для читателя, не модельная корректировка.

❌ **Не исключаем тренд.** Если индикатор стабильно растёт 12 недель подряд (μ > 0), σ всё равно считается на сырых Δ. Это означает, что trend-following движение получит низкий z-score, а разворот — высокий. Это правильное поведение для signaling panel.

❌ **Не используем absolute thresholds.** Никогда не «USD/RUB > 100 ⚠️». Только относительные через z-score. Абсолютные значения публикуются в snapshot для визуального контроля, но флаги — только z-based.

## Минимальный набор данных в snapshot для расчёта

Для каждого индикатора в файле snapshot должна быть строка вида:

```
| [Индикатор] | [value] | ... |
```

Парсер z-score читает второй столбец как value. Дополнительно:
- В файле должно быть метаданные `*Сбор: YYYY-MM-DD HH:MM MSK*` для определения возраста snapshot
- Если индикатор был ❓ в каком-то prev snapshot — он пропускается в истории (history может быть < 12 даже если snapshot'ов 12)

## Псевдокод сбора истории

```
def collect_history(indicator_name, n_weeks=12):
    files = sorted(glob('~/Macro-Snapshots/RU-*.md'), reverse=True)[:n_weeks+1]
    values = []
    for f in files:
        v = parse_indicator(f, indicator_name)
        if v is not None:  # пропускаем ❓
            values.append((parse_date(f), v))
    if len(values) < 2:
        return None  # недостаточно данных
    deltas = []
    for i in range(len(values)-1):
        dt = compute_delta(values[i+1], values[i], indicator_type)
        deltas.append(dt)
    return deltas
```

Парсинг snapshot'ов — простой regex по таблице (см. `output-template.md` для канонического формата).
