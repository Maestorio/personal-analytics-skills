# horizon_passed — горизонт прогноза прошёл

Признак: `forecast.horizon` (скаляр) либо последняя дата сетки `horizons[]` раньше даты прогона. Скрипт `monitor_alerts.py` сам выдаёт `kind: horizon_passed`
и подавляет РЕВЬЮ для этого прогноза: обновлять нечего, прогноз закрывают с исходом, чтобы исход попал в калибровку.

- **Факт:** web_search на дату горизонта (как на Шаге 4). Не нашёл — «факт не найден, проверь сам».
- **suggested_action (HIGH/MEDIUM):** `/save-to-library Закрой прогноз <тема>: на <дата горизонта> <факт>, прогноз <центр/диапазон> — сбылся | не сбылся`.
  Пара «прогноз + сценарии» одной темы — одна фраза на обе записи.
- **Исход:** захваченный факт кладётся в `outcome_log_updates[]` (§7.6); `outcome_log` и статус `resolved` пишет только save-to-library
  (`references/status-management.md`). Фраза идёт в save-to-library, а не в forecast-confidence-applier.
