# memory-structure: структура локальной авто-памяти

## Где хранится память

```
~/.claude/projects/<project-slug>/memory/
├── MEMORY.md         # индекс — единственная точка входа
├── user_*.md         # записи типа user
├── feedback_*.md     # записи типа feedback
├── project_*.md      # записи типа project
└── reference_*.md    # записи типа reference
```

`<project-slug>` — sanitized путь рабочей директории. Пример:
`-Users-alexey-Documents-Программы-claude_skills` для проекта
`/Users/you/Documents/personal-analytics-skills`.

## MEMORY.md — индекс

- Загружается автоматически в каждый разговор (до 200 строк).
- Одна строка на запись: `- [Название](файл.md) — однострочный хук` (≤150 симв).
- Содержимое записи — только в отдельных файлах, не в MEMORY.md.
- При >180 строках → обязательное уплотнение (удалить устаревшие, объединить похожие).

## Типы записей

| Тип | Файл | Хранит |
|---|---|---|
| `user` | `user_*.md` | Роль, предпочтения, уровень знаний, стиль работы |
| `feedback` | `feedback_*.md` | Что делать / не делать — корректировки от пользователя |
| `project` | `project_*.md` | Цели, дедлайны, ключевые решения текущих проектов |
| `reference` | `reference_*.md` | Ссылки на внешние ресурсы (каналы, инструменты, системы) |

## Формат каждого файла

```markdown
---
name: Краткое название
description: Одна строка — что хранит (используется для решения о релевантности)
type: user | feedback | project | reference
---

Тело записи.

Для feedback — структура:
Правило (что делать / не делать).
**Why:** причина, которую назвал пользователь.
**How to apply:** когда это правило срабатывает.

Для project — структура:
Факт или решение.
**Why:** мотивация (дедлайн, ограничение, стейкхолдер).
**How to apply:** как это влияет на рекомендации.
```

## Что НЕ хранится в локальной памяти

- Структура кодовой базы, пути файлов, архитектура — выводится из кода.
- История git, кто что менял — `git log`/`git blame` авторитетнее.
- Дублирование содержимого CLAUDE.md / SKILL.md — они уже в контексте.
- Временные детали текущей задачи — хранить в Tasks, не в памяти.
