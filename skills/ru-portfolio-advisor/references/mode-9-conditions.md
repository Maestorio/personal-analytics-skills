# Режим 9 — условия «жди X → сделай Y»

Определения условий (`Portfolio/conditions.yaml`, `conditions@2`) пишет и читает только скрипт
`save-to-library/scripts/apply_condition.py`; модель файл не открывает и не пишет, она видит только JSON-вывод скрипта.
Состояние условия (сработало, «сделал», «не актуально», отложить, вернуть) ставит сайт кнопками владельца и
задачи NAS — скилл его не трогает.

**Вызов** (корень `{root}` — в Cowork `$HOME/mnt/Claude-Memory`, путь узнаётся через `request_cowork_directory`,
в команде не зашивается; `{save-to-library}` — каталог установленного скилла save-to-library):

```bash
echo '<JSON-вход>' | python3 {save-to-library}/scripts/apply_condition.py <команда> --root {root} --by <автор> [--plan <план %>] [--snapshot <portfolio-….json>]
```

`--by` — кодлист `actor`: по слову владельца в чате — `owner`, из разбора — код режима (`mode_4`, `mode_8` …).
`ok: false` в выводе — показать `error`/`errors` владельцу, ничего не повторять «на глаз». Время, `id`, версию,
`context` и `created_*` ставит скрипт — во входе их нет.

## Команды

| Фраза | Команда и вход |
|---|---|
| «покажи условия» / «условия по MOEX» | `digest --key MOEX` (без `--key` — все действующие; `--all` — и закрытые/снятые), вход пуст |
| «добавь условие …» | `add` — вход ниже |
| «перенеси / продли / поменяй порог условия X», «у X ветка среза — до 6%» | `edit {"id": X, <только меняемые поля>, "note": "почему"}` — новая версия с тем же `id` |
| «условие X больше не нужно: <причина>», «отказываюсь от X» | `withdraw {"id": X, "reason": "<причина>"}` — причина обязательна; нет во фразе — спросить |
| «условие X исполнено / отчёт вышел / отложи / верни» | состояние — кнопки на сайте («Действия»); скилл отвечает, какую кнопку нажать: отчёт или событие вышли раньше окна — «вышел» у ждущего условия (оно станет «сработало · ждёт владельца»); сам состояние не пишешь. Итог разбора закрывает сработавшее условие решением (`decisions:` → `conditions_resolved`) |
| сверка вердиктов обзора с условиями | `crosscheck {"verdicts": {ключ: вердикт}, "horizon_days": 7}` — только флаг конфликта |
| проверка файла | `validate` |

`edit` закрытого условия (done, dismissed, expired) — ошибка: нужно новое `add`. `edit` сработавшего проходит,
состояние новой версии начинается заново (`state_reset: true` в выводе). Ключ правкой не меняется: `withdraw` + `add`.
`source` новой версии без `source` во входе — по `--by`: `owner` → слово владельца, режим → отчёт.
`add`/`edit`/`withdraw` сами перештамповывают обзор недели того же дня, где есть бумага (вывод `restamped`:
у каких бумаг сменился приоритет; `restamp_warnings` — штамп не удался, правка условия всё равно записана).

## Вход `add`

```json
{"key": "RU000A10EST2", "kind": "trade",
 "trigger": {"type": "price_above", "value": 88},
 "event_text": null,
 "while_pending": {"verdict": "HOLD", "text": "держим до цели"},
 "on_trigger": {"action": "set_verdict", "verdict": "SELL", "text": "продать 26 шт."},
 "on_expiry": {"action": "run_analysis", "text": "лимит не исполнился — разбор бумаги"},
 "not_before": null, "valid_until": "2026-10-31",
 "note": "решение владельца: выйти выше 88%",
 "source": {"kind": "owner", "doc": null}}
```

- `kind` — кодлист `condition_kind`: `trade` (при срабатывании — сделка), `review` (сначала разбор), `watch` (только
  следить). От вида зависят кнопки на «Действиях».
- `trigger.type` — `date`, `price_below`, `price_above`, `report_published`, `gate_expired`, `forecast_breach`,
  `event`. Отчёт эмитента — `report_published`: `value` — что ждём словами, плюс `"expected": "ГГГГ-ММ-ДД"`
  (ожидаемая дата) — окно `window_end` = ожидаемая дата + 3 дня поставит скрипт.
- `on_trigger.action` — кодлист `condition_action`: `run_analysis` (после срабатывания — разбор), `set_verdict`
  (нужен `verdict`), `set_target_pct` (нужен `target_pct`), `notify_only`, `reinvest` (деньги от погашения, оферты,
  купонов или продажи — в другую бумагу или корзину: `target` — корзина облигаций плана, кодлист `bond_bucket`
  (`ОФЗ/>10`, `CNY`, …), или ключ бумаги; `amount_source` — `redemption` | `offer` | `coupon` | `sale`; `verdict`
  не ставится). `text` — одна фраза действия.
- **Погашение облигации.** «Погасится → переложить деньги» — это `reinvest`, не `set_verdict`: после погашения
  бумаги нет, вердикт по ней невозможен (`apply_condition.py` отклонит «держать/докупать» с датой в день погашения
  или позже).
- **Развилка.** Действие зависит от исхода события — `on_trigger.branches: [{"if_text": "…", "then": {"action",
  "verdict", "target_pct"?, "text"}}]` и `otherwise: {…}`; `if_text` — условие ветки словами, `then.text` — одна
  фраза («добор до 10%»), рубли и лоты считает сайт по живой цене.
- **Окно.** Названные срок или начало («до 31.10», «не раньше 19.10») — в `valid_until` / `not_before`, не в текст;
  что делать по истечении — `on_expiry`. Окно включительно с обеих сторон.
- `while_pending.verdict` — текущий вердикт бумаги из последнего обзора или решения, иначе `HOLD`.
- `source` — откуда условие: по слову владельца `{"kind": "owner", "doc": null}`; из сохраняемого отчёта
  `{"kind": "report", "doc": "Portfolio/reports/<файл>.md"}`.
- План на момент постановки: при открытом снапшоте передавай `--plan <planned_share_pct>` и `--snapshot <имя файла>`
  — скрипт запишет `context`; без них вывод несёт `context_missing: true`.

Вывод `add` — `id` нового условия (`c-ГГГГ-ММ-ДД-<ключ>-<n>`); при сохранении отчёта эти `id` передаются в
`decision_write.py from-report --created …` (порядок — save-to-library Workflow N).

Режим 9 не делает анализа и снапшота не требует; сработало ли ценовое условие, видно в `digest` (статус модуля (а)).
