Этот файл содержит детальные правила trust-весов для работы с инвест-домами
(правила 19–22 скилла). Загружать при работе с сигналами IE, БКС, Альфа, SberCIB,

## Правило 19: Дифференцированный trust-вес Invest Era (двухуровневое применение)

### Уровень 1 — subdomain trust из памяти (`[lib] Invest Era`)

Задаёт базовый вес сигнала по области:
- HIGH subdomain → следовать как сильному сигналу
- MEDIUM subdomain → фильтр через брокерский консенсус и фундаментал
- LOW subdomain → дисконтировать вес ≥50%
- IGNORE subdomain → игнорировать сигналы IE в этой области

**Откуда берётся `[lib]`-запись:** её создаёт и обновляет скилл `memory-sync`
(Шаги 6–7 его workflow) — агрегирует trust-subdomain'ы из `Claude-Memory/domains/`
newest-wins-мерджем и пишет сжатую `[lib] {source}`-запись в memory_user_edits
(auto-inclusion: `pin OR HIGH`). Для принудительного обновления запусти `/memory-sync`.

Если `[lib] Invest Era` отсутствует в памяти — работай по уровню 2 (`domains/ru-sellside/invest-era-*.md`) + проверенным дефолтам из 2 аудитов (2025-03-12, 2025-11-06):

| Subdomain | Trust |
|---|---|
| `bonds-rub` | HIGH (длинные корпоратные фиксы, флоатеры — подтверждено обоими аудитами) |
| `finance-ru` | MEDIUM (ставка ЦБ, инфляция — попадания, но ретрансляция) |
| `oil-gas-ru` | LOW (систематические промахи: нефть, NVTK, санкционные истории) |
| `metals-mining-ru` | LOW (PLZL в «вершине цикла» — промах −2 в 2025-03) |
| `bonds-fx` | LOW (замещайки: низкая корреляция с курсом ≠ альфа; Т10 +2 — это caveat, не рекомендация покупать) |
| `dividend-stocks` | LOW (bull-bias без stop-loss; дивидендные тезисы слабые) |
| `long-term-strategy` | LOW (санкционные бенефициары, «вершины цикла» по сырью — кластер L-A/L-R) |

В шапке ответа явно помечай: «`[lib]`-профиль IE отсутствует, использую аудит-дефолты из `domains/ru-sellside/invest-era-*.md`».

**Примечание:** `[lib] Invest Era` существует (последний пересчёт — 2026-10-02, N=5 аудитов в `domains/ru-sellside/`; stub'ы в `ru-macro/` отдельными аудитами не считаются). Fallback выше — только если запись недоступна в текущей сессии. При расхождении `[lib]` и `INDEX.md` доверяй INDEX.

### Уровень 2 — тикер-специфические правила из `references/invest-era-profile.md`

Поверх subdomain-веса применять тикер-штрафы и тикер-бонусы:

- **LOW (повышение веса = автоматический флаг):** NVTK, FLOT, AFLT, UPRO («бенефициары снятия санкций»); KMAZ, Диасофт, Позитив, Астра, GAZP («ложные бенефициары нормализации»)
- **HIGH-сигналы по облигациям:** Эталон, Уралсталь, Балтлизинг, ЛСР, TRIB, флоатеры Кокс; CTRL и Борец Капитал как pre-warning negative-list
- Кросс-проверка на национализационный риск для корпоратов BBB / BB / ниже

### Сценарии слияния уровней

- [lib] HIGH bonds-rub + bundled HIGH по конкретному выпуску → следовать с весом HIGH
- [lib] HIGH bonds-rub + bundled указывает на национализационный риск → штраф к доле
- [lib] LOW oil-gas-ru + IE поднимает NVTK на ≥2 п.п. → автоматический флаг (двойной негативный)
- [lib] MEDIUM finance-ru + IE по SBER без bundled-флага → следовать с MEDIUM

**Системные дельты для контрсигнала по макро-прогнозам IE** (USD/RUB, ставка ЦБ, IMOEX target,
P(СВО), «вершины цикла» по сырью) — детализация в `Claude-Memory/domains/ru-sellside/invest-era-*.md`
(аудиты 2024–2025 — секция «Системные дельты»; 2026 — `reports/2026-10-02-invest-era-*.md`, §4.B и §7;
доступ Synology-first — `references/transport-layer.md`). Краткая выжимка (v3, 2026-10-02):
- **Ставка ЦБ — знак уклона сменился.** 2024: слишком ястребиный (−2...−3 п.п. к прогнозу IE).
  2026: слишком голубиный по темпу (0/3 в обзорах, 1/3 в вебинаре) — добавлять ≈+0,25 п.п.
  на каждое заседание к траектории IE. Направление — MEDIUM, темп — LOW. Фиксированной дельты нет.
- **USD/RUB — по горизонту.** ≤1 мес. — MEDIUM (тактика по тренду 3/3; развороты против
  тренда — LOW). На месяцы вперёд — IGNORE: сводный IGNORE★ сохранён (2/4 в 2026, коридор
  «до осени» пробит в обе стороны, три промаха направления в 2024–2025). Фиксированной дельты
  −25...−30 ₽ (2024–2025) больше нет — в 2026 не подтвердилась.
- **IMOEX:** target дисконт −20...−30%; тайминг входа/разворота — ноль пользы во всех 5 аудитах.
- **Нефть:** `oil-forecast` → IGNORE (LOW в обоих аудитах 2026); корень — недооценка длительности геошока.
- **P(СВО) и «стороны скоро договорятся» на горизонте >1 мес.** — брать Polymarket, не IE.
  Исключение: тайминг событий (Иран, ФРС) на горизонте ≤5 нед. с явным объяснением расхождения
  с рынком — MEDIUM (`geo-event-timing`, две ⭐ в обзорах 2026).
- **Калибровка:** вероятности IE ≥75% сбываются примерно в половине случаев — дисконтировать.
- «Вершины цикла» по золоту от IE — игнорировать (в 2026 не проверялось).

## Правило 20: Условия пересмотра профиля Invest Era

Профиль IE в `references/invest-era-profile.md` построен на материале четырёх стратегических
вебинаров (12.2024–04.2026) и 10 регулярных видео-обзоров (03–08.2026) — 5 аудитов, последний
пересмотр 2026-10-02 — в условиях СВО, ставки ЦБ 14–21%, изоляции от нерезидентов.
**Профиль становится частично или полностью невалидным при наступлении любого из триггеров:**

- **T1 (геополитический):** официальное окончание СВО или устойчивое перемирие >90 дней + начало восстановления дипломатических отношений РФ–США/ЕС.
- **T2 (санкционный):** снятие SDN-санкций с ≥2 крупных эмитентов (Лукойл / Роснефть / НВТК / Совкомфлот / Аэрофлот).
- **T3 (монетарный):** снижение ставки ЦБ до нейтрального уровня (6–8%).
- **T4 (рыночный):** возврат нерезидентов в IMOEX и снятие «О»-счетов / разморозка >50% заблокированных активов.
- **T5 (временной):** прошло ≥6 мес. с последнего пересмотра профиля (дата — в `references/invest-era-profile.md`, раздел триггеров).
- **T6 (контентный):** проведён новый ретроспективный аудит ≥1 вебинара IE с горизонтом ≥3 мес.

**Действие при триггере:** перевести профиль в статус «под пересмотром»; в шапке любого ответа с IE-сигналом добавлять предупреждение «профиль IE построен на режиме 2024–2026, текущий рынок может вести себя иначе». Запросить у пользователя обновление профиля через новый аудит. **Превентивно при T1/T2: повысить настороженность к кластеру 7 («overshoot мирной премии»).**

## Правило 21: Выбор модели по режиму

Детальная таблица маршрутизации — в `references/model-routing.md`. Краткая сводка:

- **Haiku** — методологические вопросы без файлов
- **Sonnet** — режимы 1, 2, 4, 5, 6, 7 (по умолчанию)
- **Opus** — режим 8 и многорежимные (3+8, 6+8, 4+8)

Режим 3 (Rebalance Opinion): Sonnet с эскалацией на Opus при ≥3 IE-изменениях в LOW-категории ИЛИ при запросе «пересмотр плана».

**Сигналы для эскалации Sonnet → Opus в любом режиме:**
(а) ребалансировка предполагает изменение веса LOW-тикера IE на ≥2 п.п.;
(б) рейтинговое действие или claim о национализации по позиции;
(в) геополитический сдвиг (новые пакеты OFAC/EU);
(г) запрос «пересмотр плана» целевых долей;
(д) обнаружен L-R-сигнал у позиций пользователя за период;
(е) контекст уже >150K токенов и нужен глубокий синтез.

При получении запроса на режим, требующий более мощной модели — **добавь в шапку ответа рекомендацию переключиться** (не переключай сам). Внимание: Sonnet 5 использует новый токенизатор (~+30% токенов против Sonnet 4.6 при той же цене за токен) — пере-базируй прикидки контекста.

## Правило 22: Иерархия trust-профилей инвест-домов (общая)

При работе с **любым** sell-side источником — российским или зарубежным — определяй trust-вес по трёхуровневой иерархии. Конкретные источники не перечисляются в этом файле: всё, что известно о конкретном источнике, живёт в памяти и `Claude-Memory/`.

### Уровень 1 (первичный) — `[lib] {source}` в памяти профиля

Прочти индекс памяти профиля (`mcp__memory`: `/memory-notes.md` → `/lib_<source>.md`; в старых проектах — `projects/<id>/memory-notes.md` или `MEMORY.md` auto-memory). Запись вида `[lib] {source}: ...` — компактный сводный trust-профиль (≤500 симв.) по subdomain'ам в формате `HIGH/MEDIUM/LOW/IGNORE {область}`. Применяй именно его веса как базу. Запись формируется через `memory-sync`; источник правды — файлы аудитов в `Claude-Memory/`, не сама память.

### Уровень 2 (детализация) — `Claude-Memory/{subfolder}/{source}-{period}.md`

Идти сюда, когда:
- нужны метрики (hit rate, альфа-генерация, средняя ценность) для обоснования вывода
- нужен полный разбор кластеров биасов с примерами и ссылками
- нужны системные дельты по макро-прогнозам (величины контрсигнала)
- нужен L-R sweep (что источник систематически пропускает)

Все аудит-файлы хранятся в `Claude-Memory/domains/` — поддиректории: `geopolitics/`, `ru-sellside/`, `global-banks/`, `tech-ceo/`, `ru-macro/`, `commodity-agencies/`.
Не подгружай файл заранее; читай только при явной необходимости.

**Доступ (Synology mount):**
`Read("~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/domains/{поддиректория}/{source}-{period}.md")`

Пример для Invest Era: `Read(".../Claude-Memory/domains/ru-sellside/invest-era-2025-11-06.md")`
При недоступности — остановиться и сообщить пользователю. Логика: `references/transport-layer.md`.

### Уровень 3 (bundled) — `references/{source}-profile.md` в скилле

Содержит только то, что не помещается в [lib] (≤500 симв.) и не является аудит-метрикой:
- тикер-специфические правила и антипаттерны
- триггеры пересмотра профиля
- кросс-проверки и специфические ограничения

Bundled-слой используется поверх [lib], не вместо него.

### Если `[lib] {source}` отсутствует, и в `Claude-Memory/` тоже нет файла

Это значит, ретроспективного аудита источника не было. В этом случае:
- НЕ изобретай trust-веса по слухам или общему впечатлению из training data
- Применяй общее правило: первичка > институциональные обзоры > СМИ > блогосфера
- В шапке ответа помечай: «trust-профиль {source} отсутствует, веса не калиброваны»
- Предложи пользователю запустить `retrospective-forecast-audit`

### При конфликте между [lib] и bundled

Доверять [lib] (более свежий через memory-sync), предупредить о рассинхронизации,
предложить обновить bundled.

**Запрещено:** использовать trust-вес, основанный только на собственном впечатлении из training data
или из памяти прошлых сессий вне `[lib]`-системы — без записи в [lib] или аудита в `Claude-Memory/`.

## Правило 11 (R11): атрибуция источника катализатора — `source_trust`

**Зачем.** Матрица доверия из `Claude-Memory/INDEX.md` устроена как пара
«аналитик + поддомен» (`Invest Era` × `oil-gas-ru` → IGNORE). Потребитель —
`portfolio-integrated-view` — применяет её к катализаторам обзора. До 2026-08-16
он сопоставлял с матрицей поле `source`, а там лежит проза или URL
(`https://kommersant.ru/doc/… (контекст) + заявление CFO`, `advisor estimate: отчёт
не анонсирован официально…`). Совпасть с тегом «аналитик + поддомен» такое не может
никогда: прогон 08-15 извлёк 28 IGNORE-записей и не отфильтровал ни одного
катализатора из 105 — правило при этом выглядело работающим.

**Кто отвечает.** Атрибуцию проставляет автор катализатора, то есть этот скилл
(Mode 1/2): знание «чей это сигнал» есть в момент написания, а восстановить его
потом по URL нельзя — у половины катализаторов внешнего источника нет вовсе.

**Как заполнять.**

```yaml
source_trust:
  analyst: "Invest Era"     # как в INDEX.md, дословно
  subdomain: "oil-gas-ru"   # как в INDEX.md
```

| Случай | `analyst` | `subdomain` |
|---|---|---|
| Сигнал инвестдома | имя из `INDEX.md` дословно (`Invest Era`, `БКС`, `SberCIB`) | поддомен из `INDEX.md` (`oil-gas-ru`, `bonds-rub`, `dividend-stocks`…) |
| Собственная оценка advisor | `advisor` | `self` |
| Первичка эмитента / раскрытие / MOEX ISS | `issuer_disclosure` | `primary` |
| Регулятор (ЦБ, Минфин), макростатистика | `regulator` | `primary` |
| СМИ без аналитического тезиса (только факт события) | `media` | `news` |

Значения вне `INDEX.md` матрицей не дисконтируются — это нормально: `advisor`,
`issuer_disclosure`, `regulator` и `media` в ней и не должны быть. Тег нужен, чтобы
отличить «источник проверен и не в IGNORE» от «источник не атрибутирован».

**Чего нельзя.**

- Молча опускать поле. Катализатор без `source_trust` фильтр не проверяет, и он
  попадает в `validation.trust_coverage.untagged` у потребителя; при сплошном
  отсутствии тегов отчёт обязан написать «фильтрация по доверию не работала», а не
  «низкодоверенных источников нет».
- Ставить `analyst` по впечатлению, если источника нет — для собственной оценки
  есть `advisor` / `self`.
- Подменять `source_quality`. Это разные оси: `source_quality` — насколько твёрд
  сам факт (HIGH регуляторка / MEDIUM аналитик / LOW эвристика), `source_trust` —
  чей сигнал и как он себя показал в ретро-аудитах. Дисконты применяются независимо.
