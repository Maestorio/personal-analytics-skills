# Шаблоны недельных обзоров (режимы 1 и 2)

Вынесено из `output-templates.md` при разрезке по режимам 2026-10-26 без изменений текста. MD недельного обзора собирает `scripts/render_weekly_md.py` из YAML и `changes.md` (save-flow шаг 4); шаблон ниже — структура и требования к содержанию.

Общие правила (база весов, база докупки, режимы и гейты словами, плотность абзацев, сверка ограничений, решение по бумаге — блок `decisions:`) — `references/output-templates.md`; читать вместе с ним.

**Уверенность вердикта (`advisor_verdict_confidence`, 0..1) — полнота и свежесть данных под вердиктом**, а не
вероятность исхода (та — `p_outperform_3m`, по ней журнал решений считает Брайер). Ориентир: от 0,8 — свежая
первичка (отчёт, раскрытие, рейтинговое действие) и проверенный тезис; 0,6–0,8 — тезис цел, но часть данных
старая или из вторичных источников; ниже 0,6 — ключевого факта нет (отчёт не вышел, ущерб не раскрыт, один
источник). При уверенности ниже 0,8 в `confidence_basis` — одной фразой, что именно её снижает («один
источник, отчёт не вышел»); это поле карточка и MD показывают рядом со словом «уверенность низкая/средняя».
В тексте для человека уверенность — словом (ниже 0,6 низкая · 0,6–0,8 средняя · от 0,8 высокая,
`terms_ru.conf_word`), число остаётся в YAML.

## Шаблон 1. Weekly Stocks Review

**Принципы форматирования этого шаблона (обязательно):**
- Никаких плотных абзацев-простыней. Executive summary разбит на буллет-категории, а не один абзац с перечислением всего подряд.
- Per-issuer блоки всегда структурированы по лейбл-полям (**Триггер / Цена / Источники / Вердикт**), каждый на своей строке. Если абзац по эмитенту получается длиннее 5-6 строк — принудительно разбивай на мини-блоки.
- Изменения IE берутся **строго из колонок `IE New` и `IE Old`** в файле пользователя. Если значения пустые — так и пиши "IE нет публичного обновления". Веса из закрытой подписки IE не искать в вебе.
- **Порядок в per-issuer блоке: Рекомендация ПЕРЕД Сравнением с пометками.** Рекомендация строится на фундаментале, отчётности, брокерском консенсусе и trust-взвешенных источниках — это первичная позиция. Пометки пользователя (`План`, `Статус`, `IE`, `AI`) — вторичный контекст, сравниваемый с уже сформированным выводом. Влияние пометок на рекомендацию минимально: они могут усилить уверенность при совпадении или потребовать объяснения при расхождении, но не определяют решение.

### Pre-emit checklist для Mode 1 (weekly stocks)

Перед эмиссией — если в ответе называется любая сумма/доля докупки акции:

- [ ] В ответе сказано, что акции докупаются → прогнан gate_aware_sizing.py, и в тексте
      стоят: база докупки (₽ + % NAV), остаток, закрытый для покупок гейтами (₽ + пп NAV),
      доли к базе в процентах (владелец вводит их в IntelInvest), суммы по каждой
      открытой бумаге?
- [ ] Классификация Open / под гейтом / без сигнала / на сокращение выведена поимённо,
      а не описана словами?
- [ ] Разрывы посчитаны к planned_share_pct; ie_new_pct — только secondary (fallback
      при planned == null, с явной пометкой)?
- [ ] Ни одно число докупки не получено как (target_pct × NAV − факт) и не взято из
      goals_matrix.Изменение?
- [ ] В тексте нет T*, F, S, «неподвижной точки», «1/(1−…)» и вывода формулы?
- [ ] Черновик прогнан через `gate_aware_sizing.py --lint-draft` и линт чист?
- [ ] Суммы, количества и целевые доли сделок в строках с действием есть в выводе скриптов (`sizing_to_target.py` / `gate_aware_sizing.py`, сохранённый в файлы по правилу `fanout-news.md` «Результаты — в файлы») — `lint_numbers.py --draft <черновик> --sources <файлы>` чист?
- [ ] В тексте для человека нет голого «Mode N» (режим словами + номер в скобках, `output-templates.md` § «Режимы в тексте для человека»)?
- [ ] Статусы гейтов — словами решений («держать», «наблюдать»), не кодами; вопрос владельцу — первым блоком, «да / нет» (`output-templates.md` § «Статусы гейтов и вопросы владельцу»)?
