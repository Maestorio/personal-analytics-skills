# Шаблоны режимов 3–8 (ребалансировка, разбор бумаги, фонды, оценка качества)

Вынесено из `output-templates.md` при разрезке по режимам 2026-10-26 без изменений текста.

Общие правила (база весов, база докупки, режимы и гейты словами, плотность абзацев, сверка ограничений, решение по бумаге — блок `decisions:` в шапке) — `references/output-templates.md`; читать вместе с ним.

## Шаблон 3. Rebalance Opinion

**Принципы (обязательно):**
- **Realised XIRR — backward, не forward.** Любое предложение INCREASE/DECREASE planned-доли обязано опираться на forward-аргумент (catalyst EV, fundamentals delta, stress-чувствительность, valuation gap, дивполитика 12м). XIRR упомянут только как audit-комментарий («history и forward согласованы / диверг»), а не как столбец рядом с «Моя оценка planned» и не как обоснование «X% XIRR — поднять planned».
- **Каждое предлагаемое изменение** (`Δ vs user planned ≠ 0`) сопровождается явным forward-аргументом в строке таблицы. Без него — Δ невалидно.
- Mode 3 reader-only по gate — XIRR drag не основание перекрашивать gate (это Mode 4/8).

```markdown
# Оценка ребалансировки IE от [дата] + тайминг позиций

## Executive summary
- **Изменений в IE New**: N тикеров, [кратко]
- **Согласен с**: [список тикеров]
- **Не согласен с**: [список тикеров + 1 предложение]
- **Позиции "к продаже" в твоём файле**: рекомендую [N продать сейчас, N подождать, N частично]
- **Целевые доли**: [пересмотр не нужен / рекомендую изменить на X/Y/Z]

### [ТИКЕР]: [IE Old]% → [IE New]%

- **Рекомендация**: **Следовать / Частично / Не следовать** — [аргумент]
- **Учёт твоих приоритетов**: [если у пользователя уже есть расхождение с IE — контекст]

## Тайминг продаж

### [ТИКЕР] — "[статус в файле]"
- **Ситуация**: [почему пользователь решил сократить/продать]
- **Тайминг**: **СЕЙЧАС / ПОДОЖДАТЬ ДО [событие, дата] / ЧАСТИЧНО N% сейчас + N% после [событие]**
- **Обоснование**: [триггеры, ожидаемые события, техкартина]

## Сколько можно докупить

Обязательный раздел, если в ответе называется любая сумма или доля покупки акций —
независимо от источника денег (buffer от продаж, приток кэша, купоны, погашения). Форма —
по §«Как называть базу докупки (контракт формулировок)»; числа берутся из прогона
`scripts/gate_aware_sizing.py`, не из арифметики в уме.

**База докупки — [X ₽] ([Y]% NAV).** Столько акционная книга может занимать сегодня:
[TICKER1, TICKER2, …] стоят под гейтами и не растут, поэтому докупка открытых бумаг
считается относительно этой суммы, а не относительно плановых [Z]% ([W ₽]).

**Остаток, закрытый для покупок гейтами, — [Z ₽] ([W] пп NAV):** [TICKER — что открывает,
дата/триггер; …]. Гейт без даты — назвать бессрочным явно.

**Классификация поимённо:** открыты к докупке — [TICKER, …]; под гейтом — [TICKER, …];
без сигнала — [TICKER, …]; на срез до плана — [TICKER, …]; на полное сокращение/выход —
[TICKER, …]. «На срез до плана» и «на полное сокращение» — разные вещи: у первого известна
плановая доля, у второго — нет (см. `gate-aware-sizing.md` §«Из чего состоит `F`»,
дискриминатор Rebalancing/Selling).

**Доли к базе (для IntelInvest):** [TICKER1] [X]% · [TICKER2] [Y]% (срез) · …

**Открытые к докупке и на срез:** [TICKER] [факт ₽] → [цель ₽] ([+Δ ₽] ≈ [N лотов] по
[цена] ₽, докупить), … [TICKER] [факт ₽] → [цель ₽] ([−Δ ₽] ≈ [N лотов] по [цена] ₽,
срезать), … Итого: докупить ≈ [сумма] ₽; срезать ≈ [сумма] ₽. Лоты — оценка на цены [дата].

## Тайминг покупок

### [ТИКЕР] — "[Докупка / IE рекомендует]"
- **Триггер**: [ожидание события / отскок / dip]
- **Тайминг**: [сейчас / после X / лимитная заявка на Y]

## Buffer distribution

**Принцип (methodology.md §9.1):** buffer redirect — производный шаг от per-position агрегации, не primary driver. Macro = sizing modifier, не главный аргумент. См. rebalance-framework §6.

### Per-position aggregation
- Σ Δ_i (planned_new − planned_user): **X п.п. L2** ≈ **Y п.п. L1 NAV** ≈ **Z ₽**
- Classification: [hysteresis ≤1 п.п. / intra-stocks 1–3 п.п. / **L1-redirect candidate** >3 п.п. L2 OR >1 п.п. L1]
- **Остаток, закрытый для покупок гейтами** (если в классе есть активный gate/`no_buy` с недостигнутым таргетом): **W ₽** (V п.п. L1) — отдельная строка, кандидат на Шаг 6.2 наравне с `Σ Δ_i` (не implicit-остаток). Полный разбор базы и остатка — в разделе «## Сколько можно докупить» выше; здесь достаточно итоговых чисел. См. `rebalance-framework.md` §6.1.

### Если intra-stocks redistribution
- Priority queue: reviewed_buy_more с idio catalyst > under_review с trigger > IE gap
- Каждое назначение — с forward-аргументом (catalyst, divs, fundamentals, valuation gap)

### Если L1-redirect — Total return table (mandatory)

Числа стресса — из прогона `scripts/stress_digest.py --mode 3`. Провенанс обязателен
строкой над таблицей:

**Макро-срез — `stress-[дата]-[сценарий].yaml` от [дата] (возраст [N] дн).** Горизонт
h12 — до [якорная дата], это [H] мес; дивиденды и купоны масштабируются множителем
[H/12], не 1,00 (горизонты якорные, ключ `hNN` не равен числу месяцев).

Основная колонка — **h12**, вторая (если решение обсуждается на двух годах) — h24 с
собственным множителем из таблицы скрипта. Пороги пропорции применяются к спреду на
колонке, названной основной.

| Side | Component | h12 ([H] мес) |
|---|---|---:|
| **Stocks (top-10 weighted)** | Divs net (× H/12 × 0.85) | X% |
|  | EPS growth × P/E re-rating | Y% |
|  | Σ idio catalyst EV | Z% |
|  | Stress macro EV (`stress_digest`) | W% |
|  | **TR_stocks total** | **N%** |
| **Bonds (per-ISIN)** | Держимые выпуски — carry из `bond_carry` стресса | A% |
|  | Кандидаты вне портфеля: coupons net (× H/12 × 0.87) | A′% |
|  | Кандидаты: capital gain (Duration × Δrate path) | B% |
|  | Кандидаты: − bid-ask spread | −C% |
|  | **TR_bonds total** | **M%** |
| **Spread** (M − N) | | **K п.п.** |

**Держимые облигации:** carry берётся готовым (`expected_carry_pct`), руками не
пересчитывается. **Кандидаты вне портфеля:** [78729 YTM/Dur, 78732, 78744 или эквивалент
через `scripts/moex_quotes.py`] — источник `Δrate_expected` назван явно.

**Непокрытые бумаги:** если у части книги в стрессе нет записи — назвать тикеры/ISIN и
их долю; взвешенный EV считается по покрытым.

**Если стресс старше 60 дней или отсутствует** — таблица не строится: «L1 redirect
отложен: стресс от [дата], +[N] дней» (`rebalance-framework.md` §6.3), buffer остаётся
внутри акций. Остальные разделы Mode 3 выдаются полностью.

### Redirect proportion (по spread, §6.2 правило)
- Spread K п.п. → правило: [≤10 buffer внутрь / 10–20 50:50 / 20–35 70:30 / >35 90:10]
- **Финальная пропорция: P% bonds / Q% stocks**

### Idio carve-outs внутри stocks (если bond bias)
1. [Тикер] — [HIGH-conviction catalyst: дивиденд утверждён ГОСА / Q1 МСФО validated / fresh Mode 4 reviewed_buy_more / regulatory clarification]
2. …

### Caveats
- TR-формула линейная по горизонту (без compound) — соответствует stress-методологии.
- Bond capital gain зависит от rate-path assumption — указать источник (SberCIB / IE / consensus).
- При отсутствии Mode 4 catalyst trees для топ-3 имён — L1 redirect **defer** (§6.3).
```

## Шаблон 7. Fund Selection (подбор фонда для замены сегмента)

**Принципы форматирования этого шаблона (обязательно):**
- Блок "Главный вывод" сразу после заголовка — **структурированный по буллетам**, не один плотный абзац на 6+ строк. Это самая важная часть репорта, она должна читаться за 20 секунд.
- Всё количественно: проценты, TER, годовые эффекты, суммы экономии. Никаких "фонд выглядит привлекательно".

## Шаблон 8. Stock Quality Forward Review

Режим для комбинированных запросов «эффективность прошлая + качество портфеля на 1-2 года + что заменить + тайминг + аргумент». Отличие от Rebalance Opinion: IE — опциональный инпут, центр — per-security XIRR + forward-тезис с геополитическим фильтром. Отличие от Weekly Stocks Review: горизонт 1-2 года, а не 7 дней.

**Предусловие (правило №17):** оба файла обязательны — `Общий баланс.numbers` и `trades_portfolio_*.xlsx`. Без них шаблон нельзя заполнить честно; см. «Старт сессии» в SKILL.md. Если файлов нет — запроси их и остановись, НЕ пытайся заполнить шаблон из web-поиска.

**Принципы форматирования этого шаблона (обязательно):**
- **Realised XIRR — backward-диагностика, не forward-сигнал.** XIRR per-security и XIRR корзины используются как audit-контекст и триггер для проверки тезиса («циклический убыток vs сломанный»), но **не как самостоятельный аргумент для INCREASE/DECREASE/REPLACE**. Forward-аргументы: catalyst tree EV, fundamentals delta (последние 2–4 отчёта), stress-чувствительность по сценариям, valuation gap к IE-target, дивидендная политика на 12м вперёд. См. `analysis-process.md` Шаг 7.5.
- Executive summary двухчастный: (а) количественный диагноз корзины (XIRR акций vs фонды — backward audit; разброс per-security; классификация N / N / N / N **по forward-вердикту**), (б) качественный — 3-5 самых важных выводов.
- **Таблица per-security диагностики ДОЛЖНА включать ВСЕ активные тикеры** — `holdings[]` где `asset_type == "stock"` и `status != "blocked"` (реестр по `references/stocks-methodology.md`; блока `metrics` в snapshot v2 нет). Пропуск тикера допустим только с явной пометкой «TICKER не разобран, причина: X» (например: «данных по эмитенту нет в открытых источниках за 6 мес.»). Выборочное покрытие 5-6 самых «интересных» тикеров из 20+ активных — провал задачи.
- Первая строка ответа — это заголовок с датой, а НЕ макро-обзор рынка. Если хочется начать с «ключевая ставка ЦБ» — стоп, это место для столбца «Forward-тезис» конкретной бумаги или для раздела «Мониторинг», не для шапки.
- Каждая таблица действий (продать / сократить / докупить) имеет **обязательный столбец "Источник тайминга"** с URL пресс-релиза и датой публикации. Строка без источника тайминга считается невалидной — либо источник, либо "дата не объявлена на <сегодня>".
- Макро/геополитика — встроена в столбец "Аргумент" per-security, а не вынесена отдельной простынёй.
- Если рекомендуется замена части корзины на фонд — отдельная секция с расчётом форвардного спреда (ожидаемая доходность корзины vs TER фонда, а не цитата обобщённых утверждений).
- **База весов — L2 (среди акций) для всех per-security числовых полей** (таблица, рекомендации, gap vs target). См. analysis-process.md Шаг 5.7. Сравнение с planned (PRIMARY) / IE-таргетом (secondary) / real ВСЕГДА в L2, потому что эти источники — L2. Если в выводе использован NAV-base (L1), рядом обязателен L2-эквивалент. Self-check перед эмиссией: «сравнение `real X% — target Y%` в одной базе?», «слова "выше/ниже" соответствуют знаку (real − target)?», «target — план владельца, а не молча подставленный IE-таргет?».
