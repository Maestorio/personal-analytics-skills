# Сайзинг акций при частичной заморозке книги (gate-aware sizing)

Вынесено из `stocks-methodology.md` 2026-10-26 без изменений текста (заголовки разделов понижены не были).

## Сайзинг при частичной заморозке акционной книги (gate-aware sizing)

> **Правило только для акций.** Неподвижная точка (`T*`) — база докупки для класса «акции»
> и только для него. Для облигаций и фондов база докупки — плановая, от плана
> корзины/класса: `bonds-methodology.md` (раздел «Шаг 5. Оценка плана по облигациям») и
> `funds-methodology.md`. Причина — вне акций нет per-issuer очереди фундаментальных
> гейтов, блокирующей часть класса на неопределённый срок.

> **Нотация — внутренняя.** `T*`, `F`, `S` и вывод формулы ниже нужны как обоснование
> метода и живут в этом файле и в спеке `docs/investment/gate-aware-sizing-spec.md`. В
> отчёт пользователю они не идут: там — **база докупки** и **остаток, закрытый для покупок
> гейтами**, с числами в ₽ и % NAV, дословно по контракту `output-templates.md`
> §«Как называть базу докупки».

Статус гейта акции вычисляется из её последнего решения (`Portfolio/decisions/`) модулем «последнего слова»
(`last_word.py`): проекция вердикта, срок — `review_by`, пауза докупки — 21 день от первой покупки после решения BUY/ADD
(решение без покупки докупку не закрывает; покупки — по истории снапшотов), IPO-пауза —
по справочнику бумаг, «нужен разбор» — флаг обзора новее решения, «новая» — первая покупка без решения; файла гейтов и
директив гейта нет. В контекст статус приходит выборкой (`security_digest.py`, `prior_digest.py --decisions`);
`gate_aware_sizing.py` считает его сам из `--decisions` и `--security-attrs`.

Применяется, когда среди акций текущего цикла есть хотя бы один тикер со статусом
`review_needed` / активным `no_buy`-constraint — то есть таргет по нему не достигнут,
но докупить его сейчас нельзя. Без этого правила target-₽ для докупки открытых тикеров
дрейфует между сессиями (реальный инцидент: три разных числа для одной ситуации за две
сессии — 169 659 ₽ → 217 839 ₽ → 834 387 ₽ → 657 000 ₽).

### Три варианта денежной базы для докупки

Обозначения: `T_full` = L1-план класса × NAV; `F` = сумма в замороженных/неподвижных
тикерах (не растёт за цикл); `Open` = открытые тикеры этого цикла с целевыми весами
`w_i` (Σ по открытым = `S`, доля от `T_full`).

> **Ловушка: `goals_matrix.Изменение` — не сумма докупки.** Для строки
> `{"Валюта": "RUB", "Бумага": "Акция"}` в `balance_summary.goals_matrix` поле `Изменение` —
> это разрыв до полного плана класса (`T_full`), а не база докупки открытых бумаг. Кейс
> 19.08.2026: за сумму докупки был ошибочно принят `Изменение` = 9 097 398 ₽ вместо верных
> 217 137 ₽ (расчёт от `T*`) — расхождение ×14.

| Вариант | target_i (₽ на тикер) | Вердикт |
|---|---|---|
| A. Текущая факт. сумма акций (`L2_cur`) | `w_i × L2_cur` | ❌ база сама занижена → недобор класса маскируется, разрыв никогда не закрывается |
| B. Полная плановая сумма (`T_full`) | `w_i × T_full` | ❌ открытые бумаги превышают свой же cap относительно РЕАЛЬНОЙ книги |
| **C. Неподвижная точка (принято)** | `w_i × T*` | ✅ единственный вариант без нарушения caps и без маскировки разрыва |

**Формула T\*** (условие самосогласованности — открытые бумаги ровно на целевых
весах, замороженная часть неизменна):

```
T* = F + S·T*  →  T* = F / (1 − S)
```

Gross-up: `F` — фиксированная часть, `(1 − S)` — доля, которую она должна занимать в
итоговой книге. `L2_cur < T* < T_full`, если `F` меньше своей полной целевой доли.

**`T*` ограничен сверху `T_full`.** Если замороженные бумаги стоят выше своей плановой доли
(`F > (1 − S) × T_full`), формула даёт `T* > T_full`, и открытые бумаги докупались бы сверх
плана класса. Поэтому `base = min(T*, T_full)`; сработал предел — `base_source =
fixed_point_capped`, `blocked_gap_rub = 0`, цели открытых = `w_i × T_full`. Срез идёт от той же
базы (неподвижная точка самосогласована, срез от книги — нет). Оба зеркала (`rebalance-engine.js`,
`compute_sizing` → `compute_fixed_point_target(t_full=…)`) считают одинаково.

**Замороженная бумага — в `F` своими рублями (в обоих режимах).** Заблокированная или со словом плана «ждать» бумага
входит в `F` текущими рублями, даже если она выше своей плановой доли: иначе книга после исполнения больше базы и
повторный расчёт даёт новые сделки.
Инвариант обоих режимов: книга после идеального исполнения = база; все бумаги, которые цикл не торгует (заблокированные, «держать», в коридоре), — в `F` своими рублями, доля каждой торгуемой бумаги после сделок = её плану.

**База непрерывная.** `T* = F / (1 − S)` — одна формула при любом составе `F`: блокировок нет, а спящие бумаги есть — та
же неподвижная точка, не `T_full`. Деньги до плана класса идут только в бумаги, которые докупаются сейчас, и только до их
плановой доли базы; без открытых к докупке база = книга после исполнения. `T_full` (`base_source: t_full_no_gates`) —
только когда в `F` ничего нет (все бумаги двигаются к плану). Снятие блокировки меняет базу на вклад этой бумаги, а не на
разрыв до плана класса.

**Разрыв «план − база» — три слагаемых** (поля результата): `gap_gated_rub` — недобор заблокированных бумаг до своей доли
плана; `gap_in_corridor_rub` — недобор (со знаком) спящих: «держать», в коридоре; `gap_unallocated_rub` — доля плана, не
распределённая по бумагам. Каждое — на `(1 − S)`, сумма = `blocked_gap_rub`. В отчёте «закрыто гейтами» — только первое.

**Почему НЕ вариант B**, даже если лишние деньги «просто остаются в кэше/TMON»: cap —
риск-лимит, а не декларация о намерениях. Риск реализуется на **фактически удерживаемой
позиции сейчас**, а не на гипотетической полной книге. При варианте B открытая бумага
занимает долю выше cap в РЕАЛЬНОЙ книге прямо сегодня — на всё время, пока гейт по другим
бумагам не снят (может быть недели, может быть неопределённо долго). Плюс: когда гейт
снимется, придётся подрезать переросшую бумагу, чтобы освободить место — вариант B не
приближает к целевой книге, а создаёт отложенную вынужденную продажу.

### Guard на вырожденность (деление на ноль)

Формула определена только когда `S < 1`. Перед вызовом:

- Если в `F` ничего нет (все бумаги класса двигаются к плану) — `T* = T_full` напрямую, деление не нужно.
- Если `(1 − S) < 0.01` (S близко к 1, но не равно) — **не досчитывать число**: при
  знаменателе, стремящемся к нулю, `T*` численно нестабилен. Fallback на `T_full`
  вручную + флаг на ручную проверку.

Формула выше — обоснование метода, не инструкция к исполнению. Детерминированный расчёт
(не досчитывать в уме) даёт `scripts/gate_aware_sizing.py` (обёртка над
`constraint_engine.compute_fixed_point_target`; см. `analysis-process.md` Шаг 6.1).

### Из чего состоит `F`

`F` — не только gate-заблокированные тикеры. За цикл в классе реально пять категорий:

| Категория | Определение | В `F`? | В `S`? |
|---|---|---|---|
| **Blocked** | таргет не достигнут, активный gate/`no_buy` — купить нельзя | да | нет |
| **Dormant** | таргет достигнут (в пределах hysteresis, Rule 3 — `\|real − target\| < 1 п.п.`) либо нет триггера на пересмотр — купить можно, сигнала нет | да | нет |
| **Open** | есть разрыв к таргету, гейта нет — можно двигать | нет | да (`w_i`) |
| **Rebalancing** | **срез до определённой плановой доли**; после исполнения позиция стоит на `w_i` | нет | **да (`w_i`)** |
| **Selling** | полный выход либо выход траншами без определённой целевой доли | нет | нет |

**Дискриминатор `Rebalancing` vs `Selling`** — один вопрос: *определён ли для позиции
целевой вес после сокращения, и равен ли он её плановой доле?*

- да → `Rebalancing`: позиция входит в `S` со своим `w_i`, `target_i = w_i × T*`, докупка
  выходит отрицательной и равна сумме среза;
- нет (цель 0, либо «выходим траншами», либо цель не задана) → `Selling`: как раньше, вне
  `F` и вне `S`.

Формула устойчива к смешению Blocked и Dormant в одном `F`: Dormant-тикер уже стоит на
целевой доле → не создаёт разрыв `T_full − T*`, разрыв формируется только Blocked-компонентой.
Различать их для самого расчёта не нужно, но нужно **для отчёта пользователю** — иначе
фраза «X% книги недостижимо» вводит в заблуждение, если на деле большая часть `F` — просто
позиции без сигнала, а не позиции под блокировкой.

**Почему `Rebalancing` не в `F`, хотя часть позиции остаётся неподвижной.** Обоснование
исключения `Selling` («он уменьшается, а не остаётся неподвижным») распространяется только
на продаваемую часть позиции. При срезе до плановой доли остаток неподвижен и стоит на
таргете — это `Dormant` по определению выше. Исключать его из `F` целиком (как раньше
делала категория `Selling`, не различавшая полный выход и срез) значит занижать `T*` и
удерживать открытые бумаги ниже их относительных весов — то есть получать тот же дисбаланс
корзины, ради предотвращения которого механизм и введён. Поэтому срез до определённой доли
входит в `S` со своим `w_i`, как и `Open`: арифметически это то же движение к таргету, только
с отрицательным знаком.

Полный выход/срез без определённой целевой доли (`Selling`) — по-прежнему отдельный поток,
не часть `F`: он уменьшается, а не остаётся неподвижным, и его конечный вес не определён, так
что подставить его в `S` со своим `w_i` нечем. Исключается и из `F`, и из `S` до вызова
формулы. Высвобождающийся вес не перераспределяется автоматически — отдельное инвестиционное
решение. Ожидаемая выручка от продажи добавляется в пул кэша на докупку `Open`/`Rebalancing`
отдельно от свежих пополнений — саму формулу `T*` это не меняет.

**Инвариант `L2_cur < T* < T_full`** сохраняется и при наличии `Rebalancing` — с оговоркой:
при крупном суммарном срезе (несколько тикеров одновременно режутся до заметно меньших
плановых долей) рост `S` за счёт `Rebalancing` может приблизить `(1 − S)` к нулю и включить
guard на вырожденность (см. ниже) раньше, чем при том же составе `Open` без тримов — сам
инвариант от этого не нарушается, но диапазон, в котором `T*` считается устойчиво, сужается.

### Правило неразворота

`T*` растёт при снятии каждого гейта, а цель бумаги равна `w_i × T*`. Значит бумага,
срезанная в раннем цикле, в позднем цикле формально может оказаться недобранной —
механическое применение расчёта тогда предписывает выкупить только что проданное.
Симметрично: при появлении нового гейта `T*` падает, и недавно докупленная бумага формально
оказывается в перевесе. Реальный кейс (снапшот 21.08.2026): SBERP режется в цикле 1 до
8% × 14 137 734 = 3 393 054 ₽; в цикле, где дополнительно открыты MOEX и RENI, цель того же
тикера — 3 599 694 ₽, формальный «недобор» 68 880 ₽ (0,48 пп книги).

На горизонте плана (обычно 3–6 месяцев) такой разворот — чистые потери: комиссии обеих
сделок, НДФЛ 13/15% с реализованной при срезе прибыли и обнуление трёхлетнего срока ЛДВ по
вновь купленному лоту. Экспозиция при этом не меняется — правило запрещает именно это,
не движение как таковое.

**Формулировка (редакция §10.3 `docs/investment/spec-gate-aware-sizing-trim-fix.md` —
решение владельца 26.08.2026, отменяет более раннюю и более широкую редакцию §8.2 B3 того
же документа).** Запрещён **разворот**, а не движение:

- движение в ту же сторону, что и предыдущая сделка по бумаге в этом горизонте, —
  **разрешено без ограничений**. Срезали → можно срезать ещё; докупали → можно докупать
  ещё. Ни повторной комиссии на круг, ни НДФЛ с выкупа, ни обнуления ЛДВ здесь нет —
  запрещать нечего;
- подавляется **только** обратное движение: если арифметика для бумаги с зафиксированным
  направлением требует развернуться, бумага принудительно переводится в `Dormant` с
  warning'ом, её сумма возвращается в `F`, а база (`T*`) пересчитывается без нее. Это
  требует итерации: перевод «покупаемого» тикера (`c < w·T*`, т.е. предписана докупка) из
  `S` в `F` строго уменьшает новую базу — из `c < w·T*` следует
  `(F+c)/(1−S+w) < F/(1−S) = T*`. Множество подвижных тикеров на каждом проходе, где
  что-то подавляется, строго сжимается минимум на один элемент, значит проходов не больше,
  чем исходный размер этого множества — зацикливание невозможно, но счётчик итераций и
  предохранитель на непредвиденный случай (warning при недостижении неподвижной точки)
  обязательны;
- **срочная продажа (`Selling`, полный выход) правилу не подчиняется вообще** — приоритет
  `Selling` старше признака зафиксированного направления. Явное решение владельца: если
  нужно срочно продать, на последние операции не смотрим.

**Три уровня защиты**, от самого слабого к самому надёжному:

1. **Гистерезис Rule 3** (`|real − target| < 1 п.п.` по умолчанию) — не даёт реагировать на
   шум внутри одного цикла, но не защищает от суммарного скачка `T*` при одновременном
   снятии нескольких крупных гейтов.
2. **Фиксация направления на горизонт** (признак «по бумаге уже была сделка в этом
   горизонте», `--acted TICKER=buy|trim` в `gate_aware_sizing.py`) — не даёт формальному
   расчёту молча развернуть недавнее решение; снятие признака — не автоматика, а решение
   человека по существенному основанию (смена фундаментального вердикта, разбор Mode 4,
   срабатывание условия, нарушение лимита концентрации).
3. **Обязательная проверка диапазона цели перед сделкой** — по списку обозримых состояний
   цикла (`--cycles`) посчитать цель бумаги в каждом состоянии и явно увидеть, требует ли
   какое-то из них движения в обратную сторону сверх гистерезиса, ПЕРЕД тем как исполнять
   сделку, а не постфактум.

**Требование к списку `--cycles`: он упорядочен во времени, и сегодняшнее состояние в нём
описано.** Сравнение идёт только с состояниями ПОСЛЕ сегодняшнего — уже пройденный этап
разворотом не является (для сегодняшнего C3 падение цели до уровня C2 не значит ничего).
Сегодняшнее состояние опознаётся по совпадению состава подвижных бумаг; если совпадения нет,
проверка идёт против всех состояний сразу и выдаётся warning `cycles_today_state_not_listed` —
лишнее предупреждение безопаснее пропущенного разворота, но основание сравнения при этом
ненадёжно.

Состояния с **меньшим** числом открытых бумаг из списка не выбрасываются: это и есть
«появился новый гейт» — симметричная половина проблемы, с которой начинается этот раздел.
База тогда падает, и недавно докупленная бумага оказывается в перевесе. Ранняя редакция
проверки отбрасывала такие состояния как «недостижимые» и слепла к этому случаю целиком
(правка ревью 27.08.2026).

**Не дробить сделку, если внутри горизонта возможна смена направления.** Если проверка
диапазона (уровень 3) показала риск разворота, это не повод исполнить часть суммы сейчас,
а остаток «на всякий случай» отдельной сделкой позже — дробление создаёт ровно те же
издержки (лишняя комиссия, лишнее событие ЛДВ), которые всё правило призвано убрать.
Решение — исполнять целиком сейчас или отложить целиком до следующего цикла; риск
разворота — предупреждение, а не блокировка, решение принимает владелец.

### Лимиты концентрации

Отдельная от сайзинга проверка — сколько риска несёт КАЖДЫЙ эмитент акционной книги
сегодня, а не куда книга идёт. Постановка — `docs/investment/spec-gate-aware-sizing-trim-fix.md`
§9 (задача C), модуль — `scripts/concentration_limits.py`, конфиг значений —
`references/concentration-limits.yaml`, проводка в `gate_aware_sizing.py` — §11 «Волна 3»
того же документа.

**Знаменатель — фактическая книга `L2_cur`, а НЕ база докупки (`T*`/`T_full`).** Это
принципиально и ПРОТИВОПОЛОЖНО тому, как считаются цели сайзинга: цели размещения — от
базы `T*` (куда книга ИДЁТ, план), лимиты концентрации — от факта (какой риск несётся
СЕГОДНЯ). Обоснование то же, по которому выше отвергнут вариант B: риск реализуется на
фактически удерживаемой позиции сейчас, а не на гипотетической будущей книге. «Унифицировать»
эти два знаменателя ради единообразия — регрессия, а не улучшение: она либо занижает
воспринимаемый риск (если считать по `T*`, который обычно больше `L2_cur`), либо путает
вопрос «что покупать» с вопросом «сколько уже держим».

**Действующие значения (решение владельца 21.08.2026):** один эмитент — 15% книги по
умолчанию; SBER+SBERP (именованное исключение) — 20%; сектор — 35% (принят, но не
активирован, см. ниже).

**Группировка эмитента — из конфига, не эвристикой по суффиксу `P`.** Обыкновенные и
привилегированные акции одного эмитента считаются одной позицией: `{"SBER": ["SBER",
"SBERP"]}` в `issuer_groups`. Правило «тикер + суффикс P» встречается часто, но не
универсально (депозитарные расписки, разные эмитенты с похожими тикерами) — на эвристике
нельзя строить риск-лимит, она сломается на первом же исключении из правила. Тикер, не
упомянутый ни в одной группе, — сам себе группа.

**Именованное исключение — запись, а не число.** Структура: эмитент, значение лимита,
текстовое обоснование, дата пересмотра (`review_date`). Исключение с истёкшей датой
пересмотра **не применяется** — проверка идёт по лимиту по умолчанию, с warning'ом
`exception_expired:<id>`. Исключение БЕЗ даты пересмотра конфиг не принимает вовсе (отказ
загрузки) — это была бы молчаливая отмена лимита навсегда, а не временное решение владельца.

**Реакция на нарушение — срез до лимита, блокирует ДОКУПКУ, а не срез.** Величина среза:
`current − limit × L2_cur` по группе эмитента. Нарушение лимита не даёт тикеру попасть в
`Open` (запрошенная докупка через `--open` блокируется — сильнее, чем ручной флаг:
аналитик риск-лимит вручную не отменяет, в отличие от gate/pending/IPO/user_plan, которые
`--open` преодолевает с warning'ом `manual_unblock`). Срез (`Rebalancing`/`--trim`) этому
правилу НЕ подчиняется — им нарушение и лечится, блокировать лечение бессмысленно.
Блокируется движение ВВЕРХ, а не вниз: если арифметика среза у нарушающей лимит бумаги
разворачивается в докупку (тот же S3-флип, что и в сайзинге, но здесь без предупреждения —
с твёрдым запретом), цель капается на текущую позицию, докупка не исполняется.

Нарушение лимита концентрации также **снимает признак «сделка уже была в горизонте»**
(`--acted`, см. «Правило неразворота» выше) для среза: если тикер недавно докупался
(`--acted TICKER=buy`), а сегодня арифметика требует среза из-за нарушения лимита — обычное
подавление реверса НЕ применяется. Риск-лимит — существенное основание, и оно старше
правила неразворота (в списке существенных оснований для снятия признака в «Правиле
неразворота» выше нарушение лимита концентрации уже названо явно).

**Секторный лимит выключен по умолчанию — гейт на качество данных.** Активируется
отдельным флагом (`--sector`) и обязан отказаться считать, если доля holdings с
`sector: null` в `L2_cur` превышает порог (5% по умолчанию) — считать по данным, где
почти половина книги без сектора, хуже, чем не считать вовсе: это выдать уверенное неверное
число вместо честного «не считается». На снапшоте 2026-08-21 доля `sector: null` — 45,57%
(плюс задвоенные схемы именования, `Финансовый`/`banks_finance`), поле `sector` требует
починки в `portfolio-data-loader` (PDL-I, вне области этого скилла) прежде, чем секторный
лимит можно будет включать по умолчанию.

**Отказ загрузки конфига лимитов не прерывает сайзинг.** В отличие от самостоятельного
запуска `concentration_limits.py` (где конфиг — обязательный вход, деградации нет), внутри
`gate_aware_sizing.py` это риск-надстройка над уже рабочим сайзингом: отсутствие/поломка
конфига лимитов концентрации деградирует с явным warning'ом
(`concentration_check_unavailable:<причина>`), а не останавливает весь разбор — иначе
опечатка в конфиге блокировала бы совершенно не связанный с ним расчёт базы докупки.

> **Не путать с «Concentration cost» из `analysis-process.md` Шаг 7.5.** Это ДРУГАЯ
> проверка: другой знаменатель (доля от ВСЕГО портфеля NAV, а не от акционной книги
> `L2_cur`) и другая роль (эвристический триггер «поставить fundamental gate под сомнение»
> при >7% NAV в одной thin-margin бумаге, а не жёсткий риск-лимит с блокировкой докупки).
> Лимиты концентрации этого раздела — количественная проверка с конфигом, исключениями и
> блокирующим эффектом на сайзинг; Concentration cost Шага 7.5 — качественная эвристика
> внутри анализа одного тикера. Совпадение процента-порога (15%/20% здесь, 7% там) —
> не связанные числа, сравнивать их напрямую не нужно.

### Сколько кэша считать нормальным, пока часть класса под гейтами

Когда база докупки ниже полного плана класса, деньги на разницу **никуда не деваются** —
они лежат в кэше и ждут снятия гейтов. Меряя кэш обычным целевым буфером, эту разницу
каждый раз принимают за «перебор кэша» и предлагают его куда-нибудь пристроить, хотя
пристраивать нечего: место под эти деньги уже забронировано конкретными бумагами.

```
ожидаемый_кэш = 4% × NAV + gap_gated_rub (недобор бумаг под гейтами до их доли плана)
```

**Сравнивать с `cash.liquid_rub`, а НЕ с `cash.total_rub`.** Заблокированные гейтами деньги
стоят не на брокерском остатке, а в money-market фондах (TMON/TPAY/LQDT/SBMM) — снапшот уже
складывает их в `liquid_rub` (`total_rub` + `cash_equiv_rub`). На 21.08.2026: ожидаемый
12 859 281 ₽ против `liquid_rub` 11 871 702 ₽ — расхождение −329 193 ₽, осмысленная величина.
Против `total_rub` 171 246 ₽ вышла бы «нехватка» 96%, то есть правило, которое при
односторонней тревоге молчит всегда и потому бесполезно.

Второе слагаемое на том же снапшоте — 7 718 535 ₽, это 6,0 пп NAV: ровно те деньги, место под
которые уже забронировано бумагами под гейтами.

**Тревога односторонняя — только на превышение.** Кэш ВЫШЕ ожидаемого — повод разобраться:
деньги не работают и гейтами это уже не объясняется. Кэш НИЖЕ ожидаемого — не тревога:
значит буфер частично израсходован, и при снятии гейта на докупку не хватит, но это
обычное рабочее состояние, а не аномалия. Симметричная тревога здесь давала бы ложные
срабатывания на каждом цикле, где что-то докупалось.

**Арифметику считает скрипт, не рассуждение.** `gate_aware_sizing.py` отдаёт блок
`cash_buffer` (ожидаемый кэш, обе составляющие, фактический `liquid_rub`, расхождение со
знаком) и warning `cash_above_expected` при превышении; буфер задаётся `--cash-buffer-pct`
(по умолчанию 4). Правило вынесено из чистого текста намеренно: 19.08.2026 методика сайзинга
уже была записана в референсы — и в тот же день не сработала, за сумму докупки приняли
`goals_matrix.Изменение` (ошибка ×14). Правило, живущее только в тексте, применяется через
раз. За владельцем остаётся решение, что делать с превышением, а не пересчёт формулы.

### L1-таргет класса: потолок/якорь, не квота с дедлайном

Тот же принцип («cap — риск-лимит, не декларация о намерениях»), что решён на уровне
тикера выше, действует и на уровне класса (акции 40% NAV). Throughput-лимит (Rule 2,
≤4 позиции/цикл, `rebalance-framework.md`) сам по себе цель не блокирует — это лимит на
один цикл, а циклы повторяются; пока состав Blocked меняется во времени (гейты снимаются
по календарю, новые открываются под новые триггеры), 40% достижимы за счёт
последовательного прохождения разных тикеров через Open, просто не одномоментно.

Реально блокирует — **состав, не скорость**: сумма весов у тикеров, застрявших в Blocked,
не убывает со временем (гейт бессрочный, без даты/триггера пересмотра). Докупка бумаги без
пройденного фундаментального ревью только ради «добрать план» — вариант B, применённый уже
к целому классу: подмена дисциплины косметикой на уровень выше.

**Критерий: нормальный недобор vs проблема.** При выводе L1 gap («акции X% вместо 40%») —
классифицировать причину по таблице, не давать голую цифру расхождения:

| Причина недобора | Оценка |
|---|---|
| Гейты по конкретным именам не резолвятся, но есть дата/триггер пересмотра | норма — цена дисциплины |
| Throughput (4/цикл) технически не успевает разобрать очередь | зафиксировать отдельно, кандидат на временное расширение cap per cycle |
| Гейт бессрочный, без даты, без решения — «просто висит» | это и есть проблема, но она про конкретный тикер, не про недостижимость 40% в принципе |
| Никто явно не проверял, почему факт ниже плана | дрейф — закрыть проверкой гейтов по выборке решений |

### Слова плана владельца в автоматическом режиме (`--auto`)

`user_plan` решает, что «Сейчас» делает с бумагой за пределами коридора: «держать» — ничего ни при недоборе (dormant, `user_plan:KEEP`), ни при перевесе; «привести к плану» — докупка при недоборе и срез до плана при перевесе; «докупать» — докупка при недоборе, при перевесе ничего; «ждать» — блокировка `user_plan:WAIT`; «продать» — при недоборе ничего (покупка запрещена, dormant `user_plan:SELL`), при любом перевесе срез до нуля без коридора (вес 0 в Rebalancing, лоты вверх, пустой или нулевой план строку не отбрасывает, лимит концентрации на срез не влияет). Причины блокировки собираются полностью в порядке гейт → условия → IPO-гейт и пауза докупки → план и склеиваются через «; » (коды `gate:<статус>`, `pending_buy_condition`, `sell_condition:<id>`, `condition_hold:<id>`, `ipo_gate:<q>q`, `add_cooldown:<дата>`, `user_plan:<слово>`, `no_price`); условие берётся строкой модуля условий — сработавшее и не отмеченное владельцем держит докупку («после отметки владельца»). В базе: «держать» и «докупать» без операции (dormant) — в F по текущим рублям, их вес в S не входит (бумага не торгуется, её рубли ≠ плановый вес × база; иначе книга после сделок не сходилась бы с базой и срез брал бы лишнее или недобирал); в S — только торгуемые (докупка и срез; «продать» — вес 0); «ждать» — в F по текущим рублям; гейты, условия, IPO-гейт, лимит эмитента — в F независимо от слова плана; без блокировок формула базы та же (полный план класса — только когда в F ничего нет). Те же правила — в `rebalance-engine.js` (зеркало, паритет — `test_rebalance_parity.py`).

**Каскад одним расчётом.** Коридор меряется от книги, а сделки «Сейчас» её меняют: срез худеет книгу (соседи уходят выше коридора), докупка растит (ниже). `run_auto` итерирует: сделки → идеальное исполнение в модели → доли от книги после исполнения → переклассификация → снова, пока набор торгуемых бумаг не перестанет меняться; бумага, раз попавшая в сделки, в них остаётся. Предел — число бумаг + 1; база не досчиталась на очередном проходе — результат первого прохода и `cascade.converged = false`. Строки, попавшие в сделки из-за сдвига долей, — `cascade: true`. Повторный расчёт после исполнения даёт ноль сделок. Докупаемая бумага с целью ниже текущей не торгуется и уходит в F.

**Неразворот 14 дней (`defaults.no_reversal_days`, мягкий).** Авто-режим не предлагает докупку бумаги, проданной меньше 14 дней назад, и срез купленной (`no_reversal:<до>`; сделки — по истории снапшотов). Снимает событие позже дня сделки: новое решение по бумаге или правка её плана (слово или доля); цена не снимает. В ручном режиме правило то же, но мягкое: разворот в пределах 14 дней допустим, только если назван снимающий его повод — новое решение или правка плана; без него — не предлагать (для сделок из `--acted` — жёсткое правило неразворота выше).

**Горизонт известных дат (`defaults.known_dates_horizon_days` = 7), только для срезов.** Недобранная заблокированная бумага, у которой все блокировки снимаются в известную дату ≤ сегодня + 7, и на эту дату гейт открыт целиком (модуль (б) на ту дату: не истёк срок решения, нет «наблюдать», «нужен разбор», другой паузы, действующих условий), считается открытой для базы СРЕЗОВ (`base_trim_rub`, срезы меньше), но сегодня не покупается (`opens_on`). Снимаются в срок: пауза докупки, IPO-пауза, условие с датой, ценовое условие с датой начала окна при цене уже за порогом («если цена удержится», `opens_if_price_holds`). Не снимаются в срок: гейт, отчёт или событие, цена без даты.

**Первая покупка.** Тикер плана с `planned_share_pct > 0` и словом «докупать» или «привести к плану», которого нет среди активных акций снапшота, `run_auto` разворачивает в синтетическую строку с долей 0 и стоимостью 0 (`first_buy_candidates`); она проходит те же правила, но гейт должен разрешать: нет решения — blocked `gate:new_position` («после разбора бумаги»); решение есть — статус по нему (старое решение проданной бумаги обычно истекло — `gate:review_aging`). Цена — `quotes@1` (`--quotes`) с лотом, иначе цена IE из `ie_model.positions[].current_price_rub` с лотом 1 (`lot_known: false`), иначе blocked `no_price`. IPO-пауза по справочнику бумаг считается и у бумаги без позиции. Слова «держать», «ждать», «продать» и нулевая доля плана строки не создают.

**IPO-гейт (`defaults.ipo_pause_quarters = 8` кодлистов).** Докупка заблокирована, пока у бумаги в справочнике бумаг `ticker_class: ipo` и `listed_at` + 8 кварталов позже сегодняшней даты (`ipo_gate:<q>q`, снимется в дату конца паузы). Гейт разбором не снимается: вердикт «держать»/«наращивать» его не отменяет, снимает только время (решение владельца 28.10.2026: участие в IPO в прошлом было одной из причин потерь). Он отличается от статуса `new_position`, который про отсутствие разбора.
