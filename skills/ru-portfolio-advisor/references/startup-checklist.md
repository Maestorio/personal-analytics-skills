# Старт сессии — обязательный чек-лист

На первом сообщении пользователя, ДО любого содержательного ответа:

---

**Шаг 0. Запроси Cowork-доступ к Synology (ОБЯЗАТЕЛЬНО, до любого чтения файлов).**

Выполни `Glob("*", path="~/Library/CloudStorage/SynologyDrive-home/Claude-Memory")`.
- Если ошибка или пусто → немедленно вызови `request_cowork_directory(path="~/Library/CloudStorage/SynologyDrive-home/Claude-Memory")` и объясни пользователю: «Нужен доступ к Synology Drive — в каждой новой сессии Cowork доступ нужно давать заново. Нажмите "Разрешить".»
- После получения доступа → повтори Glob. Если снова ошибка → остановись и сообщи пользователю (альтернативного транспорта нет).
- **Не читай никаких файлов и не сообщай об отсутствии snapshot до завершения этого шага.**

**Шаг 0.1. Проверка trust-профиля (если запрошен Mode 1, 3 или 8).**
Проверь наличие `[lib] Invest Era` (или другого ожидаемого источника) в auto-memory.
- Если профиль **есть** — продолжай обычно.
- Если профиля **нет** — в шапке ответа явно укажи:
  > «`[lib]`-профиль `Invest Era` не загружен. Использую консервативные дефолты: облигации = HIGH, макро по ставке = MEDIUM, всё остальное = LOW. Дефолты описаны в `references/trust-hierarchy.md` уровень 2.»
  И продолжай с дефолтами — не блокируй выполнение режима.

**Шаг 1. Определи режимы.** По триггерным фразам запроса (см. раздел «Восемь основных режимов работы» в SKILL.md). Запрос может быть многорежимным — правило №14 требует выполнить все, не редуцировать. Выпиши режимы во внутреннем плане (не в ответ пользователю, если не спросит).

**Шаг 2. Проверь входные данные.** Примени правило №17. Если обязательные входные данные отсутствуют (ни snapshot, ни файлы) — запроси и остановись. Это жёсткий gatekeeper; пропускать нельзя.

**Шаг 2а. Недоступный внешний вход — вопрос владельцу, а не оговорка (IE-ASK).** Если материал, на
который опирается режим, получить не удалось — обзор/стрим/вебинар Invest Era за пейволом, страница
не открылась, файл не приложен, — **остановись и спроси**, ДО расчёта: что нужно, откуда (вставить
текст, приложить файл, ссылка), как без него изменится вывод. Вывод с оговоркой «нет доступа»
допустим только после ответа владельца «доступа нет» / «не нужно». Кейс 16.10.2026, режим 3: в
отчёте «данные IE за пейволом», хотя доступ у владельца есть. (Отсутствие `[lib]`-профиля — не этот
случай: Шаг 0.1, дефолты.)

**Шаг 3. Проверь новизну входных данных.** После получения данных:
- Для Weekly Review (режимы 1, 2): если `snapshot.as_of_date` старше 7 дней — предупреди, что данные могут быть устаревшими, но продолжай.
- Для Returns Analysis, Rebalance Opinion, Stock Quality Forward Review: если snapshot старше 14 дней — попроси обновить через `portfolio-data-loader`.
- Если в snapshot видишь `data_quality_flags` с severity `error` — не галлюцинируй, сообщи о проблеме.

**Шаг 3.5. Загрузи предыдущий обзор — ОБЯЗАТЕЛЬНО для режимов 1 и 2, ДО fan-out.**
Через Glob найди самый свежий `Portfolio/weekly-reviews/weekly-review-{stock|bond}-*.yaml`
и возьми **выжимку**, а не файл целиком (YAML 150–260 КБ):
```bash
python3 scripts/prior_digest.py --prior {прошлый weekly-review-*.yaml} --today {review_date} \
  --conditions {root}/Portfolio/conditions.yaml --decisions {root}/Portfolio/decisions \
  --reports-dir {root}/Portfolio/reports --macro-dir {root}/macro-snapshots
```
`{root}` — корень Claude-Memory (в Cowork `$HOME/mnt/Claude-Memory`, узнаётся через `request_cowork_directory`).
Выжимка даёт вердикты, гейты словами, условия **с заметкой и пометкой «решение владельца»** (уже принято —
не переспрашивать: 26.10 обзор снова спросил о срезе OZON, решённом 16.10), **последний макроснимок с датой**
(ставка, инфляция, курс, Brent, RGBI — не писать «не собирались», если снимок есть), катализаторы с окном, **разборы бумаг после прошлого
обзора** с записанными из них решениями (их вывод — исходная точка, не переоценивать заново; полный отчёт —
точечно), гейт каждой акции из её последнего решения и **устаревшие гейты с последним отчётом по бумаге** — их в
обзоре писать формулировкой из выжимки, а не «нужен разбор» / «гейт устарел» без ссылки на решение. Файлы условий,
решений и отчётов целиком не читать. Имя эмитента для промтов sweep — из прошлого YAML точечно
(`issuer` / первая строка `fundamental_score_basis`), не чтением файла целиком.

Это не то же самое, что Шаг 9.5 (срез ограничений): тот строит `user_constraints`
из условий и плана уже после формирования вердиктов, а здесь нужна **фактическая
база до начала сбора новостей**. Из предыдущего обзора берётся:
- **авторитетное имя эмитента по каждому ключу** (`issuer` / первая строка
  `fundamental_score_basis`) — идёт в промт субагентам яруса 1 вместе с именем из
  `snapshot.holdings[].name`;
- **уже известные факты** (`dividend_forward.policy_state`, объявленные даты отчётностей,
  действующие gate-статусы) — чтобы не искать заново то, что зафиксировано, и чтобы
  ловить противоречия в агентских ответах;
- `carried_over: true` блоки прошлого прогона — им приоритет на переповерку в этом.

Прецедент 15.08.2026: обзор загружался только на этапе сохранения, поэтому в чат ушли
«PLZL платит 30% EBITDA» (дивиденды приостановлены до 2030 — зафиксировано в обзоре 06.08),
«BTBR = BitRiver» (в обзоре 06.08 — B2B-Center) и три «даты не объявлены» при известных
датах. Артефакты пришлось чинить на сохранении, а пользователь читал неверный текст.

**Шаг 3.6. Журнал решений — вопросы об отказах и точность (режимы 1 и 2; AIR-1).**
Выборка, не файл журнала: `python3 scripts/journal_digest.py --root {root} --class stock|bond` (`missing: true` —
журнала нет, шаг пропусти, не создавай).
- `pending_questions[]` своего класса (`stock` для режима 1, `bond` для режима 2) — **в начале ответа,
  до обзора**, задай их списком, дословно (`question`). Каждый вопрос — один раз: журнал сам убирает
  отвеченные и устаревшие, повторять из прошлых сессий нельзя. Ответ «пропустить» — тоже ответ.
  Получив ответы, предложи «сохранить ответы» → save-to-library Workflow P (`refusals.yaml`,
  `episode_id` дословно из `pending_questions`). Владелец не ответил — продолжай обзор, не настаивай.
- `summary.<класс>` — одна строка в шапку обзора: «Прошлые направленные вердикты: созрело N
  эпизодов, верных M (3 мес., против индекса)». Без оценок и выводов — это зеркало, а не вход
  вердиктов (R15): на вердикты этой сессии журнал не влияет.
План и смысл — `docs/investment/portfolio/air-1-decision-journal-plan.md` §7а (в репозитории).

**Шаг 3.7. Бумага пропала из снапшота или количество изменилось без сделки (PDL-SNAP).**
Исходники (`trades*.xlsx`, `.numbers`) **не открывать** — их парсит только `portfolio-data-loader`
(single-ownership), а в облаке у тебя и парсера нет. Порядок:
1. условия и решения по бумаге — `python3 scripts/security_digest.py --root {root} --key K` (закрытые условия —
   `apply_condition.py digest --key K --all`): снятые, «сделал», решение «продать»;
2. снапшот → `data_quality_flags`, `cash_reconciliation` (дрейф кэша на сумму позиции — признак
   продажи вне выгрузки), `reconciliation`;
3. журнал решений по бумаге — `python3 scripts/journal_digest.py --root {root} --key K`;
4. не прояснилось — **один вопрос владельцу** («ЭталонФин5 исчез из снапшота без сделки — продана?»),
   ответ — в `trades_since_prior` / `closed_positions` и caveats; без ответа — «причина не
   установлена», не догадка.
Кейс 16.10.2026: обзор облигаций искал `trades.xlsx` и `.numbers` на Synology, а ответ («продана
владельцем, в снапшоте нет из-за сбоя синхронизации с брокером») лежал в истории условия
`ru000a10est2-above-1310`.

**Шаг 4. Запусти обязательные инструменты режима.** Перечень — в разделе «Восемь основных режимов работы» → `→` пункты под каждым режимом. Для режима 8 — ОБЯЗАТЕЛЬНО: (1) прочитать `returns` и `per_instrument_xirr` из snapshot; (2) запустить `scripts/moex_quotes.py` для свежих котировок; (3) запустить `scripts/stress_digest.py --mode 8` — макро-фильтр и вердикт свежести стресса. Для режима 3 — `scripts/stress_digest.py --mode 3` перед разделом buffer distribution (процедура — `references/stress-reading.md`).

**Шаг 5. Форматируй ответ по соответствующему шаблону: общие правила — `references/output-templates.md`, шаблон режима — `references/templates-weekly.md` (1–2) или `references/templates-other-modes.md` (3–8).** Не изобретай свою структуру. Не начинай ответ с макро-обзора, если шаблон требует Executive summary с количественным диагнозом корзины.

**Провенанс плана в снапшоте.** Откуда план, доли IE, цели и корзины — говорит `plan_check`: `source: plan_only`
и `applied: true` — из `Portfolio/plan.json` сайта на `plan_updated_at` (штатный путь, «Общий баланс» не нужен).
`balance_carried_from` и `balance_summary.carried` относятся только к перечисленным там полям (`iis_positions`,
`names`, `cash_drift` …), а не к плану: писать «план взят из прошлого снапшота» по этим полям — ошибка.
Позиции ИИС-3 — по `iis_positions_source`: `trades_export` — по сделкам выгрузки ИИС-3 (актуальны на дату её последней операции), `balance` — из баланса, `carried` — из прошлого снапшота (одна строка в ограничениях с датой `balance_carried_from`).

## Конкретные требования по файлам (режим → что нужно)

| Режим | Входные данные |
|---|---|
| 1 (Weekly Stocks Review) | Snapshot обязателен |
| 2 (Weekly Bonds Review) | Snapshot обязателен |
| 3 (Rebalance Opinion) | Snapshot обязателен; стресс опционален — без него откладывается только L1-redirect |
| 4 (Single Analysis) | Snapshot обязателен; для доходности — нужен `per_instrument_xirr` в snapshot |
| 5a (Fund Analysis конкретного фонда) | Snapshot обязателен |
| 5b (Fund Selection) | Опциональны, можно без snapshot |
| 6 (Returns Analysis) | Snapshot обязателен (нужен блок `returns` + `per_instrument_xirr`) |
| 7 (ИИС-3 Buy Advice) | Snapshot + сумма пополнения |
| 8 (Stock Quality Forward Review) | Snapshot обязателен (нужен полный v2 с `per_instrument_xirr` по всем активным акциям); стресс не старше 60 дней, иначе режим не выполняется |

## Активация при отсутствии данных

Advisor **не активируется по существу**, если:
- В сообщении не приложен snapshot И
- В `Portfolio/snapshots/` нет свежего snapshot (< 14 дней) через transport-layer И
- Пользователь не дал явной команды работать без данных

Без файлов пиши только: «Для этого анализа нужны данные. Проще всего: (а) если snapshot уже есть в `Portfolio/snapshots/` — дай мне доступ к нему; (б) если нет — запусти `portfolio-data-loader` с `Общий баланс.numbers` + `trades_portfolio_*.xlsx`.» И остановись.
