# Rebalance Opinion Framework

Пользователь использует балансировку от Invest Era как мнение, но не 1:1. Задача скилла — дать осмысленное мнение о том, стоит ли следовать новой ребалансировке IE целиком, частично, или использовать собственные веса. Плюс подход к тому, "стоит ли сейчас продавать бумаги к продаже или подождать".

## METH-2: Mode 3 — Reader-only по gate

Mode 3 — **не** updater fundamental gate (это Mode 4/8). Mode 3 берёт inherited gate из выборки решений
(`security_digest.py --key` по бумаге или `decision_write.py digest --key`: гейт — проекция последнего решения)
и применяет stability constraints. Решение ребалансировки по бумаге, если оно есть, — запись в `decisions:` шапки
отчёта. См. `docs/investment/portfolio/new_met.md` §3.9–§3.10.

### Иерархия target (METH-2)

- `planned_share_pct` — primary target (из snapshot.ie_actual.per_ticker[T]). Разрывы
  считаются к этому полю, пока оно не `null`.
- `ie_new_pct` — secondary signal, применяется **только** когда `planned_share_pct == null`
  (fallback) — и тогда в reasoning явной пометкой отмечено, что использован fallback
  (тикер и причина отсутствия planned). Не подменяет planned, когда оно задано.
- `real_share_pct` — текущее положение.

Таблица долей выводит `planned_share_pct` и `ie_new_pct` **всегда парой** — правило
парных колонок, `analysis-process.md` Шаг 5.

**База: все три поля — L2 (% среди акций для акций; % среди облигаций для бондов).** См. analysis-process.md Шаг 5.7. Caps в "п.п." ниже — тоже L2-проценты-пункты. Аллокация классов (Акции 40% / Облигации 50% / Кэш 4% / Другое 6%) — отдельный L1-уровень, не путать с per-security caps.

### Stability rules (4 правила)

1. **Cap per position per cycle** — таблица caps по статусу (см. ниже); все п.п. — L2
2. **Cap per cycle** — ≤4 позиции за один rebalance, приоритет: gate=broken → under_review с trigger → drift ≥2 п.п. (L2)
3. **Hysteresis** — не двигать если `|real - target| < 1 п.п.` (L2) И нет триггера
4. **Continuity check** — прочитать предыдущий weekly-review, не разворачивать verdict без gate-flip объяснения

### Таблица caps по gate status

| Status | Cap drift | INCREASE разрешён | REDUCE разрешён |
|--------|-----------|-------------------|-----------------|
| `new_position` (≤4 нед в портфеле) | 0.5 п.п. | да (small) | да |
| `none` (нет записи) | 1.0 п.п. (×0.5 от обычного) | нет | да |
| `review_needed` | **skip** в блок `pending_review` | — | — |
| `reviewed_keep` | 1.0 п.п. (default) | да | да |
| `reviewed_buy_more` | 1.0 п.п., приоритет в queue | да | да |
| `reviewed_under_review` | 1.0 п.п. | нет | да |
| `review_aging` | 1.0 п.п. | нет | да |
| `reviewed_reduce` | 40% позиции за цикл | нет | да (план Mode 4) |
| `divested` | ignore | — | — |

### Блок pending_review

Mode 3 выводит отдельный markdown-блок:

```markdown
## Pending Gate Reviews

Эти позиции в текущем цикле НЕ обрабатываются ребалансом — требуется Mode 4:

| Тикер | Status | Установлено | Trigger |
|-------|--------|-------------|---------|
| SBER  | review_needed | 2026-05-13 mode_1 | Q1 NIM упал с 5.8% до 4.7% |
```

После Mode 4 пересмотра — в следующем Mode 3 эти тикеры доступны для действий.

### Carve-outs

- **Полный гейт-крах на крупной позиции** (banker's-style: банкротство/делистинг/санкция против эмитента) — Правило 1 (40% cap) отменяется, выход за 1 цикл оправдан. Признак — код события из `references/critical-events-list.md` (closed enum) в обосновании бумаги.
- **Налоговая оптимизация** (закрытие года, ИИС-3 окончание периода) — Cap per cycle расширяется до 6–8 (только в декабре или при триггере IIS).
- **Денежная база cap'а при частичной заморозке класса** (только акции — gate-aware
  sizing, `docs/investment/gate-aware-sizing-spec.md`): если в классе акций есть хотя бы
  один тикер под активным gate/`no_buy` с недостигнутым таргетом — Cap per position
  (Правило 1) оценивается относительно **базы докупки** (то, во что акционная книга
  может вырасти сейчас, пока часть бумаг стоит под гейтами), а не относительно полного
  плана класса. Без гейтов в классе — относительно факт. `L2_cur`, как обычно. Никогда не
  относительно полного плана класса, пока в классе есть хоть один активный блокирующий
  gate/constraint — иначе открытая бумага формально проходит cap-проверку, но фактически
  превышает риск-лимит на РЕАЛЬНО удерживаемой книге (см. `gate-aware-sizing.md`
  §«Сайзинг при частичной заморозке», вариант B). Базу докупки считает скрипт, не
  рассуждение: `python3 scripts/gate_aware_sizing.py --snapshot <snapshot> --open
  <TICKER,...>` (вызов в процессе — `analysis-process.md` Шаг 6.1).

   > строки `RUB × Акция` `Изменение` показывало 3 032 466 ₽, реальная сумма докупки

## Шаг 1. Diff IE New vs IE Old

Для каждого тикера, где `IE New != IE Old`:
- Что изменилось (+/- п.п.).
- Если IE опубликовали обоснование (на сайте Invest Era) — прочитай и кратко цитируй.
- Оцени своё отношение к этому изменению.

## Шаг 1а. Категория доверия для каждого изменения IE

Перед оценкой каждого `IE New != IE Old` определи доверительную категорию тикера по `references/invest-era-profile.md`:

- 🟢 **HIGH** (negative-list по акциям и облигациям; конкретные облигационные выпуски с YTM и офертой; тактические точки входа на коррекциях ≥10%; тайминг шагов ставки ЦБ) — следовать как сильному сигналу
- 🟡 **MEDIUM** (большие имена с понятным фундаменталом — PLZL, SBER, MOEX, RENI; ставочные акции при подтверждённом цикле снижения) — фильтровать через брокерский консенсус
- 🔴 **LOW** («бенефициары снятия санкций» — NVTK, FLOT, AFLT, UPRO; геополитические таргеты; курсовые прогнозы; «вершины цикла» по сырью; bias против ОФЗ) — флагировать, дисконтировать вес ≥50% или предлагать не следовать

**Если IE New ПОВЫШАЕТ вес LOW-категории на ≥2 п.п.** (особенно NVTK / FLOT / AFLT / UPRO) — это автоматический сигнал к разбору с предложением «не следовать». Указать пользователю историю промахов IE по этому кластеру (3/3 вебинара) и применить системные дельты для контрсигнала из `invest-era-profile.md`.

**Если ≥3 IE-изменений приходится на LOW-категорию** — эскалировать модель на Opus (см. правило №21), потому что фильтрация требует много рассуждений по каждой бумаге.

**Проверка триггеров пересмотра профиля IE (правило №20):** перед применением фильтра HIGH/MEDIUM/LOW кратко проверь, не сработал ли какой-то из триггеров T1–T6 (окончание СВО, снятие SDN, ставка к нейтральной, возврат нерезидентов, 6 мес. с пересмотра, новый аудит). Если да — добавь в шапку ответа предупреждение «профиль IE построен на режиме 2024–2026, текущий рынок может вести себя иначе» и применяй фильтр с дополнительной осторожностью.

## Шаг 2. Сравнение позиций пользователя с IE New

Для каждого тикера (все три — L2, % среди акций):
- `Доля Планируемая` (что пользователь сейчас считает правильным, planned_share_pct) vs `IE New` (что IE предлагает, ie_new_pct).
- `Доля Реальная` (что по факту в портфеле сейчас, real_share_pct) vs `Доля Планируемая`.

**Три типа расхождений:**

1. **Осознанное расхождение.** Пользователь сам решил держать больше/меньше IE. Например, SBER 10% у пользователя vs 6% у IE. Не пытайся "исправить" без веской причины. Скорее подтверди его позицию или укажи новый триггер, меняющий картину.

2. **Дрейф из-за цен.** Доля реальная отошла от доли актуальной из-за движения котировок. Например, Полюс вырос — его доля реальная выше актуальной. Здесь предложи ребаланс: продать часть, купить отстающие.

3. **Позиция к закрытию/сокращению.** В колонке "План" (или "Статус") стоит "Продать", "Сокращение на X%", "Докупка". Пользователь уже определился. Твоя задача — оценить тайминг.

## Шаг 3. Тайминг продаж и покупок

Когда в файле стоит "Продать" или "Сокращение", пользователь спрашивает: продать сейчас или подождать.

**Критерии "продать СЕЙЧАС":**
- Негативный триггер произошёл и рынок ещё не полностью переварил (опережающий сигнал).
- Отчётность/корп.событие слабое, консенсус ещё не пересмотрел таргеты.
- Рост цены против фундаментала ("продать в рост").
- Регуляторные или санкционные риски приближаются.

**Критерии "подождать":**
- Ожидается позитивное краткосрочное событие (дивиденды, отчёт, корп.новость).
- Технически бумага в зоне поддержки — может отскочить.
- Рынок в коррекции, продажа усугубит просадку.
- Ликвидность низкая, продажа сдвинет цену.

**Частичная продажа:**
- Если тезис пока не сломан, но вес избыточен → продать часть, оставить "ногу" на потенциальный upside.

Для каждой позиции из списка "к продаже" дай конкретный ответ: **продать сейчас / подождать до события X / частично**, с обоснованием.

## Шаг 4. Макро-распределение

Проверь матрицу Валюта × Тип. Отклонения:

Из файла пользователя на 14.04.2026 (пример — реальные цифры пересчитывай!):
- RUB-Акция: 38.2% vs план 40% → недовес 1.8 п.п., в пределах шума.
- RUB-Облигация: 18.3% vs план 20% → недовес 1.7 п.п.
- USD-Облигация: 22.7% vs план 10% → **сильный перевес 12.7 п.п.**
- EUR-Облигация: 4.3% vs план 10% → недовес 5.7 п.п.
- CNY-Облигация: 6.7% vs план 10% → недовес 3.3 п.п.

Сумма валютных: 33.7% vs план 30% → перевес, но внутри USD сильно перетянут. Классический кейс, где внутренние перекосы существеннее общей суммы.

**Что рекомендовать:**
1. Констатация "USD перегружен" бесполезна — пользователь и так видит.
2. Рекомендация "продать USD, купить EUR/CNY" — только если есть макро-аргумент.
3. Рекомендация "пересмотреть план с 10/10/10 на 15/8/7" — если USD-замещайки дают существенно лучший YTM при том же риске.

Для каждого решения — аргументация:
- USD-замещайки дают спред Y bps к UST → адекватная или нет?
- CNY-замещайки при укреплении юаня vs ослаблении → стратегический взгляд?
- EUR — где эмитентная база (Газпром, НОВАТЭК), какие риски?

## Шаг 5. Доли типов активов (Акции vs Облигации) — L1 от NAV

Текущие доли vs "Общие планы" (все цифры — L1, % от NAV; для per-security сравнений см. Шаг 2 в L2):
- Акции: план 40%, в файле 38.2%.
- Облигации: план 50%, в файле ~52%.
- Золото TGLD: план 3%, факт 2.0% (USD-Другое).
- Другое Рентал ПРО: план 3%, факт 1.8% (RUB-Другое).
- Кеш: план 4%, факт 4.9%.

Расхождения небольшие. Но если макро-картина меняется, обсуди изменение плана:

**Аргументы для повышения доли акций (с 40% до 45%):**
- Устойчивый цикл снижения ставки → переоценка акций вверх.
- Фундаментальная недооценённость рынка (индекс P/E низок исторически).
- Геополитическая разрядка.
- Высокий реальный ВВП-рост.

**Аргументы для понижения доли акций (с 40% до 35%):**
- Ускорение инфляции / цикл повышения ставки.
- Санкционная эскалация.
- Фискальный кризис (бюджетный дефицит + высокая долговая нагрузка).
- Сильный рост корп.рисков и дефолты.

**Аргументы для повышения доли облигаций:**
- Пик ставки пройден → дюрационная игра на ОФЗ.
- Ставка высока исторически → YTM жирные и по корп.

**Разграничение со Шагом 6:** этот шаг — про **долгосрочный** пересмотр L1 targets (40/50/4/6) при структурных макро-сдвигах (rate cycle, sanction escalation/relief, фискальные шоки). Tactical **per-cycle** redirect buffer от per-position решений — отдельная задача, см. Шаг 6.

## Шаг 6. Tactical buffer distribution (per-cycle)

После Шагов 2–4 сформирован вектор `Δ_i = planned_new_i − planned_user_i` по активным тикерам. `Σ Δ_i` = buffer (в L2 п.п. среди акций). Buffer может быть положительным (freed from trims) или отрицательным (need add from elsewhere).

**Правило иерархии (methodology.md §9.1):** per-position decisions формируются **первыми** на основании fundamental gate + idio catalysts + macro как sizing modifier. Buffer distribution — **производный** шаг от агрегации, не primary driver. Macro в рамках Mode 3 — modifier, не главный аргумент.

### Шаг 6.1. Классификация buffer

| Размер buffer | Действие |
|---|---|
| ≤ 1 п.п. L2 (~50K ₽ на типичном NAV 13M) | fold into hysteresis, не редистрибутить |
| 1–3 п.п. L2 | distribute внутри stocks по priority queue (reviewed_buy_more с idio catalyst > under_review с trigger > IE gap) |
| > 3 п.п. L2 OR > 1 п.п. L1 NAV | candidate на L1 redirect (stocks → bonds/fund/cash). **Mandatory** Шаг 6.2 |

**Остаток, закрытый для покупок гейтами.** Buffer по активным тикерам (`Σ Δ_i`,
выше) — не единственный источник. Если в классе есть заблокированные гейтом тикеры,
часть L1-плана класса недостижима по построению до снятия гейта (методика —
`docs/investment/gate-aware-sizing-spec.md` §5, `gate-aware-sizing.md` §«Сайзинг при
частичной заморозке»). Это и есть остаток, закрытый для покупок гейтами: сумма в ₽ и в
пп NAV, и что его открывает — поимённо, по каждому тикеру, с датой или триггером (гейт
без даты называется бессрочным явно). Считает `scripts/gate_aware_sizing.py`. Эта сумма —
обязательная отдельная строка классификации buffer, кандидат на Шаг 6.2 наравне с
`Σ Δ_i`, а не implicit/ручной остаток. В отчёте разделять явно: «buffer от активных
тикеров» vs «остаток, закрытый для покупок гейтами» — это разные источники с разным
горизонтом разблокировки (первый закрывается within-cycle, второй — по календарю
пересмотра гейта).

### Шаг 6.2. Total return сравнение при L1 redirect (mandatory)

Если buffer кандидат на L1 redirect — пересчитать total return для двух сторон.
Все числа стресса приходят из прогона `scripts/stress_digest.py --mode 3`
(процедура и поля — `references/stress-reading.md`), не из чтения YAML фрагментами.

**Горизонт.** Основной срез — **h12** стресса, вторая колонка — h24. Ключ `hNN` не равен
числу месяцев: горизонты якорные, реальная длина берётся из `horizon_ends` и печатается
скриптом (для прогона 15.08.2026 h12 = 10,5 мес, h24 = 22,5 мес). Множитель `H/12` —
из колонки «множитель», не литеральные `12/12` и `24/12`. Пороги пропорции ниже
применяются к спреду **на срезе, названном основным в таблице**.

**Свежесть.** Стресс старше 60 дней или отсутствует → L1-redirect **defer** (§6.3),
buffer остаётся внутри акций; 30–60 дней → считаем, но пропорция помечается «проверить
после refresh». Лестница целиком — `references/stress-reading.md` §2.

**Stocks side (top-10 weighted по `real_share_pct` в оставшейся корзине):**

```
TR_stock_i = DivYield_12m × (H/12) × (1 − 0.15)         # divs net of tax, H — реальные месяцы среза
           + EPS_growth × P/E_re_rating_factor          # fundamental delta
           + Σ idio_catalyst_EV (из Mode 4/8 inherited) # idiosyncratic
           + stress_macro_EV_i                           # macro contrib, из stress_digest.py

Σ Stocks TR = Σ_i (real_share_pct_i × TR_stock_i)
```

Взвешенный `stress_macro_EV` по top-10 и по всей книге скрипт считает сам; там же —
список бумаг, которых в стрессе нет (их доля не должна молча уходить в ноль).

**Bonds side (per-instrument, НЕ кластер).** Две разные группы, в отчёте не смешиваются:

1. **Держимые выпуски** — carry берётся готовым из `bond_carry` стресса
   (`expected_carry_pct` на срезе: купоны + pull-to-par + fx + reinvest, взвешено по
   сценариям, с CI и реальным `t_live_months`, обрезанным погашением или офертой).
   Пересчитывать их руками не нужно — это лишнее допущение о траектории ставки поверх
   уже посчитанного.
2. **Кандидаты вне портфеля** (например, длинные ОФЗ 78729 / 78732 / 78744, если их в
   книге нет) — YTM и duration через `scripts/moex_quotes.py` или MOEX ISS на дату отчёта:

```
TR_bond_j = Coupon_annual × (H/12) × (1 − 0.13)         # coupons net
          + Duration_j × Δrate_expected                  # capital gain at rate path
          − bid_ask_spread_pct                           # transaction cost
```

Источник `Δrate_expected` называется явно (SberCIB / IE / consensus). Если конкретный
bond mix не выбран — построить min-3 кандидата (короткая ОФЗ, средняя ОФЗ, корп AAA) и
взять weighted by intended allocation.

**Redirect rule (по spread = TR_bonds − TR_stocks):**

| Spread | Пропорция redirect | Семантика |
|---|---|---|
| ≤ 10 п.п. | buffer **внутри** stocks (idio catalysts dominate) | spread узок, дивиденды + idio перекрывают bond carry advantage |
| 10–20 п.п. | 50/50 stocks/bonds | смешанный сигнал, hedge |
| 20–35 п.п. | 70/30 bonds/stocks | структурный bond bias, idio HIGH-conviction carve-outs |
| > 35 п.п. | 90% bonds | strong structural bond bias, тактический stocks exit |

**ЗАПРЕЩЕНО** обосновывать L1 redirect только stress-EV cluster spread (`EV_stocks_cluster − EV_bonds_cluster`) — он пропускает:
- Дивиденды акций за 20 мес (топ div payers дают +20-25 п.п. к stocks TR)
- Idio catalysts (Q1 МСФО profitability inflection, gate-corrected reviewed_buy_more)
- Instrument-specific bond carry (длинные ОФЗ при rate-cut дают +30-36% за 20 мес vs cluster average +18%)

### Шаг 6.3. Carve-out — нет catalyst tree inheritance

Если Mode 4/8 не предоставили idio catalysts для топ-позиций (в последних отчётах разбора по бумаге
нет per-ticker catalyst trees) **или** макро-сторона недоступна (стресса нет / он старше
60 дней — `references/stress-reading.md` §2), `TR_stock` пересчёт неполный. В этом случае:
- L1 redirect **defer** до следующего Mode 3 после Mode 4 для топ-3 имён
- Buffer остаётся внутри stocks с минимальными движениями (priority queue по §6.1)
- В отчёте явно зафиксировать причину: «L1 redirect отложен, ожидаются catalyst trees для
  [тикеры]» либо «L1 redirect отложен: стресс от `<дата>`, +`<N>` дней»

Не считать на incomplete TR — это вернёт ту же ошибку, что v3 от 2026-05-16.

### Шаг 6.4. Continuity vs previous Mode 3

Если предыдущий Mode 3 уже redirect'нул buffer через L1 (например, 70/30 bonds/stocks), новый Mode 3 не должен разворачивать пропорцию без:
- Gate-flip на топ-3 позиции (новый idio catalyst), ИЛИ
- Structural macro-trigger (rate cycle inflection, sanction event, фискальный шок), ИЛИ
- Refresh stress-теста с существенно изменёнными EV (сравнивается срез с тем же ключом
  горизонта; смена `run_id` сама по себе не аргумент)

### Шаг 6.5. Idio carve-outs внутри stocks

Даже при сильном bond bias (spread > 20 п.п.), часть buffer допустимо вернуть в stocks для позиций с **HIGH-conviction idio catalysts**, не зависящих от макро-сценария:
- Дивиденд утверждён ГОСА (факт, не прогноз)
- Q1/H1 МСФО с validated profitability inflection
- Reviewed_buy_more с свежим Mode 4 (<30 дней)
- Regulatory clarification устранила tail risk

Список carve-outs ограничен ≤5 позиций, обоснование — по каждой отдельно.

## Расхождения пользователя с IE (кейсы, которые пользователь уже обозначил)

Пользователь явно сказал: "в акции Мосбиржи или Сбербанка я больше верю". То есть:
- SBER/SBERP у пользователя выше, чем IE (10%+9% vs 6% IE по одному).
- MOEX у пользователя 10% vs отсутствует в IE-модельном портфеле.
