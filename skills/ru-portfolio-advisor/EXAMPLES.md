# Примеры использования ru-portfolio-advisor

Готовые промты для 9 режимов + рекомендуемые модели, уровень effort и web search, стиль ответа.

> Актуализировано: 2026-10-13.
>
> **SYNC:** меняешь здесь режимы, промты, модели или effort — поправь и справку вьюера
> `tools/assets/help/viewer/02-models.md` в репозитории (на сервер — деплоем), таблица «Режимы советника» `{#modes}` (пользовательское зеркало).

> **Главный принцип (2026-07): промт несёт только дельту.** Стандартные проверки каждого
> режима зашиты в скилл (SKILL.md + references) — их НЕ нужно перечислять в промте.
> У каждого режима ниже есть блок **«Что скилл сделает сам»** — это зеркало обязательных
> шагов методологии. В промте остаётся: период/горизонт, фокус, ограничения, нестандартный формат.

Входные данные:
- **Режимы 1–8**: скилл сам читает `Portfolio/snapshots/portfolio-<latest>.json` (snapshot v2, age ≤ 14 дней) из Claude-Memory через Synology mount. Snapshot генерируется `portfolio-data-loader`.
- **Режим 6** (Returns Analysis): данные уже в snapshot — блоки `returns` и `per_instrument_xirr`. Ничего прикладывать не нужно.
- **Режим 9** (Conditions): pure-CRUD работает без snapshot; `evaluate`/`fire` требуют цен → snapshot.
- **Ничего не прикладывать** — скилл сам запросит Cowork-доступ и прочитает файлы.

**Прогнозы и сценарии (Claude-Memory/forecasts/, scenarios/)** используются только upstream-скиллами:
- `macro-forecast-chain` → `portfolio-scenario-stress` → `Portfolio/stress/stress-*.yaml`
- ru-portfolio-advisor читает stress-файл в двух режимах: ребалансировка (Mode 3) и оценка качества акций на 1–2 года (Mode 8) — прогоном `scripts/stress_digest.py --mode 3|8`, не руками. Mode 8 при stress старше 60 дней отказывает; Mode 3 деградирует: откладывается только перенос денег между классами (L1-redirect), остальное выполняется полностью. В режимах 1, 2, 4–7 stress-файл не нужен.

Обозначения в таблицах:
- **Effort** — сколько модель думает перед ответом: low / medium / high / xhigh / max. Выше — точнее на сложных решениях, но дольше и дороже по квоте. **max не рекомендуется** — расход без выигрыша для задач скилла. Отдельного переключателя «Extended Thinking» больше нет: глубину задаёт только effort.
- **Effort мин.** — ниже не опускаться (качество обзора упадёт); **Effort опт.** — рекомендуемый уровень.
- **WS** — обычный Web Search
- **—** — не требуется

> ⚠ **Deep Research для режимов скилла не используется** (правило №18 SKILL.md): это
> субагент, не читающий SKILL.md — теряются охват тикеров, шаблоны, per-security XIRR.
> Все режимы решаются через snapshot + точечные web_search.

Общие настройки на уровне проекта:
- Системная инструкция: "Отвечай на русском, структурно, списки вместо длинных параграфов. Для каждого фактологического утверждения — ссылка на источник с датой. Не добавляй дисклеймеры вида 'это не инвестиционная рекомендация'."
- Стиль ответа по умолчанию: `Explanatory` или кастомный "структурный, технический".

## Режим 1. Обзор акций за неделю (Weekly Stocks Review)

Запускается раз в неделю (например, понедельник утро).

| Модель | Effort мин. / опт. | WS |
|---|---|---|
| **Sonnet** | medium / **high** (лёгкий вариант: low / medium) | да |

### Что скилл сделает сам (не повторять в промте)

- **В начале ответа задаст накопившиеся вопросы об отказах** из журнала решений (выборка `journal_digest.py`, каждый вопрос — один раз): отвечай до обзора (можно «пропустить»); не ответил — обзор идёт дальше. Ответы сохраняются через save-to-library.
- **Загрузит предыдущий обзор до сбора новостей** — имена эмитентов, уже известные факты и дивидендная политика берутся оттуда, а не ищутся заново.
- При ≥5 тикеров **сбор новостей делегирует субагентам** (fan-out), сам поиски не выполняет.
- Реестр тикеров — строго из snapshot: активные `holdings` (stock, не blocked) + планируемые (`planned_share_pct`) + кандидаты IE (`ie_summary.list_in_ie_not_in_portfolio`). Выборочно «интересные» не выбирает.
- Классификация каждой позиции по 5 тегам: СРОЧНО ПРОДАТЬ / СРОЧНО ДОКУПИТЬ / ДЕРЖАТЬ-НАБЛЮДАТЬ / ПОДУМАТЬ О СОКРАЩЕНИИ / НЕТ НОВОСТЕЙ (одной строкой в конце).
- **Таблица покрытия R-COV**: по каждому тикеру — проверен (дата) / carry-over / не проверен + причина. «Проверено всё» без таблицы — запрещено.
- **Условия**: только читает выборку (`apply_condition.py digest`) и сверяет вердикты (`crosscheck`); ⏳/✅ блок в отчёте, явная резолюция каждого сработавшего. Условий не пишет — закрыть или перенести: кнопка на сайте или «перенеси условие …» (Режим 9).
- **Гейты**: берёт из последних решений; при hard-триггере — флаг «Нужен разбор» у бумаги в обзоре.
- **IE-дисциплина**: таблица отклонений ≥1.5 пп + дрейфы без записанного решения.
- **IPO-гейт** (правило №23): `listing_age_quarters < 8` → BUY/ADD запрещён.
- **Горизонты**: если не заданы — спросит «прошлый или новый?» по предыдущему обзору.
- Оценка целевой доли акций — от `balance_summary` (goals_overall).

### Промт

```
Сделай еженедельный обзор акций с последнего отчёта.
Подготовь файлы для сохранения.
```

Всё. Период («за 7 дней» / «с последнего отчёта»), фокус («особое внимание банкам»)
и нестандартный формат — единственное, что имеет смысл добавлять.

### Альтернативный лёгкий вариант

```
Быстрый обзор акций за неделю: только явные триггеры — отчёты, рейтинговые
действия, скачки цен >±10%, громкие новости. Для каждого флага: 1 строка + ссылка.
Без детального разбора позиций и без файлов для сохранения.
```

⚠ В лёгком варианте таблица покрытия честно покажет большинство тикеров как
«не проверен (лёгкий режим)» — такой обзор нельзя сохранять как полноценный weekly.

## Режим 2. Обзор облигаций за неделю (Weekly Bonds Review)

| Модель | Effort мин. / опт. | WS | Зачем |
|---|---|---|---|
| **Sonnet** | medium / **high** | да | Фокус на макро + рейтинговые действия + кредитные события. Effort — для оценки кривой и дюрации. |

### Что скилл сделает сам (не повторять в промте)

- **В начале ответа задаст накопившиеся вопросы об отказах** из журнала решений (выборка `journal_digest.py`, по одному разу) — отвечай до обзора.
- **Загрузит предыдущий обзор до сбора новостей**; при ≥5 эмитентов **сбор новостей делегирует субагентам**.
- Рейтинговые действия (АКРА, Эксперт РА, НКР, НРА) по эмитентам портфеля.
- Сущфакты e-disclosure по замещайкам и ВДО (оферты, дефолты, купоны).
- Макро-фон: решения ЦБ, инфляция, доходности ОФЗ, комментарии.
- Валютная картина USD/EUR/CNY: инфраструктура замещаек, спреды к UST/Bund.
- Отклонения от плана по всем 9 корзинам — план↔факт строго из готового блока
  `balance_summary.bonds_plan_vs_fact` (не кэшируется между сессиями), с учётом
  компенсации внутри валютного блока и отдельно — оси срока ОФЗ (`>10`/`<10`),
  флоатеров и кредитной лестницы `AA+`/`A`/`B+` у корпоратов.
- YTM везде (никаких «текущих доходностей») — правило №2 SKILL.md.
- При макро-аргументах за пересмотр плана — конкретные новые цифры.

### Промт

```
Сделай обзор облигаций с последнего анализа.
Подготовь документы для сохранения в памяти.
```

## Режим 3. Ребалансировка (Rebalance Opinion)

Запускается, когда Invest Era публикуют новую ребалансировку (пользователь переносит
веса в Numbers → data-loader кладёт их в snapshot), или когда нужно общее мнение.

| Модель | Effort мин. / опт. | WS | Зачем |
|---|---|---|---|
| **Sonnet*** | high / **high** (на Opus*: high / xhigh) | — | Задача рассуждения, не сбор данных. Точечный поиск — добавь в промте «по необходимости используй поиск». |

### Что скилл сделает сам

- Изменения IE — строго из snapshot `ie_actual.per_ticker` (`ie_new_pct` vs `ie_old_pct`);
  файлы не прикладываются, веб для чисел не используется (правило №10).
- Пометки пользователя — из `user_plan` / `user_status` / `user_note_ie` / `user_note_ai`.
- Гейт-статусы (reader-only) + stability rules: caps по статусу, ≤4 позиции за цикл, hysteresis.
- Отклонения подкорзин облигаций (валютных и рублёвых, все 9) — план↔факт из
  `balance_summary.bonds_plan_vs_fact`.
- **Суммы и лоты докупки акций — только через `scripts/gate_aware_sizing.py`** (с учётом заморозок, режим `--auto`); база докупки называется в ответе. Из головы и из `goals_matrix → Изменение` суммы не берутся.
- **Правило неразворота и лимиты концентрации** (`references/gate-aware-sizing.md`): недавно докупленное не режется обратно без существенного основания; перекос в сектор/эмитента ограничивается лимитами.
- **Стресс:** прогон `scripts/stress_digest.py --mode 3` → строка «Stress macro EV» и bond-сторона таблицы TR. Stress старше 60 дней или нет файла — откладывается только перенос денег между классами.
- **Живые цены MOEX** применяются поверх снапшота до расчёта.

### Промт

```
Оцени свежую ребалансировку IE (изменения уже в snapshot) и дай мнение.
— С какими изменениями соглашаться / нет, тайминг по позициям к продаже/докупке.
— У меня есть осознанные расхождения с IE — если пометки нет, а доля сильно
  отличается от IE New, уточняй у меня.
— Если не согласен с моими расхождениями — веский макро/фундаментальный аргумент,
  иначе оставь как есть.
```

> Суммы и лоты скилл берёт из `gate_aware_sizing.py`, в промте их задавать не нужно.

### Вариант "быстрое мнение" перед крупным действием

```
Я думаю продать N% [ТИКЕР] сегодня. Проверь: есть ли в ближайшие 2 недели
события (отчёт, дивиденды, корп.новости), ради которых стоило бы подождать?
Коротко, до 200 слов.
```

> «Быстрое мнение — продать N%» может упереться в правило неразворота и лимиты концентрации: если по бумаге недавно была обратная сделка, скилл так и скажет.

## Режим 4a. Разбор акции (Single Stock Analysis)

Когда нужно глубоко разобрать одну акцию. Разбор бумаги (Mode 4) — updater фундаментального гейта
(METH-2): контекст бумаги берёт выборкой `security_digest.py`, вывод кладёт в блок `decisions:` шапки отчёта →
решение и гейт записывает save-to-library при сохранении отчёта (Workflow N).

| Модель | Effort мин. / опт. | WS | Зачем |
|---|---|---|---|
| **Sonnet*** | medium / **high** (на Opus*: high / high) | да | Глубина по одному эмитенту: МСФО, peer comparison, брокерские мнения. |

### Промт (конкретная бумага из портфеля)

```
Глубокий анализ [ТИКЕР] по методологии скилла.
Фокус: стоит ли держать текущую долю (скилл возьмёт её из snapshot),
как она соотносится с IE-целью и planned, что ожидать на горизонте
12 месяцев, есть ли триггеры к сокращению / докупке.
```

### Промт (новая потенциальная бумага)

```
Разбери [ТИКЕР] как кандидат в портфель.
Бизнес, финансы за 4-8 кв., оценка vs peer-median, риски, драйверы,
рекомендация — добавлять или нет, и если да, то с какой долей и при каких условиях входа.
```

```
Разбери облигацию [ISIN или название] по методологии скилла.
— Параметры выпуска, оферта, амортизация.
— YTM на сегодня (и YTP если есть оферта) с датой и источником.
```

```
Разбери эмитента [название], выпуски которого у меня есть: [ISIN1, ISIN2].

кредитные события за последние 6 месяцев.
```

### Промт (кандидат для ИИС-3)

```
Подходит ли [ISIN] для ИИС-3 "дальних" облигаций?
Критерии: дюрация 5+ лет, фиксированный купон, высокий рейтинг (ОФЗ или AAA/AA),
YTM привлекательнее сопоставимой ОФЗ.
Если да — при какой цене входа; если нет — предложи 2-3 альтернативы.
```

## Режим 6. Доходность (Returns Analysis)

Запускается, когда есть вопрос про доходность. **Все данные уже в snapshot v2** —
блоки `returns` (total / restricted / by_type) и `per_instrument_xirr`. Ничего
прикладывать и никакие скрипты запускать не нужно.

> ⚠ Single-ownership (2026-06): `portfolio_returns.py` живёт в
> `skills/portfolio-data-loader/scripts/` — advisor его НЕ запускает. Ретроспектива
> на произвольную дату (`--as-of`), нестандартный период (`--start-date`) или offline
> (`--no-moex`) — это перегенерация snapshot через `portfolio-data-loader`, после
> которой advisor интерпретирует готовые числа.

| Модель | Effort мин. / опт. | WS | Зачем |
|---|---|---|---|
| **Sonnet** | low / **medium** | — | Вычисления уже сделаны data-loader'ом; нужна интерпретация. |

### Базовый промт (общая доходность)

```
Какая у меня доходность? Дай разбивку:
— Вся история (XIRR, ROI, TWR годовая)
— С 01.03.2022 без заблокированных (активная часть)
— Per-type: stock / bond / fund отдельно
И объясни, где главная проблема портфеля, если она есть.
```

Смотри в первую очередь `returns.by_type` (restricted) — там видно, какой подпортфель тянет.

### Промт (диагностика проблемы)

```
Какая у меня доходность по типам активов с 2022? Где проблема —
в прямых акциях, прямых облигациях или фондах? Сравни TWR подпортфелей
между собой. Если какой-то подпортфель сильно отстаёт, предложи,
что с ним делать.
```

### Промт (ретроспектива на дату / произвольный период)

```
Как выглядела доходность моего портфеля на конец 2024 года?
Если в снапшоте этого нет — скажи, что нужно перегнать portfolio-data-loader
с --as-of 2024-12-31, и что именно я получу.
```

### Промт (сравнение с фондами)

```
Выгоднее ли было держать всё в фондах, чем управлять прямыми бумагами?
Сравни TWR моих прямых акций с TWR моих фондов за период с 01.03.2022.
Если разница большая — обоснуй, есть ли причины держать прямые бумаги
(дивидендный поток, ЛДВ, специфические фундаментальные ставки).
```

### На что обращать внимание в ответе

- **XIRR total может быть отрицательным** — это нормально при большой доле заблокированных бумаг (по default оцениваются в 0 ₽). Главная метрика качества управления — `returns.restricted` и per-type.
- **Разрыв между XIRR и TWR** показывает timing пополнений: XIRR выше TWR — пополнения на просадках; ниже — на пиках.
- **Realised XIRR — backward-диагностика, не forward-сигнал** (см. «Что не делать» SKILL.md): не обосновывает изменение planned-долей.

## --save-to-library: сохранение YAML для integrated view

Скилл генерирует YAML для downstream (`portfolio-integrated-view`, viewer) и выводит его
в чат для проверки. **Ничего не пишется в Claude-Memory без явной команды `/save-to-library`**
(исключение — условия: их по Режиму 9 пишет скрипт save-to-library `apply_condition.py`).

### Промт (только облигации → bonds YAML + MD)

```
/ru-portfolio-advisor --save-to-library
Еженедельный обзор облигаций.
```

→ `weekly-review-bond-<date>.yaml` + `weekly-review-bond-<date>.md` в код-блоках.

### Промт (акции + облигации → оба комплекта)

```
/ru-portfolio-advisor --save-to-library
Еженедельный обзор акций и облигаций.
```

→ обзор акций (Mode 1) + обзор облигаций (Mode 2) последовательно, два YAML + два MD. **Имя MD = имя YAML** (Phase 10.4).

### Что произойдёт при самом сохранении (`/save-to-library`, Workflow F)

- Python-валидация (`validate-weekly-review-stock` / `-bond`): drift-имена, полнота полей,
  reconcile-чек, R-COV warning на молчаливый carry-over. Блокеры → отказ в записи.
- F2.6 — carry-over check активных constraints против прошлого обзора.
- Обзор условий и решений не пишет: гейт по бумаге считается из последнего решения, флаг «Нужен разбор»
  обзора действует, пока обзор новее решения.
- INDEX.md + `_sync_log.md`.

## Несколько бумаг одного типа разом

Отдельного режима нет — выбор зависит от вопроса:

| Что хочешь | Режим | Модель / effort |
|---|---|---|
| 2–4 акции, вопрос по каждой («разбери SBER, LKOH и YDEX») | разбор акции (Mode 4a) по каждой в одном запросе | Sonnet*, high / high |
| 5+ акций или вся корзина: «какие держать, какие заменить» | оценка качества акций на 1–2 года (Mode 8) | Opus, high / xhigh |
| 2–4 облигации («что с ГазКЗ-29Д и ПИК К 1Р5») | разбор облигации (Mode 4b) по каждой в одном запросе | Sonnet, medium / high |
| Все облигации портфеля — что изменилось | обзор облигаций за неделю (Mode 2) | Sonnet, medium / high |
| Несколько фондов — каждый по отдельности | разбор фонда (Mode 5a) по каждому | Sonnet, medium / high |
| Несколько фондов — какой из них выбрать | подбор фонда (Mode 5b) | Sonnet, medium / medium |

Повтор одного режима по нескольким бумагам — **не** «несколько режимов в одном запросе»: Opus
обязателен только для связок разных режимов (3+8, 6+8, 4+8). При 5+ бумагах в разборе
(Mode 4) ответ становится длинным и поверхностным — лучше оценка качества (Mode 8) или
несколько запросов по 2–4 бумаги.

Промт (пример):
```
Разбери SBER, LKOH и YDEX (разбор акции, Mode 4a): по каждой — тезис, риски, что изменилось за месяц, вердикт.
```

## Кастомные стили ответа

Если в твоём Claude настроены стили, рекомендуемые для этого скилла:

- **"Аналитический отчёт"** — структурный, с заголовками, таблицами, ссылками. Для Weekly и Single Analysis.
- **"Короткое действие"** — 3-10 строк, только action items. Для быстрых вопросов и отложенных условий (Mode 9).
- **"Рассуждение"** — для Rebalance Opinion: показывай ход мысли, альтернативы, trade-offs.
- **"Числовой отчёт"** — для Returns Analysis: таблицы по типам, явные XIRR/TWR в процентах, минимум прозы.
