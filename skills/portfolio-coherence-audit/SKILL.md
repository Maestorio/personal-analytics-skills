# portfolio-coherence-audit — Fable deep-pass (сфера 3)

Мета-слой НАД пайплайном. Не дублирует `portfolio-integrated-view` (он уже даёт spread, per-position α,
tail-flags). Даёт ровно то, чего нет ни в одном fixed-schema скилле: согласованность допущений между
артефактами, немоделированные факторные взаимодействия, и атаку на собственный вывод синтеза.

## Целевая модель и каденс

- **Stage R — `claude-fable-5`.** Задача длинная, много разно-схемных входов, ценность в перекрёстных
  связях — это порог, который Opus/Sonnet не берут надёжно. Если весь разбор помещается в один заход
  Opus без потери когерентности — эта задача НЕ для Fable, не запускай.
- **Каденс:** ежемесячно ИЛИ на смене режима (шаг ставки ЦБ, санкционный сдвиг, слом нефти). Дорогой
  прогон — не еженедельно. Всё еженедельное остаётся на дешёвых тирах.

## Двухстадийность (жёстко)

Всё детерминированное делается ДО Fable. Fable не парсит файлы — он читает один готовый bundle.

### Stage P — подготовка (Python, без LLM)

Запусти скрипт. Он сам находит последние артефакты и валидирует их:

```bash
python3 skills/portfolio-coherence-audit/scripts/build_coherence_bundle.py \
  --dir "<Claude-Memory root>" --asof <YYYY-MM-DD> \
  --out coherence-input-bundle-<YYYY-MM-DD>.json
```

Либо явные пути: `--snapshot --stress --weekly-stock --weekly-bond --integrated-view`
(+ опц. `--macro-marginal --macro-scenarios --prev-bundle`). PyYAML обязателен
(`pip install pyyaml --break-system-packages`).

При автопоиске (`--dir`) под ключом `stress` лежат числа пересчёта сайта `Portfolio/stress/auto/recalc-<стресс>.yaml`, если он есть для самого свежего стресса; возраст стресса и порог 90 дней считаются по стрессу скилла (дата суждений), а сведения о пересчёте — в `stress_recalc` и `provenance`. При `narrative_stale` тексты стресса относятся к числам дня прогона. Явный `--stress` пересчёт не подставляет.

**Прошлый bundle для диахронного диффа** ищется автоматически рядом с `--out`
(свежайший `coherence-input-bundle-*.json` с датой раньше `--asof`); держи bundle'ы в одной
папке — тогда `diachronic` (закрылось/висит/новое) заполняется сам.

**watch_verdict — детерминированный гейт дорогого прогона.** Stage P сам решает, есть ли
сигналы для Fable (`watch_verdict.fable_recommended` + список `signals`): первый прогон —
baseline; дальше — только НОВЫЕ противоречия / mc-флаги / one-sided оси / reinforcing-пересечения
/ consensus-флаги против прошлого bundle. `false` ≠ запрет — это «новых сигналов нет», календарный
месячный прогон остаётся решением пользователя. Запускать Stage P и читать вердикт может любая
дешёвая сессия (скрипт без LLM) — Fable нужен только для Stage R.

**Gate — критично.** Скрипт возвращает код выхода:

- `0` — bundle готов (`consistency.status` = `ok`/`degraded`). Идёшь в Stage R.
- `2` — **HARD STOP.** Рассинхрон **даты снапшота** между артефактами (нормализуется в YYYY-MM-DD из
  `snapshot.as_of_date` / `stress.portfolio_snapshot_id` / `weekly.snapshot_id` /
  `integrated_view.inputs.snapshot_date`), устаревший или отсутствующий обязательный вход.
  **НЕ запускай Fable-рассуждение.** Сообщи пользователю, какой артефакт устарел/разошёлся (из
  `consistency.reasons`) и что перезапустить в пайплайне. Кросс-артефактный анализ на рассинхронных
  входах бессмыслен.

При `status: degraded` (у части артефактов дата снапшота не читается, но конфликта нет) — продолжай, но
перенеси предупреждение в §0 итогового артефакта.

### Stage R — рассуждение (Fable)

Читай ТОЛЬКО `coherence-input-bundle-<date>.json`. В нём уже посчитаны кандидаты; твоя работа — суждение,
не пересчёт.

- **R1 — Consistency verdict.** Из `contradiction_candidates` (отсортированы: `point_sign_conflict` и
  число `points_outside_cone` сверху) отбери *существенные* противоречия. Механика: сценарии стресса
  дают `scenario_cone` [min,max] — сам по себе это НЕ противоречие. Противоречие = независимый точечный
  взгляд (`point_views` = **macro-L1**; weekly числовых не даёт — там `macro_dependency` это тег
  сценария A–D/null) **вне конуса** (с допуском) или два точечных взгляда, конфликтующих по знаку.
  Для каждого объясни, **ломает ли** это equity-vs-bond вывод integrated-view. Если
  `contradiction_candidates` пуст — различай: (а) в `assumption_ledger` есть строки `source_class: point`
  → числовая сверка прошла, L1 **внутри** конуса (согласованы), так и напиши; (б) точечных строк нет →
  **пробел покрытия** (не загружен macro-marginal). Отдельно: **качественные** противоречия (общая
  слепая зона всех сценариев, напр. «девальвация без паузы ЦБ») детектор по числам не ловит — ищи их
  суждением как слой поверх bundle.
- **R2 — Off-diagonal interpretation.** Из `factor_overlap.rows` возьми строки `both_legs: true`.
  `direction: reinforcing` = фактор двигает equity- и bond-ногу в одну сторону → **скрытая концентрация
  сверх** `factor_overlap.stress_concentration_ratio` (спред «акции−облигации» её маскирует).
  `direction: offsetting` = естественный хедж. **Единицы:** беты разных факторов несравнимы напрямую
  (`factor_definitions`: cbr_rate — п.п., usdrub — %, sanctions/geopol — шкала −1…+1). Внутри одного
  фактора equity vs bond сравнимо; для ранжирования факторов домножь бету на масштаб движения фактора
  в сценариях (`scenario_cone`/`assumption_ledger`) — это твоё суждение, не выкладка скрипта.
- **R3 — Red-team.** Атакуй equity-vs-bond вывод integrated-view
  (`passthrough_numbers.integrated_view`) методами Pre-mortem + Devil's Advocate + Reversibility.
  Дай вердикт устойчивости **Высокая / Средняя / Низкая** + назови ЕДИНСТВЕННОЕ несущее допущение,
  чей flip ломает вывод, + фальсификатор (что увидим, если оно неверно).
- **R5 — Детерминированные находки (v1.3, уже посчитаны Stage P — изложи и оцени существенность,
  не пересчитывай).** Разложи по §1–§3 артефакта:
  - `scenario_blindspots.one_sided_factors` — оси без обратного мира (напр. `cbr_rate` всегда вниз →
    нет мира «пауза/повышение ЦБ»; `usdrub` всегда вверх → нет укрепления рубля). Пара одно-сторонних
    факторов = отсутствующий совместный мир (девальвация без паузы ЦБ). `locked_pairs` — супер-факторы
    (обе ноги как один риск) / встроенные хеджи.
  - `mc_divergence.flagged` — два центральных значения ноги или CI не покрывает headline, от которого
    считался spread (класс §1.2). Если `bond` флагнут на всех горизонтах — доверять ширине CI спреда нельзя.
  - `unrealizable_exposure` — blocked-позиции в выводе (+ сверься с вердиктом обзора облигаций `WATCH` на distressed).
  - `iis3` — дюрация-риск на льготном счёте.
  - `consensus_dispersion` — где сценарный конус **уже** аналитического разброса (`stress understates
    dispersion`) → стресс переоценивает уверенность по фактору; **шире** → наоборот.
  - `joint_tail` (v1.4) — совместный хвост ЧИСЛОМ: ячейки сценарий×горизонт, где equity- и
    bond-ноги минусовые одновременно (`worst` = худшая по combined). Это ценовой слой без carry
    (bond carry смягчает) — оговори это при изложении §3.
  - `diachronic` (v1.4) — дифф с прошлым bundle: `persisting` ≥2 прогона = **систематическое**
    расхождение пайплайна (качественно другой сигнал, чем свежее), `closed` — что пайплайн закрыл.
    `null` = первый прогон, базы нет.
  - `point_confidence` в кандидатах R1 (v1.4) — FCA-уверенность L1-точки: противоречие от точки
    с confidence 0.4 и от точки с 0.8 — разные по весу находки.
- **R4 — Emit.** Сначала собери **TL;DR** (см. output-schema §TL;DR), затем полный артефакт
  `coherence-audit-<date>.md` по схеме `references/output-schema.md` (`coherence-audit@1.1`).
  **Запиши в файл** и продублируй TL;DR + основное в чат — порядок в §«Вывод и сохранение».

## Железные правила

- **Только анализ. Никаких buy/sell, лотов, цен, лимиток.** Это верхний аналитический слой.
- **Не пересчитывай числа.** XIRR/YTM/ΔP&L/веса берутся из bundle как есть. Никакой арифметики LLM
  поверх точных данных. Stage P только переупаковал числа.
- **Не дублируй integrated-view.** Секция §5 артефакта явно перечисляет, что остаётся downstream
  (spread, per-position α, tail-flags). Приёмочное правило: каждая твоя находка должна быть тем, чего
  НЕТ в `integrated-view@1.3`. Воспроизводимо fixed-schema скиллом → выкинь.
- **Не подменяй отсутствующий вход своим мнением.** Нет обязательного артефакта → это Stage P уже
  остановил (exit 2).
- **ИИС-3** не получает SELL/TRIM-подтекста (и так вне области, но фиксируем инвариант экосистемы).
- Уважай `schema_notes` bundle: там перечислены поля, прочитанные по предположению. Если находка
  висит на таком поле — пометь её пониженной уверенностью.

## Вывод и сохранение (по умолчанию — в файл)

**Шаг 0.** Перед первой записью в Claude-Memory прочитать `_hub/settings.json`; `ai_mode: off` → в Claude-Memory не писать, сообщить владельцу, что сайт в режиме без ИИ и правки идут с сайта.

1. **Всегда записывай** полный артефакт в файл
   `Claude-Memory/Portfolio/coherence-audits/coherence-audit-<date>.md` (папку создай, если её нет).
   Не жди команды «сохрани» — это дефолт.
2. **В чат** выведи только: блок **TL;DR** + 3–5 главных пунктов (вердикт устойчивости, несущее
   допущение, топ-находки §1–§3, статус R1: «L1 внутри конуса» / «пробел покрытия») + путь к файлу.
   **Не** дублируй весь артефакт в чат.
3. Если запись недоступна (нет подключённой папки `Claude-Memory`) — тогда выведи полный артефакт
   inline и явно предупреди, что файл не записан.

Альтернатива (на потом): регистрация через `save-to-library` (новый Workflow O, та же папка) — требует
однострочного дополнения save-to-library пользователем.

## Приёмочный self-check перед выдачей

1. Каждая находка §1–§3 отсутствует в integrated-view? (иначе — дубль, убрать)
2. Ни одного пересчитанного числа? (все — из bundle)
3. R3 назвал ровно одно несущее допущение + фальсификатор?
4. `predictions_for_review` ≥ 3, с `check_date`/`auto_checkable`/`check_what`?
5. Секция «Что НЕ показано» указывает на первоисточники?
6. Полный артефакт **записан в файл** `Portfolio/coherence-audits/`, а в чат ушли только TL;DR + основное?
7. TL;DR есть первым блоком и укладывается в ~6 строк?
