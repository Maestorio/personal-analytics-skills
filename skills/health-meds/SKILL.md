# health-meds

Целевая модель: **Opus**. Медицинская справка — приоритет корректности над
стоимостью (правило репозитория: корректность > читаемость > стоимость > скорость).
Haiku недопустим.

**Скилл не даёт медицинских рекомендаций.** Он переносит факты из официальных
инструкций в файл и указывает, откуда взял каждый. Решения о приёме — врач.

## Хранилище — ВНИМАНИЕ: два разных `Claude-Memory`

```
HEALTH_ROOT = ~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/Health
```

`Health/` — поддерево единого `Claude-Memory/` на Synology (с миграции
2026-08-13 всё дерево вне облачных синков). `references/transport-layer.md`
описывает общий протокол транспорта; рабочий корень (`SCOPE_ROOT`) этого
скилла — `HEALTH_ROOT` выше, и **проверять доступность надо именно к нему:**

1. `Glob("*.json", path=HEALTH_ROOT)`;
2. пусто или ошибка → `request_cowork_directory(path=HEALTH_ROOT)` и повторить;
3. снова ошибка → **остановиться и сообщить пользователю** (альтернативного
   транспорта нет, никуда не писать).

**Корень `Claude-Memory/` не запрашивать и не листать.** Скиллу нужны два файла
в `Health/`; `Portfolio/`, `forecasts/`, `travel-planner/` и прочее дерево к
аптечке отношения не имеют. Проверяй путь перед каждой записью.

Файлы:

| Файл | Роль |
|---|---|
| `meds.json` | аптечка, `health-meds@1` — читаем и пишем |
| `labs.json` | биомаркеры, `health-labs@1` — **только читаем** (цель ссылок `affects`) |

`meds.json` — живое состояние: мастер на Synology, деплой с Mac его не трогает.
Никакого web-API: скилл работает с файлом напрямую через Read/Write.

## Контракт `health-meds@1` — плоский, два писателя

У файла два писателя: **страница** (`tools/health.html`, форма правки) и **этот
скилл**. Схема плоская — вложенных `user`/`ref` НЕТ (health-plan.md §1.5 описывает
модель, которая не отгружена; победил плоский набор полей дизайна, см. §0 плана).

Поэтому пространства имён не разводят писателей, и безопасность держится на трёх
правилах, зашитых в `scripts/validate_meds.py`:

| | Поля | Правило |
|---|---|---|
| **Человек** | `name` `dose` `regimen` `timing` `form` `taking` `prescribedBy` `expiry` `notes` | скилл **не пишет никогда**; `merge_ref` отклоняет попытку |
| **Справка** | `inn` `class` `for` `indications` `interactions` `affects` `affects_strength` `group` | пишет скилл (`group` — не перетирая ручной выбор) |
| **Провенанс** | `ref_meta` | пишет только скилл; страница не рисует, но проносит через правку |

**`form` — поле человека, и это осознанно.** Ибупрофен бывает таблетками, гелем,
сиропом и свечами; какая упаковка лежит в ЭТОЙ аптечке, из инструкции не следует.
Дозировка намекает («400 мг» — вероятно таблетки), но намёк — не факт. Скилл может
предложить форму в отчёте и попросить подтвердить; писать сам — нет. То же с
`dose`, `expiry`, `prescribedBy`.

**Непустое поле справки без `ref_meta` считается заполненным рукой и не
перетирается** — форма страницы включает `Показания`/`Взаимодействия`, человек мог
набить их сам. Перетереть можно только явным `--overwrite-manual`, и это надо
предложить пользователю, а не решить самому.

```json
"ref_meta": {
  "filled_at": "2026-07-17",
  "confidence": "high|medium|low",
  "fields_filled": ["inn", "class"],
  "sources": [{"title": "ГРЛС — Аторвастатин", "url": "https://…", "fetched": "2026-07-17"}]
}
```

**Стержень: заявил поле в `fields_filled` — предъяви `sources`.** Факт о лекарстве
без источника валидатор не пропускает (blocking).

**Полей `atc` / `standard_dose` / `storage` / `shelf_after_open` из плана §1.5 в
схеме нет** — их некуда положить и негде показать. Не запихивать в чужие поля:
`notes` принадлежит человеку, `interactions` — про взаимодействия. Нужны — сначала
поля на странице и в валидаторе сайдкара, отдельной задачей.

## Процедура

### 1. Прочитать и оценить очередь

Read `{HEALTH_ROOT}/meds.json` и `{HEALTH_ROOT}/labs.json`. Затем:

```bash
python3 skills/health-meds/scripts/validate_meds.py validate \
  --meds "{HEALTH_ROOT}/meds.json" --labs "{HEALTH_ROOT}/labs.json"
```

Есть blocking — **остановиться и показать пользователю**: файл уже сломан, чинить
его вслепую нельзя.

Очередь работы (валидатор про пустые записи молчит — у них нет issues; очередь
берётся из файла напрямую или функциями `pending_ids` / `stale_ids`):
- **по умолчанию** — записи, где ни одно поле справки не заполнено;
- **`--refresh`** — записи со справкой старше года (по `ref_meta.filled_at`);
- ручные записи (справка есть, `ref_meta` нет) — **не в очереди**; упомянуть в
  отчёте и спросить, обновлять ли.

Партия > 8 лекарств — предупредить о времени и спросить, делать ли всё.

### 2. Собрать справку по каждому лекарству

Лестница источников и правила уверенности — `references/sources.md`. Кратко:
официальная инструкция (ГРЛС · DailyMed · SmPC) → авторитетный вторичный
(РЛС · Vidal · drugs.com) → ничего. Аптечные сайты, блоги, форумы — не источник.

⚠ **`confidence: high` надо заслужить первичкой, и это проверяется.** Если все
источники записи — вторичные (`rlsnet.ru`, `vidal.ru`, `drugs.com`), валидатор даёт
**blocking**: либо открыть ГРЛС/инструкцию, либо честный `medium`. Правило появилось
не из теории: первый прогон 2026-07-17 проставил `high` семнадцати записям подряд по
РЛС и Vidal, ни разу не открыв ГРЛС, — и это пришлось откатывать. Незнакомый домен
(инструкция на сайте производителя) трактуется в пользу записи.

Что ищем (всё — опционально, кроме честности):

| Поле | Что кладём |
|---|---|
| `inn` | МНН, действующее вещество: `аторвастатин` |
| `class` | фарм-класс коротко: `статин`, `НПВС`, `H1-блокатор` |
| `for` | от чего, одной строкой человеческим языком |
| `indications` | показания из инструкции, 1–3 предложения |
| `interactions` | взаимодействия + предупреждения прозой (страница рисует блок warn-стилем) |
| `affects` | id биомаркеров из `labs.json`, на которые препарат влияет |
| `affects_strength` | `{id: strong\|moderate\|weak}` — **сила влияния на каждый** |
| `group` | назначение — блок в списке аптечки, **только из словаря ниже** |

### `group` — назначение

По этому полю страница раскладывает аптечку на блоки: «болит горло — что есть».
Словарь **закрыт**, значение вне списка `merge` отклоняет: блока с незнакомым
ключом на странице нет, и лекарство молча пропало бы из списка.

| Ключ | Блок | Ключ | Блок |
|---|---|---|---|
| `cold` | Простуда и ОРВИ | `allergy` | Аллергия |
| `throat` | Горло | `skin` | Кожа |
| `cough` | Кашель | `eye` | Глаза |
| `pain` | Боль и воспаление | `abx` | Антибиотики |
| `gi` | ЖКТ | `heart` | Сердце и сосуды |
| `sleep` | Сон и тонус | `other` | Прочее |

Выбирать по **ситуации, в которой за лекарством лезут**, а не по фармгруппе.
Тантум верде — «обезболивающее противовоспалительное» по классу, но человек
берёт его при боли в горле: `throat`, не `pain`. Драмина — антигистаминное по
классу, но берут её от укачивания: `other`, не `allergy`. Комбинированное
средство от простуды идёт в `cold` целиком, даже если в показаниях перечислены
и температура, и горло, и нос.

**Ручной выбор неприкосновенен.** Это единственное справочное поле, которое
человек штатно переопределяет на странице, поэтому правило для него строже
общего: непустой `group` не перетирается **никогда** — даже если его записал
предыдущий прогон скилла и `ref_meta` у записи есть. Только `--overwrite-manual`.
Пустое поле означает «страница разложит по описанию», а не «Прочее»: у неё есть
эвристика по `class`/`for` как запасной вариант.

⚠ Словарь продублирован в `MED_GROUPS` (`validate_meds.py` и `tools/health.html`) —
при изменении править во всех трёх местах.

**Не выдумывать.** Источник не подтвердил — поле не заполняется и не заявляется в
`fields_filled`. Пустое поле честнее правдоподобной догадки: это медданные, и
цена ошибки здесь не «некрасиво», а «человек поверил». В `merge` неподтверждённое
передаётся как `null`.

Торговое название ≠ состав: у дженериков и комбинированных препаратов сверяйся с
конкретной формой и дозировкой из `user`-полей (`dose`, `form`). Если по названию
нельзя однозначно определить препарат (например, разные производители под одним
брендом) — не гадать, вернуть запись пользователю с вопросом.

### 3. Перепроверить (обязательный второй проход)

Собранное сверить с источником заново — не по памяти, а перечитав страницу.
Расхождение между источниками → первичка (инструкция) выигрывает, `confidence`
понижается на ступень, расхождение упоминается в отчёте. Не разрешается —
`confidence: low` и поле либо пустое, либо с явной оговоркой в прозе.

### 4. Взаимодействия — по всем принимаемым

Матрица считается по парам среди `taking: true` (страница подсветит только
активные). Проверять именно пары, а не «взаимодействия вообще». В `interactions`
конкретного лекарства писать прозой, с кем именно и что происходит.

Взаимодействие с непринимаемым препаратом из аптечки — упомянуть в отчёте, в файл
не тащить: завтра `taking` изменится, а текст останется врать.

### 5. Связь с биомаркерами и сила влияния

`affects` — **только id, реально существующие в `labs.json`**. Битая ссылка молча
рвёт связь вкладок: карточка маркера не покажет препарат, и по странице этого не
увидеть. Валидатор проверяет (blocking), но сверяйся заранее — id вида
`ldl`/`alt`, не `cholesterol_ldl`.

Класть только то, на что препарат влияет **как на измеряемый показатель**
(статин → `ldl`, `alt`), а не «связано по теме».

**`affects_strength` обязателен к заполнению вместе с `affects`** — иначе карточка
врёт равенством. У аторвастатина ЛПНП падает на десятки процентов, а гликированный
гемоглобин сдвигается на десятые доли: без разметки оба выглядят одинаковым чипом,
и человек читает «влияет» там, где влияние незаметно.

| Сила | Когда |
|---|---|
| `strong` | эффект — причина назначения либо сопоставим по величине (статин → `ldl`) |
| `moderate` | устойчивый, клинически заметный, но не главный (статин → `tg`, `alt`) |
| `weak` | измеримый, но мелкий; класс-эффект, редкое явление (статин → `hba1c`, `hdl`) |

Сила — про **величину сдвига показателя**, а не про важность контроля. КФК у статина
проверяют не потому, что он её сильно двигает, а потому что редкий рост опасен: это
`weak` в разметке и место в `interactions` прозой.

Не подтвердил источник величину — не размечай: валидатор даст warning со списком
неразмеченных, страница нарисует их нейтрально. Это честнее выдуманной силы.

### 6. Записать

Собрать `enrich.json`:

```json
{ "atorvastatin": {
    "fields": { "inn": "аторвастатин", "class": "статин",
                "for": "снижение холестерина", "indications": "…",
                "interactions": "…", "affects": ["ldl", "alt"] },
    "confidence": "high",
    "sources": [{"title": "ГРЛС — Аторвастатин", "url": "https://…",
                 "fetched": "2026-07-17"}] } }
```

Сначала **dry-run** — он перечитывает файл (страница могла изменить его, пока шёл
поиск), сливает только поля справки и валидирует результат:

```bash
python3 skills/health-meds/scripts/validate_meds.py merge \
  --meds "{HEALTH_ROOT}/meds.json" --labs "{HEALTH_ROOT}/labs.json" \
  --enrich /tmp/enrich.json --today {YYYY-MM-DD}
```

Прочитать отчёт (что записано / что не тронуто как ручное / чего не хватило
данных / что отклонено как поле человека). Только потом — `--apply`. При
blocking скрипт не пишет файл: чинить вход, не валидацию.

Валидация — в скрипте, а не в прозе: это правило репозитория (защита контрактов
от model drift), и здесь оно же не даёт модели уговорить себя записать догадку.

### 7. Отчёт пользователю

Показать таблицей: лекарство · что заполнено · `confidence` · источник. Отдельно —
что осталось пустым и почему (источник не подтвердил / препарат не опознан),
расхождения между источниками, найденные взаимодействия между принимаемыми.

Закрыть дисклеймером: **справочно, не медицинская рекомендация; дозировки
приведены из инструкции и не являются назначением.**

## Pre-emit checklist (перед `--apply`)

- [ ] путь записи — `SynologyDrive-home/Claude-Memory/Health/`;
- [ ] `enrich.fields` не содержит `name` `dose` `regimen` `timing` `form`
      `taking` `prescribedBy` `expiry` `notes`;
- [ ] у каждого заполненного лекарства непустые `sources` с живыми URL, которые
      реально открывались в этой сессии (не по памяти);
- [ ] `affects` сверен с `labs.json`, у каждого id размечена `affects_strength`;
- [ ] неподтверждённое передано как `null`, а не угадано;
- [ ] второй проход (§3) выполнен, `confidence` отражает его результат;
- [ ] `high` стоит только там, где реально открыта первичка (иначе `medium`);
- [ ] dry-run прочитан, ручные поля осознанно не тронуты;
- [ ] merge → exit 0.

python3 skills/health-meds/tests/test_validate_meds.py
