# stage1-polish-prompt.md

Инструкция для модели в **export-mode Stage 1**. Применяется ДО рендера
PDF: модель читает оригинальный `1_dr_reports.md`, выдаёт «отполированную»
версию для presentation-grade output'а, а уже её рендерит детерминированный
Python-скрипт (`stages/stage1.py`).

Stage 1 PDF — **structured DR-архив**: 20-полевые карточки авторов
сгруппированы по регионам, наверху — сводка META-DIAGNOSTICS, в panel
закладок (outline) PDF'а — пункт на каждую карточку формата
«N · Автор — «Название отчёта»». Read-only справочный документ для
self: открыл, нашёл автора по региону, перечитал его POI / жалобы.

**Принцип:** polish = переформатирование под аудиторию, НЕ переписывание
фактов. Все 20 полей карточек, URL'ы, цитаты в поле 18 (Жалобы), цифры
META-DIAGNOSTICS (распределения, POI-критика per region) и WARN-формулировки
— дословно. Удаляется/перефразируется только pipeline-жаргон.

**Когда применять:** `recipient = self` (единственный режим Stage 1 — для
parents/гида DR-база не нужна).

---

## Что на входе и что на выходе

**Вход:** полный markdown файла стадии 1 — YAML frontmatter + body
(37+ карточек × 20 полей + META-DIAGNOSTICS).

**Выход:** markdown того же формата (YAML + body), с применёнными ниже
трансформациями. Никаких пояснений, no preamble — только сам markdown.

---

## Трансформации

Применять **все** по порядку. Если какая-то не применима — пропустить,
не упоминать.

### T1. Cover title

H1-заголовок переписать в человеко-читаемый формат:

**Было:** `# Stage 1: Сырая структурированная база отчётов независимых путешественников по Камбодже и Лаосу`

**Стало:** `# {Регионы человекочитаемо} · DR-база отчётов`

Примеры:
- `# Камбоджа и Лаос · DR-база отчётов`
- `# Северный Вьетнам · DR-база отчётов`
- `# Южная Аргентина · DR-база отчётов`

Регионы брать из YAML (`regions`) или из `trip_id` (`камбоджа_лаос_2026-02`
→ «Камбоджа и Лаос»). **Сезон, число отчётов, длительность в заголовок
НЕ включать** — они идут в подзаголовок обложки и в таблицу параметров
(формируются скриптом из YAML + маркера T2).

### T2. Маркер параметров поездки (для таблицы на обложке)

Первой строкой body (СРАЗУ после закрывающего `---` frontmatter, ПЕРЕД
вступительным абзацем и первым `## РЕГИОН …`) вставить маркер
`[[поездка: …]]`. Скрипт собирает из него таблицу ключевых параметров
обложки. Поля разделены `|`, формат `ключ: значение`:

```
[[поездка: группа: Алексей | регионы: Камбоджа → Лаос | сезон: февраль 2026 | темп: размеренный]]
```

Поля (все опциональны — указывай те, что выводимы из контекста/профиля):
- **группа** — кто едет. Только имя(имена) или собирательное название
  группы. Без слов «соло», «один человек», без паспортов/возрастов.
  - 1 человек: `Алексей`
  - 2+ человека по именам: `Алексей и Мария`
  - собирательно: `Родители`, `Семья`, `Друзья`
  Это единственный источник строки «Кто едет» в обложке — без маркера
  её не будет.
- **регионы** — маршрут стрелками (`Камбоджа → Лаос`); человекочитаемо.
  Если нет естественного «порядка», просто `и`-список: `Камбоджа и Лаос`.
- **сезон** — «месяц год» (если не задан — скрипт выведет из trip_id).
- **темп** — `размеренный` / `сбалансированный` / `активный`.

Число отчётов, количество регионов, дату DR-прогона, языки источников
скрипт берёт сам из YAML / META-DIAGNOSTICS — в маркер их НЕ дублировать.

### T3. Маркер `[[карточка: …]]` для нормализации tonality / focus / flags

Перед каждым `### Карточка N` в каждом регионе вставить маркер
`[[карточка: …]]`. Это страховка: исходный DR-output часто кладёт
сигналы tonality и контекст прямо в H3 (`### Карточка 4 — tonality: critical`,
`### Карточка 26 — ключевой ФЕВРАЛЬСКИЙ отчёт`) — формат не строгий,
парсер должен иметь канонический источник.

```
[[карточка: tonality: critical | focus: photo | flags: residence]]
### Карточка 4
1. **URL и название:** ...
```

Поля (все опциональны — указывай те, что выводимы из контента карточки):
- **tonality** — `critical` если у автора в поле 18 (Жалобы) явная
  POI-критика с цитатой («overrated», «boring», «развод», «детское
  рабство», «pushy sales», «уехать сразу после Сием-Рипа»). Иначе
  опускай. Сезонные жалобы (мгла, дождь, температура — поле 6) **не**
  делают карточку critical.
- **focus** — короткий тег фокуса из поля 13: `photo` / `culture` /
  `nature` / `architecture` / `food` / `adventure` / `mix`.
  Скрипт нормализует сам, но явный тег ускоряет.
- **flags** — через запятую, опц.: `residence` (автор-резидент или
  поездка > 1 месяца), `photo` (поле 20 = ЯВНЫЕ — фотограф с
  оборудованием/постобработкой), `iconic` (отчёт purely по
  iconic-локации типа Ангкор-Ват без побочных мест).

Маркер **необязательный** — fallback-парсер читает inline-суффикс H3
regex'ом и grep'ом по `tonality: critical` в поле 18. Маркер просто
канонизирует — снимает риск ошибочной классификации.

### T4. Strip pipeline-жаргон

В body убрать / переименовать:
- «независимая пара» / «независимые путешественники» (про группу) →
  «самостоятельная пара» / «путешествуют самостоятельно» (каноническая
  формулировка архетипа `самостоятельные`; не трогать компонент
  похожести `independence` — «независимость планирования»);
- финальный `**КОНЕЦ STAGE 1.**` и любые подписи «к Stage 2 / для Stage 2
  / Stage 2 разберётся» в конце документа — пользователю это не нужно;
- вступительный абзац-метадиагностика про «Карточек — N, по всем M
  регионам ≥4» — оставить, но без формулировок «Stage 1 / OUTLIER не
  проставляется / поле OUTLIER» (они про методологию пайплайна, не
  про содержание базы);
- inline-суффиксы в H3 (`— tonality: critical`, `— ФЕВРАЛЬ 2026`,
  `— ключевой ФОТО-ФОКУС`) **оставить как есть** — это содержательные
  метки, парсер их использует как fallback к маркеру T3.

### T5. Сохранять дословно

- **YAML frontmatter** — все поля (parser читает YAML дословно;
  `trip_id`, `stage`, `regions`, `season`, `dr_run_date`, `reports_count`,
  `meta_diagnostics_warnings`, `created`).
- **20 полей** каждой карточки — содержимое, нумерация (1-20), формат
  `**Поле:** значение`. Не переписывать значения, не переупорядочивать
  поля, не объединять.
- **URL'ы** — дословно (поле 1, ссылки в логистике, GPS-координаты).
- **Цитаты в поле 18** — дословно с эмфазой `*…*` и переводом в скобках
  (`*«It is simply boring…»* (Кратко: скучно, шумно)`). Это самые
  ценные данные для downstream.
- **Имена POI / отелей / ресторанов** — с латинской транслитерацией в
  скобках при первом упоминании (`Ангкор-Ват (Angkor Wat)`,
  `Бан-Жок (Bản Giốc)`).
- **META-DIAGNOSTICS** — все числа per region, проценты распределений,
  формулировки WARN'ов (`WARN-1: 0% местноязычных…`),
  список «Источники, которые пробовал…» — дословно.

### T6. Strip эмодзи

Эмодзи не рендерятся (DejaVu/CID шрифты без emoji glyphs — quадраты).
Stage 1 артефакт обычно без эмодзи, но проверь и убери:
- ⚠️ в начале WARN-строк → убрать (renderer сам обернёт в amber-box);
- 📍 🏨 🎯 ✅ ❌ если попадаются — убрать.

### T7. Транспорт и размещение — только тип, без перечислений

Renderer применяет дополнительные cleanup'ы к полям 11 (Транспорт) и 12
(Размещение), но polish может сделать заранее — артефакт будет чище.

**Поле 11 (Транспорт).** Оставь только тип(ы) транспорта, без:
- перечисления конкретных операторов / авиалиний / автобусных компаний
  («(рейсы AirAsia, Asiana, Bangkok Airways, …)» — убрать всю скобку);
- цен и тарифов;
- маршрутов между городами (если важно для понимания — оставь, иначе
  убери);
- повторов одного типа транспорта в разных городах («тук-тук в храмах;
  тук-тук в Pub Street; тук-тук назад» → «тук-тук»).

Хорошо: `Тук-тук, авиа`, `Автобус, ночной поезд, такси`,
`Аренда байка (125cc)`, `Easy rider тур`.
Плохо: `Тук-тук по храмам $15 туда-обратно; авиа в Сием-Рип (рейсы
AirAsia, Asiana, Bangkok Airways, Cambodia Angkor Air, China Eastern,
Lao Airlines, Singapore Airlines)`.

**Поле 12 (Размещение).** Оставь **только тип** размещения — отель /
хостел / homestay / гестхаус / квартира / кемпинг / luxury / бунгало.
Без названий конкретных отелей, без описаний удобств, без цен,
без дистанций до достопримечательностей.

Хорошо: `Отель`, `Хостел`, `Homestay`, `Отель в Сием-Рипе + хостел в
Пномпене`.
Плохо: `Koulen Hotel (3 ночи, бассейн на крыше, 500 м до Pub Street);
рекомендует Central Blance Residence как бюджетный вариант (15 мин
пешком до центра)`.

Если конкретные имена отелей будут нужны на Stage 5 (для бронирования)
— они уже есть в исходном DR-output, скилл не удаляет данные из
первоисточника, только из presentation-PDF.

### T8. Распределения META-DIAGNOSTICS — на русском

В подсекциях `## Распределение по стилям…`, `## Распределение по фокусу
автора` и т.п. замени english-термины на русские:

| EN | RU |
|---|---|
| backpacker | бэкпэкер |
| mid-range independent | миддл-сегмент самостоятельно |
| mid-range | миддл-сегмент |
| luxury | люкс |
| organized tour | организованный тур |
| digital nomad | диджитал-номад |
| hardcore adventure | хардкор-адвенчура |
| family | семья |
| photography-focused | фото-фокус |
| food-focused | гастро-фокус |
| cultural deep-dive | культурное погружение |
| standard tourist circuit | стандартный туристический маршрут |

Числа, проценты, номера карточек — дословно. Renderer применяет тот же
маппинг как страховку, но текст в polished.md будет аккуратнее, если
сделаешь сразу.

### T9. Warnings — консолидировать, дедуплицировать, переписать

DR-output типично кладёт warnings в **два** места — YAML
`meta_diagnostics_warnings` (короткие формулировки) и `## WARNINGs`
секцию body (часто расширенные формулировки тех же warning'ов плюс
дополнительные NOTE'ы). Это даёт визуальные дубли в PDF.

**Что делать:**

1. Объединить warning'и **из обоих источников** (YAML +
   `## WARNINGs` body).
2. **Дедуплицировать семантически** — если два warning'а говорят про
   одну и ту же проблему (даже разными словами), объединить в один.
   Примеры дубликатов:
   - «WARN-1: 0% местноязычных источников (kh/lao/thai)» (YAML) и
     «WARN-1: 0% местноязычных источников (kh/lao/thai). Khmer440,
     phnompenhpost… не дают personal travel reports — они новостные»
     (body) → одна строка с самой информативной формулировкой.
3. **Переписать каждый warning одной человекочитаемой фразой** —
   убрать pipeline-жаргон (`WARN-N:`, `B1-awd.ru:`, `NOTE:` префиксы;
   они нужны были для трейсинга, в PDF — шум).
4. Результат записать в YAML `meta_diagnostics_warnings:` как
   block-список из ≤6 пунктов. Каждый пункт — одна сентенция, без
   нумерации в начале.
5. **Удалить `## WARNINGs` секцию из body** — она теперь полностью
   дублируется YAML'ом.

**Пример** (КЛТ_1, до polish'а):

```yaml
meta_diagnostics_warnings:
  - "WARN-1: 0% местноязычных источников (kh/lao/thai) — нет personal travel reports на кхмерском/лаосском/тайском"
  - "WARN-2: POI-критика Тямпасак/Боловен = 2 отчёта (минимальный порог, прямого «overrated»-отчёта нет)"
  - "WARN-4: ~60% отчётов датированы 2018–2023; приоритет 2024–2026 выполнен только для ~40%"
  - "B1-awd.ru: BPC-challenge заблокировал доступ — 0 карточек добавлено"
```
+ в body:
```
## WARNINGs
- **WARN-1:** 0% местноязычных источников... (расширенная формулировка)
- **WARN-2:** POI-критика для региона Тямпасак/Боловен — только 2 отчёта...
- **WARN-3:** Доля стиля backpacker близка к 30% — приемлемо, не превышает 50%.
- **WARN-4:** Несколько карточек ссылаются на источники старше 5 лет...
- **WARN-5:** Большинство критических отчётов про burning season сосредоточены в северных регионах...
- **NOTE:** Многие EN-источники содержат affiliate-ссылки...
```

**После polish'а:**

```yaml
meta_diagnostics_warnings:
  - "0% источников на местных языках (кхмерский/лаосский/тайском) — Khmer440, phnompenhpost и аналоги новостные, не travel reports"
  - "POI-критика Тямпасак/Боловен — только 2 отчёта, у нижнего порога; прямого «overrated» нет"
  - "Доля бэкпэкер-стиля близка к 30% — приемлемо, не доминирует"
  - "Только ~40% отчётов за 2024–2026; остальные 2018–2023 для full-text body"
  - "Критика burning season сосредоточена в северных регионах — отражает реальную сезонную проблему, не смещение выборки"
  - "Многие EN-источники с affiliate-ссылками, но критерий «не маркетинговый пост туроператора» соблюдён"
```
+ `## WARNINGs` секция из body **удалена**.

**Renderer** возьмёт `meta_diagnostics_warnings` дословно и выведет
одним warning-box'ом с bullet-list'ом. Если polish не выполнен — он
сделает fallback с грубым ключ-дедупом, но смысловые повторы могут
остаться.

**Не путать с содержанием:** факты, числа, формулировки причин — не
изменять. Только переписать в одну человекочитаемую фразу на warning.

### T10. НЕ трогать

- **YAML frontmatter**.
- **Числа** (reports_count, per-region counts, проценты распределений,
  POI-критика per region).
- **20 канонических полей карточки** (имена и порядок 1-20).
- **Содержательные имена регионов в H2** (`## РЕГИОН 1: Сием-Рип и
  Ангкор (Siem Reap & Angkor), Камбоджа` — сохрани полностью с
  латинской транскрипцией и страной).
- **Цитаты, URL'ы, GPS-точки, имена авторов**.

- [ ] Поле 11 (Транспорт): без перечисления операторов/тарифов/

- [ ] Поле 12 (Размещение): только тип (отель / хостел / homestay /

- [ ] Warnings: YAML.meta_diagnostics_warnings — консолидированный
      ≤6-пунктовый список одной фразой на warning, дедуплицировано

- [ ] YAML frontmatter, 20 полей карточек (имена/порядок), цитаты в

После polish — `polish_check.py` сверит, что число H2-регионов, число
H3-карточек, длина и YAML-поля не сломаны. Любое нарушение → исправить
и перепрогнать polish.

## Формат ответа

Один markdown-блок начиная с `---` (YAML frontmatter) и до конца файла.
Без обёртки в \`\`\`markdown. Без вводных фраз и trailing-комментариев.
Готово к скармливанию в
`export.py --input polished.md --stage 1 --recipient self`.
