## Часть 1 — Контракт формата (канон)

### Маркер карточки
- **Канон (эмитить так):** `## КАРТОЧКА N` — heading, порядковый номер.
- **Терпимые варианты** (парсер принимает, но не канон): `**КАРТОЧКА N**`,
  `### Карточка N`, `Card N`, `Report N`, `Отчёт N`; регистр любой, ведущий
  ноль (`01`) ок.
- **Регион — НЕ часть канона карточек.** Карточка по природе по-авторная и
  мульти-региональная; группировать карточки по регионам **не нужно**. Export
  не группирует — он находит все карточки плоским сканом и выдаёт списком;
  покрытые регионы показывает строкой (из суффикса заголовка, напр.
  `## КАРТОЧКА 2 (multi-region: Пекин + Сиань)`). Регион — свойство POI
  (Stage 3). Любые `## РЕГИОН N:`-обёртки в DR-выводе игнорируются экспортом.

### Разделитель карточек
- **Канон:** `---` (ровно 3 дефиса) между соседними карточками. Парсер терпит
  `-{3,}` (включая `-----`), но эмитить **`---`**. Самый надёжный признак
  границы — маркер карточки, не ширина разделителя.

### Роспись 20 полей — ЖЁСТКАЯ (имена и порядок канонические, не переименовывать)

20 полей (канонические имена):

1. URL и название отчёта
2. Платформа публикации (и язык исходника, если не русский / английский —
   `vi` / `ja` / `zh` / `ko` / `es` / etc.)
3. Имя или ник автора
4. Дата публикации
5. Месяц и год поездки, длительность
6. Сезон с особенностями ({season_specific_features})
7. Состав группы (соло / пара / семья / группа друзей / организованный тур)
8. Возрастной диапазон автора (если можно оценить)
9. Стиль путешествия — один тэг **по-русски**, из списка: бэкпэкер /
   миддл-сегмент самостоятельно / бюджетно самостоятельно / мотобайк
   самостоятельно / люкс / организованный тур / диджитал-номад /
   хардкор-адвенчура / семья / фото-фокус / гастро-фокус / культурное
   погружение / стандартный туристический маршрут / микс
10. Темп (количество локаций, среднее число дней на локацию)
11. Транспорт (байк, easy-rider, ночные автобусы, частные водители,
    тур-группы, поезда, аренда машины)
12. Тип размещения — сегмент **по-русски**: отдельные номера / хоумстей /
    отели / люкс / хостелы с общими спальнями / кемпинг. Имена конкретных
    отелей и сетей — как в оригинале, не переводить
13. Главный фокус автора — один тэг **по-русски**: архитектура / природа /
    культура / фото / гастрономия / приключения / отдых / микс
14. POI с тональностью — полный список упомянутых мест с тональностью
    каждого: рекомендует / нейтрально / критикует / жалеет о посещении /
    жалеет что пропустил
15. Hidden gems — отдельно подсвети «нетуристические» или «hidden gems»
    места из отчёта
16. Логистические заметки автора (что сработало, что нет, лайфхаки)
17. Упоминания диетических ограничений и как справлялся
18. Жалобы и проблемы — переоценённые места, опасности, разводы, погодные
    провалы. **Это про POI-туристические-ловушки**, не про сезонную
    дымку или общие условия (для сезонного — поле 6).
19. Главная рекомендация одной фразой прямой цитатой
20. Признаки фотографических интересов (упоминание оборудования,
    рассветной/закатной съёмки, постобработки)

Если содержания для поля нет — `не указано`, поле не убирать и не переименовывать.
Запрет на pre-marking `OUTLIER` в любом из 20 полей (OUTLIER — категория Stage 2).

### YAML-шапка (заполняется частью до DR, частью после)

```yaml
---
trip_id: {trip_id}
stage: 1_dr_reports
travelers_profile: profiles/{profile_id}.md
regions: [...]
season: {season}
dr_run_date: YYYY-MM-DD
reports_count: N
meta_diagnostics_warnings: [...]
mode_b_decisions: {...}        # опц., ТОЛЬКО при Mode B (довыборка)
created: YYYY-MM-DD
---
```

- `reports_count` — **top-level** ключ (column 0), НЕ под `regions:`. Парсер
  (`REPORTS_COUNT_PATTERN = ^reports_count:\s*(\d+)$`) матчит только верхнеуровневый
  — съехавший под список `regions:` отступ не распознаётся → diagnostic error.
- Согласованность счётчиков: YAML `reports_count` == TL;DR «собрано N отчётов»
  == header `## Полная база отчётов ({N})`.

### Формы полей (на что смотреть консьюмеру)
- **Поле 14 (POI с тональностью)** — список; допустимы обе формы: инлайн-
  перечисление в одну строку **и** bullet-список. Downstream (Stage 3) обязан
  принимать обе (исторически bullet-форма у B2-карточек терялась при extraction).
- **Поля 9 / 12 / 13 (стиль, размещение, фокус) — просим по-русски, принимаем
  любой язык.** Значения пишет Deep Research по промту §6; DR недисциплинирован
  и регулярно отдаёт английские тэги (`mid-range independent`, `photography-focused`).
  Это **не дрейф формата** и не повод чинить файл: экспорт русифицирует значения
  детерминированно через словарь (`scripts/data/taxonomy.json`, группы
  `report_style` / `report_focus`). Русская просьба в промте снижает долю
  английских значений; словарь остаётся страховкой постоянно. Consumer (Stage 2
  §6.2) читает поля семантически и обязан принимать обе формы.

## Часть 2 — Реестр копий (где формат продублирован в рантайме)

Этот контракт продублирован в рантайм-загружаемых местах. Правишь формат здесь —
синхронизируй их; drift-тест сверяет.

**Ось A — внутристадийная (`stage1-dr-prompt.md`):**
- §6 промт-шаблон для DR — стр. 579–828; **роспись 20 полей — 733–767** (помечена
  «ЖЁСТКАЯ»); формат-нота вывода — 776–778.
- §7.1.3 YAML-шапка для сохранения — 852–869.
- Инлайн-пример Mode B (маркеры карточек + META-скелет) — 1180–1201.
- §8 «Структура выходного файла» (YAML 1242–1253 + скелет тела) — 1237–1270.

**Ось B — кросс-стадийная (потребители артефакта):**
- Stage 2 (`../stage2/stage2-similarity.md` + `parse_dr_cards.py`) — читает карточки.
- Export-парсеры Stage 2 (`scripts/export/`).

**Парсер (`scripts/parse_dr_cards.py`) — реальные якоря (что он действительно
распознаёт):**
- `CARD_MARKER_PATTERN` (стр. 93), `CARD_MARKER_LINE_RE` (104) — маркер карточки
  (канон `##` + терпимые).
- `SEP_LINE_RE` (112) — разделитель `-{3,}`.
- `URL_PATTERN` (85) — поле 1 (URL).
- `NAME_FIELD_PATTERNS` (119) — поле 3 (имя автора).
- `REPORTS_COUNT_PATTERN` (370) — top-level `reports_count`.

Парсер **не** экспонирует роспись всех 20 полей (он card-splitter + diagnostic).
Поэтому drift-тест сверяет полную роспись только между документными копиями
(канон ↔ §6), а парсер-ногу ограничивает якорями выше.

## Часть 3 — Известные дрейфы / на что смотреть при чтении `1_dr_reports.md`

Не нужно при генерации. Помогает при чтении / парсинге / дебаге артефакта.

- **Разделитель `-----` вместо `---`.** В реальном прогоне схлопнул 56 карточек в
  9 (парсер ждал `---`). Закрыто: `SEP_LINE_RE` терпит `-{3,}` + marker-first
  split (граница по маркеру, не по разделителю). При ручном чтении: не доверять
  числу карточек на глаз — сверять с `reports_count`.
- **Поле 14 bullet-списком** вместо инлайн-строки → awk-extraction на Stage 3
  пропускал POI у B2-карточек. Консьюмер обязан принимать обе формы.
- **Типографские кавычки** `“Ханой”` / `«…»` вместо прямых — в названиях/цитатах.
- **Маркер `**КАРТОЧКА N**`** (bold) вместо канона `## КАРТОЧКА N` (heading) —
  парсер терпит оба, но при ручной обработке учитывать.
- **`reports_count` уехал с отступом** под список `regions:` → сломанный YAML,
  top-level парсер не находит. Эмитить ровно `reports_count: N` на верхнем уровне.
- **Смешанный формат B2-карточек** (буллеты/нестандартные метки полей) — дрейф
  компаундится вниз по пайплайну, не локализуется на Stage 1.
