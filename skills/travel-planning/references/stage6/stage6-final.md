# stage6-final.md

Полная спецификация Stage 6 — финишной доводки. На входе — **устаканенный**
финальный план `5_final_plan_v{N}.md` (маршрут уже выбран и не итерируется) и
профиль группы. На выходе — отдельный файл `6_final_v{N}.md` с добавками,
которые **не влияют на выбор маршрута**, но нужны в финале: координаты
маршрута для обзорной карты, дорожное досье, инкорпорация косметической брони
и (по явному запросу) углубления.

Философия и место в пайплайне — `../methodology.md`.

## 1. Назначение

**Одна атомарная задача:** довести **устаканенный** маршрут (`5_vX`) до
trip-ready идеала, добавив то, что **не влияет на выбор маршрута**, но нужно в
финале. Stage 6 не переисследует POI, не строит варианты, не меняет логику
дней — он **финиширует**.

Граница (правило решения): *нужно, чтобы ВЫБРАТЬ маршрут или ЗАБРОНИРОВАТЬ →
Stage 5; пост-решение, считается ОДИН раз → Stage 6.* Stage 5 = прочный
каркас (с ним уже можно ехать). Stage 6 = идеал.

**Состав (компоненты одной задачи «финиш»):**

- **Ядро (детерминированно / всегда):**
  - **Координаты маршрута** — резолвятся двухтиерно (§6.2) и **персистятся в
    `6_final.md`** (таблица `точка | lat | lon | источник` + порядок маршрута
    + подписи рёбер). Это полная спека обзорной карты; рисует карту
    Export-рендерер из этих координат, не сама стадия.
  - **Дорожное досье** (§6.3) — визы / транзит, медицина / прививки / денге /
    высота, страховка, этикет (съёмка / хоумстей), сводная упаковка,
    экстренные номера / больницы, связь и деньги.
  - **Инкорпорация косметической брони** (§6.4) — реальные билеты / номера /
    подтверждённые отели (статус, ref).
- **Enrichment (ТОЛЬКО по явному запросу, §6.5):** история региона / города,
  конкретные точки / рестораны / онсэны / кофейни. Не делается само — иначе
  Stage 6 безграничен.

**Инвариант (анти-дрейф).** Stage 6 **НЕ редактирует** `5_final_plan.md` —
файл immutable, остаётся SSOT маршрута. Stage 6 только ЧИТАЕТ его и пишет
ОТДЕЛЬНЫЙ `6_final.md` с добавками. Слияние (5_vX + карта + добавки) —
**механическое на экспорте**, не правка плана. Маршрут / дни ни разу повторно
не прогоняются через модель → дрейф плана и накопление ошибок через шаги
исключены; ошибки Stage 6 заперты в добавках (худший случай — неверная
карта, не испорченный план; таблица координат ревьюабельна по столбцу
«Источник»).

## 2. Inputs / Outputs

**Inputs:**

- `5_final_plan_v{max}.md` — **устаканенный** план (latest версия). REQUIRED.
  Читается, не правится.
- `profiles/{profile_id}.md` — для досье (медицина / диета / платёжная
  инфраструктура / гражданство для виз). REQUIRED (резолвится из YAML 5_vX,
  поле `travelers_profile`).
- `0_scope.md` — OPTIONAL quality input (направление, сезон, country quota →
  визы / сезонные риски в досье). Если найден в travel_root, но не приложен →
  STOP / спросить (правило optional quality-inputs из `../../SKILL.md`).
- **Факты брони** — OPTIONAL, от пользователя (билеты / отели / переезды + ref).
- **Запросы enrichment** — OPTIONAL, явные.

**Output (артефакт в чат, manual save пользователем):**

- `{travel_root}/trips/{trip_id}/6_final_v{N}.md` — versioned (как 4/5).
  YAML + тело по §8.

**Backward-compat (жёстко):** старый / менее подробный 5_vX на входе НЕ
должен вызывать ошибку. Новые поля / маркеры опциональны на входе; отсутствие
≠ ошибка.

**Downstream:** Export mode рендерит `6_final.md` в финальный PDF, механически
сшивая рендер 5_vX (билдеры stage5) + обзорную карту + досье / бронь /
углубления.

## 3. Поток

2 turn'а в стандартном случае.

### Turn 1 — пользователь

«финиш для {trip_id}», «Stage 6 для {trip_id}», «доведи план до идеала»,
«досье и карта», «шестой шаг».

### Turn 2 — скилл

**0. Model self-check (обязательный первый шаг).** Назвать модель одной
строкой: «Я модель: <name>. Stage 6 рассчитан на Sonnet + adaptive
thinking».

- **Sonnet + adaptive thinking** — оптимально, продолжать.
- **Opus** — допустимо (overkill: Stage 6 — retrieval / компиляция, не
  Opus-интеграция), продолжать.
- **Sonnet без thinking** — остановиться: «Stage 6 на Sonnet без thinking
  не поддерживается (досье деградирует — пропускаются прививки / этикет /
  экстренные контакты). Включи adaptive thinking». Дождаться решения.
- **Haiku** — **остановиться**: «Stage 6 не поддерживается на Haiku.
  Открой новый чат на Sonnet + adaptive thinking. Не нажимай «Continue»
  после safety pause — это переводит на Haiku». Логика — `../../SKILL.md`
  блок про safety filter.

1. **Gate-проверки (§4).** Если хоть одна не выполнена — отказ ОДНОЙ строкой.

2. **Mode detection (§6.1).** Нет предыдущего `6_*.md` → **fresh**; есть →
   **update**. Объявить одной строкой в начале Turn 2.

3. **Получить `5_final_plan_v{max}.md`** — источник по приоритету
   `../storage-and-naming.md` §8.0 (приложенный файл → Synology mount).

4. **Read профиля.** Извлечь: гражданство (для виз), `## Гастрономия`
   (диета → медицина / этикет), `## Платёжная инфраструктура` (деньги в
   досье), хронические особенности (для медицины).

5. **Read `0_scope.md`** (если доступен): направление, сезон, country quota →
   визы и сезонные риски досье. Если найден в travel_root но не приложен —
   STOP с одной строкой вопроса.

6. **Резолв координат (§6.2).** Собрать список точек маршрута (регионы /
   базы / ключевые POI из 5_vX) → Tier-1 `scripts/geocode.py` (детерминированно)
   → ненайденные добить Tier-2 (знание модели) → собрать таблицу
   `## Координаты маршрута` с порядком маршрута и рёбрами.

7. **Сборка дорожного досье (§6.3).** Активный web search для виз / прививок /
   этикета / экстренных контактов / связи под направление и гражданство.

8. **Инкорпорация брони (§6.4)** — если пользователь дал факты косметической
   брони. Структурная — направить НАЗАД в Stage 5.

9. **Enrichment (§6.5) — СПРОСИТЬ, если не запрошен явно.** Stage 6 —
   единственное место в пайплайне, где углубления уместны: во время
   планирования они мешают, при финализации нужны. Пользователь про них
   помнить не обязан, поэтому спрашивает скилл, ОДИН раз, и вопрос сам несёт
   границы — иначе в ответ прилетит «по всем местам маршрута», а это уже не
   дорожный документ (см. §6.5, гейт в `polish_check.py`).

   Вопрос задавать ровно так, подставив регионы из 5_vX:

   > Добавить в финал раздел «Углубления» — короткие справки для чтения в
   > дороге? Предлагаю по одной на страну и на каждый регион маршрута:
   > {страна}, {регион 1}, {регион 2}, … — итого {N} блоков.
   > Каждый блок: ≤5 предложений плюс строка источника.
   > Ответьте «да», «нет» или назовите свой список тем.
   > Справка по каждому POI в дорожный документ не поместится — такой
   > материал идёт отдельным файлом в `внешние_справки/`.

   - Ответ «нет» или молчание в update-режиме при уже существующей секции —
     переиспользовать её как есть, заново не собирать.
   - Ответ шире бюджета — не выполнять молча: сузить до регионов, а остальное
     предложить вынести в `внешние_справки/`, назвав это в `warnings`.
   - В fresh-режиме без ответа пользователя секцию НЕ создавать: правило §10
     «не делать enrichment без явного запроса» остаётся в силе, вопрос его не
     отменяет, а делает осознанным.

10. **Pre-emit checklist (§6.6) — обязательно** ДО записи.

11. **Output — environment-aware** (паттерн Stage 5 §3 шаг 14):
    - **Write/Bash доступен:** сохранить `6_final_v{N}.md`, в чат — короткий
      summary + `computer://`-ссылка.
    - **Write недоступен** (claude.ai chat): Message 1 = готовый
      `6_final_v{N}.md` целиком; Message 2 = save instruction + summary.

**Стоп.** Пользователь сохраняет файл, опционально запускает Export для
финального PDF (карта + досье).

## 4. Gate-проверки на входе

Применяй ДО запуска работы. Если хоть одна не выполнена — отказ ОДНОЙ
строкой с конкретным указанием, чего не хватает.

| Что | Обязательно | Если не задано |
|---|---|---|
| `trip_id` | да | спросить или предложить из существующих (Glob) |
| `5_final_plan_v{N}.md` в `trips/{trip_id}/` | да | отказать: «запусти Stage 5» |
| Маршрут **устаканен** (не идёт новая итерация 4/5) | да | если маршрут ещё выбирается — это Stage 4/5, не 6 |
| `profile_path` | да | резолвится из YAML 5_vX (`travelers_profile`) |

**Отказ при отсутствии Stage 5:**

```
Stage 6 требует устаканенный финальный план Stage 5.
Не нашёл `{travel_root}/trips/{trip_id}/5_final_plan_v{N}.md`.

Запусти Stage 5: «Stage 5 для {trip_id}».

Стоп.
```

ОДНА строка ответа — ничего больше.

**Transport consent gate** для 5_vX, если он не приложен и Synology
недоступен — общий механизм `../storage-and-naming.md` §1.4.

## 6. Промт — методика доводки

### 6.1 Mode detection

Детерминированно:
- Нет предыдущего `6_*.md` (Glob `trips/{trip_id}/6_*_v*.md`) → **fresh**:
  строим координаты / досье / enrichment с нуля.
- Есть предыдущий `6_*.md` → **update**: мёрж новых фактов брони / новых
  enrichment-запросов; ранее собранные координаты / досье переиспользуются.

Объявление одной строкой: «Mode: {fresh|update}. {Одна фраза-обоснование}».

### 6.2 Координаты — двухтиерный резолв + персист

**Tier 1 (детерминированный, скрипт).** `scripts/geocode.py` (stdlib): на вход
— список имён точек маршрута (регионы / базы / ключевые POI из 5_vX), опц.
страны поездки для ограничения. Скрипт читает забандленный газетир
`scripts/data/gazetteer.json` (Natural Earth populated places), матчит
Russian↔English через транслит + alias + fuzzy в пределах страны, возвращает
найденные точки с координатами (`source: gazetteer`) + список ненайденных.

Координата всегда из газетира (реальные данные), даже если подсказать
английское имя — это и держит Tier-1 ревьюабельным. Хит-рейт: крупные города
высоко (Ханой / Сеул / Пусан / Буэнос-Айрес), деревни низко (Сапа /
Мукангчай / Эль-Чальтен → Tier 2).

Вызов (пример):

```bash
echo '{"points": ["Ханой", {"name": "Кёнджу", "en": "Gyeongju"}, "Сапа"],
       "countries": ["Vietnam"]}' | python3 scripts/geocode.py
```

Для точек, чьё русское имя далеко от ascii-написания (корейские города,
сложная транслитерация), передавай английскую подсказку `en` — координата
всё равно берётся из газетира.

**Tier 2 (модель, для ненайденных).** Доопредели координаты ненайденных
точек своим знанием городов; пометь `source: model`. Это ориентир, не
навигация — деревни и небольшие POI газетир не покрывает.

**Персист в `6_final.md`** — секция `## Координаты маршрута` (формат — §8):
ревьюабельная таблица `№ | Точка | lat | lon | Источник | Дни` + строка
порядка маршрута + список рёбер (вид транспорта / время / тип: обычное /
узкое звено / перелёт). Тип ребра извлекается из 5_vX (дневные `📍`-переезды
+ сводная таблица транспорта). Это полная спека карты, persisted один раз →
Export-рендерер её читает, не пересобирая из дней.

### 6.3 Дорожное досье

H2-секция `## Дорожное досье` с под-секциями (H3), включаемыми по
релевантности направления и профиля:

- **Визы и транзит** — по гражданству из профиля + транзитные страны
  (визы / e-visa / безвиз / visa-on-arrival, срок действия паспорта).
- **Медицина и прививки** — рекомендованные прививки, малярия / денге /
  высотная болезнь по региону, аптечка под хронические особенности профиля.
- **Страховка** — покрытие (медэвакуация, активности — треккинг / дайвинг),
  ориентир суммы.
- **Этикет** — съёмка (храмы / люди), хоумстей / онсэн правила, дресс-код
  по святыням, чаевые.
- **Упаковка** — сводный список под сезон / активности (таблица / чеклист).
- **Экстренные контакты** — местные службы (полиция / скорая), посольство /
  консульство РФ, ближайшие крупные больницы (таблица).
- **Связь и деньги** — SIM / eSIM, мессенджеры, наличные vs карты, обмен.
  Три проверки, которые ломаются молча и потому обязательны:
  - **Откуда покупается eSIM.** Агрегаторы (Airalo, Mobimatter и пр.)
    могут не принимать оплату из страны проживания — в том числе через
    VPN. Тогда «куплю заранее» не работает: план связи строится либо на
    покупке с рабочей иностранной картой, либо на покупке **по прилёте
    через аэропортовый Wi-Fi**, либо на локальной SIM по паспорту на
    стойке. Писать выбранный путь явно, а не «eSIM или SIM».
  - **Местная валюта до вылета.** Если валюта не экзотическая и
    продаётся дома — часть суммы покупается заранее, и весь узел
    «обменник в первый день / банкомат в горах» схлопывается. Проверять
    это **до** того, как строить маршрут вокруг обменных лавок.
  - **Какие карты реально работают** — из профиля, а не из гражданства.
    Карта, которую «планируют оформить», в досье идёт как TODO, а не
    как платёжный канал; карта, которой реально платили в похожем
    регионе, — как канал.

**Web search активно** для виз / прививок / этикета / экстренных контактов /
SIM — данные направления-специфичны и меняются. Указывать источник или TODO,
не выдумывать.

**Досье — авторитетный источник справочных фактов финала (fact-SSOT).**
Шапка Stage 5 несёт booking-critical факты одной строкой (визовый режим,
FX, перелёт); досье даёт **полную, актуализированную** версию справочного
слоя. Если факт упомянут кратко в Шапке (визовый режим), досье его
разворачивает; при расхождении **превалирует досье** (оно web-searched на
финал). Не противоречить самому себе: одна формулировка факта, авторитетный
носитель — досье.

**Структура (читаемость).** Досье — операционный справочник; рендер даёт
под-секциям воздух, но «сплошняк» прозы он не разобьёт. Внутри под-секции
структурируй: короткие абзацы, bullet'ы для перечней (прививки / что везти),
таблицы для пар «ключ → значение» (экстренные контакты, упаковка). H4
(`####`) — для разбивки длинной под-секции на смысловые блоки.

### 6.4 Бронь — в ОБЕ стадии

Бронь = новый входной факт-ограничение.

- **Косметическая** (номер брони, подтверждение, цена — маршрут не меняется)
  → **Stage 6**: секция `## Бронирования` (подтверждённые билеты / отели /
  переезды + ref) + лёгкий статус-оверлей «забронировано». Не переписывать
  строки отелей 5_vX (он immutable) — аддитивная секция.
- **Структурная** (отель на окраине ломает логистику дня; переезд фиксирует
  плечо несовместимо с планом) → НАЗАД в **Stage 5** → новый 5_vX
  перепланирует. Stage 6 НЕ перепланирует.

Решает пользователь по структурности. Если бронь структурная — направить
назад в Stage 5 одной строкой-подсказкой, не финишировать поверх.

### 6.5 Enrichment (только по явному запросу)

Секция `## Углубления` с под-разделами (H3) ТОЛЬКО по явно запрошенным темам
(история региона / города, конкретные рестораны / онсэны / кофейни). Границы:
не разрастаться, opt-in. Без явного запроса секция не создаётся.

**Бюджет блока — не более 5 предложений**, плюс отдельная строка
`Источник: …` (в бюджет не входит). Оба требования — не пожелание, их
проверяет `polish_check.py` до рендера, и нарушение блокирует прогон.

Почему так:

- Stage 6 читают с телефона в пути. Блок длиннее пяти предложений там не
  дочитывают, а лишние предложения — ровно то место, где модель добирает
  объём вымыслом: по крупному городу материала много, по дальнему посёлку
  мало, а тон остаётся одинаково уверенным.
- Историческая справка без источника непроверяема. Провенанс здесь работает
  ровно как `source: gazetteer|model` у координат: он не делает утверждение
  верным, но делает его ревьюабельным.
- Превосходные степени («первый», «старейший», «единственный») — конструкции
  с наибольшей долей ошибок. Без источника их не писать, а выбрасывать.

Запрос шире бюджета (например «сводка по каждому POI маршрута») — это НЕ
дорожный документ. Такой материал идёт отдельным файлом в `внешние_справки/`
(см. `storage-and-naming.md`), а в `## Углубления` остаётся короткая выжимка.

## 7. Правила работы

### Граница LLM vs скрипт

| Что | Где |
|---|---|
| Tier-1 геокодинг по газетиру (транслит / fuzzy / bbox) | скрипт `geocode.py` |
| Tier-2 координаты ненайденных точек | модель |
| Извлечение порядка маршрута + типов рёбер из 5_vX | модель (семантика прозы дней) |
| Web search виз / прививок / этикета + синтез досье | модель |
| Мёрж косметической брони | модель |
| Отрисовка карты из персистнутых координат | скрипт (Export-рендерер) |

Stage 6 — **модель + один детерминированный скрипт** (`geocode.py`). Карту
рисует Export-рендерер, не сама стадия.

### Web search guidelines

- **Целевые поиски:** визы по гражданству; рекомендованные прививки и
  региональные болезни; этикет святынь / съёмки; телефоны экстренных служб и
  адрес посольства РФ; SIM / eSIM операторы.
- **Указывать источник** — URL или TODO. Не выдумывать визовые сроки,
  телефоны, медицинские рекомендации.

### Стиль

- **Плотно, по делу.** Досье — операционный справочник, не эссе.
- **Цены — ориентир + TODO** (страховка, SIM); систематический bias занижения
  не маскировать под факт.
- Никаких эмодзи в заголовках H2/H3.

### Формат `## Координаты маршрута` (контракт рендерера)

Рендерер парсит секцию детерминированно (`scripts/export/stages/stage6.py`):

- **Таблица** — заголовки матчатся по ключам: имя точки (`точк` / `регион` /
  `место`), `lat` (или `шир`), `lon` (или `долг`), `источник`, `дни`.
  Строки без распознанных lat / lon пропускаются. Десятичная точка или запятая.
- **`**Маршрут:**`** — последовательность номеров точек через `→`. Повтор
  номера = старт == финиш (петля). Если строки нет — порядок по таблице.
- **`**Рёбра:**`** — нумерованный список, по одной строке на переход. Формат
  `N. {откуда} → {куда} — {подпись} ({тип})`. Подпись — после ` — `; тип в
  скобках управляет стилем линии:
  - `обычное` / нет маркера → сплошная линия;
  - `узкое звено` → красная толстая линия;
  - `перелёт` (или «рейс» / «самолёт») → пунктир.
  Хвостовой `({тип})` срезается из подписи (стиль линии уже его кодирует).

## 9. Граничные случаи

### 9.1 Stage 5 не устаканен (идёт итерация)

Если маршрут ещё выбирается (свежий 4_v{N+1} / 5_v{N+1} в работе) — Stage 6
преждевременен. Отказать одной строкой: «Маршрут ещё итерируется — финиш
делается один раз после устаканивания. Заверши Stage 4/5, потом запусти
Stage 6». Stop.

### 9.2 Бронь структурная

Пользователь дал факт брони, ломающий логистику (отель на окраине, переезд с
несовместимым плечом). Не финишировать поверх. Направить: «Эта бронь
структурная (меняет логистику дня) — подай её в Stage 5, он перепланирует
вокруг факта; затем вернись в Stage 6». Stop.

### 9.3 Деревня / POI не в газетире (Tier-1 miss)

Tier-1 вернул точку в `unresolved`. Доопредели координату Tier-2 (знание
модели), пометь `source: model` в таблице. Не оставлять точку без координат —
иначе карта рвётся. Если координата совсем неизвестна — исключить точку из
карты с явной строкой в `warnings`.

### 9.4 0_scope.md недоступен

Визы / сезон собираются из trip_id и 5_vX. В `warnings` отметить:
«0_scope.md недоступен — направление / сезон выведены из плана, сверить
country quota вручную».

### 9.5 Профиль без гражданства

Визовая под-секция помечается TODO: «гражданство в профиле не указано —
визовые требования общие, уточнить по факту гражданства». В YAML — `warnings`.

### 9.6 Update mode: новая бронь / enrichment

Предыдущий `6_*.md` существует. Переиспользовать собранные координаты и досье;
домёржить новую косметическую бронь / новый запрос enrichment. Не пересобирать
координаты заново, если маршрут тот же.

## 10. Что НЕ делать

- НЕ редактировать `5_final_plan.md` — он immutable SSOT маршрута. Писать
  только отдельный `6_final.md`.
- НЕ дублировать день-за-днём контент 5_vX в `6_final.md` — только добавки.
- НЕ пересматривать решения Stage 0 / 3 / 4 / 5 (scope, POI, варианты, дни).
- НЕ строить варианты, не менять маршрут, не переаллоцировать ночи.
- НЕ финишировать поверх структурной брони — направлять назад в Stage 5.
- НЕ делать enrichment без явного запроса (Stage 6 иначе безграничен).
- НЕ выдумывать визовые сроки / прививки / телефоны экстренных служб —
  web search с источником или TODO.
- НЕ оставлять точки маршрута без координат (карта рвётся) — Tier-2 добивает.
- НЕ выдумывать координаты Tier-1 — газетир детерминирован; ненайденное идёт
  в Tier-2 с пометкой `model`.
- НЕ использовать чистый `$NN` для долларовых цен. Только `\$NN` / `USD NN` /
  backtick.
- НЕ изобретать имя файла. Строго `6_final_v{N}.md`.
- НЕ продолжать на Haiku (model self-check, шаг 0).
- НЕ писать «Сохранить как» в тело файла.

## 11. Следующий шаг

После того как пользователь сохранил `6_final_v{N}.md`:

- Опционально активируется **Export mode** (`/travel-planning` → «pdf финала»,
  «финальный pdf с картой»).
- Export собирает финальный PDF механически: рендер 5_vX (билдеры stage5) +
  обзорная карта маршрута (из координат `6_final.md`) + дорожное досье / бронь
  / углубления приложениями. Контент 5_vX повторно через модель не прогоняется
  (ноль дрейфа).

Скилл не запускает Export автоматически — пользователь решает.

Если по результату Stage 6 выяснилось, что бронь оказалась структурной или
маршрут требует пересмотра — возврат на Stage 5/4 (пользователь решает).
