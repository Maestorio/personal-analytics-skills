# stage6-polish-prompt.md

Инструкция для модели в **export-mode Stage 6**. Применяется ДО рендера
финального PDF: модель читает оригинальный `6_final_v{N}.md`, выдаёт
«отполированную» версию, а уже её рендерит детерминированный Python-скрипт
(механически сшивая рендер 5_vX + карта + досье).

**Принцип:** polish = переформатирование под аудиторию, НЕ переписывание
фактов. Координаты (числа, таблица, порядок маршрута, рёбра), визовые сроки,
телефоны экстренных служб, прививки, ref брони — сохраняются **дословно**.
Удаляется / перефразируется только pipeline-жаргон и англицизмы.

**Когда применять:** при `recipient ∈ {self, parents}`. Для archive /
debugging — пропускать.

---

## Что на входе и что на выходе

**Вход:** полный markdown `6_final_v{N}.md` — YAML frontmatter + body.

**Выход:** markdown того же формата (YAML + body), с применёнными ниже
трансформациями. Никаких пояснений, no preamble — только сам markdown.

---

## Трансформации

Применять **все** по порядку. Неприменимые к конкретному файлу — пропустить.

### T1. Cover title

H1-заголовок переписать в человеко-читаемый формат.

**Было:** `# Stage 6 — Финал: вьетнам_север_2026-09`

**Стало:** `# Финал · {Страна/регион} · {N} ночей · {сезон/месяц год}`

Длительность / сезон взять из связанного плана (тело отражает 5_vX) либо из
`trip_id`. Примеры:
- `# Финал · Северный Вьетнам · 11 ночей · сентябрь 2026`
- `# Финал · Южная Корея · 18 ночей · март–апрель 2024`

Если регион не очевиден — оставить `{trip_id без подчёркиваний и слаг-даты}`.

### T2. Frontmatter

**Сохранить ОБЯЗАТЕЛЬНО** (нужно рендереру):
- `trip_id` (anchor'ы / имя файла);
- `stage: 6_final` (роутинг renderer'а);
- `iteration` (версия финала → номер `_vN` выходного файла; удалишь →
  выход `_v1` и travel-окно спрячет его как устаревший);
- `source_plan` (рендерер по нему находит устаканенный 5_vX для механической
  сборки — **удаление сломает рендер**);
- `created` (футер), `travelers_profile`, `warnings`.

**Можно убрать** (внутреннее): `coords_source_summary`, `booking_incorporated`,
`enrichment_requested` — это про процесс сборки, не про сам финал. Числовая
ревьюабельность источника координат остаётся в столбце «Источник» таблицы.

### T3. Русификация англицизмов в досье

В видимом тексте досье заменить англицизмы на русские эквиваленты (но НЕ
трогать имена собственные, коды служб, номера телефонов):
- `visa-on-arrival` → «виза по прибытии»;
- `eSIM` оставить (термин), но `data-plan` → «тариф на интернет»;
- `borderline` → «пограничный»; `checklist` → «чеклист» / «список»;
- `travel insurance` → «страховка путешественника».

### T4. Снять pipeline-жаргон

- Удалить служебные секции, если есть: `## Следующий шаг`, `## Что дальше`.
- «независимая пара» / «независимые путешественники» (про группу) →
  «самостоятельная пара» / «путешествуют самостоятельно» (каноническая
  формулировка архетипа `самостоятельные`; не трогать компонент
  похожести `independence` — «независимость планирования»);
- Фразы вида «Tier-1 / Tier-2 резолв», «mode: fresh» из тела убрать —
  пользователю это не нужно; столбец «Источник» (gazetteer / model) в таблице
  координат остаётся как ревьюабельный сигнал.

---

## Что НЕ трогать (жёстко)

- **`## Координаты маршрута`** целиком: числа `lat` / `lon`, столбец
  «Источник», строку `**Маршрут:**`, список `**Рёбра:**` и их типы (обычное /
  узкое звено / перелёт). Это спека карты — любое изменение чисел / порядка /
  типов ломает обзорную карту. Заголовки колонок и формат строк сохранять
  дословно (рендерер парсит их детерминированно).
- **Факты досье**: визовые сроки, требования к паспорту, прививки, телефоны
  экстренных служб, адрес посольства, суммы страховки.
- **Бронь**: номера / ref / статусы.
- **Структуру H2/H3** секций досье и порядок (рендерер сшивает их
  приложениями).

## Sanity-check (после polish)

`scripts/export/polish_check.py` сверяет polished ↔ source по профилю
`6_final` (длина 0.85–1.15, H2 ± 1, таблицы ± 1, checkbox'ы без изменений).
Если разошлось — polish переделать, не сохранять.
