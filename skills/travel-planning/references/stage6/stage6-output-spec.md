## Часть 1 — Контракт формата (канон)

### Инвариант (анти-дрейф)
Stage 6 **НЕ редактирует** `5_final_plan.md` (immutable SSOT маршрута). `6_final.md`
хранит ТОЛЬКО добавки (координаты + досье + дельты брони + углубления) — **день-за-днём
контент 5_vX НЕ дублируется**. Финальный PDF собирается механически на экспорте.

### Секции (канонические заголовки)
1. `## Координаты маршрута` — **обязательна** (спека обзорной карты).
2. `## Дорожное досье` — обязательна.
3. `## Бронирования` — опц. (только при фактах косметической брони).
4. `## Углубления` — опц. (только по явному запросу enrichment).

День-за-днём блоки (`### День N`, иконки `📍🏨🎯💰⚠️`) в `6_final.md` **не
эмитятся** — это контент 5_vX, он рендерится механически из устаканенного плана.

### Блок `## Координаты маршрута` (парсит `parse_coords_section`)
Три части, в порядке:

1. **Таблица точек.** Заголовки колонок матчатся по ключам (регистр игнорируется):
   - имя точки — `Точка` / `Регион` / `Место` / `Пункт`;
   - `lat` (или `шир`); `lon` (или `долг`); `Источник` (`gazetteer` / `model`);
   - опц. `Дни`.
   Строки без распознаваемых `lat`/`lon` пропускаются; точка/запятая как
   десятичный разделитель.
2. **`**Маршрут:**`** — последовательность номеров точек через `→`. Повтор номера
   = старт == финиш (петля). Нет строки → порядок по таблице.
3. **`**Рёбра:**`** — нумерованный список, по одной строке на переход:
   `N. {откуда} → {куда} — {подпись} ({тип})`. Подпись — после ` — `. **Тип ребра**
   (в скобках или по ключевым словам) управляет стилем линии:
   - `обычное` / нет маркера → сплошная линия;
   - `узкое звено` → красная толстая линия;
   - `перелёт` (или `рейс` / `самолёт` / `авиа`) → пунктир.
   Хвостовой `({тип})` срезается из подписи.

Пример — `stage6-final.md` §8.

### Блок `## Дорожное досье` — под-секции H3 (канонический набор)
`### Визы и транзит` · `### Медицина и прививки` · `### Страховка` · `### Этикет` ·
`### Упаковка` · `### Экстренные контакты` · `### Связь и деньги`. Включаются по
релевантности направления/профиля. Рендер раскладывает их через
`info_box` (`> …`) / `data_table` (md-таблица) / `bullet_list` (`- …`).

### YAML / формат (Pre-emit)
`stage: 6_final`; **`source_plan: 5_final_plan_v{N}.md`** — обязателен (рендерер по
нему находит устаканенный 5_vX; удаление ломает сборку); `coords_source_summary`
соответствует столбцу «Источник» таблицы. Долларовые цены escape'нуты
(`\$NN` / `USD NN` / backtick); YAML три дефиса; имя файла `6_final_v{N}.md`; нет
«опущено for brevity»; нет «Сохранить как» в теле. Полная YAML-схема —
`../storage-and-naming.md` §6.7.

### Опциональные / backward-compatible
Старый/менее подробный 5_vX на входе НЕ ломает Stage 6. Секции `## Бронирования`
/ `## Углубления` опциональны; их отсутствие ≠ ошибка. `check_format` валидирует
выход (новый `6_final.md`), не вход.

## Часть 3 — Известные дрейфы / на что смотреть при чтении `6_final.md`

- **Дрейф колонок таблицы координат** (переименовали `Точка`→`Город`, убрали `lat`)
  → `parse_coords_section` не соберёт узлы → карта не построится. Заголовки
  колонок держать в наборе ключей (часть 1).
- **Дрейф ключевых слов типа ребра** (написали `перелет` без `ё` — ловится;
  но новый синоним вне `_AIR_RE`/`_LONG_RE` — нет) → ребро отрисуется как
  «обычное». Новый синоним — править И спеку, И `_edge_kind`.
- **Удаление `source_plan` из YAML** (например, чрезмерным polish) → рендерер не
  найдёт 5_vX → сборка падает. Поле обязательно (polish T2 его сохраняет).
- **Дублирование дней 5_vX в `6_final.md`** — нарушение инварианта; финал рендерит
  дни из устаканенного 5_vX, повтор раздувает и расходится.
