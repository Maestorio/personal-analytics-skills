## Часть 1 — Контракт формата (канон)

### 6 категорий POI (канонические имена)
`STRONG CONFIRMED` · `WEAK CONFIRMED` · `HIDDEN GEM` · `CONTESTED` · `RED FLAG`
· `LOW SIGNAL` (в коде `aggregate_pois.py` — underscore-форма
`STRONG_CONFIRMED` …). Категорию считает **скрипт** по counts, LLM только
извлекает упоминания. **Приоритет правил категоризации** (сверху вниз):
`CONTESTED` → `RED FLAG` → `STRONG CONFIRMED` → `WEAK CONFIRMED` → `HIDDEN GEM`
→ `LOW SIGNAL`. Anti-bloat: `STRONG CONFIRMED > 50%` или `RED FLAG > 30%` от всех
POI → warning.

### Язык таксона: ключ — в YAML, ярлык — в теле

Одна категория, две формы. **YAML и JSON-payload — английский ключ; тело
`.md` — русский ярлык.** Ярлык не переводится моделью: копируется вербатим
из `category_label` (POI) / `cluster_category_label` (кластер) output'а
`aggregate_pois.py`. Источник переводов — `scripts/data/taxonomy.json`.

| Ярлык в теле | Ключ (YAML / JSON) | Счётчик в YAML |
|---|---|---|
| СИЛЬНОЕ ПОДТВЕРЖДЕНИЕ | `STRONG_CONFIRMED` | `strong_confirmed` |
| СЛАБОЕ ПОДТВЕРЖДЕНИЕ | `WEAK_CONFIRMED` | `weak_confirmed` |
| СКРЫТАЯ ЖЕМЧУЖИНА | `HIDDEN_GEM` | `hidden_gems` |
| СПОРНЫЙ | `CONTESTED` | `contested` |
| КРАСНЫЙ ФЛАГ | `RED_FLAG` | `red_flags` |
| СЛАБЫЙ СИГНАЛ | `LOW_SIGNAL` | `low_signal` |

Категории автора в теле — так же: `HIGH` → ВЫСОКАЯ, `OUTLIER` → ОСОБЫЙ
СИГНАЛ, `MEDIUM` → СРЕДНЯЯ, `LOW` → НИЗКАЯ.

**Что остаётся английским в теле** (якоря парсинга, не таксоны):
`#### Cluster:`, `**Combined with:**`, `**Cluster:**`, `**Iconic status:**`,
`**Iconic exception:**`, `**⚠ Tourist-trap archetype:**`, заголовки секций.

### Категории автора (вход, 4)
`HIGH` · `OUTLIER` · `MEDIUM` · `LOW` (`VALID_AUTHOR_CATEGORIES`) — ключи
payload'а. `high_neg` = high_criticize + high_regret_visited. LOW-авторы
читаются только для RED FLAG.

### Два режима (авто по доле HIGH, порог 30%)
`abundant` (≥30%, WEAK требует high_recommend==2) / `scarce` (<30%, WEAK
допускает high_recommend==1). Отличие — **ровно одно правило** WEAK_CONFIRMED.

### Структура output (§8 — по регионам)
- POI группируются **по регионам** (регионы по убыванию числа POI), ярлык
  категории — в заголовке каждого POI (`#{N} **{name}** ({local}) — СЛАБЫЙ
  СИГНАЛ`); сортировка region-first (`region_order` из скрипта).
- Поля 2–3 POI — счётчики под русскими ярлыками: `2. ВЫСОКАЯ: {N} (рекоменд. …)`,
  `3. ОСОБЫЙ СИГНАЛ / СРЕДНЯЯ / НИЗКАЯ: {a} / {b} / {c}`.
- Выдержки (поле 4) — `- {Автор} #{N} ({ЯРЛЫК КАТЕГОРИИ АВТОРА}): {текст}`;
  ярлык + двоеточие — якорь экспортного парсера.
- Под каждым POI — пустое поле **`Комментарий пользователя:`** (ручная калибровка
  перед Stage 4).
- Опц. per-POI флаги: `commonly_combined_with: [{poi_name, why}]` (synergy-пары),
  `iconic_exception` (reason). Категорию НЕ меняют — ортогональные аннотации.
- Региональные **`**тег:**`**-строки (заполняются пользователем; DOCX round-trip).
- Опц. строка **`**Комментарий к региону:** …`** в шапке региона (до первого
  кластера/POI) — заполняет пользователь, скилл не эмитит. Метка без
  «Комментарий пользователя» (иначе сломается сверка `total_pois`).

### YAML-шапка
`trip_id`, `stage: 3_poi_aggregation`, `aggregation_mode` (abundant/scarce),
`mode_per_region`, `clusters[]`, счётчики категорий, `aggregates`
(`synergy_pairs`, `iconic_exceptions`), опц. `previous_plan`.

### Реестр авторов (обязательная хвостовая секция) — self-contained экспорт
В **конце** файла — секция `## Источники (реестр авторов)`, по строке на
каждого автора `cNN`, упомянутого в выдержках. Делает Stage 3 **самодостаточным
для экспорта одним файлом** (URL/год авторов не тянутся из Stage 1 на рендере).

Формат строки (pipe-делимитер, 4 поля):
```
- cNN | имя автора | год | <url-поле как в поле 1 Stage 1>
```
- `url-поле` копируется **дословно** из поля 1 Stage 1-карточки `#N` —
  включая мульти-URL и метки: `<url1> (Пекин) + <url2> (Сучжоу) — «Название»`.
- `год` — из поля 4 Stage 1 (можно пусто).
- Экспортёр парсит url-поле тем же разборщиком, что и Stage 1
  (`_parse_report_urls`): метки `(…)` → текст ссылки, иначе название→url1 +
  «часть 2/3». Без реестра экспорт деградирует к атрибуции `cNN Имя` без ссылок.

Пример:
```
## Источники (реестр авторов)

- c01 | Иван Кезлинг | 2016 | <https://kezling.ru/china> — «Великая стена (фото)»
- c11 | KIE | 2018 | <https://t.ru/id_36699> (Пекин) + <https://t.ru/id_42768> (Сучжоу) — «Прогулки»
```

## Часть 3 — Известные дрейфы / на что смотреть при чтении `3_poi_pool.md`

- **Заголовки POI:** em-dash / bold / скобки в названиях ломали extraction на
  экспорте — канонизировать пунктуацию.
- **Нестандартный тег** (не из канона, напр. «Мукангчай хотелось бы») → не
  резолвится → `tag_parse_warnings`; молча меняет состав вариантов Stage 4.
  Правило: каждый тег резолвится в канон ИЛИ фиксируется в warnings.
- **Дедуп имён POI** («горы Аватар» = «Чжанцзяцзе») — зона LLM при извлечении;
  при чтении учитывать возможные дубли.
- **Источник поля 14** (POI с тональностью) приходит из `1_dr_reports.md`; если
  там оно ушло в bullet-список — на Stage 3 часть POI могла потеряться (см.
  `stage1-output-spec.md` часть 3).
- **Legacy-имя файла** `3_poi_aggregation.md` принимается наряду с каноном
  `3_poi_pool.md` (export глобит оба); `stage:`-id остаётся `3_poi_aggregation`.
