# stage0-polish-prompt.md

Инструкция для модели в **export-mode Stage 0**. Применяется ДО рендера
PDF: модель читает оригинальный `0_scope.md`, выдаёт «отполированную»
версию для presentation-grade output'а, а уже её рендерит
детерминированный Python-скрипт (`stages/stage0.py`).

Stage 0 PDF — **landscape-витрина регионов**: hero-обложка, карточки
longlist'а сгруппированы по role (Core / Supporting / Niche /
Borderline), кликабельный заголовок каждой карточки ведёт на Google
Images. Read-only — дальнейший выбор регионов делается через теги в
Stage 3.

**Принцип:** polish = переформатирование под аудиторию, НЕ переписывание
фактов. Все числа ночей, density-теги, причины исключения, reserve-пары,
сезонные оговорки — дословно. Удаляется/перефразируется только
pipeline-жаргон.

**Когда применять:** `recipient = self` (для parents Stage 0 в v1
не делается — это presentation для самого путешественника перед DR).

---

## Что на входе и что на выходе

**Вход:** полный markdown файла стадии 0 — YAML frontmatter + body.

**Выход:** markdown того же формата (YAML + body), с применёнными ниже
трансформациями. Никаких пояснений, no preamble — только сам markdown.

---

## Трансформации

Применять **все** по порядку. Если какая-то не применима — пропустить,
не упоминать.

### T1. Cover title

H1-заголовок переписать в человеко-читаемый формат:

**Было:** `# Stage 0 v2 — Региональное сужение: Камбоджа и Лаос, февраль 2026`

**Стало:** `# {Регионы человекочитаемо} · регионы для DR`

Примеры:
- `# Камбоджа и Лаос · регионы для DR`
- `# Южная Аргентина · регионы для DR`
- `# Корея · регионы для DR`

Регион брать из `## Контекст для следующих стадий` или из
`country_quota`/`longlist` (страны региона). **Длительность, сезон, темп
в заголовок НЕ включать** — они идут в подзаголовок hero-блока и в
таблицу параметров (формируются скриптом из YAML + маркера T2).

### T2. Маркер параметров поездки (для таблицы на обложке)

Первой строкой body (СРАЗУ после закрывающего `---` frontmatter, ПЕРЕД
`## Контекст для следующих стадий`) вставить маркер `[[поездка: …]]`.
Скрипт собирает из него таблицу ключевых параметров под hero. Поля
разделены `|`, формат `ключ: значение`:

```
[[поездка: группа: Алексей | регионы: Камбоджа → Лаос | сезон: февраль 2026 | темп: размеренный]]
```

Поля (все опциональны — указывай те, что выводимы из контекста/профиля):
- **группа** — кто едет. Только имя(имена) или собирательное название
  группы. Без слов «соло», «один человек», без паспортов/возрастов.
  - 1 человек: `Алексей`
  - 2+ человека по именам: `Алексей и Мария`
  - собирательно: `Родители`, `Семья`, `Друзья`
  Это единственный источник строки «Кто едет» в обложке — без маркера
  её не будет.
- **регионы** — маршрут стрелками (`Камбоджа → Лаос`); человекочитаемо.
  Если нет естественного «порядка» (страны в quota), просто `и`-список:
  `Камбоджа и Лаос`.
- **сезон** — «месяц год» (если не задан — скрипт выведет из trip_id).
- **темп** — «размеренный» / «сбалансированный» / «активный».

Страны, число регионов в longlist, цель по ночам/регион скрипт берёт сам
из YAML — в маркер их НЕ дублировать.

### T3. Маркер role для каждого региона в longlist'е

Перед каждым `### {регион}` в секции `## Longlist` вставить маркер
`[[регион: …]]`. Это страховка: КЛТ_1 legacy-формат группирует Region
universe по странам, а role в YAML может отсутствовать — маркер даёт
скрипту канонический источник role-классификации.

```
[[регион: имя: Сием-Рип и Ангкор | role: core | density: HIGH | сезон: ok | ночи: 3-5]]
### Сием-Рип и Ангкор
…
```

Маркер — **машинный вход рендерера, не видимый текст**: его ключи и значения
пишутся **английскими** (`role: core`, `density: HIGH`), даже когда тело
артефакта русское («Роль: Ядро», «Плотность: высокая»). Не «русифицировать»
маркер.

Поля:
- **имя** — точная копия `### {название}` (без суффикса «— RESERVE»).
- **role** — `core` / `supporting` / `niche` / `borderline`. Опирайся на
  honest assessment («уверенный кандидат» → core; «пограничный» →
  supporting; «niche»-фит профиля → niche; «скорее skip» → borderline).
  Тело может называть роль по-русски («Роль: Ядро», заголовок группы
  `### Ядро поездки (4)`) — в маркер кладётся английский ключ.
  Для legacy КЛТ_1, где роль явно не размечена: must-кандидаты (Ангкор,
  Луангпрабанг, Тямпасак, Пномпень) — core; reserve-пары — supporting.
- **density** — `HIGH` / `MED` / `LOW` (берётся из YAML `density_tag`).
- **сезон** — короткий тэг: `ok` / `risk` / `bad` / `blocked`. Длинное
  объяснение остаётся в проse longlist'а, для chip'а в карточке нужен
  только тэг.
- **ночи** — `{min}-{optimum}` (берётся из YAML).
- **non-canonical: да** — опц. флаг, если регион помечен non-canonical
  и при этом находится в longlist'е (скрипт также читает YAML
  `non_canonical_regions[].status: in_longlist`, маркер — резерв).

### T3b. Блок «Что увидишь» для каждого региона longlist'а

ВАЖНО: presentation-карточка должна давать пользователю **конкретное
представление**, что он увидит в регионе, не просто differentiator
методологического уровня. Блок добавляй **ПЕРВОЙ строкой ПОСЛЕ заголовка
`### {регион}`** (внутри тела региона), затем пустая строка:

```
### {регион}
**Что увидишь:** {3-5 конкретных впечатлений / достопримечательностей через ; }

{остальное тело региона}
```

**Критично — позиция.** Блок «Что увидишь» **обязан** стоять ВНУТРИ своего
`### {регион}` (после заголовка), а НЕ перед ним. Если поставить перед
заголовком — рендерер отнесёт его к ПРЕДЫДУЩЕму региону (сдвиг описаний на
одну карточку), а у первого региона блок уедет в преамбулу секции. Маркер
`[[регион: …]]` (T3) при этом остаётся ПЕРЕД `### {регион}` — он извлекается
глобально и от позиции не зависит; «Что увидишь» — позиционно-зависим.

Источник материала — раздел `Состав:` из проse longlist'а для этого
региона + `## Region universe` описание. Перепиши в формат «короткие
точки впечатлений», не enumeration POI и не fact-sheet.

Примеры:

```
**Что увидишь:** ансамбль Ангкор-Ват на рассвете; «лесные» руины Та-Прохм с корнями деревьев на стенах; outlying-храмы Бенг-Меалеа и Кох-Кер без толп; ночной рынок Сием-Рипа; ремесленные деревни Артизанс-д'Ангкор.
```

```
**Что увидишь:** мыс слияния Меконга и Нам-Кхан; королевские монастыри со старыми фресками; гора Пхуси на закате с видом на излучину реки; утренний tak bat (сбор подаяний); водопад Куангси с бирюзовыми ваннами; франко-лаосские шопхаусы.
```

```
**Что увидишь:** Ват-Пху — кхмерский храм V-XIV вв. на склоне Линга-Парвата; кофейные плантации плато Боловен; водопады Тат-Фан, Тат-Юанг, Тат-Лор; деревни горных народов; прохладное нагорье против жары долины.
```

Правила:
- 3-5 точек, разделены `;`. Длина одной точки — 4-8 слов.
- **Конкретные** имена (Ангкор-Ват, не «храмовый комплекс»; Пхуси, не
  «обзорная точка»). Это критично — общие слова не дают представления.
- Включай и **обязательное** (Ангкор-Ват — must), и **non-canonical**
  (outlying-храмы Кох-Кер — wow-фактор без толп).
- Сезонные wow-моменты («рассвет», «закат», «утренний tak bat»,
  «бирюзовые ванны зимой») приветствуются — они продают регион.
- НЕ дублируй с `## Region universe` дословно — это компиляция выжимок
  для presentation.
- НЕ добавляй цены / расписания / часы — это работа Stage 5.

Если в исходном Stage 0 артефакте `Состав:` для региона тонкий или
отсутствует — собирай блок из universe-описания + проse longlist'а;
твоя задача — дать пользователю «картинку», что он увидит.

**Кандидаты на замену (вне longlist'а).** Экспорт показывает ВСЕ регионы
единой сеткой: выбранные (✓ идут в DR) и не вошедшие (◌ кандидат на замену —
пользователь может подставить такой вместо выбранного). Карточка кандидата
рендерится из описания региона в `## Region universe` (для role-группировки) +
причины из `## Excluded regions`. Поэтому **держи universe-описания
конкретными** (1–2 реальных достопримечательности), чтобы кандидат был
оценим для свапа. «Что увидишь» для кандидатов добавлять не обязательно —
достаточно концентрированного universe-описания.

### T4. Имена H2-секций

**Сохранять дословно** (renderer матчит их по префиксу):
- `## Контекст для следующих стадий`
- `## Region universe`
- `## Longlist`
- `## Excluded regions`
- `## Non-canonical found`
- `## Темп и распределение по странам` (легаси: `## Tempo + country quota`)
- `## Honest assessment`

**Подавлять (убрать из polished output'а):**
- `## Следующий шаг` — pipeline-жаргон («Stage 1 DR-промт …»),
  пользователю в presentation-выдаче этого знать не нужно.

### T5. Strip pipeline-жаргон в видимых местах

В заголовках секций и H3-подзаголовках регионов — убрать:
- «Stage N», «v2», «schema_version» — внутренняя нумерация пайплайна;
- «longlist» в заголовке секции (само понятие сохраняем в проse) —
  заменить на «Регионы для DR» в `## Longlist (N) — для DR Stage 1` →
  оставить как `## Longlist` (renderer покажет «Регионы для маршрутного
  списка»).

Формулировка про группу (в т.ч. в `## Контекст для следующих стадий`):
«независимая пара» / «независимые путешественники» → «самостоятельная
пара» / «путешествуют самостоятельно» (каноническая формулировка архетипа
`самостоятельные`). Компонент похожести `independence` («независимость
планирования») не трогать — это другое понятие.

В body (региональные описания) НЕ переписывать — там это содержательно
(например, «evidence перед route», «non-canonical» — это термины
методологии, сохраняем).

### T6. Strip эмодзи

Эмодзи всё равно вырезаются на рендере (DejaVu не имеет глифов).
Убирать их явно в polished-output, чтобы polish-diff был чистым.
Stage 0 артефакт обычно без эмодзи, но проверь — встречается ⚠️ в
`warnings`.

### T7. НЕ трогать

- **YAML frontmatter** — все поля как есть (parser читает YAML дословно).
- **Числа** (ночи, density, longlist_count, total_regions_analyzed,
  formula_target_nights_per_region) — дословно.
- **Содержательные имена регионов** — не русифицировать, не переводить,
  не сокращать (это контракт с пользователем — он эти имена знает).
- **`## Region universe`** разбивку — сохранить как есть (по странам в
  legacy КЛТ_1, либо по role в новых артефактах). Скрипт устойчив
  к обоим форматам.
- **`reserve_for` / `substitute_reason`** в YAML — дословно.
- **`## Excluded regions`** список — дословно (порядок и причины).
- **`## Honest assessment`** — дословно.
