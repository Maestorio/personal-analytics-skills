# stage2-polish-prompt.md

Инструкция для модели в **export-mode Stage 2**. Применяется ДО рендера:
модель читает оригинальный `2_similarity.md`, выдаёт «отполированную»
версию, а уже её рендерит детерминированный Python-скрипт
(`stages/stage2.py`) в PDF (scoring-витрина) или HTML (интерактивный
lookup).

Stage 2 — **similarity-фильтр авторов** DR-базы по профилю. Каждый автор
получает score 0–10 по 6 компонентам (style/focus/pace/independence/
depth/demo) и категорию HIGH / MEDIUM / LOW / OUTLIER / UNSCORED. Это
**lookup-документ**: найти HIGH-карточку, понять, почему score такой,
взять reading list для Stage 3.

**Принцип:** polish = переформатирование под аудиторию, НЕ переписывание
scoring. Все числа (компоненты `value→contribution`, total, проценты
распределения), категории, формулировки «Тянет вверх/вниз», `SIGNAL`,
URL'ы и полная таблица — **дословно**. Удаляется/перефразируется только
pipeline-жаргон.

**Когда применять:** `recipient = self` (единственный режим Stage 2).

---

## Что на входе и что на выходе

**Вход:** полный markdown файла `2_similarity.md` — YAML frontmatter +
body (распределение, warnings, reading list с per-author breakdown,
полная таблица, компактный per-author MEDIUM/LOW).

**Выход:** markdown того же формата (YAML + body), с применёнными ниже
трансформациями. Никаких пояснений, no preamble — только сам markdown.

---

## Трансформации

Применять **все** по порядку. Если какая-то не применима — пропустить,
не упоминать.

### T1. Cover title

H1-заголовок переписать в человеко-читаемый формат, без `Stage 2 v…` /
технического жаргона:

**Было:** `# Stage 2 — Similarity filter: камбоджа_лаос_2026-02`

**Стало:** `# {Регионы человекочитаемо} · Похожие авторы`

Примеры:
- `# Камбоджа и Лаос · Похожие авторы`
- `# Южная Аргентина · Похожие авторы`

Регионы брать из `trip_id` / контекста. Число авторов, веса, пороги
скрипт берёт сам из YAML — в заголовок НЕ включать.

### T2. Маркер параметров поездки (для шапки/обложки)

Первой строкой body (СРАЗУ после закрывающего `---` frontmatter, ПЕРЕД
`## Контекст для следующих стадий`) вставить маркер `[[поездка: …]]`.
Скрипт собирает из него подзаголовок обложки PDF и header-label HTML.
Поля разделены `|`, формат `ключ: значение`:

```
[[поездка: кто: Алексей | длительность: 13 ночей | сезон: март 2025 | регионы: Патагония]]
```

Поля (все опциональны — указывай выводимые из контекста):
- **кто** — имя(имена) или собирательное название. Без «соло»,
  возрастов, паспортов.
- **длительность** — `13 ночей`.
- **сезон** — `март 2025`.
- **регионы** — человекочитаемо (`Ушуая → Калафате → Чальтен` или
  `Патагония`).

Без маркера подзаголовок обложки будет пуст (trip_id уже в заголовке,
полный контекст идёт info-box'ом ниже) — это допустимо, но маркер
делает обложку информативнее.

### T3. Strip pipeline-жаргон

В body убрать / переименовать:
- «независимая пара» / «независимые путешественники» (про группу) →
  «самостоятельная пара» / «путешествуют самостоятельно» (каноническая
  формулировка архетипа `самостоятельные`; не трогать компонент
  похожести `independence` — «независимость планирования»);
- секцию `## Следующий шаг` (и любые подписи «для Stage 3 / Stage 3
  разберётся / переходи к Stage 3») — это методология пайплайна, не
  содержание витрины;
- блок «Сохранить как …» — он не должен попадать в файл (выдаётся
  отдельным сообщением в чат), но если просочился — удалить;
- в `## Контекст для следующих стадий` оставить факты (кто едет,
  длительность, сезон, размер выборки, ключевые findings), убрать
  формулировки про механику скилла («similarity_score.py»,
  «reading_list передаётся в Stage 3»).

### T4. Strip эмодзи из body

Эмодзи не рендерятся в PDF (DejaVu/CID-шрифты без emoji glyph'ов).
В самом файле Stage 2 эмодзи быть не должно (см. spec §7), но проверь
и убери из секции `## Warnings` маркеры `⚠️` / `ℹ️` в начале пунктов —
severity передаётся словом (`critical:` / `borderline:` / `info:`),
renderer сам обернёт всё в amber-box. HTML тоже не зависит от эмодзи.

### T5. Сохранять дословно (контракт с парсером)

Эти элементы парсер читает дословно — **не переписывать, не
переупорядочивать, не округлять**:

- **YAML frontmatter** — все поля (`trip_id`, `stage`, `weights_used`,
  `thresholds_used`, `*_count`, `warnings`, `created`,
  `archetype_used`/`weights_source` если есть).
- **Строки компонентов** — формат `C1 style {value}→{contribution} ·
  C2 focus … · C6 demo …` (или компактный `C1 {value}→{contribution} ·
  …`). Стрелка `→`, разделитель `·`, null как `C6 demo —`. Числа
  дословно. Строка может быть перенесена на 2 физических строки
  (`C1…C3 ·` / `C4…C6`) — это нормально, парсер их склеит; не «чинить».
- **Заголовки авторов** — `#N **Имя** — {total}/10 [user_added]
  [confidence: …]` (или без `**`, или `(MEDIUM)` для компактных).
- **`SIGNAL:` строки** OUTLIER-авторов — дословно (ключевой сигнал).
- **«Тянет вверх:» / «Тянет вниз:»** — дословно (можно подчистить
  опечатки, но не сокращать смысл).
- **Полная таблица всех авторов** — все строки `| # | Автор | Score |
  Категория | URL |`, отсортированы по score. **Ни одного автора не
  опускать** «for brevity».
- **URL'ы** — дословно.
- **Проценты и числа распределения**, строка `**Confidence:** …`.

### T6. НЕ трогать

- **YAML frontmatter**.
- **Любые числа**: компоненты, contributions, total, проценты,
  confidence breakdown, counts.
- **Категории и пороги.** Канон тела — русский ярлык (ВЫСОКАЯ / СРЕДНЯЯ /
  НИЗКАЯ / ОСОБЫЙ СИГНАЛ / БЕЗ ОЦЕНКИ), легаси-файлы несут английский
  (HIGH / MEDIUM / …). **Не переводить ни в одну сторону** — ни EN→RU
  («помогу русификации»), ни RU→EN («верну канон»): обе формы валидны,
  экспорт печатает их по-русски сам. Перевод ярлыка = правка данных,
  а не языка изложения. То же для severity warnings
  (`критично:` / `critical:`) — оставить как пришло.
- **Состав reading list** (кто в обязательных / особый сигнал / расширенный) —
  это решение скрипта, не polish'а.
- **Имена авторов, URL'ы**.

Polish НЕ имеет права переклассифицировать автора, изменить score,
добавить/убрать автора из reading list или из полной таблицы.

## Чек-лист перед сдачей

- [ ] H1 — человекочитаемый («{Регионы} · Похожие авторы»), без
      `Stage 2 v…`.
- [ ] Маркер `[[поездка: …]]` стоит сразу после frontmatter, перед
      `## Контекст`.
- [ ] `## Следующий шаг`, подписи «для Stage 3», блок «Сохранить как»
      удалены.
- [ ] Эмодзи `⚠️`/`ℹ️` из `## Warnings` убраны (severity — словом).
- [ ] Строки компонентов (`C1 …→… · …`), `SIGNAL:`, «Тянет вверх/вниз»,
      проценты, `Confidence` — не тронуты.
- [ ] Полная таблица — все авторы на месте, отсортированы по score,
      ничего не опущено.
- [ ] YAML frontmatter, категории, состав reading list, score'ы, URL'ы
      — не тронуты.
- [ ] Никаких «Stage 2 / similarity_score.py / Stage 3 разберётся» в
      видимых местах body.

После polish — `polish_check.py` сверит длину, число H2, таблицы и
YAML-поля. Любое нарушение → исправить и перепрогнать polish.

---

## Формат ответа

Один markdown-блок начиная с `---` (YAML frontmatter) и до конца файла.
Без обёртки в \`\`\`markdown. Без вводных фраз и trailing-комментариев.
Готово к скармливанию в
`export.py --input polished.md --stage 2 --recipient self [--format pdf|html]`.
