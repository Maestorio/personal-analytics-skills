# HTML→PDF рендер-слой

Презентационный слой экспорта, рендерящий стадии в **self-contained
print-ready HTML** на единой дизайн-системе и конвертирующий в PDF браузерным
движком. Параллелен reportlab-слою (`pdf_lib` + `stages/`): тот остаётся
fallback. **Слой извлечения контента (`stages/stageN.extract_content`) общий —
HTML-рендереры его переиспользуют без изменений** и отвечают только за разметку.

## Файлы (относительно `scripts/export/`)

| Файл | Назначение |
|---|---|
| `assets/design-tokens.css` | Дизайн-токены `:root` (палитра/типошкала/ритм/чипы). Единый источник стиля. |
| `assets/design-components.css` | CSS компонентов (`.cover-*`, `.statband`, `.ribbon`, `.section-plate`, `.day`, `.program`, `.box--*`, `.chip--*`, `.data-table`, `.scard`, `.opt-card`, `.comps`, `.poi`, `.passport`, `.notelist` …). |
| `assets/nav-layer.{css,js}` | Навигационный слой TNAV: оглавление всегда под рукой (см. ниже). |
| `fonts/IBMPlex*.ttf` | Шрифты (latin+cyrillic+₽₩€→↔, табличные цифры). |
| `html_lib.py` | Сборка документа + inline/block markdown + конвертация в PDF. |
| `stages_html/stageN.py` | Рендерер стадии: `extract_content` → разметка на CSS-классах. |

## `html_lib` API

- `build_html_document(body, *, title, embed_fonts=True, landscape=False,
  nav=True, doc_key="", prep_md="")` — полный HTML: `<head>` с инлайн-CSS
  (токены+компоненты) и `@font-face` (base64-TTF при `embed_fonts`, иначе
  ссылки на `fonts/`); print-CSS (`@page A4`, лист = страница).
  `landscape=True` — A4 landscape (Stage 0). `nav=False` — без навигационного
  слоя. `doc_key` — стабильный ключ документа (trip_id) для буфера отметок.
  `prep_md` — имя файла плана, в который слой пишет отметки подготовки
  (резолвится `prep_sync.resolve_plan_md`; пусто → запись недоступна).
- `nav_layer()` — `<style>`+`<script>` навигационного слоя из
  `assets/nav-layer.{css,js}`.
- `md_inline(text, *, todo=True)` — inline markdown → HTML: md-ссылки, голые
  URL и **голые домены** (`srail.or.kr` → ссылка; `8.4/10` не трогается),
  bold/italic, TODO-подсветка. Стадии правил защищены сентинелами — TODO/bold
  не лезут внутрь ссылок.
- `md_block(text)` — block markdown → HTML: параграфы, md-таблицы → `.data-table`,
  bullet-списки → `.notelist` (контент в обёрточном `<div>`; вложенные пункты
  сдвигаются вправо по отступу источника), `---` → тонкая линия.
- `html_to_pdf(html_str, out_path)` — конвертация через headless-chromium
  (`--print-to-pdf`). На платформе HTML→PDF может выполнять core `pdf` skill;
  HTML-экспорт (сохранить строку) работает без движка.

## Рендеринг стадии

```python
from export.stages import stage5
from export.stages_html import stage5 as h5
ex = stage5.extract_content(adapted)          # общий слой извлечения
h5.build_html(ex, "out.html", recipient="self", embed_fonts=True)
```

Сигнатуры `build_html(extracted, output_path, *, recipient, embed_fonts)`
едины; исключения — **Stage 6** (`build_html(s6_parsed, output_path, *,
source_file=…)`: резолвит устаканенный 5_vX по YAML `source_plan`, встраивает
географическую карту + приложения + локатор/ленту из координат) и **Stage 2**
(на вход — объект `Stage2Content`).

Единая точка входа движка — `stages_html.render_html(stage_id, adapted,
output_path, *, recipient, embed_fonts, source_file)`: толерантно резолвит
`stage_id` (`«5_final_plan»` / `«5_stage»` / `«5»` → канон), сам делает
`extract_content` и зовёт нужный `build_html`. `has_builder(stage_id)` — есть
ли рендерер для стадии.

## CLI (`export.py`)

```bash
# HTML (Claude Design) — самодостаточный файл.
python3 export.py --stage 5 --trip корея_2025 --format html

# PDF через HTML-движок (default --engine html): HTML-сайдкар + конвертация.
python3 export.py --stage 5 --trip корея_2025 --format pdf

# Fallback на reportlab (пишет PDF локально без браузера).
python3 export.py --stage 5 --trip корея_2025 --format pdf --engine reportlab
```

`--engine html` (**default**) — новый презентационный слой; перехватывает
`--format html` и `--format pdf`. `--engine reportlab` — fallback (и для DOCX
Stage 3, у которого HTML-аналога нет). Маршрут:

| `--format` | engine=html | engine=reportlab |
|---|---|---|
| `html` | `stages_html` → `.html`, `RenderRequest(html)` | реестр (напр. Stage 2 — интерактивный lookup) |
| `pdf` | HTML→PDF: `.html`-сайдкар + конвертация | reportlab пишет PDF напрямую |
| `docx` | — (не перехватывается) | реестр (Stage 3) |

**HTML→PDF (`--format pdf`, engine=html):** рендерит `.html`-сайдкар рядом с
целевым `.pdf`, затем пытается локальный headless-chromium (`html_to_pdf`).
Если chromium есть — пишет PDF и `local_conversion=true`. Если нет (как на
платформе) — `local_conversion=false`, а `RenderRequest.notes` несёт инструкцию
отдать сайдкар core `pdf` skill для серверной конвертации. `RenderRequest`
выводится в stdout (JSON); `--write-request <path>` дублирует на диск.

## Навигационный слой TNAV (`assets/nav-layer.{css,js}`)

Оглавление, доступное из любой точки документа: на телефоне — плавающая панель
(«Разделы» → шторка со списком, контекстная кнопка, «наверх»), на десктопе —
липкий рельс слева с подсветкой по прокрутке. Дизайн — Claude Design, проект
`553ebbf1-cf71-453d-9d71-39b0427aee77`; имена классов `tnav-*` — контракт с
дизайном, не переименовывать.

Ключевые свойства:

- **Меню строится скриптом ИЗ документа** — `.section-plate`/`.anno` (разделы),
  дальше первое найденное из `.day` → `.poi[data-poi]` → `.opt-card` →
  `.scard` → `[id^=author-]`. Рендереры под меню ничего не размечают, поэтому
  оно не может разойтись с содержимым. Обратная сторона: **переименование этих
  классов молча опустошает меню** — прикрыто drift-гардом в
  `tests/test_html_export.py` [17].
- **Контекстная кнопка зависит от документа**: идёт поездка → «Сегодня X/Y»
  (прыжок на текущий день, X — номер дня по календарю плана), поездка впереди →
  «До старта N дней» → «Заранее», прочие стадии → счётчик («Места · 84»).
  В режиме рельса тот же статус — строкой под заголовком рельса («Идёт · день
  X из Y» / «До старта · N дн»), а у «Заранее» — счётчик несохранённых
  отметок (кнопки «Сохранить» в рельсе нет, сохранение — из шторки).
- **Рельс или панель** решает ширина окна: рельс — при окне ≥ 1100px и месте
  слева от листа A4 ≥ 202px, то есть окно ≥ ~1200px. Кабинет (`travel.html`)
  открывает стадию окном 1280px — там рельс помещается.
- **«↑ В начало»** в рельсе — сразу под списком глав (как в читателе
  кабинета). Переход по меню держит подсветку на цели, дальний переход
  (> 2 экранов) — мгновенный.
- **Переключателя темы нет** (с 2026-10): тема берётся из кабинета по
  `hub-theme` при открытии; кнопка внутри iframe кабинета перекрашивала только
  документ, не страницу вокруг.
- **Даты дней** — атрибут `data-date="ГГГГ-ММ-ДД"` на `.day`, считает
  `stages_html/stage5.iso_dates()`: в заголовке дня года нет, он берётся из
  `trip_id`/`season` и переносится на границе января. Года нет → атрибута нет
  → кнопка «Сегодня» просто не появляется (штатное состояние).
- **«Заранее»** собирает разбросанные подготовительные блоки (критические
  пункты, чеклист за 2 недели, брони, TODO) в одну шторку со счётчиками, а
  пункты `[ ]` внутри `.note-item` становятся живыми чекбоксами прямо в
  документе. Хранятся они в самом плане (`.md`) — см. раздел про `prep_sync`
  ниже; локальный буфер под ключом `doc_key` (trip_id) держит только то, что
  ещё не записано, и потому общий у `5_план` и `6_финал`.
- **Печать не затрагивается**: `#tnav-root` скрыт в `@media print`, чекбоксы
  прячутся, «[ ]» возвращается на бумагу. Проверено: PDF со слоем и без —
  байт в байт.
- **Автономность**: ни одного внешнего запроса, только инлайновые CSS/SVG/JS.
- Высота панели отдаётся наружу как `--tnav-bottom` — под неё сдвигается
  плавающая кнопка «Сохранить» edit-слоя Stage 3/4.
- **Stage 2 в HTML слоя не получает осознанно**: это интерактивный lookup со
  своим шаблоном (нет ни `.page`, ни плашек) и собственной навигацией.

### Старые экспорты — `inject_nav.py`

Новые экспорты получают слой сами. Экспорты, собранные ДО его появления,
пересобрать нельзя без потери **полиша**: полированный вход (`polished_*.md`
с маркерами) часто эфемерный — на диске остались только сырой `.md` и готовый
HTML. Для них есть `scripts/export/inject_nav.py`:

```bash
python3 inject_nav.py --dry-run trips/регион_a_2027          # показать, что будет
python3 inject_nav.py --backup-dir /tmp/bak trips/регион_a_2027
```

Вырезает прежний блок (идемпотентно, поэтому работает и как апгрейдер слоя),
ставит `data-tnav-key` из имени файла (в NFC — macOS отдаёт имена в NFD),
доводит CSS панели «Сохранить» Stage 3/4 до генератора, проставляет `data-date` по видимой
подписи «День N · DD.MM» (год — из `trip_id` в имени) и вставляет слой перед
`</body>`. Содержимое документа не трогает: снятие слоя и добавленных
атрибутов даёт исходный файл байт в байт (проверяется тестом). Второй
реализации слоя нет — блок берётся из `html_lib.nav_layer()`, даты считает
общий с экспортом `stage5.iso_from_daydates`.

## Ограничения / правила

- **Цвета токенов — в `oklch()`**; современные браузеры их рендерят. Для
  reportlab те же значения сконвертированы в hex (`style.py`).
- **Шрифты** — IBM Plex Sans/Mono. Геометрию-маркеры даёт CSS (`::before`),
  эмодзи не используются.
- **Карта** (Stage 6) — географическая (границы страны + рёбра-полудуги),
  узлы-аэропорты с маршрута убираются. Рисуется matplotlib → PNG, встраивается
  как `<img src="data:image/png;base64,…">` (без него HTML строится без карты).
- HTML **print-ready**: `@page A4`, `.page` = лист; конвертер просто печатает.
- **Геометрия листа — `box-sizing:border-box` на `.page`, без media-условия.**
  `.page` описан как `width:794px` (ровно A4 при 96dpi) **плюс** `padding:--pad`
  (48px) с двух сторон, поэтому при `content-box` внешняя ширина листа = 890px
  против 793.7px страницы A4, а `@page{margin:0}` перекос поглотить нечем —
  конвертер молча срезает правый край на 12% (полоса дат обложки, правые колонки
  таблиц, край карты). Дефект жил в CSS, а не в конвертере, поэтому бил по всем
  стадиям и всем движкам (кейс 2026-09-03: правило стояло только под
  `@media screen`, у печати была пометка «ровно A4» — про padding забыли).
  Правило обязано действовать в обоих медиа ещё и потому, что иначе PDF не
  совпадает с экранным превью: на экране контент 698px, в печати был 794px.
  Регрессия — `test_html_export.py`, блок «печатная геометрия листа».
- **Русификация видимого вывода** — `html_lib.ru_anglicisms(text)` заменяет
  структурные англицизмы экспорта (`on_target` → «в рамках бюджета», `In-trip`
  → «В поездке», `all-in` → «всё включено», `multi_region_tour` →
  «мульти-регион-тур», `vs target` → «к плану»). Применяется точечно к тексту
  перед `md()`/`md_block()` (бюджет-таблицы Stage 5, контекст Stage 0) — НЕ
  глобально (URL/код не трогает). Свободную англоязычную прозу (цитаты авторов)
  не русифицирует — это контент, а не разметка.
- **Карточки-витрины** (`.scard-grid`): по умолчанию 2 колонки (`cols-3` — 3,
  `cols-1` — одна на всю ширину). Детализированные карточки (Stage 1 источники,
  Stage 2 авторы) — `cols-1`, иначе контент не помещается. `.scard{min-width:0}`
  страхует от переполнения грида длинным контентом.
- **Плашки секций** — через `html_lib.plate(title, *, no, sub)`: filled
  `.section-plate` — РОВНО ОДНА на стадию (её заголовок); все группы/подразделы —
  `sub=True` (`section-plate section-plate--sub`, всегда с базовым классом). `no`
  — моно-индекс слева (§ S0 / core / HIGH). Смена темы внутри секции —
  `html_lib.anno(text)`. Правило «одна filled на стадию» защищает от «стены teal».

### Отметки подготовки живут в плане (`prep_sync.py`)

Галочка пункта `[ ]` пишется В СТРОКУ плана (`- [x] Выкупить билеты`), а не в
отдельное хранилище. Следствия: отметка переживает пересборку экспорта (едет
вместе со своей строкой), наследуется новой версией плана, попадает в PDF
(reportlab рисует `[x]` как ☑) и видна с другого устройства.

- **Куда писать** — `prep_sync.resolve_plan_md`: выбор по СОДЕРЖИМОМУ (доля
  совпавших пунктов), имя — лишь подсказка. Имя врёт: у Китая `6_final.md`
  объявляет `source_plan: 5_final_plan_v1.md`, а на диске `5_final _plan_v1.md`.
  У Stage 6 цель — тот же `5_vX` (своего чеклиста у финала нет). Уверенного
  кандидата нет → блока `tnav-prep-config` нет, слой честно говорит, что
  отметки живут только в браузере.
- **Сопоставление** — `normalize_item`: md-ссылки → текст, разметка/URL/
  пунктуация вон, «ё»=«е», регистр и пробелы схлопнуты. На реальных данных
  48/48 (Китай) и 29/29 (Вьетнам). Скобки принимаются как `[ ]`, `[]`, `[x]`,
  `[х]`; запись приводит к канону.
- **Когда писать** — по кнопке «Сохранить в план», не на каждый клик. Клики
  копятся в localStorage, шторка показывает «В плане: N · не сохранено: M».
  Запись — под логином (`hub-auth`, как edit-слой Stage 3), 409 → перечитать и
  повторить один раз. Чтение состояния плана при открытии — публичное (сам
  `.md` лежит в открытой зоне), поэтому гость видит актуальные отметки.
- **Сверка HTML ↔ план** показывается в шторке всегда: «Сверка с планом: 48 из
  48 · в плане отмечено 3 из 48» плюс раскрывающиеся списки «HTML старше
  плана» / «нет строки в плане» / «текст встречается дважды». Это отладочный
  слой технологии: расхождение видно сразу, а не выясняется в поездке.
- **Правда за планом**: при расхождении страница подтягивает своё состояние к
  файлу (экспорт статичен и помнит скобки на момент сборки).

**Панель не режет подписи.** Кнопки в панели не сжимаются (`flex: 0 0 auto`);
если в ширину не помещаются, подпись снимается ЦЕЛИКОМ по приоритету (сначала
контекстная кнопка, потом «Разделы», в последнюю очередь действие сохранения),
счётчик остаётся всегда. Признак «не влезло» меряется при запрещённом сжатии
(класс `is-measuring`): `scrollWidth` панели всегда равен `clientWidth` (flex
ужимает вместо переполнения), а у текста с `text-overflow: ellipsis` ширины
почти совпадают — обе метрики дают ложное «влезло», на чём две попытки фикса и
прокололись. Гард — `tests/test_nav_layout.py` (headless-chromium, 320–430 px;
без playwright — честный пропуск).
