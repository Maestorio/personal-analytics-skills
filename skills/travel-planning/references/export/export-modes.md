# export-modes.md

Spec режима «E» (Export). Превращает stage-артефакты (`5_final_plan.md`,
`3_poi_pool.md`, и т.д.) в presentation-grade **HTML** (дефолт) / PDF / DOCX
под конкретного получателя.

---

## ⛔ ЖЁСТКИЕ ПРАВИЛА (читать первым)

**Эти правила имеют приоритет над любым твоим желанием «сделать лучше».**

1. **НЕ пиши собственный генератор HTML/PDF/DOCX.** Не создавай `gen_pdf.py`,
   не вызывай `reportlab` / `python-docx` напрямую, не пиши свой layout.
   Рендер делает **только** `scripts/export/export.py`. Он уже умеет:
   дизайн-систему Claude Design (HTML), CJK-шрифты, PDF-outline (закладки),
   плашки дней с бюджетом, section-бары, warning-боксы, гиперссылки,
   цветокод регионов, русификацию таксонов. Свой код это сломает и потеряет
   фичи.

2. **Дефолт-формат — HTML для ВСЕХ стадий 0–6.** `export.py --stage N`
   без `--format` отдаёт HTML. PDF или DOCX — **только по явному
   `--format pdf` / `--format docx`**. Не решай сам «наверное, нужен PDF» —
   если пользователь не попросил формат, делай HTML.

3. **Твоя работа — только Polish-шаг** (текстовая трансформация markdown
   по `references/stage{N}/stage{N}-polish-prompt.md`). Всё остальное
   (sanity, render) — это запуск готовых Python-скриптов через Bash.

4. **Если скрипт упал — чини причину, не заменяй скрипт.** Для HTML-экспорта
   зависимостей рендера нет (stdlib). Для `--format pdf` через reportlab-
   движок или для карты Stage 6 — `pip install reportlab matplotlib
   --break-system-packages`. Не переписывай рендер «с нуля» — нарушение №1.

5. **НЕ копируй и НЕ переименовывай пакет `scripts/export`.** Запускай
   `export.py` **по месту** (`python3 <путь>/scripts/export/export.py …`),
   даже из read-only локации. Копирование папки ломает относительные импорты
   (`from export import …`) и теряет `scripts/taxonomy.py` (лежит **уровнем
   выше** `export/`) — это стоило целого цикла отладки на живом прогоне.

6. **Порядок шагов фиксирован:** Polish → сохранить polished.md →
   `polish_check.py` → если OK → `export.py`. Не пропускать sanity.

**Триггеры режима E** (любой из): `/travel-planning export`,
`/travel-planning экспорт`, «экспортируй план», «сделай HTML/PDF плана»,
«export Stage 5» + приложенный stage-артефакт.

## Дефолт-формат и матрица стадия × формат (Р1)

| Стадия | Дефолт (`--format` не задан) | По явному запросу |
|---|---|---|
| 0 scope | **HTML** (витрина регионов) | PDF |
| 1 dr-reports | **HTML** | PDF |
| 2 similarity | **HTML** — интерактивный lookup | PDF (статичная витрина) |
| 3 poi | **HTML** | PDF · **DOCX** (operative + round-trip) |
| 4 variants | **HTML** | PDF |
| 5 final-plan | **HTML** | PDF |
| 6 финал | **HTML** (план + карта + досье) | PDF |

- **HTML — self-contained** (инлайн CSS + шрифты base64): открывается в
  браузере как 1:1 превью, конвертируется в PDF headless-chromium или core
  `pdf` skill. Движок по умолчанию `--engine html`.
- **`--format pdf`** идёт через тот же HTML-слой (HTML→PDF). Авто-цепочка
  локальной конвертации: headless-chromium → weasyprint; если ни одного
  нет — handoff в core `pdf` skill (это штатный путь на платформе, не
  сбой). `wkhtmltopdf` в авто-цепочку **не входит** (Qt WebKit ≈2012 без
  поддержки CSS grid — карточки/паспорт рассыпаются в столбик); включить
  его в обход авто-цепочки можно только явным env
  `TRAVEL_PDF_ENGINE=wkhtmltopdf` — это деградация качества, не
  рекомендуется. `--engine reportlab` даёт нативный локальный PDF (и
  обязателен для DOCX Stage 3).
- **Исключение: `--stage 6 --format pdf` по умолчанию собирает нативный
  reportlab, а не HTML→PDF** (решение 2026-09-03). Stage 6 — единственная
  стадия, чей PDF существует ради бумаги: его печатают и берут в поездку.
  Нативный движок даёт номера страниц и колонтитул с провенансом («финал ·
  из 5_final_plan_v6.md · создан …»), которых у HTML→PDF нет вовсе, и не
  зависит от того, какой конвертер оказался в системе — три экспорта одного
  вьетнамского финала прошли через wkhtmltopdf, weasyprint и chromium и дали
  13/25/26 страниц. Содержимое при этом то же: оба движка рендерят один
  polish-md через один парсер (замер: покрытие текста 87,5% против 87,6%).
  **HTML Stage 6 остаётся на дизайн-системе** — это основной артефакт
  «проверить с телефона». Перекрыть дефолт можно в обе стороны:
  `--stage 6 --format pdf --engine html` вернёт HTML→PDF. Без установленного
  reportlab экспорт печатает предупреждение и сам откатывается на HTML→PDF —
  но только когда движок не задан явно.
- **Печатный Stage 6 идёт без видимого оглавления и без счётчика «Пунктов к
  проверке» на обложке.** Оглавление занимало половину первого листа и
  дублировало PDF-outline — закладки в сайдбаре остаются, а на бумаге листают,
  а не кликают. Счётчик считал секцию «TODO для верификации», которой в
  дорожном PDF нет (`TRIP_DROP_PROGRESS`), то есть обложка обещала пункты,
  которых в документе не найти. Оба обрезает `TRIP_DROP_PRINT`; Stage 5 и то,
  и другое сохраняет — это планировочный документ.
- **Кабинетные атрибуты снимаются в ОБЕИХ ветках Stage 6** (`TRIP_DROP_OFFICE`):
  «Вариант X» в кикере обложки, подстрочник с вердиктом о попадании в бюджет,
  колонка «Вероятность» в плане реагирования на риски (вместе с её сноской) и
  ссылки на стадии конвейера в прозе («Stage 3 #43», «vs target Stage 4»). Это
  следы того, что документ был предметом выбора и защиты бюджета: в поездке
  варианта уже нет, вероятность либо реализовалась, либо нет, а номера стадий
  читателю плана не с чем соотнести. Метки TODO внутри операционного текста
  («**TODO:** онлайн-регистрация за 24 ч») снимаются только в PDF — это прогресс
  подготовки, и в интерактивном HTML он остаётся, как секция TODO и чеклист.
  Снимается ТОЛЬКО разметка: у ссылки — сама ссылка, у метки — метка, но не
  задача. Голое слово «TODO» в прозе («Было (v5, TODO)») не трогается — это
  упоминание, а не маркер.
- **Подвал печатного Stage 6 — «финал · создан ДАТА», без имени исходного 5_vX.**
  Имя — внутренний адрес пайплайна, на бумаге оно повторялось на каждой из трёх
  десятков страниц. Провенанс не потерян: он уходит в свойства файла (PDF
  `subject`), где его видно в свойствах и не видно читателю.
- **Секции печатного Stage 6 начинаются условным разрывом, а не жёстким.**
  Раньше каждая секция стартовала с новой страницы независимо от своей длины —
  документ набирал листы с тремя строками (на живом вьетнамском финале четыре
  из двадцати восьми), а обложка после чистки читалась просто как пустая
  страница, потому что карта уходила на следующую. Теперь перенос происходит,
  только если до низа осталось меньше четверти листа (`_SECTION_MIN_SPACE_PT`);
  то же правило действует для карты и приложений Stage 6. Замер: 28 страниц →
  24, полупустых 6 → 2 (обложка с картой и хвост последней секции).
  Планировочный Stage 5 разбивку «одна секция = свои страницы» сохраняет.
- **DOCX Stage 3** — только `--engine reportlab` (python-docx); round-trip
  импорт заполненного файла — тоже reportlab-ветка.

**Просят оба формата (HTML и PDF) — это ДВА запуска `export.py`** (один с
`--format html`, второй с `--format pdf`) на одном и том же polished-md;
polish и sanity не повторяются. Порядок запусков не важен: PDF-путь пишет
свой промежуточный HTML в отдельное имя (`{stem}_print.html`) и файл
HTML-экспорта не трогает. Это сознательно два прогона, а не один флаг:
PDF-документ реально другой (Stage 1 — landscape и 2 колонки, Stage 3/4 —
без edit-слоя), рендерить его всё равно нужно отдельно.

**⚠️ HTML-сайдкар PDF-рендера ≠ HTML-экспорт.** При `--format pdf` движок
пишет промежуточный `{stem}_print.html` и конвертирует его — сайдкар может
быть в альт-ориентации (Stage 1 → landscape + 2 колонки для PDF) и не несёт
edit-слоя Stage 3/4. При успешной локальной конвертации сайдкар удаляется;
при handoff к core `pdf` skill остаётся до конвертации (после — можно
удалить). Настоящий HTML-**экспорт** (`--format html`) — отдельный файл
`{stem}.html` (портрет, 1 колонка); PDF-прогон его не трогает. Если
пользователь просил HTML, запускай `--format html` (или без `--format`),
а не PDF-путь.

**Принцип:** двухслойная архитектура.

```
1. POLISH layer (модель, не детерминирована):
   stage_N.md → polished_stage_N.md
   • переименование pipeline-фраз
   • удаление internal metadata
   • человеко-читаемые заголовки
   Инструкции: references/stage{N}/stage{N}-polish-prompt.md

2. SANITY check (Python, детерминирован):
   diff source ↔ polished по счёту секций/чисел/checkbox'ов
   Скрипт: scripts/export/polish_check.py

3. RENDER layer (Python, детерминирован):
   polished.md → final.{html,pdf,docx}
   Скрипт: scripts/export/export.py
```

Polish — добавляет judgment (что для людей, что для пайплайна).
Sanity — ловит «галлюцинации» (дроп дня, изменение цены, over-rewriting).
Render — даёт визуальную стабильность (одинаковый layout каждый раз).

**Каждая рендеримая стадия имеет СВОЙ polish-prompt.** На сегодня:
- Stage 0 → `references/stage0/stage0-polish-prompt.md`
- Stage 1 → `references/stage1/stage1-polish-prompt.md`
- Stage 2 → `references/stage2/stage2-polish-prompt.md`
- Stage 3 → `references/stage3/stage3-polish-prompt.md`
- Stage 4 → `references/stage4/stage4-polish-prompt.md`
- Stage 5 → `references/stage5/stage5-polish-prompt.md`
- Stage 6 → `references/stage6/stage6-polish-prompt.md`

`polish_check.py` — stage-aware: профиль выбирается по полю `stage:` из YAML.
Подробнее — `docs/travel-planning/export/export-design.md §2.5`.

## Trigger / gate

Пользователь в **новой чат-сессии** (рекомендуется Sonnet base, без T)
запускает `/travel-planning export` и **прикрепляет** stage-артефакт
(`5_final_plan_v{N}.md`, `4_variants_v{N}.md`, `3_poi_pool.md`, …).
Опционально: `recipient` (`self` / `parents` / `field` / …; дефолт `self`)
и `--format` (если не HTML).

Активационный gate: один stage-артефакт (приложен ИЛИ доступен по `trip_id`)
+ распознаваемая YAML-шапка с `stage: N_*`. Нет файла и нет `trip_id` —
consent-gate (`storage-and-naming.md §1.4`).

**Почему новая сессия:** plan-building использует Opus + extended thinking
(дорого) и забит DR-отчётами/similarity; polish — механические
трансформации, обычная Sonnet справится ~10× дешевле и без дрейфа.
Polish-output должен быть auditable отдельным чистым артефактом.

**`recipient=field` (полевая версия Stage 5).** In-trip план без
подготовительных и review-секций: исключаются «Документы/визы/перелёт»,
«Критические подготовительные», «Чеклист за 2 недели», «TODO для
верификации», «Diff» и «Обоснование ключевых решений»; остаются дни, карты,
сводные, гастрономия, план рисков. Имя файла получает суффикс `полевой`.

## Полный поток режима E (на примере Stage 5)

`EXP=scripts/export`. Пути — относительно корня скилла.

```
┌─────────────────────────────────────────────────────────────────┐
│ Step 0 (только если нужен --format pdf/docx локально): deps      │
│  $ pip install reportlab matplotlib --break-system-packages      │
│  HTML-экспорт (дефолт) зависимостей НЕ требует.                  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 1: Считать stage-артефакт                                   │
│  • из приложенного к чату файла, либо                            │
│  • Read({travel_root}/trips/{trip_id}/5_final_plan_v{max}.md)    │
│  • сохранить копию, СОХРАНИВ версию в имени: 5_final_plan_v{max}.md│
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 2: Polish — ЕДИНСТВЕННЫЙ шаг с твоим участием                │
│  • Прочитать references/stage5/stage5-polish-prompt.md           │
│  • Применить ВСЕ трансформации к markdown; keep/drop YAML-полей — │
│    там же. НО frontmatter `iteration`/`trip_id`/`stage` СОХРАНИТЬ │
│    ВСЕГДА — из `iteration` берётся версия выходного файла.        │
│  • Сохранить polished, СОХРАНИВ версию в имени: polished_v{max}.md│
│  Пропустить polish, если recipient=archive или --no-polish.      │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 3: Sanity check (запуск скрипта, НЕ свой код)               │
│  $ python3 $EXP/polish_check.py --source 5_final_plan_v{max}.md \ │
│                                 --polished polished_v{max}.md     │
│  • exit 0 → продолжаем; exit 1 → показать violations, повторить  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 4: Render (запуск скрипта по месту, НЕ свой код)            │
│  $ python3 $EXP/export.py --input polished_v{max}.md --stage 5 \ │
│                           --recipient self         # → HTML      │
│  Версия выхода = frontmatter `iteration` (строго соответствует   │
│  плану); если stderr выдал «⚠ ВЕРСИЯ: … iteration = N» — проверь, │
│  что подан свежий md (имя/iteration совпадают с v{max}).         │
│  Для PDF: добавить --format pdf. Упал на ImportError → Step 0.   │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ Step 5: Презентация в чате                                       │
│  «Готов HTML: {trip_id}_финальный_план_v{N}.html (N = версия     │
│   плана). Polish: T1/T4/T9. Sanity OK. PDF — по запросу.»        │
└─────────────────────────────────────────────────────────────────┘
```

> **Строгое соответствие версии (v0.66).** Имя выходного файла (`_vN`) берётся
> из frontmatter `iteration` md, а не из имени входного файла. Раньше workflow
> сохранял копию как `5_final_plan.md`/`polished.md` (без версии) → выход
> получался `_v1` даже для v5-плана, и travel-окно прятало его как устаревший.
> Теперь: (1) `export.py._resolve_version` берёт версию из `iteration` и громко
> предупреждает при расхождении с именем; (2) polish обязан сохранять
> `iteration`; (3) рабочие копии именуй с `_v{max}`. Все три вместе гарантируют
> версия(вход) == версия(выход).

**Порядок секций Stage 5 (render).** Обложка → «Чего нет в маршруте» →
регионы маршрута → Шапка → критические пункты → дни (с titler-блоками) →
сводные → план рисков → TODO → Чеклист за 2 недели → «Обоснование ключевых
решений» (только `self`). Перестановка — на уровне рендера; контент
артефакта не меняется.

## Отличия по стадиям

Все стадии идут по тому же 5-шаговому потоку; ниже — только отличия.
Дефолт-формат везде HTML (см. матрицу выше).

- **Stage 0 (scope).** Polish: `[[поездка]]`/`[[регион]]`-маркеры, T3b «Что
  увидишь» (3–5 конкретных впечатлений — основной контент карточек). HTML —
  портрет-витрина регионов longlist'а; PDF (`--format pdf`) — landscape.
  Имя: `{trip_id}_регионы.{html,pdf}` (без `_v{N}`).
- **Stage 1 (dr-reports).** Polish: T1 cover, T2 `[[поездка]]`, T3 опц.
  `[[карточка: …]]`. **Format-зависимая ориентация:** HTML → портрет +
  1 колонка; PDF → landscape + 2 колонки. Устойчив к трём входным форматам
  (pure DR без YAML — тогда `--trip`; Mode A.wrap; Mode B с awd.ru-карточками
  + `sample_curation_note`). Имя: `{trip_id}_dr_отчёты.{html,pdf}`.
- **Stage 2 (similarity).** **HTML (дефолт) — интерактивный lookup**
  (тёмная тема, фильтр HIGH/MED/LOW/OUTLIER, сортировка, click-to-expand,
  табы «Scoring»/«Практика» из соседнего `1_dr_reports.md` по URL). PDF
  (`--format pdf`) — статичная светлая scoring-витрина. Имя:
  `{trip_id}_фильтр_авторов.{html,pdf}`.
- **Stage 3 (poi).** HTML — дефолт-витрина POI; на хостинге с generic
  write-API (`GET /api/health` + `GET /api/file?path=` + `POST /api/save
  {path, content, base_hash}`) страница сама становится operative: теги
  регионов кликабельны, у комментариев POI textarea, «Сохранить» пишет
  правки в исходный `3_*.md` рядом со страницей (конфликт версий по hash →
  «обнови страницу»; без API — обычная статика; правки применяются с той же
  семантикой, что DOCX-round-trip). **DOCX (`--format docx`)** — офлайн
  operative-документ: пользователь заполняет теги регионов (anketa-чекбоксы)
  и комментарии POI, затем `export.py --import {trip_id}_места.docx`
  round-trip'ит обратно в `3_poi_pool.md` (counts/выдержки/категории не
  трогаются).
  **⚠️ Имя md в странице — каноничное `3_*.md`, НЕ имя polished-черновика.**
  Страница просит файл у write-API по имени, зашитому при сборке, а whitelist
  сайдкара пускает только `trips/{id}/3_*.md`. Рендер из `polished_stage_3.md`
  зашивал имя черновика → фоновый запрос ловил тихий 403, правки не работали
  без единого сообщения (регион_a_2027, 2026-07-27). С 2026-07-27 каноничное имя
  резолвится автоматически — **по директории ВЫВОДА**, поэтому:
  — выход Stage 3 должен идти в каноническую директорию поездки
  `trips/{trip_id}/`, где лежит `3_poi_pool.md` (рендер во временный каталог
  даст витрину без правок — это не сбой, а отсутствие источника рядом);
  — приёмка после сборки: `grep -o '"mdFile": "[^"]*"' {файл}.html` обязан
  показать `3_*.md`; увидел `polished_*` — страница нерабочая, пересобери;
  — если правки на странице не поднимаются при живом API, страница теперь
  сама пишет причину в углу («вне whitelist» / «нет файла») — не гадай.
  PDF (`--format pdf`) — read-only витрина. **Self-contained,
  один файл:** современный `3_poi_pool.md` несёт реестр авторов
  (`## Источники (реестр авторов)`) и описания регионов внутри — передавай
  только его. Legacy-fallback ищет соседний `1_dr_reports.md`, если реестра
  нет. Имя: `{trip_id}_места.{html,docx,pdf}`.
- **Stage 4 (variants).** HTML/PDF — read-only витрина сравнения вариантов;
  блок `## Решение` не рендерится (выбор — за пользователем в md). Подсекции
  вариантов (маршрут/логистика/риски) рендерятся. Имя:
  `{trip_id}_варианты_v{N}.{html,pdf}`.
- **Stage 6 (финал).** Render — **механический ассемблер**: читает
  `6_final.md`, находит устаканенный `5_vX` по YAML `source_plan` (immutable),
  генерит обзорную карту (matplotlib → PNG), собирает полное тело 5_vX +
  карта + приложения (досье / бронь / углубления). Контент 5_vX повторно
  через LLM не прогоняется → ноль дрейфа. `source_plan` **обязано
  сохраниться** при polish. Имя: `6_{trip_id}_финал_v{N}.{html,pdf}`.
  Деградация: без matplotlib/координат — карта пропускается; PDF без
  reportlab — падает с подсказкой поставить.

## Известные ограничения

1. **Polish не детерминирован** — между прогонами Sonnet выдаст слегка
   разные тексты. OK для presentation; нужна bit-stable — `--no-polish`.
2. **Polish может сломаться на длинных планах** (>100K токенов) — потеря
   контента; sanity-check поймёт. Митигация исчерпания контекста: keep/drop
   YAML-полей задан прямо в stage5-polish-prompt (не выясняй чтением кода);
   не копируй пакет `scripts/export` (правило №5).
3. **Polish — только текущие Sonnet / Opus.** Старые модели нестабильно следуют
   многоточечной prompt-инструкции.
