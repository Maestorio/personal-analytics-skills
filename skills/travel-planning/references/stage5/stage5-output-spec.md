## Часть 1 — Контракт формата (канон)

### 9 обязательных секций (канонические заголовки, порядок)
1. `## Контекст и ключевые параметры`
2. `## Шапка`
3. `## Критические подготовительные пункты`
4. `## Маршрут по дням`
5. `## Сводные таблицы`
6. `## План реагирования на риски`
7. `## Чеклист за 2 недели до поездки`
8. `## Diff с предыдущим планом` *(только если `previous_plan != null`)*
9. `## TODO для верификации`

**Адаптивное сжатие запрещено** — 9 секций всегда (surgical → diff + изменённые
дни НЕ делается; потеря контекста при чтении через год). При размере, не
вмещающемся в один ответ — split на `5_final_plan_part_b.md`, не «опущено for
brevity».

### Блок дня — фиксированные иконки-секции
`📍` переезд · `🏨` отель (имя+район+рейтинг+ориентир-цена+TODO; повторная ночь
в том же отеле → строка `🏨` ОПУСКАЕТСЯ) · `🎯` программа (часовая разбивка) ·
`💰` бюджет дня (диапазон ₽) · `⚠️` риски/swap. Иконки — **только в блоках дней**.

### Опциональные конвенции Этапа-2 (backward-compatible)
Набор иконок дня и 9 секций **не меняется**. Поверх них — опциональные
маркеры/конвенции (отсутствие ≠ ошибка; старый план рендерится без них):
- `[[бронь: план]]` / `[[бронь: забронировано]]` — статус брони в начале
  строки `🏨` (Stage 5 = «план»; «забронировано» — пост-бронь).
- `[[погода: {краткий риск}]]` — погодозависимый день/активность (явный
  маркер, не keyword-детект).
- `*Источник: {тег/автор Stage 3}*` — inline-атрибуция якорного POI в `🎯`
  курсивом (звёздочки, не подчёркивания; только POI, не рестораны).
- `**Замысел маршрута:** {2–3 фразы}` — опц. первая строка `## Контекст и
  ключевые параметры`; рендер выносит на обложку.
- `⚠️`-блок дня = **короткий указатель**; полная развёртка контингенси — в
  `## План реагирования на риски` (#8). Глубокий рационал — в под-секцию
  `**Логика ключевых решений:**` Контекста, не в текст дня (#12).
Детали — `stage5-final.md` §6.3.1. Потребитель маркеров — рендер
(`stages/stage5.py`: чипы брони/погоды, тезис на обложке).

### Счётчик TODO
`todo_verification_items` в YAML == числу TODO-чекбоксов (`- [ ]`) в секции
`## TODO для верификации` (проверяет `check_format.py check_todo_count`).

### Режимы
`surgical` (структура == previous_plan) / `reconstructive` (нет previous_plan ИЛИ
структура отличается, в т.ч. **реордер регионов**). Mode-detection —
детерминированно по упорядоченному списку регионов.

### Формат / YAML (Pre-emit Класс E)
Долларовые цены escape'нуты (`\$NN` / `USD NN` / backtick); YAML три дефиса; имя
файла `5_final_plan.md`; нет «опущено for brevity»; нет «Сохранить как» в теле.

## Часть 3 — Известные дрейфы / на что смотреть при чтении `5_final_plan.md`

- **Счётчик TODO врёт:** `todo_verification_items` в YAML расходился с числом
  TODO в теле (v1 24/21, v2 24/22) — велся вручную. Закрыто `check_format
  check_todo_count`; при чтении сверять YAML с фактом.
- **Неперсист большого reconstructive-плана** (v1: «file didn't persist → rebuild
  in chunks»). В v2 не воспроизвёлся. Если повторится — chunked-emit с прогоном
  валидатора по склеенному файлу (TODO 6).
- **Неэскейпленный `$`** парными долларами ломал визуальные viewers (md→KaTeX);
  цены escape'ить.
- **Реордер регионов** (тот же набор, переставленный порядок) — это
  **reconstructive**, не surgical (пересобирается каждое межрегиональное плечо).
