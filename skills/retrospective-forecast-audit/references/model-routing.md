## Прикидка контекста для типичного запроса скилла

| Компонент | Размер (приблизительно) |
|---|---|
| SKILL.md (полный) | ~12K токенов |
| Все references (читаются по запросу) | +8–15K на запрос |
| EXAMPLES.md | ~10K |
| Транскрипт вебинара/интервью (1–2 ч) | ~15–25K |
| Web search results на 1 запрос | ~5–15K |
| Deep Research output (если запущен ДО активации скилла) | ~30–60K |
| Системный промпт + другие skills + инструменты | ~25–35K |
| История диалога | ~5–20K |

**Baseline для Light Audit (5–8 тезисов):** 80–120K токенов.
**Full Audit без DR (15–30 тезисов):** 150–250K токенов.
**Full Audit с предзаранее собранным DR-досье (workflow B) + длинный транскрипт:** 250–450K токенов.

→ **Haiku НЕ подходит для скилла вообще** (200K cap легко превышается уже на baseline; рассуждения слишком слабые для трёхшкальной классификации). Использовать запрещено.

## Таблица: режим аудита → модель

| Параметр материала | Sonnet OK (Light) | Эскалация на Opus (Full) | Refusal (Sonnet) |
|---|---|---|---|
| Число тезисов | ≤8 | 9–15 | ≥16 |
| Длина транскрипта | ≤45 мин (~8K слов) | ≥45 мин | ≥2 ч |
| Композитных тезисов (требуют A/B/C) | ≤3 | ≥4 | — |
| Многодоменный материал (финансы + геополитика + tech) | нет | да | да + большой объём |
| Запуск Deep Research внутри сессии скилла | **запрещено** | **запрещено** | **запрещено** |
| DR-досье собрано пользователем ДО активации скилла (workflow B) | OK как input | OK и часто полезно | OK |
| Запрос «делай docx» при ≥10 тезисах | пограничная — переключи на Opus | строго Full | — |

**Логика выбора режима:**

1. Если активна **Opus** → всегда Full (даже для маленьких материалов; затрат это не сильно увеличит, а методология полнее)
2. Если активна **Sonnet**:
   - Все параметры в колонке Sonnet OK → Light Audit
   - Хотя бы один параметр в колонке Opus → Light Audit + предупреждение в шапке (см. ниже)
   - Параметры в колонке Refusal → Refusal (см. ниже)
3. Если активна **Haiku** → отказ. Текст: «Этот скилл требует Sonnet или Opus. Haiku не подходит для трёхшкальной классификации прогнозов и легко выходит за 200K контекста. Переключи модель в селекторе».

## Шаблоны предупреждений в шапке ответа

### Если Sonnet выбран на материал среднего размера (Light с эскалационным флагом)

> ⚠️ Этот материал тянет на Full Audit (причина: [9–15 тезисов / композитов ≥4 / многодоменный]). На Sonnet я делаю Light Audit с сокращениями (опущены глубокие разборы дорогих ошибок, расширенные метрики и оси). Ядро — таблица вердиктов и итоговый дифференцированный вердикт — без сокращений. Для полной версии переключи модель на Opus и повтори запрос.

### Refusal (тезисов ≥16, или транскрипт ≥2 ч, или одновременно несколько доменов с большим объёмом)

> ⚠️ На Sonnet качественный аудит этого материала не получится. Ориентировочная оценка объёма: [N тезисов / M часов транскрипта / K доменов].
>
> Опции на выбор:
> 1. **Ограничить покрытие** — выбираем вместе топ-15 приоритетных тезисов, делаю Light Audit только по ним, остальные явно помечаются как «не разбирались в этой сессии».
> 2. **Переключить на Opus** — в селекторе модели; повторяешь запрос; получаешь полный аудит без потерь.
>
> Что выбираешь?

## Сигналы для эскалации с Sonnet на Opus в любом режиме

Если в процессе Light Audit выяснилось одно из следующего — приостанови работу и предложи пользователю переключиться на Opus:

1. По мере извлечения тезисов выяснилось, что их фактически ≥16 (изначально оценка была меньше)
2. Появились нетривиальные композитные тезисы с глубиной ≥4 слоёв (вместо стандартных A/B/C)
3. Материал требует кросс-доменной верификации (один тезис трогает финансы + геополитику + tech)
4. Обнаружен крупный кластер ошибок ≥5 тезисов с ценностью ≤−2 — в этом случае shape-of-error блоки критичны (а они есть только в Full)
5. Пользователь явно запросил deep dive по конкретному тезису — Sonnet даст поверхностный разбор

В любом из этих случаев ставь паузу:

> Обнаружил [причина]. Light Audit по этому материалу даст значимые потери качества. Рекомендую переключиться на Opus и повторить запрос. Готов продолжить и сейчас в Light, если ты понимаешь ограничения — подтверди.

## Сигналы для деэскалации на Sonnet (если активна Opus)

Этих сигналов почти не бывает — Opus справляется с любым материалом скилла. Имеет смысл только если:
- Материал явно тривиальный: ≤5 тезисов, моно-домен, чистый транскрипт, нет композитов
- Пользователь явно сказал «не нужна полная глубина, давай быстро»

В таких случаях можно молча сделать Light на Opus — это редкий кейс.

## Запрет на Haiku

Скилл **не запускается на Haiku** ни в каком режиме. Причины:
- 200K контекста легко превышается даже на Light Audit с обычным транскриптом
- Трёхшкальная классификация (исполнение / консенсус / локализация) + L-R sweep + матрица ценности — это глубина рассуждений, на которой Haiku даёт значимо худшее качество
- Маркеры 🌍 vs 👤 (мировая ошибка vs сольный промах) — Haiku систематически путает классы

Если активна Haiku — отказ + перенаправление на Sonnet минимум.

## Как пользователь переключает модель

**В приложениях Claude (claude.ai, мобильный/десктоп):**
- Селектор модели в верхней части окна чата
- Переключение применяется к новым сообщениям; история сохраняется

**Со стороны скилла:**
- Скилл сам не переключает модель — пользователь решает
- Если режим требует более мощной модели — **в шапке ответа добавить предупреждение** (шаблоны выше)
