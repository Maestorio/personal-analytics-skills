# Шаблоны вывода

## Шапка отчёта (обязательна для Full и Light)

В самом верху отчёта (и в чате, и в docx — на первой странице):

### Full Audit
```
# Ретроспективный аудит [тип материала] [источник] от [дата прогноза]
**Тип анализа:** Full Audit · **Модель:** [модель прогона с версией, напр. Opus X.Y] · **Дата оценки:** [дата сегодня]
```

Пример:
```
# Ретроспективный аудит вебинара Invest Era (А. Николаев) от 12.03.2025
**Тип анализа:** Full Audit · **Модель:** Opus X.Y · **Дата оценки:** 24.04.2026
```

### Light Audit
```
# Ретроспективный аудит [тип материала] [источник] от [дата прогноза]
**Тип анализа:** Light Audit · **Модель:** [модель прогона с версией, напр. Sonnet X.Y] · **Дата оценки:** [дата сегодня]

> ⚙️ **Режим:** Light Audit. Опущены глубокие разборы дорогих ошибок,
> расширенные метрики и качественные оси. Ядро аудита (таблица вердиктов
> и итоговый дифференцированный вердикт) — без сокращений.
> Для полной версии переключи модель на Opus и повтори запрос.
> Для разбора конкретной ошибки можешь запросить отдельным сообщением.
```

В docx плашка о сокращениях оформляется как Quote/Callout-блок (фон `#F2F2F2`, левый бордер `#7F7F7F` шириной 4 pt) — компактно, ниже основной шапки.

## Summary Box (обязателен между шапкой и §0)

Цель — за 3 секунды дать читателю общую картину аудита до перехода к таблицам. Размещается СТРОГО между шапкой (или плашкой о сокращениях для Light) и §0 Reference set.

### Шаблон

```
**Сводка:** N тезисов · Hit rate XX% · Альфа-генерация XX% (A/B Contrarian верных) · Средняя ценность ±X.XX · Доверительный вес: HIGH/MEDIUM/LOW по [домен 1], [LOW/IGNORE] по [домен 2]
**Главный вывод:** [одно предложение, 15–25 слов]
```

### Поля и поведение при `н/п`

| Поле | Что показывать | Если данные отсутствуют |
|---|---|---|
| N тезисов | Количество засчитываемых (без ⏳ и 🌪) | всегда заполняется |
| Hit rate | % тезисов с Ш1 ≥ +1 | `Hit rate н/п (все тезисы ⏳)` если N=0 |
| Альфа-генерация | верных Contrarian / всех Contrarian | `Альфа-генерация н/п` если знаменатель = 0 |
| Средняя ценность | сумма / N | всегда, если N > 0 |
| Доверительный вес | домены, где автор HIGH/MEDIUM, и где LOW/IGNORE | минимум один HIGH-сегмент и один LOW-сегмент |

### Главный вывод — антипаттерны

❌ Размытое summary: «Источник имеет смешанный track record с сильными и слабыми сторонами».
❌ Безусловно положительное: «Stratfor — отличный геополитический аналитик».
✅ Конкретно и дифференцированно: «Stratfor — media-grade, не decision-grade продукт; альфа есть, но компенсируется повторяющимися сольными промахами на 30-летнем horizon».

### В docx

Размещается на первой странице ниже шапки, выше Цветовой легенды. Оформление — компактная таблица 1×2 или 2 параграфа с выделением `bold` для меток. Шрифт Arial 11 pt.

## Формат цитат тезисов (обязателен)

Все цитаты иноязычных тезисов в таблицах вердиктов, §3 shape-of-error, §3.M мета-аудите и §4 развёрнутых разборах оформляются по единому шаблону:

```
«Перевод на русский язык» (en: "Original ≤15 words")
```

### Примеры

✅ Правильно:
```
«ЕС официально рухнет как политический союз к 2015 году» (en: "EU probably will officially collapse as a political union by 2015")
«Россия не выживет в текущей форме» (en: "Russian Federation will not survive in its current form")
«Германия начнёт продолжительный экономический спад» (en: "Germany will begin an extended economic decline")
```

❌ Неправильно:
```
"EU probably will officially collapse as a political union by 2015" — оригинал без перевода
«Россия не выживет в текущей форме (RF will not survive)» — оригинал без кавычек и языкового тега
«ЕС развалится к 2015» — парафраз вместо точного перевода + потерян оригинал
```

### Особые случаи

- Цитата на русском в оригинале — без двойной записи: `«Ставка ЦБ снизится до 14% к концу года»`
- Длинная цитата (>15 слов оригинала) — оригинал сокращается до ключевой фразы ≤15 слов с многоточием в нужном месте, перевод даётся целиком
- Несколько связанных цитат от одного автора — первая раскрывается полностью с переводом и оригиналом, последующие — только перевод со ссылкой `[см. T1 для оригинала]`

## §8 Предложение режимов (обязательный финальный блок)

Размещается строго в конце отчёта, после §7 Итогового вердикта. В чате — формулировка ниже; в docx — финальная страница «Что дальше» с тем же содержанием.

```markdown
### §8 · Что дальше

Если профиль этого источника пригодится в будущем, могу:
- **(A) SAVE** — сохранить полный файл аудита на Synology `Claude-Memory/{subfolder}/` через скилл `save-to-library`. Локальный [lib]-кеш в памяти обновится при ближайшем `memory-sync`. Покажу YAML frontmatter до сохранения, жду «да». **Рекомендуется по умолчанию для аудитов с хотя бы одним HIGH-subdomain или для регулярно используемых источников.**
- **(B) EXPORT** — сгенерировать структурированный Markdown-блок для вставки в SKILL.md другого скилла, работающего с этим источником.
- **(A+B)** — оба варианта последовательно (сначала save-to-library, потом export-блок).

Также по запросу: разбор конкретного тезиса в формате shape-of-error (для Light-режима) или повторная генерация docx (если был только текстовый ответ).
```

Это обязательный блок: его отсутствие — методологический брак. Режим A — рекомендуемый по умолчанию для большинства аудитов; явно подчеркни рекомендацию, если в §7 есть HIGH-сигналы.

## Light Audit — таблица вердиктов

Light отличается от Full тем, что декомпозиция A/B/C для композитных тезисов идёт **inline в строке** таблицы вердиктов, а не в отдельной §1.

### Колонки Light-таблицы

| Колонка | Содержание | Когда заполнять |
|---|---|---|
| № | T1, T2, ... | всегда |
| Тезис | цитата, усечённая до ~80 симв. | всегда |
| Кат. | Макро / Объект / Рек. / Риск | всегда |
| **Слой A** | предпосылка (если применимо) | только для композитных |
| **Слой B** | каузация (если применимо) | только для композитных |
| **Слой C** | калибровка (если применимо) | только для композитных |
| Ш1 | −2/−1/0/+1/+2/⏳/🌪 | всегда |
| Консенсус | Consensus/Contrarian/Off-market/Split/❓ | всегда |
| Локализ. | L0/L-A/L-B/L-C/L-R | всегда |
| Маркеры | 🌍/👤/⚠️/⭐ | всегда |
| Цен. | −3..+3 | всегда |
| Источник | ссылка на первоисточник | всегда |

Для монослойных тезисов колонки A/B/C остаются пустыми (прочерк «—»). Для композитных в них короткие фразы (1–3 слова), не полный анализ. Это компромисс ради сохранения декомпозиции в Light без отдельной таблицы.

### Шаблон Light-таблицы

```markdown
| № | Тезис | Кат. | A | B | C | Ш1 | Консенсус | Локализ. | Маркеры | Цен. | Источник |
|---|-------|------|---|---|---|----|-----------|----------|---------|------|----------|
| T1 | «...» | Макро | условие | следствие | целевое значение | +2 | Consensus | L0 | — | +1 | [link] |
| T2 | «...» | Объект | — | — | — | −1 | Contrarian | L-C | 👤 | −1 | [link] |
```

Light-таблица в docx использует ту же цветовую схему по Шкале 1, что и Full (см. ниже), но не имеет дополнительных страниц с §3 shape-of-error.

Используй когда: явный запрос пользователя ИЛИ (Full Audit И тезисов ≥10).

### Структура документа (Portrait A4, поля 2 см)

```
[Страница 1]
 ├─ Шапка: Тип анализа · Модель · Дата оценки (плюс источник, дата прогноза)
 ├─ Summary Box: N тезисов · Hit rate · Альфа · Ср. ценность · Дов. вес + 1 строка вердикта
 ├─ Цветовая легенда (компактная, 2 строки)
 └─ Сводка метрик (Hit rate · Полная точность · Альфа · Ретрансляция · Средняя ценность · N тезисов)

[Страница 2+] — для Full Audit
 ├─ §0. Reference set (ключевые факты на дату оценки, маркированный список)
 ├─ §1. Промежуточная таблица декомпозиции A/B/C (только для тезисов с 2+ слоями)
 ├─ §2. Таблица вердиктов (главная — все тезисы, цветные строки, колонка Маркеры)
 ├─ §3. Shape-of-error блоки (только для тезисов с ценностью ≤ −2)
 ├─ §3.M. Мета-аудит вторичного источника (опционально, если применимо)
 ├─ §4. Развёрнутые разборы (Contrarian, L-R, ценность ≥+2 — полные цитаты с переводом и обоснование)
 ├─ §5. Оценка по 7 осям (текст)
 ├─ §6. Методологические ограничения
 ├─ §7. Итоговый вердикт + рекомендации по использованию
 └─ §8. Что дальше (предложение режимов A/B/A+B) — обязательный финальный блок

[Light Audit — если запрошен docx по явному запросу]
 ├─ Шапка + плашка о Light
 ├─ Summary Box (тот же формат)
 ├─ §0 (короткий, 5–7 фактов)
 ├─ §2-Light Таблица (с inline A/B/C колонками)
 ├─ §4-light Метрики (3 шт)
 ├─ §5-light Качественные оси (3 шт)
 ├─ §6 Ограничения
 ├─ §7 Итоговый вердикт
 └─ §8. Что дальше (обязательно)
```

### Развёрнутые разборы — формат (§4)

**НЕ использовать отдельные Word-таблицы на каждый тезис** — это формат для проспективного анализа (пример: стрим-анализ). Для ретроаудита применяй структурированные подразделы.

Разбирай только тезисы с ненулевым интересом: все Contrarian, все L-R, все с ценностью ≤ −1 или ≥ +2. Остальные — строки таблицы вердиктов достаточно.

Формат каждого развёрнутого разбора:

```
──────────────────────────────────────────────────────
§2.N  [Шкала1 пиктограмма]  [Кат.]  [Ценность: ±X]
      Цитата полная: «...»

      Консенсус на [дата]: [позиция] | Источник: [ссылка]
      Слой A — [реализовалась / не реализовалась]: [данные]
      Слой B — [подтвердилось / опровергнуто]: [данные]
      Слой C — [точно / промах X%]: [данные] | Источник: [ссылка]
      
      Вывод: [2–3 строки: почему такая оценка, если есть альфа — 
              объяснить уникальность; если сольный промах — 
              локализовать ошибку]
──────────────────────────────────────────────────────
```

Разделитель между разборами — горизонтальная линия (`BorderStyle.SINGLE`, 1pt, `#CCCCCC`).

## Verdict Table — текстовый формат (отчёт в чате)

Каждый тезис — отдельная строка. Если тезис длинный — цитата в усечённом виде «…», полная версия в развёрнутом списке под таблицей.

| # | Тезис (цитата) | Кат. | Горизонт | Слой A | Слой B | Слой C | Ш1 | Ш2 | Ш3 | Маркеры | Ценность | Источники факта |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | «...» | Макро | Q4 2025 | реализовалась | подтвердилось | промах −30% | +1 | Consensus | L-C | — | −1 | [ссылка] |
| 2 | «...» | Объект | Q3 2025 | не реализовалась | н/п | н/п | −2 | Contrarian | L-A | 👤 | −2 | [ссылка] |
| 3 | «...» | Рек. | без горизонта | — | — | — | ⏳ | Consensus | — | — | — | — |
| 4 | «...» | Макро | Q2 2025 | не реализовалась | н/п | н/п | −2 | Consensus | L-A | 🌍 | 0 | [ссылка] |
| 5 | «...» | Объект | год 2025 | реализовалась | подтвердилось | точно | +2 | Contrarian | L0 | ⭐ | +3 | [ссылка] |

**Условные обозначения колонок:**
- Слои A/B/C: реализовалась/не реализовалась/частично; подтвердилось/опровергнуто; точно/промах X%; н/п если не проверяется из-за провала предыдущего слоя
- Ш1: −2/−1/0/+1/+2/⏳/🌪
- Ш2: Consensus/Contrarian/Off-market/Split/❓
- Ш3: L0/L-A/L-B/L-C/L-R (или сочетание, например L-A+L-R)
- Маркеры: 🌍 мировая ошибка / 👤 сольный промах / ⚠️ L-R штраф / ⭐ альфа (комбинации через пробел)
- Ценность: −3...+3 по матрице ценности
- Источники: ссылки на первоисточники для верификации факта

После таблицы — развёрнутый список с полными цитатами и обоснованием каждой оценки 2–4 строками.

Выводить для каждого тезиса с ценностью ≤ −2. Структура:

```
──────────────────────────────────────────────────────
§3.N  👤  [Кат.]  [Ценность: −2]
      Цитата полная: «...»

      Ложная предпосылка в модели автора:
      [Что именно было неверно в исходном предположении]

      Игнорируемые факторы (доступные на дату прогноза):
      1. [Фактор] — источник: [ссылка]
      2. [Фактор] — источник: [ссылка]

      Паттерн у автора:
      [Совпадает ли с другими ошибками того же типа? Название паттерна из domain-файла]

      Стоимость ошибки для следовавшего рекомендации:
      [Упущенная выгода / потери в % или ₽/$ за период]
──────────────────────────────────────────────────────
```

## Audit File for save-to-library (Режим A)

Этот раздел описывает структуру файла, который скилл генерирует и передаёт в `save-to-library` при выборе пользователем режима A. Файл состоит из двух частей: обязательного YAML frontmatter и полного текста отчёта (§0–§7), который уже сформирован к этому моменту.

### Обязательный YAML frontmatter

Полный список полей и допустимых значений — в `project-memory-context.md` (контекст проекта). Здесь — рабочий шаблон с пояснениями:

```yaml
---
source: "Invest Era"                  # ОБЯЗАТЕЛЬНО — ключ агрегации источника
period: "2024-2025"                   # рекомендуется — диапазон покрытия аудита
audit_type: "Full"                    # Full | Light
audit_model: "[модель прогона с версией]"              # модель, которой делался аудит
audit_date: "2026-04-26"             # ОБЯЗАТЕЛЬНО — дата аудита YYYY-MM-DD
last_updated: "2026-04-26"           # = audit_date при первой записи
theses_count: 23                     # количество разобранных тезисов в §2
hit_rate: 0.41                       # доля прогнозов с Ш1 ≥ +1 (0.0–1.0)
alpha_generation: 0.36               # доля Contrarian-L0 (верный contrarian) от всех Contrarian
avg_value: 0.18                      # средний балл ценности тезиса (−3..+3)

trust:                               # ОБЯЗАТЕЛЬНО — subdomain → trust level
  bonds-rub: HIGH
  finance-ru: MEDIUM
  oil-gas-ru: LOW
  usd-rub-forecast: IGNORE
  # стандартные subdomain'ы для домена — в project-memory-context.md
  # каждый subdomain: HIGH | MEDIUM | LOW | IGNORE

pin: false                           # true — принудительно включать в memory независимо от trust

skill_version: "v0.7"               # версия retrospective-forecast-audit (актуальная)
meta_audit_used: false              # §3.M мета-аудит вторичного источника применялся?
data_source: "primary"              # primary (первоисточник материала) | secondary (через посредника)
deep_research_used: false           # двухэтапный workflow B с Deep Research использовался?
---
```

### После frontmatter — полный текст отчёта

Включает в порядке:
- Шапка (название, тип анализа, дата прогноза, дата оценки)
- Summary Box (свёрнутая сводка)
- §0 Reference set
- §1 Промежуточная таблица декомпозиции (для Full)
- §2 Таблица вердиктов
- §3 Shape-of-error блоки (для Full с тезисами ценности ≤−2)
- §3.M Мета-аудит вторичного источника (опционально)
- §4 Развёрнутые разборы (Contrarian, L-R, ценность ≥+2 или ≤−1)
- §5 Оценка по 7 (Full) или 3 (Light) осям
- §6 Методологические ограничения
- §7 Итоговый вердикт + дифференцированный доверительный вес

§8 в файл аудита НЕ включается — это интерактивный блок для чата, а не часть архивной записи.

### Поле trust — главный элемент для memory-sync

Заполнение `trust` критично: именно из него `memory-sync` строит компактную [lib]-запись. Стандартные subdomain'ы для каждого домена:

- **geopolitics:** long-term-russia, short-term-russia, eu-future, china-collapse, china-rise, middle-east, iran, us-domestic, nato-future, nuclear-proliferation, migration-eu
- **ru-sellside:** iis-targets, long-term-strategy, oil-gas-ru, metals-mining-ru, it-tech-ru, finance-ru, consumer-ru, bonds-rub, bonds-fx, dividend-stocks, small-caps-ru, etfs-ru
- **global-banks:** us-equities, european-equities, emerging-markets, oil-forecast, commodities-non-oil, currency-forecasts, ny-rates, crypto, ai-stocks-bubble, recession-call, sector-rotation
- **tech-ceo:** agi-timeline, model-capability, regulation-ai, compute-economics, space-tech, biotech-future
- **ru-macro:** ru-rates-forecast, ru-inflation, usd-rub-forecast, cny-rub-forecast, ru-budget, ru-economy-growth, ru-banking-system

Использовать только эти имена для cross-source сравнений. Если ни один subdomain не подходит — обсуди с пользователем добавление нового и обнови `project-memory-context.md` отдельно (вне основного flow аудита).

### Правила trust levels

| Уровень | Когда ставить |
|---|---|
| `HIGH` | Источник систематически точен в этом subdomain (hit rate ≥60% И/ИЛИ Contrarian-L0 ≥30% от всех Contrarian) |
| `MEDIUM` | Частично точен — hit rate 40–60%, есть зоны компетенции и зоны промахов в одной области |
| `LOW` | Слабая точность — hit rate <40%, паттерн ошибок устойчив |
| `IGNORE` | Источник систематически ошибается, многократно подтверждённый паттерн (≥3 промаха в одной области без коррекции) |

Каждый trust level в файле аудита должен быть подкреплён данными из §2/§3/§4: НЕ ставь trust без обоснования в тексте отчёта.

### Антипатерны (так нельзя)

❌ **Заполнить trust «по ощущению» без §2/§3/§4 в отчёте:** YAML соответствует методологии, текст — нет. Save-to-library валидирует наличие YAML, но не сверяет его с текстом — ответственность на тебе.

❌ **Сократить trust до 1–2 subdomain'ов:** аудит на 23 тезисов с 1 subdomain в trust — это потеря информации. Обычно из аудита в 15–25 тезисов получается 4–8 subdomain'ов с разными trust-уровнями.

❌ **Использовать нестандартный subdomain без обсуждения:** `trust: pricing-strategy: HIGH` — отсутствует в каноне; либо переформулируй (`consumer-ru: HIGH`), либо добавь новое имя в `project-memory-context.md` отдельным шагом.

❌ **Превратить аудит в пустую обёртку YAML:** save-to-library принимает файл с YAML и текстом отчёта; YAML без текста — antipattern. Полный текст §0–§7 обязателен.

### Процесс передачи в save-to-library

1. Сгенерируй YAML frontmatter по шаблону. Все обязательные поля заполнены, без `?`/`tbd`.
2. Преобразуй итоговый текст отчёта (§0–§7) в одну строку Markdown без §8 (он только для чата).
3. Покажи пользователю YAML frontmatter и одну строку summary trust в формате `[lib]` для предпросмотра. Дословно:
   ```
   Готов передать save-to-library такой YAML:
   {YAML frontmatter}

   Сводный trust для [lib]-кеша после следующего memory-sync будет:
   [lib] {source}: {summary} | last_audit {date} | N=1

   Файл сохранится как Claude-Memory/{subfolder}/{filename}.md.
   Подтвердить?
   ```
4. Дождись явного «да».
5. Вызови save-to-library, передав ему YAML + полный текст. Скилл сам:
   - Валидирует YAML
   - Определит subfolder (если неоднозначно — спросит у пользователя)
   - Проверит дубли
   - Сохранит файл и обновит INDEX.md (subfolder + master)
   - Предложит запустить memory-sync (отдельный шаг, отдельный confirmation)
6. Если save-to-library озвучивает сомнения — передай вопросы пользователю как есть.
7. Если save-to-library недоступен (скилл не установлен, Synology mount недоступен) — fallback на старое поведение: сгенерируй компактную запись (≤500 симв.) по шаблону ниже и запиши через `memory_user_edits`. Явно предупреди: «save-to-library недоступен; пишу только в локальную память. При следующем memory-sync это перезатрётся, если на Synology не появится исходный файл аудита».

### Fallback-шаблон компактной записи (при недоступности save-to-library)

```
[lib] {source}: {trust_summary} | last_audit {YYYY-MM-DD} | N=1
```

Лимит — 500 символов. Примеры:

```
[lib] CFR: HIGH iran, MEDIUM russia | last_audit 2026-04-22 | N=1
[lib] Stratfor: HIGH long-term-russia, MEDIUM middle-east, IGNORE eu-future | last_audit 2026-04-22 | N=3
[lib] Atom: MEDIUM small-caps-ru, LOW long-term-strategy | last_audit 2026-01-15 | N=1 (pinned)
```

Это **только fallback**, основной путь — Synology через save-to-library.

## Skill Export Block (Режим B)

Выдавай как кодовый блок Markdown, чтобы пользователь скопировал целиком:

````markdown
## Профиль источника: [Название]
**Дата аудита:** YYYY-MM-DD
**Период покрытия:** YYYY-MM-DD — YYYY-MM-DD
**Тип источника:** [квартальная стратегия sell-side / геополитический think tank / Telegram-аналитик / интервью CEO / экономический прогноз]

### Сильные стороны (использовать с весом HIGH)
- **[Область 1]:** [обоснование]. Hit rate в этой области: X% (Y/Z тезисов).
- **[Область 2]:** [обоснование]. Альфа-генерация: верных contrarian-тезисов A из B.

### Слабые стороны (использовать с весом LOW или игнорировать)
- **[Область 1]:** [обоснование]. Hit rate: X% (Y/Z тезисов), персональных ошибок K.
- **[Область 2]:** [обоснование].

### Систематические biases
- **[Bias 1]** (например, нарративный оптимизм по разрешению геополитических кризисов): проявляется в ситуациях [описание].
- **[Bias 2]** (например, anchoring к prior consensus при смене режима): проявляется при [описание].

### Метрики точности
- Hit rate общий: X%
- Hit rate по [домен 1]: Y%
- Hit rate по [домен 2]: Z%
- Альфа-генерация: A верных contrarian из B всего contrarian = C%
- Доля ошибок толпы (Consensus-L-A): D%
- Доля персональных ошибок: E%
- Средняя ценность тезиса: F (по шкале −3...+3)

### Рекомендации по использованию в skill
- **Принимать сигналы с весом HIGH** на: [тип задачи 1], [тип задачи 2]
- **Принимать сигналы с весом MEDIUM** на: [тип задачи 3]
- **Игнорировать сигналы** на: [тип задачи 4], [тип задачи 5]
- **Обязательно кросс-проверять** через [консенсус-источники] при: [условие, например, contrarian-тезисах по геополитике]

### Дата актуальности профиля
Профиль основан на аудите прогнозов от YYYY-MM-DD до YYYY-MM-DD.
Переоценить при накоплении новых данных после YYYY-MM-DD (примерно через [период]).
````

### Принципы заполнения экспорт-блока

- **Каждое утверждение в "Сильные/Слабые" — с количественной метрикой.** Без числа = не годится.
- **Biases формулируй как поведенческий паттерн, не как ярлык.** Не «оптимист», а «нарративный оптимизм по разрешению геополитических кризисов: автор склонен принимать заявления о готовности к переговорам за намерение их вести».
- **Рекомендации формулируй как предписания для другого скилла.** Принимай / игнорируй / кросс-проверяй — а не «возможно стоит обратить внимание».
- **Дата следующего аудита** — оценочная, обычно 6–12 месяцев в зависимости от частоты публикаций источника. Для квартальных аналитиков — после следующих 4 квартальных циклов. Для геополитики — после следующего крупного события из их прогнозов.
