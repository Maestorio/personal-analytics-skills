# health-labs

Целевая модель: **Opus**. Чтение медицинских документов и справочный
контент — приоритет корректности над стоимостью (правило репозитория:
корректность > читаемость > стоимость > скорость). Haiku недопустим.

**Скилл не даёт медицинских рекомендаций и не интерпретирует конкретный
результат.** Он переносит данные из документов как есть и пишет общую справку
о том, что измеряет тест.

## Модель хранения — ровно два места (решение владельца 2026-09-29)

```
SRC_DIR     = ~/Library/CloudStorage/SynologyDrive-home/Медицинские анализы   (первоисточник — ТОЛЬКО чтение)
HEALTH_ROOT = ~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/Health   (данные страницы)
```

| Файл в `HEALTH_ROOT` | Роль | Как пишется |
|---|---|---|
| `labs.json` | числа, **главный файл** (пересборки из CSV больше нет) | `scripts/intake.py`, через зеркало — единственный писатель скилла; точки `source: manual` принадлежат владельцу — скилл их не меняет и не дублирует (при выключенном ИИ их вводит сайт) |
| `studies.json` | исследования (заключения) | `intake.py` (через зеркало) **и** страница (правка текста, write-API) |
| `studies/` | копии файлов исследований | `intake.py` копирует из `SRC_DIR`; страница тоже кладёт файл (`POST /api/hd/upload`, без перезаписи) |
| `intake-log.json` | какие файлы первоисточника разобраны | `intake.py` |
| `biomarkers-info.json` | справочник what/up/down | `scripts/validate_labs_info.py merge` |

`labs.json` пишет только `intake.py` (единственный писатель — через зеркало
безопасно). У `studies.json` писателей два: `intake.py` (через зеркало) и
страница (свободный текст, через write-API с `base_hash`) — решение владельца
2026-09-29: ради правки текста на сайте риск принят и прикрыт бэкапами.
Страница после записи скрипта получает 409 и сама ничего не затрёт. Обратный
случай — зеркало Мака отстало от правки на сайте (так 2026-09-02 `health-meds`
стёр 20 препаратов) — ловится частично: скрипт перечитывает `studies.json`
перед записью и **перед каждой записью кладёт копию `labs.json` и
`studies.json` в `.intake-backups/`**; плюс `.versions/` сервера и история
версий Synology Drive. Поэтому перед `--apply` спросить пользователя, не
правил ли он исследования на сайте в последние минуты; правил — подождать
синка (обновить страницу и убедиться, что правка видна в зеркале).

Первоисточник не трогается никогда: ни переименований, ни удалений, ни
записи рядом. `meds.json` / `vaccinations.json` / `vitals.json` /
`anamnesis.json` скилл не пишет (это страница и `health-meds`); `anamnesis.json`
читает — для предложений в анамнез и пометок «замер во время болезни».

Доступность проверяется точечно: `Glob("*.json", path=HEALTH_ROOT)` и
`Glob("*", path=SRC_DIR)`; ошибка → запросить доступ к этой папке и повторить;
снова ошибка → стоп. Корень `Claude-Memory/` не листать.

Все скрипты вызываются путём **относительно корня скилла** (`scripts/…`).

## Режим A — внести документы

Полный справочник (классификация документов, правила чтения, словарь
показателей, формат `PLAN.json`, что проверяет скрипт) — **`references/intake.md`,
прочитать перед первым планом в сессии.**

1. **Что нового.** `python3 scripts/intake.py scan` — файлы первоисточника,
   которых нет в `intake-log.json`, с подсказкой «анализ?/исследование?».
2. **Прочитать каждый документ** (`pdftotext -layout`; скан — `pdftoppm` +
   картинка; HTML — без тегов; фото распечатки — по «Фото бумажных
   документов» в `references/intake.md`, HEIC не читается). Числа — только из документа; нормы нет в
   документе → `ref: null`. Сомнение в соответствии «название ↔ число» —
   не угадывать, вынести в `notes` как `⚠ Проверить: …`.
3. **Собрать `PLAN.json`** во временной папке: пункт на документ (или на
   исследование из нескольких файлов). Лабораторный анализ — только точки и
   `lab` (лаборатория из документа; не нашёл — спросить владельца, не угадывать);
   исследование — `study` + его точки; точка уже есть в `labs.json` —
   `link_only`. Маркеры — по словарю из `references/intake.md`, новый заводить
   только после поиска существующего. Любое УЗИ (ЭхоКГ, ЦДС) — вид «УЗИ».
4. **Dry-run:** `python3 scripts/intake.py apply PLAN.json` — прочитать отчёт,
   blocking исправить в плане, предупреждения запомнить.
5. **Показать пользователю ДО записи** таблицей: файл → исследование (вид ·
   область · дата) → сколько точек и каких; отдельно — все `⚠ Проверить`,
   предупреждения dry-run, новые категории и маркеры, что ушло в `notes`
   (только параметры проведения — все измерения идут в показатели). Отдельным
   блоком — **«Предложение для анамнеза»**: диагнозы, операции, болезни из
   документов, которых ещё нет в `anamnesis.json` → `self`, и точки, сданные во
   время болезни из `self.history` (формат — `references/intake.md`). Вносит их
   владелец на странице. Ждать явного «да».
6. **Запись:** `python3 scripts/intake.py apply PLAN.json --apply`. Порядок
   внутри: файлы → `studies.json` → `labs.json` → лог.
7. **Файлы, которые вносить не нужно** (дубль, уже внесено раньше через
   Ornament, не медицинский документ) — пометить, чтобы `scan` их больше не
   показывал: `python3 scripts/intake.py mark --note "почему" ФАЙЛ… --apply`.
8. Новые маркеры без справки → режим B. Новые маркеры без нормы → нормы из
   рекомендаций (ниже).

### Нормы из клинических рекомендаций (`set-ref`)

Норма, напечатанная в документе, идёт в план (`ref` точки) и главнее всего.
Нет в документе — норму можно поставить из клинических рекомендаций, **только
сверив её с первоисточником** (текст рекомендации, не пересказ): файл
`{marker_id: {"ref": …, "src": "рекомендация, год, пол/возраст; как получено"}}`
→ `python3 scripts/intake.py set-ref REFS.json` (dry-run) → `--apply`. Скрипт
ставит `ref` + `ref_src` на точки без нормы (или с прежней нормой из
рекомендаций), пересчитывает статус; норму из документа не трогает никогда.
Страница показывает источник под нормой. Правила:
- пол, возраст, площадь тела — учитывать, если норма от них зависит (брать
  строку для пользователя, в `src` так и написать);
- пересчитанная норма (градиент из скорости и т.п.) — с формулой в `src`;
- у стандарта оговорки («единого стандарта нет», «зависит от точки
  измерения») → `{"text": …}` без числового статуса;
- подтверждённой нормы нет — норму **не ставить**, сказать пользователю.

## Режим B — справка биомаркеров

1. `python3 scripts/validate_labs_info.py coverage --labs "$HEALTH_ROOT/labs.json" --info "$HEALTH_ROOT/biomarkers-info.json"`
   → `missing` (очередь работы), `default_category_flag` (маркер попал в
   «Биохимия крови» по умолчанию — спросить пользователя, не завести ли
   категорию), `orphans` (запись справки без маркера — предложить удалить).
2. Написать `what` (список 1–2 абзацев) / `up` / `down` (проза) по каждому
   маркеру из `missing`. Стиль, длина, таблица «`kind` ↔ заголовок на
   странице», образец для величины без нормы — `references/methodology.md`.
3. Собрать `enrich.json` вида `{ "marker_id": { "what": [...], "up": "…", "down": "…" } }`.
4. Dry-run → прочитать отчёт → `--apply`:
   `python3 scripts/validate_labs_info.py merge --info "$HEALTH_ROOT/biomarkers-info.json" --labs "$HEALTH_ROOT/labs.json" --enrich /tmp/enrich.json --today {YYYY-MM-DD}`
   (+ `--apply`). Без `--overwrite` существующие записи не переписываются;
   `--overwrite` — только осознанно и с упоминанием в отчёте.
5. Отчёт: маркер · что добавлено; что осталось без справки и почему; orphans.

Запись справки с `manual: true` внесена человеком со страницы: `merge` её не
переписывает даже с `--overwrite` (`skip_manual`). Отчёт `reports/*.md` и справку
маркера может писать и сайт — теми же `validate_report.check` и `merge_info`.

Провенанс справки — лёгкий (решение владельца 2026-08-05): без
`sources`/`confidence` на запись, общая дата `generated` в файле. Незнакомый
тест, понадобился WebSearch — написанное проверяется вторым чтением
источника.

Отчёт пользователю в обоих режимах закрывается дисклеймером: **справочно, не
медицинская рекомендация; текст не интерпретирует конкретный результат и не
заменяет консультацию врача.**

## Режим C — сохранить отчёт

Отчёт по данным (разбор, флаги, чек-лист к врачу) пишется в разговоре с
пользователем — **скилл его не сочиняет** (см. «не интерпретирует» выше). Скилл
приводит готовый текст к формату `health-report@1` и кладёт в `reports/`:

1. Прочитать `references/report-format.md`.
2. Добавить шапку **только из содержания отчёта**: `summary` — его прямой
   ответ, `flags` — его главные пункты, `todo` — его чек-лист, `markers` — id
   из `labs.json`. Ничего медицинского от себя; уровень флага — как в тексте
   (красные флаги отчёта → `red`, «обсудить с врачом» → `warn`).
3. `python3 scripts/validate_report.py check ОТЧЁТ.md --labs "$HEALTH_ROOT/labs.json"`
   → ошибки исправить.
4. Показать шапку пользователю, после «да» —
   `python3 scripts/validate_report.py save ОТЧЁТ.md --health "$HEALTH_ROOT" --topic ТЕМА --labs … --apply`.

## Режим D — давление и пульс из Apple Health

«Импортируй давление из Apple Health», «внеси экспорт Apple Health».
`scripts/apple_health_bp.py --root "$HEALTH_ROOT" plan EXPORT` → показать
сводку → после «да» `… apply EXPORT`. Среднее за день в рядах `exam_bp_sys`,
`exam_bp_dia`, `exam_pulse` `labs.json`. Ручные замеры на страницу вносит
человек: скилл `vitals.json` не пишет, только читает (дни с ручным замером
пропускаются). Экспорт: Здоровье на iPhone → профиль → «Экспортировать все
медданные» → `export.zip` в папку «Медицинские анализы» или путь в запросе.
Правила и разбор формата — `references/apple-health.md`.

## Pre-emit checklist

Режим A (перед `--apply`):
- [ ] каждое число сверено с документом; ни одной нормы «по памяти»;
- [ ] документ пройден построчно: каждая строка — либо показатель, либо текст
      карточки (`conclusion`/`notes`); ничего не потеряно, числа не продублированы;
- [ ] сомнительное — в `notes` с `⚠ Проверить` и названо пользователю;
- [ ] маркеры по словарю `references/intake.md`, дублей по смыслу не заведено;
- [ ] вид исследования из списка страницы, УЗИ любого органа — «УЗИ»;
      «Другое» — с поясняющей `area`;
- [ ] dry-run чистый, предупреждения прочитаны; план показан, «да» получено;
- [ ] пользователь не правил исследования на сайте прямо перед записью (или правка уже видна в зеркале);
- [ ] диагнозы из документов сверены с `anamnesis.json` → `self`; новые — в блоке «Предложение для анамнеза», в файл не записаны;

Режим B (перед `--apply`):
- [ ] у каждой записи непустые `what` (список), `up`, `down`;
- [ ] текст отражает реальный смысл теста, не угадан по созвучию;
- [ ] `default_category_flag` обсуждён с пользователем до написания справки;
- [ ] `--overwrite` не использован без явного намерения.

## Архив: конвертер из CSV

`scripts/build_health_json.py` (выгрузка Ornament → `labs.json`) — история
миграции. Запись отключена: без `--legacy-overwrite` отказ, а поверх
`labs.json` с точками `intake.py` (`study`/`src`) — отказ всегда. Живым
остаётся только `--selftest` парсеров.

## Тесты (для разработки скилла — не часть рабочей процедуры)

```bash
python3 scripts/intake.py selftest
python3 tests/test_intake.py
python3 scripts/build_health_json.py --selftest
python3 tests/test_validate_labs_info.py
python3 tests/test_validate_report.py
python3 tests/test_apple_health_bp.py
```

`test_intake.py` — scan/mark, dry-run не пишет, запись (новая категория и
маркер, точка с `study`/`src`, копия файла, лог), `link_only` и пересчёт
`kind`, 14 blocking-случаев без побочных записей, статус по референсу,
`add_files`, отказ при `studies.json`, изменённом после чтения, бэкап до записи, имена в
NFD, обязательная лаборатория у анализа (78 проверок). Остальные — парсеры архивного конвертера (46) и
справочник (50). `test_validate_report.py` — шапка отчёта: 18 blocking,
предупреждения, check/save без перезаписи, паритет уровней со страницей (47).
