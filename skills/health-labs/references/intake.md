# Режим «внести документы» — справочник

Загружается из `SKILL.md` при внесении новых документов. Скрипт —
`scripts/intake.py`, здесь — что он ждёт на входе и как этот вход готовить.

## Модель хранения (решение владельца 2026-09-29)

Ровно два места, больше никаких:

| Место | Что | Кто пишет |
|---|---|---|
| `SynologyDrive-home/Медицинские анализы/` | первоисточник: PDF/JPG/HTML как выдала клиника | человек; скилл **только читает** |
| `Claude-Memory/Health/` | данные страницы | скилл и страница |

Внутри `Health/`:

- `labs.json` — **главный файл чисел**. Пересборки из CSV (Ornament) больше
  нет, `build_health_json.py` — архив. Пишет только `intake.py`, через
  зеркало (единственный писатель).
- `studies.json` — исследования. Два писателя: `intake.py` (через зеркало)
  и страница (правка текста, write-API с `base_hash`) — риск принят
  владельцем ради правки на сайте. Страница после записи скрипта получит 409;
  обратное (зеркало отстало от правки на сайте) прикрыто перечитыванием перед
  записью и бэкапом `labs.json`/`studies.json` в `.intake-backups/` перед
  каждой записью. Перед `--apply` спросить, не правились ли исследования на
  сайте только что.
- `studies/` — копии файлов исследований (скрипт копирует из первоисточника).
- `intake-log.json` — какие файлы первоисточника разобраны (`ingested` /
  `skipped`). По нему `scan` находит новое.

**Связь исследование ↔ биомаркеры** — одной стороной: точка `labs.json` несёт
`study` (id исследования) и `src` (имя файла первоисточника). Обратное
направление страница вычисляет сама. У обычных анализов крови `study` нет —
это норма, а не пробел.

## Классификация файла

| Документ | Что вносить |
|---|---|
| Лабораторный анализ (кровь, моча, кал, антитела) | только точки `points`, **без** `study`; `lab` пункта — лаборатория (обязательно, см. ниже) |
| Инструментальное исследование (ЭКГ, УЗИ, рентген, КТ, МРТ, ЭНМГ, эндоскопия) | `study` + точки его чисел с привязкой |
| Осмотр врача с измерениями (офтальмолог) | `study` вида «Другое» + точки измерений |
| Второй документ того же исследования (прочтение ИИ, протокол к итогу ЭНМГ) | тот же пункт плана: оба файла в `src`, второй — в `study.files` |

**Вид исследования** — строго из списка страницы: МРТ · КТ · УЗИ · ЭКГ ·
Рентген · ЭНМГ · Эндоскопия · Другое. **Любое ультразвуковое — «УЗИ»**
(ЭхоКГ, ЦДС сосудов, УЗИ нерва), орган — в `area` («сердце (ЭхоКГ)»,
«сосуды шеи (ЦДС)»). Флюорография — «Рентген». «Другое» — только когда ни один
вид не подходит; тогда `area` должна сама объяснять, что это («глаза (осмотр
офтальмолога)»): страница показывает её вместо слова «Другое».

## Чтение документа

1. Текстовый PDF — `pdftotext -layout`. Скан (текста нет) —
   `pdftoppm -r 110 -png` и прочитать картинку. HTML — снять теги. JPG —
   читать картинку.
2. **Числа — только из документа.** Ни одного значения по памяти, ни одной
   «типичной нормы». Нормы в документе нет → `ref: null`, статус `na`.
3. Вёрстка PDF часто съезжает (колонки таблицы в одну строку). Если
   соответствие «название ↔ число» не очевидно — не угадывать: внести
   однозначное, сомнительное вынести в `notes` строкой
   `⚠ Проверить: …` и назвать пользователю.
4. Клиника — из документа (логотип тоже считается; номер медкарты — только
   как подсказка, вслух назвать как неуверенность).

## Предложение для анамнеза

`anamnesis.json` (раздел `self`: аллергии, хронические болезни, перенесённые
болезни, операции, травмы, госпитализации) ведёт владелец на странице —
скилл его только читает. При разборе документов показать владельцу блок:

| Что | Когда | Вид | Откуда |
|---|---|---|---|
| Невропатия латерального кожного нерва бедра слева | 08.2024 | хроническое | ЭНМГ 26.08.2024 |

- **Брать:** диагноз с МКБ-кодом или словами «диагноз», выписку,
  больничный, консультацию с заключением, операцию, травму, аллергическую
  реакцию из документа. Вид — `chronic`, `illness`, `surgery`, `injury`,
  `hospitalization`, `allergy`.
- **Не брать:** «Z00.x — общий осмотр», находки без диагноза (единичный очаг
  на КТ — это исследование, не болезнь), то, что уже есть в `self.history` или
  `self.allergies` (сверять по смыслу и дате, не по точной строке).
- **Точки во время болезни:** если дата новой точки попадает в событие
  `self.history` вида `illness`/`injury`/`surgery`/`hospitalization` (от `start`
  до `end` + 28 дней) — назвать это фактом в показе плана («ЛПНП 07.10 — через
  5 дней после ОРВИ»). Вывод «значение искажено» — не делать, это разбор.

## Фото бумажных документов

Старые распечатки владелец добавляет фотографиями. Скрипт имена файлов не
разбирает, дата и всё остальное — из содержимого.

- **Формат.** Читаются JPG/PNG/PDF. HEIC/HEIF (фото iPhone по умолчанию) — нет:
  `scan` предупредит; попросить владельца пересохранить как JPEG или, лучше,
  отсканировать (ниже). Первоисточник не конвертировать и не переименовывать.
- **Лучший путь для владельца:** «Файлы» на iPhone → ⋯ → «Отсканировать
  документы» → сохранить в «Медицинские анализы»: многостраничный PDF, ровный
  и без бликов. Имя — `ГГГГ-ММ-ДД что` (по желанию; не обязательно).
- **Несколько фото одного бланка** (страницы, оборот) — один пункт плана, все
  файлы в `src`. Признаки одного документа: одна дата/номер заказа/лаборатория,
  продолжение таблицы.
- **Чтение фото:** повернуть/увеличить картинку при нужде; блик, обрез, смазано,
  от руки, сомнение в цифре или запятой → не угадывать, `⚠ Проверить:` с
  указанием строки и назвать владельцу. Единицы и норма — с бланка; нормы нет
  на бланке → `ref: null`.
- **Дата** — дата взятия материала (не печати бланка); нет на бланке → спросить
  владельца, не брать дату файла или съёмки.
- **Дубли:** распечатка того же анализа, что уже есть PDF (та же дата и
  значения) → `link_only` либо `mark --note "дубль распечатки"`. Расхождение
  значений с уже внесённым → показать владельцу, ничего не перезаписывать.
- **Старые лаборатории и методы:** другая единица или норма — нормально, у
  каждой точки свои `unit`/`ref`; маркер — по словарю, новый не заводить из-за
  другой единицы.
- **Много фото сразу:** план — по визитам (дата + лаборатория), показывать
  владельцу партиями, а не одной простынёй.

**Правило полноты (владелец, 2026-09-29): из документа не теряется ничего.**
Что стало показателем — в `points`; всё остальное содержательное —
заключение, описание, качественные находки («блокады нет», «клапаны б/о»),
параметры проведения, сомнения — в `conclusion`/`notes` исследования. Перед
планом пройти документ построчно и убедиться, что каждая строка попала
либо в показатель, либо в текст карточки. Сырой копией протокола `notes`
не заполнять: числа, ставшие показателями, в тексте не дублируются.

**Правило владельца (2026-09-29): каждое измеренное число протокола — в
показатели**, даже если повтор не очевиден: динамика появится, когда
исследование повторят. В `notes` уходят только **параметры проведения**, а
не измерения: сила/длительность стимула, расстояние, аппарат, доза облучения,
рост/вес на момент исследования. Величина дана диапазоном («14–19 мм²») —
в `notes`, не в показатели. Норма напечатана в документе (у ЭНМГ — «норма
скорости 60 м/с») → `ref` (`{"op":"≥","value":60}`); не напечатана → `null`.

Два столбца с одной величиной разной точности (ЭНМГ: «Лат.» 2,0 и «Время»
1,96) — вносить точное значение, в `notes` сказать, что второе — оно же,
округлённое. Новый id — латиницей `[a-z0-9_]`, короткий, с префиксом
категории, стороны — суффиксом `_r`/`_l`.

## Формат PLAN.json

```json
{
  "new_categories": [{"key": "ecg", "name": "ЭКГ"}],
  "new_markers": [
    {"id": "ecg_qtc", "name": "Интервал QTc", "category": "ecg", "unit": "мс"}
  ],
  "items": [
    {
      "src": ["2025-10-16 ЭКГ.pdf"],
      "study": {
        "date": "2025-10-16", "kind": "ЭКГ", "area": "сердце",
        "conclusion": "дословно заключение врача (+ описание, если оно содержательное)",
        "clinic": "Клиника «Чайка»", "doctor": "Фамилия И. О., специальность",
        "notes": "прочее из протокола; ⚠ Проверить: …",
        "files": [{"as": "2025-10-16-экг.pdf", "from": "2025-10-16 ЭКГ.pdf"}]
      },
      "points": [
        {"marker": "ecg_qtc", "date": "2025-10-16", "value": 411, "unit": "мс", "ref": null}
      ]
    },
    {
      "src": ["2026-10-05 Общий анализ крови.pdf"],
      "lab": "Инвитро",
      "points": [
        {"marker": "hgb", "date": "2025-01-15", "value": 140, "unit": "г/л", "ref": {"low": 120, "high": 160}}
      ]
    },
    {
      "src": ["2026-08-04 Офтальмолог.pdf"],
      "study": {"ref": "s20260804-eye"},
      "points": [
        {"marker": "ostrota_zreniya_visus_os", "date": "2026-08-04", "link_only": true}
      ]
    }
  ]
}
```

- `src` — имена файлов первоисточника, 1+. Каждый файл — ровно в одном пункте.
- `study` — новое исследование **или** `{"ref": id}` — привязка к уже
  существующему (внесённому страницей/раньше). `study.id` можно не задавать:
  скрипт соберёт `s<ДАТА>-<слаг вида и области>`.
- `{"ref": id, "add_files": [{"as", "from"}]}` — дописать файлы к
  существующему исследованию (пустой `file` заполняется первым, остальные —
  в `more_files`). `src` пункта добавляется в `src` исследования.
- `study.files` — что скопировать в `Health/studies/`: `as` — имя там
  (`ГГГГ-ММ-ДД-вид[-область].pdf`, строчными, через дефис), `from` — файл из
  `src`. Первый — основной (`file`), остальные — `more_files` (кнопки в панели).
- `points[].marker` — id или точное имя маркера. `value` — число; текстовый
  результат — `text`. `ref` — `{"low","high"}` | `{"op","value"}` |
  `{"text"}` | `null`. `status` не нужен: скрипт считает его по `ref`.
- `lab` — лаборатория, выполнившая анализ; пишется у пункта (на весь
  документ), у точки можно переопределить. **Обязательно у каждой точки без
  исследования** — иначе blocking. Искать в тексте документа: шапка, подвал,
  «Исполнитель», сайт, юрлицо. Имена — как уже в `labs.json`: `Инвитро`
  (в т.ч. франчайзи «ООО Инновационная медицина», сайт invitro.ru),
  `Гемотест`, `Helix`, `KDL`, `ГКБ № 67`, `Клиника Эксперт`, `Чайка`.
  Общий номер заказа (или соседний ИНЗ Инвитро) с уже опознанным документом
  — та же лаборатория; вывод назвать владельцу в плане. Новая лаборатория —
  короткое название без ООО/ГБУЗ. **Не нашёл явного названия — спросить
  владельца** при показе плана («чей это анализ?»), не угадывать по косвенным
  признакам (формат номера заказа, вёрстка). У точек исследования (ЭКГ, УЗИ…)
  `lab` не нужен — клиника живёт в `study.clinic`.
- `link_only: true` — точка уже есть в `labs.json` (например, перенесена из
  Ornament), нужно только привязать её к исследованию. Значение не меняется.

## Что проверяет скрипт (blocking — ничего не пишется)

Файл первоисточника есть и ещё не разобран · вид исследования из списка ·
заключение непустое · id исследования свободен · в `studies/` нет **другого**
файла с тем же именем · маркер существует (или заведён в `new_markers`, без
дубля по имени) · категория известна · дата ISO · нет второй точки маркера на
ту же дату (дубль → `link_only`) · `value` — число · `ref` валиден · у точки
анализа (без исследования) указана лаборатория `lab`.

Предупреждения (не блокируют, но их надо прочитать и сказать пользователю):
единица точки ≠ единице маркера; дата точки ≠ дате исследования.

После записи маркер пересчитывает `ref`/`unit` по последней точке и `kind`:
`num`, если все точки числовые (прежнее правило конвертера делало
авторефрактометрию «качественной» — без графика).

## Порядок записи

Файлы → `studies.json` → `labs.json` → `intake-log.json`.
`studies.json` первым: только его запись может отказать (файл изменился после
чтения — синк привёз другую версию) — тогда `labs.json` не тронут, и точки не
ссылаются на несуществующее исследование; просто повторить `apply`. Лог
последним: упавший прогон не пометит файлы разобранными, и `scan` покажет их
снова. Если упало уже после `studies.json` — повторный `apply` упрётся в
«исследование уже есть»: заменить в плане `study` на `{"ref": id}`.
