# Формат отчёта `health-report@1` (папка `Health/reports/`)

Отчёт — **Markdown-файл с шапкой**. Шапка — короткая сводка, которую страница
рисует карточками (флаги цветом, чек-лист, ссылки на биомаркеры); тело —
обычный Markdown, страница показывает его своим рендером (адаптивно под экран,
в теме страницы). Почему не HTML/PDF — решение владельца 2026-09-29: вид
подстраивается под экран только когда рисует страница, а `.md` дешевле для
Claude, правится руками и читается следующим отчётом.

**Скилл отчёт не пишет** — медицинский разбор делается в разговоре с
пользователем. Скилл только проверяет формат (`validate_report.py check`) и
кладёт файл в `reports/` (`save`).

## Имя файла

`ГГГГ-ММ-ДД-тема.md`, строчными, через дефис: `2026-09-29-общий.md`,
`2026-12-10-липиды.md`. Дата в имени = `date` шапки. `save` называет файл сам.

## Шапка

Первая строка файла — `---`, шапка кончается следующей строкой `---`.
Внутри — только строки `ключ: значение`, пункты списка `  - …` (под ключом с
пустым значением) и пустые строки. Значения — одной строкой, без кавычек
(кавычки останутся в тексте буквально). Комментариев `#` в шапке нет.

```markdown
---
schema: health-report@1
title: Общий отчёт по медицинским данным
date: 2026-09-29
data_asof: 2026-09-29
summary: Острых отклонений нет; значимых пунктов четыре — липиды, фолаты, масса тела, прививки.
flags:
  - warn | Дислипидемия | показатель X выше цели на пример-значение; контроль не проводился несколько месяцев (вымышленный пример)
  - warn | Дефицит фолатов | показатель Y ниже порога — вымышленный пример
  - info | Масса тела | показатель Z, плавный тренд — вымышленный пример
todo:
  - Сдать липидограмму, Lp(a), АЛТ, HbA1c
  - Через 3 месяца — ОАК, фолаты, B12
markers: ldl, folate, hgb
---

# Общий отчёт по медицинским данным — 29.09.2026
…тело отчёта…
```

| Ключ | Обяз. | Что | Ограничения |
|---|---|---|---|
| `schema` | да | `health-report@1` | ровно так |
| `title` | да | заголовок в списке отчётов | ≤ 90 символов |
| `date` | да | дата отчёта | `ГГГГ-ММ-ДД` |
| `data_asof` | нет | дата самых свежих данных, на которых построен отчёт | `ГГГГ-ММ-ДД`, не позже `date` |
| `summary` | да | прямой ответ в 1–2 предложения | ≤ 300 символов |
| `flags` | нет | главные пункты: `уровень \| заголовок \| пояснение` | ≤ 8; заголовок ≤ 40, пояснение ≤ 220 |
| `todo` | нет | чек-лист к врачу / на пересдачу | ≤ 10 пунктов по ≤ 160 |
| `markers` | нет | id биомаркеров из `labs.json` через запятую — кнопки на странице | ≤ 12, каждый существует |

**Уровни флага** (страница красит и подписывает):

| Уровень | Подпись | Когда |
|---|---|---|
| `red` | Срочно | красный флаг: к врачу без ожидания |
| `warn` | Обсудить | отклонение, которое стоит обсудить с врачом |
| `info` | Наблюдать | пограничное, тренд, пробел в данных |
| `ok` | В норме | важное «проверили — всё в порядке» |

Неизвестный ключ — ошибка (опечатка в `flag:` иначе молча потеряла бы флаги).

## Тело

Обычный Markdown: заголовки `#`–`####`, абзацы, списки, таблицы `|…|`,
**жирный**, *курсив*, `код`, ссылки `[текст](https://…)`, цитаты `>`, `---`.
Сырой HTML не показывается (рендер его экранирует) — не использовать.
Первая строка `# …` тела на странице скрывается: заголовок уже в шапке.

## Команды

```bash
python3 scripts/validate_report.py check ОТЧЁТ.md [--labs "$HEALTH_ROOT/labs.json"]
python3 scripts/validate_report.py save ОТЧЁТ.md --health "$HEALTH_ROOT" --topic общий [--apply]
```

`check` — ошибки (blocking) и предупреждения; код выхода 1 при ошибках.
`save` — dry-run по умолчанию; с `--apply` пишет
`reports/<date>-<topic>.md`. Файл с тем же именем и другим содержимым не
перезаписывает — нужна другая тема или явное удаление старого владельцем.
