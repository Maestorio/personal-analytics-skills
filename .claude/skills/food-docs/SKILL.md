# /food-docs

Точечная загрузка документации перед работой над разделом «Еда».
Отпочковался от `/design-docs`: раздел вырос до собственного контура
(страница + данные + скрипты + инструкция генератора + своя зона API), и
тянуть ради правки рецепта дизайн-док вьюера и HTML-экспорт travel стало
дороже, чем полезно.

Проектный скилл — живёт в `.claude/skills/` репозитория `claude_skills`
(рядом с `design-docs`, `investment-docs`, `travel-docs`), осмыслен только
внутри него. Все пути ниже — относительно корня репозитория.

**Дизайн страницы — по-прежнему у `/design-docs hub`.** Сюда он не
дублируется: если задача про вид и вёрстку кабинета в целом (токены, обе
темы, плитки хаба) — это туда. Здесь — про «Еду» как предметную область.

## Использование

```
/food-docs page          # страница tools/food.html: экраны, состояние, правки
/food-docs data          # БД раздела: products / recipes / shopping, схемы
/food-docs recipes       # инструкция генератора рецептов + мультиварка
/food-docs scripts       # tools/food/*.py — валидатор, сопоставление, КБЖУ
/food-docs api           # запись: зона /api/fd/*, Caddy, деплой
/food-docs tests         # что гонять после правок
/food-docs page data     # несколько тем
/food-docs               # без аргумента → показать карту и спросить
```

## Процедура

1. **Разобрать аргумент** в список тем:
   - `page` (страница) · `data` (данные) · `recipes` (инструкция генератора и
     техника) · `scripts` · `api` · `tests`;
   - синонимы: `страница`/`food.html`/`ui` → page; `продукты`/`каталог`/
     `рецепты-файлы`/`список покупок`/`json` → data; `инструкция`/`промт`/
     `мультиварка`/`генератор` → recipes; `кбжу`/`валидатор`/`сопоставление` →
     scripts; `запись`/`caddy`/`деплой`/`sidecar` → api;
   - несколько токенов → объединение; пусто → показать карту ниже и спросить.
2. **Всегда прочитать сначала** — общее для любой темы:
   - шапку `tools/food.html` (комментарий-архитектура: состояние `S`, полная
     перерисовка `render()`, точечная `patchHTML()`, делегирование событий,
     порядок загрузки apiGet → публичный fetch);
   - раздел «Хранилище» ниже — где физически лежат данные.
3. **Для каждой темы** прочитать её строку каталога. Грузить только это.
4. **Кросс-темное** (держать в голове при любой правке раздела):
   - **Данные лежат НЕ в репозитории.** `Claude-Memory/Food/` — на Synology:
     `~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/Food/`.
     В репозитории — только страница, скрипты и документация.
   - **Зеркало Synology на Mac ненадёжно в сторону NAS→Mac.** Читать можно,
     но данные могут быть устаревшими; запись целого файла с Mac затирает
     правки, сделанные со страницы. Правки данных, которые человек трогает со
     страницы (`shopping.json`, отметки «куплено»), с Mac не писать.
   - **Свободные строки, а не enum.** `category` продукта (отдел) и `category`
     рецепта (тип блюда) — свободный текст: незнакомое значение падает в
     «прочее», но не роняет сохранение и не прячет запись. Единственный
     оправданный enum — `state: cooked|dry` (опечатка там тихо отключает
     пересчёт варёного веса).
   - **Идентичность рецепта — имя файла**, поле `id` внутрь не пишется.
   - **Правило КБЖУ одно на обе стороны**: этикетка продукта приоритетнее,
     Этуотер 4/9/4 — только при её отсутствии. Расхождение страницы и
     `nutrition.py` — баг (ловится контракт-тестом).
   - **Телефон** — основной сценарий: список покупок открывают в магазине,
     рецепт читают на кухне. Поля ввода ≥16px, длинные токены переносить,
     полная перерисовка обязана возвращать прокрутку и окна, и модалки.
   - **Любая правка `food.html` → поднять `VERSION`** (константа в начале
     скрипта, печатается в подвале). Хотя бы minor и на мелкой правке: по
     версии на скриншоте видно, ту ли сборку человек смотрит, — иначе «не
     работает» неотличимо от «старая версия из кеша».
   - **Данные читать и писать через API NAS, а не через зеркало на Маке.**
     Зеркало `SynologyDrive-home` в сторону NAS→Mac отстаёт: 2026-08-09 два
     рецепта, переименованных на странице утром, в зеркало не приехали вовсе, и
     правка «по зеркалу» их не увидела. `GET /api/fd/file?path=…` отдаёт правду
     с хэшем, `POST /api/fd/save` с `base_hash` физически не даст затереть
     чужую свежую версию (409). Адрес NAS в домашней сети — `192.168.1.10:8080`.
     Зеркало годится для быстрого обзора, но не для записи и не для выводов.
   - **Правка требует обновления контейнера → выдать команды, а не сказать
     «нужно задеплоить».** `tools/hosting/api/server.py` (зона `/api/fd/*`),
     `Caddyfile` и `docker-compose.yml` живут НА NAS и синком не доставляются.
     Тронул их — закончи ответ готовыми командами из «Обновление контейнера —
     шпаргалка» (`tools/hosting/SYNOLOGY-SETUP.md`) и скажи прямо, что не
     заработает до обновления: страницы рисуют кнопки по признакам из
     `/api/health` (`food_create`, `food_delete` …), поэтому «старый сайдкар»
     выглядит просто как отсутствующая кнопка. Правки `food.html` и
     `assets/` обновления контейнера НЕ требуют.
   - После правок — прогнать тесты темы `tests` (ниже).
5. **Доложить, что загружено**, и ждать задачу. Если просили
   «проанализируй/проверь» — выдать анализ и ждать; править сразу только по
   «исправь/сделай».

## Хранилище

```
~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/Food/
├── products.json          # каталог продуктов (food-products@1)
├── shopping.json          # список покупок (food-shopping@1)
├── recipes/<slug>.json    # ПО ФАЙЛУ НА РЕЦЕПТ (food-recipe@1)
├── recipes.json           # легаси-пустышка, не используется
├── inbox/                 # сюда кладут .md руками / синком из проекта Claude.ai
└── .versions/             # бэкапы, которые делает сайдкар перед записью и удалением
```

Страница читает рецепты **листингом каталога** (Caddy отдаёт JSON при
`Accept: application/json`): положил файл — рецепт появился.

## Что в этом скилле НЕ живёт

- Дизайн-система, токены, обе темы, плитки хаба → `/design-docs hub` и
  `/design-docs tokens`.
- Раздел «Здоровье» (соседний том, свои схемы) → `/design-docs health`.
- Хостинг целиком (все зоны, не только еда) → `/design-docs hosting`.
- Инвестиционный и travel-контуры — вообще другие деревья
  (`/investment-docs`, `/travel-docs`).

## Принципы

- **Минимум контекста.** Грузить только доки запрошенных тем.
- **Данные — на Synology, не в git.** Прежде чем править данные, помнить про
  одностороннее зеркало и про то, что страницу человек мог трогать час назад.
- **Схемы менять — вместе с валидатором.** `validate_food` в сайдкаре
  отклоняет структурно битый файл: расширил формат на странице — расширь и
  валидатор, иначе сохранение молча упрётся в 400.
- **Язык — русский** (как и вся документация репозитория).
