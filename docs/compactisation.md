# Подготовка большого проекта на Claude Code + Claude.ai к переходу Max → Pro: ранжированные методики (август 2026)

**Bottom line:** главный рычаг экономии лимитов при переходе на Pro — это не выбор модели, а сокращение постоянного контекстного «налога», который списывается на КАЖДОМ обороте сессии; ваш CLAUDE.md в ~190 КБ и 8 раздутых SKILL.md — это именно такой налог, и их сжатие даст больший эффект, чем любая другая мера. При этом ключевое устаревшее убеждение сообщества снято: Pro в 2026 году даёт доступ к Opus 5 («the strongest model on Claude Pro» — anthropic.com/news/claude-opus-5), поэтому стратегия «на Pro Opus недоступен» неверна.

## TL;DR
- **Сожмите постоянный контекст в первую очередь.** CLAUDE.md грузится в начале каждой сессии и никогда не вытесняется — 5000-токенный файл стоит 5000 токенов на каждом обороте (KDnuggets; Claude Code docs). Ваш реестр тестов на 74% файла обязан переехать в on-demand reference или в HTML-комментарии (которые вырезаются до попадания в контекст — dev.to/Claude Code docs). Это мера №1 по соотношению эффект/трудозатраты.
- **Pro-лимиты в 2026: два слоя.** 5-часовое скользящее окно (удвоено 6 мая 2026, пиковые урезания сняты — morphllm) + недельный кап «across all models» плюс отдельный недельный счётчик по Opus (support.claude.com). Всё это — общий пул с claude.ai и Cowork (support.claude.com).
- **Маршрутизация и гигиена сессий важнее «магии».** `Sonnet 5 по умолчанию + opusplan` (Opus в планировании, Sonnet в исполнении), `/clear` вместо `/compact` при смене задачи, «тёплый» кэш (5-мин TTL, обновляется при каждом чтении) — дают предсказуемую экономию. Внешние repo-map/индексы и консолидация скиллов ради экономии описаний, наоборот, обычно не окупаются.

## Key Findings (фактическая база с источниками)

### Актуальное состояние лимитов Pro/Max (август 2026)
- **5-часовое окно удвоено 6 мая 2026** для Pro/Max/Team/seat-Enterprise; одновременно убрано урезание лимитов в пиковые часы. Дословно: «The five-hour limits were doubled on May 6, 2026 for Pro, Max, Team, and seat-based Enterprise plans, and peak-hour reductions were removed» (morphllm.com/claude-code-usage-limits). Прежнее пиковое окно затрагивало будни ~13:00–19:00 GMT и сильнее всего било по Pro. **Дополнительно:** был введён +50% буст к недельным лимитам (≈13 мая 2026), продлённый до 19 августа 2026 (explainx.ai) — временная мера, которую стоит перепроверять по дате.
- **Недельные капы существуют и на Pro.** Официально: «Pro plans also have a weekly usage limit that applies across all models. Weekly limits reset at a fixed time each week that is assigned to your account» (support.claude.com/en/articles/8325606-what-is-the-pro-plan, ред. 10 июня 2026). Утверждение части блогов, что «Pro освобождён от недельных капов» (st-hakky) — **устарело/неверно**.
- **Отдельный недельный счётчик Opus на Pro.** Дашборд Settings → Usage показывает «when your plan's weekly usage limit resets for Opus only and all other models» — и это доступно Pro-подписчикам (support.claude.com/en/articles/9797557-usage-limit-best-practices, ред. 2 июня 2026). Отдельный **Sonnet-only** недельный кап официально описан в контексте Max/Claude Code; для Pro официальных формулировок о выделенном Sonnet-кэпе нет — считать неподтверждённым.
- **Модели на Pro:** default — Sonnet 5 (с 30 июня 2026); Opus 5 доступен и является «the strongest model on Claude Pro» (anthropic.com/news/claude-opus-5; @claudeai в X, 24 июля 2026). Это отменяет прежний совет «на Pro только Sonnet».
- **Единый пул.** «Both Pro and Max plans offer usage limits that are shared across Claude and Claude Code, meaning all activity in both tools counts against the same usage limits» (support.claude.com/en/articles/11145838). Claude Code в IDE тоже списывается из того же пула.
- **Важное изменение по субагентам/SDK (15 июня 2026):** программное использование через Claude Agent SDK и `claude -p` больше НЕ списывается из подписки, а идёт из отдельного месячного кредита ($20 на Pro): «Starting June 15, 2026, Claude Agent SDK and claude -p usage no longer counts toward your Claude plan's usage limits» (support.claude.com/en/articles/15036540). Интерактивные субагенты внутри сессии Claude Code — по-прежнему из общего пула. **Поправка 2026-10-20: отделение отложено — на Pro `claude -p` и Agent SDK по-прежнему тратят лимит подписки (`api-migration/analysis-2026-10-20.md` §2); на отдельный кредит не рассчитывать.**
- Приблизительные ориентиры сообщества (не публикуются Anthropic официально): ~45 сообщений/5 ч на Pro; ~40–80 ч Sonnet-класса в неделю (deployhyre.com, aiplanfinder.com, techcrunch.com 28 июля 2025). Относиться как к оценкам; истина — в Settings → Usage.

### Контекстный «налог» и деградация
- CLAUDE.md загружается до чтения кода/задачи и **не вытесняется** всю сессию: «a 5,000-token CLAUDE.md costs 5,000 tokens on every single turn» (kdnuggets.com). Практический потолок — «under ~200 lines» (dev.to/nishilbhave; maketocreate.com).
- HTML-комментарии блочного уровня вырезаются до попадания в контекст (нулевая стоимость токенов) — dev.to со ссылкой на Claude Code docs 2026.
- «Context rot»: технический отчёт Chroma «Context Rot: How Increasing Input Tokens Impacts LLM Performance» (Hong, Troynikov, Huber; 14 июля 2025; trychroma.com/research/context-rot) протестировал 18 LLM, включая GPT-4.1, Claude 4, Gemini 2.5, Qwen3: «performance grows increasingly unreliable as input length grows». Независимые пересказы фиксируют падение точности «by 30 to 50 percent well before the documented limit» (glasp.co); для моделей с окном 1M эффект проявляется около 300K–400K токенов. Практики держат загрузку ≤60% окна (datacamp.com).
- Свежая сессия Claude Code «сжигает ~20K токенов» на системный промпт + определения инструментов + CLAUDE.md ещё до первого сообщения; каждый MCP-сервер добавляет схемы навсегда (практический предел 5–8 серверов) — datacamp.com.

### Механика prompt caching
- TTL по умолчанию 5 минут, продлевается при каждом чтении кэша: активная сессия «keeps the cache warm indefinitely»; пауза >5 мин — кэш испаряется, следующий запрос холодный (claudecodecamp.com; code.claude.com/docs/en/prompt-caching).
- **Ценообразование кэша (официально, platform.claude.com/docs/en/build-with-claude/prompt-caching):** чтение из кэша = 10% базовой цены input-токена («Cache reads: When cached content is used (10% of base input token price)»); запись 5-мин кэша = +25% к базовой цене (1.25×). То есть заголовочные «90% экономии» реальны только на input-стороне; output-токены полной ценой.
- Кэш в Claude Code «effectively scoped to one machine and directory»; системный промпт включает рабочую директорию, платформу, shell, версию ОС — смена любого инвалидирует префикс (code.claude.com/docs).
- Смена модели инвалидирует кэш: «A model switch can feel free until you notice the slower turn that follows» (code.claude.com/docs).
- Порог кэширования: 1024 токена (Sonnet/Haiku — подтверждено docs Anthropic: «Minimum 1,024 tokens»), 2048–4096 (Opus); системный промпт Claude Code ~4000 токенов, всегда проходит порог (claudecodecamp.com).
- Cache read не считается в ITPM rate limit (respan.ai). 1-часовой TTL — только через ENABLE_PROMPT_CACHING_1H и по факту релевантен API/Bedrock, не подписке (code.claude.com/docs).
- claude.ai Projects: загруженные документы кэшируются, «only new/uncached portions count against your limits» (support.claude.com/en/articles/9797557).

### Skills / progressive disclosure
- На старте грузятся только name+description из YAML (~60 токенов на скилл); тело SKILL.md — при срабатывании; reference-файлы — по мере необходимости. «a project with 8 skills consumes 500 tokens at startup instead of 70,000» (dotzlaw.com; platform.claude.com/docs).
- Официальная рекомендация: «Keep SKILL.md body under 500 lines»; при превышении — дробить на файлы (platform.claude.com/docs/.../best-practices).
- «Keep references one level deep from SKILL.md» — при глубокой вложенности Claude делает частичные чтения (`head -100`) и получает неполную информацию (platform.claude.com/docs).
- Для reference-файлов >100 строк — оглавление в начале, чтобы Claude видел объём при частичном чтении (platform.claude.com/docs).
- Чек-листы/воркфлоу с шагами и петлями валидации официально поощряются (это прямо релевантно вашим Python-скриптам с ~4000 проверок) — platform.claude.com/docs.

### Субагенты
- Изоляция контекста реальна, но «Subagents are not automatically cheaper»: архитектура добавляет накладные (промпты, определения инструментов, лишние round-trips); для мелких задач субагент расточителен (kdnuggets.com).
- «Whatever the subagent returns lands in your main context verbatim» — субагент, сделавший 8000 токенов работы и вернувший отчёт на 3000, стоит вам 3000 (hackernoon.com).
- Каждый субагент стартует с нуля: «Your system prompt, CLAUDE.md, any files it reads, all billed fresh. Five subagents… five full context loads» (dev.to/stevengonsalvez). ⇒ раздутый CLAUDE.md умножается на число субагентов.
- Выигрыш субагента = когда 10000 токенов внутренней работы возвращаются как 500-токенное резюме (hackernoon.com). Fan-out оправдан на дешёвой модели (Haiku/Sonnet) и на действительно независимых задачах (mindstudio.ai; code.claude.com/docs/en/costs).
- Снят кап в 200 субагентов на сессию (github.com/anthropics/claude-code CHANGELOG).

### Сессионная гигиена
- «/clear costs nothing. /compact reads the entire conversation in order to summarize it, so compacting a large context is itself a large request» (claudefa.st; systemprompt.io).
- Практика: `/compact` только пока кэш тёплый (в пределах 5 мин); если простой >5 мин — дешевле `/clear` + свежий старт, т.к. холодный `/compact` заново обрабатывает весь контекст (systemprompt.io).
- Микрокомпакция: крупные tool-outputs сбрасываются на диск, в контексте остаётся ссылка; «hot tail» недавних результатов виден, остальное — cold storage по пути (decodeclaude.com, 21 янв 2026).
- Авто-компакт-буфер сокращён с ~45K до ~33K токенов в начале 2026 (claudefa.st); компакция стала «мгновенной» с v2.0.64 (cometapi.com).
- Батчинг: группировать несколько правок/вопросов в одно сообщение (support.claude.com/en/articles/9797557).

### Маршрутизация моделей
- `/model opusplan` (он же opus-plan): Opus в plan mode, авто-переключение на Sonnet при исполнении — «Sonnet consumes much less of your weekly quota» (christopherspenn.com; wmedia.es; code.claude.com/docs/en/model-config).
- Переход Opus→Sonnet на исполнении экономит ~40% input и ~40% output токенов (howdoiuseai.com); Sonnet закрывает ~80–90% задач (systemprompt.io; claudefa.st).
- `/advisor` держит Opus доступным «по вызову» во время исполнения, в отличие от opusplan (wmedia.es).
- `/effort` и MAX_THINKING_TOKENS — отдельный рычаг: на рутине снижать (claudefa.st).

### Русский язык (специфика проекта)
- Кириллица токенизируется существенно хуже английского. Рецензируемый замер (arXiv 2605.24718, «The Tokenizer Tax Across 25 European Languages»): «налог» растёт в ~2.5× от английского (1.2 токена/слово) к славянским (2.2–2.5); гайды по оптимизации дают для не-латинских алфавитов (кириллица/иврит/арабский) 2.5–3.2× английского. По байтам — примерно 2× («a sentence translated to Russian will be encoded by ~2× more bytes than its English version», co-tok.github.io). Транслитерация в латиницу сокращает число токенов примерно вдвое (ikriv.com; отмечено «Claude produces different results, but the overall picture is similar»). Академически: англо-ориентированные токенизаторы дробят русское слово на много токенов, что «reduces the amount of information that could be stored in the context» (Vikhr, arxiv 2405.13929).
- Следствие: весь ваш постоянный русскоязычный контекст (CLAUDE.md, тела SKILL.md) обходится в токенах дороже английского эквивалента — эффект сжатия для вас усилен.

## Details — ранжированный список методик

Ранжирование по (эффект на расход лимитов × применимость к вашему проекту / трудозатраты). Для каждой: суть, источник, оценка эффекта, риски.

### 1. Радикально сжать CLAUDE.md: «тонкий корень + доки по требованию» — ВЫСШИЙ ПРИОРИТЕТ
**Суть.** CLAUDE.md списывается на каждом обороте и никогда не вытесняется; при ~190 КБ (оценочно ~40–50K токенов, а на кириллице эффективный «вес» выше) это доминирующая статья расхода 5-часового окна, особенно на Pro. Аннотированный реестр тестов (74% файла) не нужен модели постоянно — вынесите его в reference-файл, подгружаемый скиллом-навигатором по требованию, либо, если это заметки для человека, оберните в блочные HTML-комментарии (вырезаются до контекста, стоимость 0). Цель корня — «under ~200 lines».
**Источник.** kdnuggets.com («5,000-token CLAUDE.md costs 5,000 tokens on every single turn»); dev.to/nishilbhave и maketocreate.com (порог ~200 строк, HTML-комментарии со ссылкой на Claude Code docs 2026); datacamp.com (~20K стартового налога).
**Оценка эффекта.** Прямое сокращение постоянного налога: перевод реестра из ~140 КБ в on-demand убирает десятки тысяч токенов с каждого оборота. При ~45 сообщениях/5ч на Pro экономия мультипликативна по всей сессии; дополнительно снижает «context rot» (Chroma 2025: падение точности на 30–50% ещё до документированного лимита).
**Риски.** Потеря быстрой доступности реестра тестов для модели; митигируется скиллом-навигатором с точными путями и grep-подсказками. HTML-комментарии подходят только для того, что модели читать НЕ нужно.

### 2. Сессионная гигиена: `/clear` по умолчанию, тёплый кэш, батчинг — ВЫСОКИЙ ЭФФЕКТ / НИЗКИЕ ЗАТРАТЫ
**Суть.** `/clear` при каждой смене задачи (стоит 0), `/compact` — только для продолжения той же задачи и только пока кэш тёплый (≤5 мин с последнего сообщения). При простое >5 мин `/compact` становится дорогим (заново читает весь контекст) — дешевле `/clear`. Группируйте правки в одно сообщение.
**Источник.** claudefa.st, systemprompt.io (стоимость /compact vs /clear; правило 5 минут); decodeclaude.com (микрокомпакция); support.claude.com/en/articles/9797557 (батчинг).
**Оценка эффекта.** Устраняет экспоненциальный рост input-токенов (вся история пересылается каждым запросом — mindstudio.ai). Один холодный `/compact` на большом контексте = один крупный запрос; замена на `/clear` экономит этот объём целиком.
**Риски.** `/clear` теряет весь контекст — используйте `/rename`+`/resume` для возврата; при DAG-пайплайне фиксируйте состояние в файле-артефакте (plan/todo), а не в истории чата.

### 3. Дробление 8 SKILL.md > 500 строк на диспетчер + references по режимам — ВЫСОКАЯ ПРИМЕНИМОСТЬ
**Суть.** Оставить в SKILL.md только навигацию (что делает скилл + когда + карта reference-файлов), а режимы/детали вынести в отдельные файлы, подгружаемые по требованию. Держать ссылки на один уровень от SKILL.md; в reference-файлах >100 строк — оглавление.
**Источник.** platform.claude.com/docs/.../best-practices (порог 500 строк; «references one level deep»; ToC для файлов >100 строк; «avoid deeply nested references»); dotzlaw.com (8 скиллов = ~500 токенов на старте вместо 70000).
**Оценка эффекта.** Тела скиллов грузятся только при срабатывании — вынос деталей в references снижает пиковую загрузку контекста при активации скилла; в вашем пайплайне с model-routing по скиллам это напрямую растягивает окно.
**Риски.** (а) Дрейф ссылок — reference-файл переименован, ссылка мертва; митигируется тестом целостности ссылок (у вас уже есть инфраструктура Python-тестов). (б) Потеря чек-листов при дроблении — держите чек-листы/петли валидации в теле SKILL.md, а не в глубоких references (официально они должны быть видимы на шаге исполнения). (в) Слишком глубокая вложенность → частичные чтения `head -100` и неполная информация.

### 4. Маршрутизация: Sonnet 5 по умолчанию + Opus точечно (opusplan) — ВЫСОКИЙ ЭФФЕКТ
**Суть.** На Pro поставить дефолтом Sonnet 5; для архитектурных решений/планирования — Opus 5 точечно через `/model opusplan` (Opus планирует, Sonnet исполняет). Это прямо соответствует вашему принципу model-routing по скиллам, но на уровне фаз.
**Источник.** anthropic.com/news/claude-opus-5 и @claudeai (Opus 5 «strongest on Claude Pro»); christopherspenn.com, wmedia.es, code.claude.com/docs/en/model-config (opusplan); howdoiuseai.com (~40% экономии input/output при Opus→Sonnet).
**Оценка эффекта.** Основная масса токенов сессии тратится на исполнение; перевод исполнения на Sonnet кратно снижает расход Opus-квоты (у Opus отдельный недельный счётчик — беречь его особенно важно). Sonnet закрывает ~80–90% задач.
**Риски.** На кириллице и сложных DAG-зависимостях Sonnet может чаще ошибаться — держите Opus доступным через `/advisor` для точечных консультаций; следите, что после plan mode произошло авто-переключение на Sonnet.

### 5. Дисциплина prompt caching: стабильный префикс, без смены модели в середине — СРЕДНЕ-ВЫСОКИЙ ЭФФЕКТ
**Суть.** Держите начало контекста стабильным (системный промпт, CLAUDE.md, определения инструментов идут в кэшируемый префикс); не переключайте модель и не меняйте MCP-набор в середине задачи — это инвалидирует кэш и даёт «холодный» дорогой оборот. Работайте сериями сообщений с паузами <5 мин, чтобы кэш не остывал.
**Источник.** code.claude.com/docs/en/prompt-caching (scope machine+directory; смена модели → медленный оборот); platform.claude.com/docs (чтение кэша = 10% базовой цены input, запись 5-мин = 1.25×); claudecodecamp.com (тёплый кэш; порог 1024 токена); respan.ai (cache read не в ITPM).
**Оценка эффекта.** Cache read ≈ 10% цены обычного input; на подписке это транслируется в более медленное исчерпание 5-часового окна, т.к. повторный системный контекст читается дёшево. Чем стабильнее и меньше префикс, тем дольше живёт окно. NB: экономия только на input — output-токены полной ценой.
**Риски.** 1-часовой TTL релевантен API, не подписке — не тратьте усилия на keep-alive пинги в Claude Code. Любое редактирование CLAUDE.md/скиллов инвалидирует префикс на следующем старте (это нормально — разовый холодный оборот).

### 6. Экономика субагентов: fan-out только на дешёвых и только при реальной изоляции — СРЕДНИЙ ЭФФЕКТ, ОСТОРОЖНО
**Суть.** Субагент выгоден, когда много «шумной» внутренней работы сворачивается в короткое резюме И задачи действительно независимы. Fan-out запускать на Haiku/Sonnet (CLAUDE_CODE_SUBAGENT_MODEL), не на Opus. Для мелких/последовательных операций субагент дороже прямого действия.
**Источник.** kdnuggets.com («not automatically cheaper»); hackernoon.com (возврат verbatim; 10K→500 = выигрыш); dev.to/stevengonsalvez («five subagents = five full context loads»); claudefa.st (persistent worker вместо новых спавнов).
**Оценка эффекта.** Пока CLAUDE.md раздут, КАЖДЫЙ субагент перезагружает его целиком — сначала выполните меру №1, иначе fan-out умножит налог. После сжатия — субагенты для независимых веток DAG (напр. параллельная проверка нескольких скиллов) окупаются.
**Риски.** Дублирование контекста; многословные резюме; для зависимых шагов DAG субагенты должны идти последовательно (параллелизм только для несвязанных задач). Интерактивные субагенты списываются из общего Pro-пула — как и Agent SDK/`claude -p` (поправка 2026-10-20, `api-migration/analysis-2026-10-20.md` §2).

### 7. Русскоязычная специфика: машинно-ориентированные доки — на английском — СРЕДНИЙ ЭФФЕКТ, ТОЧЕЧНО
**Суть.** Кириллица стоит в ~2.5–3.2× больше токенов (arXiv 2605.24718; olivomarco.github.io). Для постоянно загружаемого, машинно-ориентированного контекста (CLAUDE.md-инструкции, frontmatter/description скиллов, служебные reference) рассмотрите английский — это прямое сокращение веса префикса. Пользовательский контент/доменные тексты, где важен русский, оставить как есть.
**Источник.** arXiv 2605.24718 (славянские 2.2–2.5× vs английский 1.2 токена/слово); ikriv.com (транслитерация ≈ вдвое меньше токенов); ai-tldr.dev, promptcost.org (2–3× бюджет для не-английского); Vikhr arxiv 2405.13929.
**Оценка эффекта.** Перевод только description+инструкций скиллов и корня CLAUDE.md на английский может срезать заметную долю их токенов при неизменном смысле; в сумме с мерой №1 усиливает эффект.
**Риски.** Смешение языков может слегка ухудшать следование инструкциям; описания скиллов (`description`) должны точно матчить запрос — если ваши запросы к Claude на русском, английский description может хуже срабатывать. Тестировать discovery после перевода.

## Что НЕ работает (не окупается для вашего профиля)

1. **Внешние repo-map / кодовые индексы для среднего репозитория.** Для ~21 скилла с уже готовой картой архитектуры и скиллами-навигаторами внешний индекс дублирует то, что уже делает progressive disclosure, и добавляет постоянный вес. Точечное чтение конкретных файлов дешевле «look around the repo» (kdnuggets.com; dev.to/stevengonsalvez). Бюджет усилий лучше вложить в меры №1 и №3.
2. **Консолидация скиллов ради экономии на описаниях.** На старте грузятся только name+description (~60 токенов/скилл) — 21 скилл ≈ ~1–1.3K токенов метаданных, это шум на фоне 190 КБ CLAUDE.md. Слияние скиллов ломает model-routing и progressive disclosure, раздувает тела и снижает точность discovery (platform.claude.com/docs: «Claude uses description to choose the right Skill from potentially 100+»). Экономия мнимая.
3. **Keep-alive пинги для 1-часового кэша на подписке.** 1-часовой TTL — фича API/Bedrock; в Claude Code на подписке дефолт 5 минут, обновляется при активности. Скрипты пинга нерелевантны и лишь жгут пул (code.claude.com/docs; dev.to/whoffagents).
4. **Агрессивная авто-компакция как стратегия.** Ожидание стены и авто-компакт теряют контекст и обходятся дорого («panicked auto-compact mid-thought»); дисциплина `/clear`+артефакты состояния лучше (brainy.ink; claudefa.st). Один пользователь потерял 3 часа работы на lossy авто-компакции (datacamp.com).
5. **Ставка на Opus «по умолчанию».** У Opus отдельный недельный счётчик; на Pro он исчерпается быстрее всего. Дефолт-Opus сжигает квоту на рутине без выигрыша в качестве (systemprompt.io; github issue #44976: 60–70% токенов уходят на задачи, где хватило бы Sonnet/Haiku).

## Recommendations — поэтапный план

**Этап 0 (до перехода на Pro, 1–2 сессии).** Снять baseline: `/context` (разбивка токенов по категориям) и `/usage` (на Pro/Max показывает разбивку по skill/subagent/MCP и флаги поведений >10% расхода — code.claude.com/docs/en/costs). Зафиксировать текущий стартовый налог сессии в токенах.

**Этап 1 — мера №1 (наибольший ROI).** Вынести аннотированный реестр тестов (74% CLAUDE.md) из корня в reference-файл, подгружаемый скиллом-навигатором; то, что нужно только человеку, — в HTML-комментарии. Цель корня: ≤200 строк. **Порог успеха:** стартовый налог сессии (по `/context`) упал в разы; если корень всё ещё >~10–15K токенов — резать дальше.

**Этап 2 — меры №3 и №4.** Раздробить 8 SKILL.md >500 строк на диспетчер+references (чек-листы оставить в теле), добавить тест целостности ссылок в вашу Python-инфраструктуру. Поставить дефолтом Sonnet 5, освоить `/model opusplan` и `/advisor`. **Порог:** тела скиллов при активации грузятся частично; Opus-недельный счётчик в Settings→Usage расходуется заметно медленнее.

**Этап 3 — меры №2 и №5 (привычки).** `/clear` по умолчанию, `/compact` только «по-тёплому», батчинг правок, без смены модели/MCP в середине задачи. **Порог:** число оборотов до исчерпания 5-часового окна выросло.

**Этап 4 — меры №6 и №7 (точечно, после №1).** Включить fan-out субагентов на Sonnet/Haiku только для независимых веток DAG; перевести машинно-ориентированные доки/описания на английский с проверкой discovery. **Порог отката:** если качество discovery/следования упало — вернуть русский для затронутых описаний.

**Триггеры пересмотра.** Если после этапов 1–3 вы регулярно упираетесь в недельный кап «all models» (а не только в 5-часовое окно) — это сигнал, что объём работы превышает Pro в принципе; тогда решение не техническое, а тарифное (вернуться на Max 5x или включить usage credits по API-ставкам, support.claude.com/en/articles/12429409). Отслеживайте, в какой именно кап упираетесь (Settings→Usage показывает тип и время сброса).

## Caveats (в т.ч. устаревшие после изменений 2026)

- **Устарело: «на Pro нет Opus».** Неверно с 2026 — Opus 5 доступен и является сильнейшей моделью Pro (anthropic.com/news/claude-opus-5). Старые гайды (truefoundry и др.), утверждающие «Pro does not support Opus», игнорировать.
- **Устарело: «Pro освобождён от недельных капов».** Неверно — недельный кап across-all-models применяется к Pro (support.claude.com/en/articles/8325606). Также неверна ориентация на «2x по выходным»: пиковые урезания сняты 6 мая 2026.
- **Временная мера:** +50% к недельным лимитам (≈13 мая 2026) продлён до 19 августа 2026 (explainx.ai) — после этой даты недельный «потолок» может ужаться; перепроверьте по факту.
- **Устарело: «45K буфер авто-компакта».** Снижен до ~33K в начале 2026 (claudefa.st).
- **Sonnet-only недельный кап на Pro — не подтверждён.** Официально описан для Max/Claude Code; для Pro Anthropic формулирует только «Opus only vs all other models». Не стройте план вокруг отдельного Sonnet-кэпа на Pro.
- **Числа сообщений/часов (45/5ч, 40–80ч/нед) — оценки сообщества, не официальные.** Anthropic не публикует фиксированные значения; единственный источник истины — Settings→Usage / `/usage` (support.claude.com; laozhang).
- **Оценка «190 КБ ≈ 40–50K токенов» приблизительна** и для кириллицы занижена (реальный токен-вес выше). Проверьте точное значение через `/context` в вашем проекте.
- **Изменение по Agent SDK (15 июня 2026)** касается только программного `claude -p`/SDK; интерактивные субагенты в сессии по-прежнему из общего пула. Не путать при планировании автоматизаций. **Поправка 2026-10-20:** само изменение отложено, на Pro `claude -p`/SDK тоже идут из общего пула (`api-migration/analysis-2026-10-20.md` §2).
- Часть замеров (экономия %, пороги 60%/83.5% и т.п.) — из инженерных блогов и отдельных пользовательских тестов, не из официальной документации; относиться как к ориентирам, а не гарантиям.
