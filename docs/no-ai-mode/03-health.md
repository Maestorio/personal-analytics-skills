## 3. Что можно перенести на сайт без LLM

Общий механизм (два варианта, оба с готовым образцом в репозитории):
- **A. Расширить hub-api** (`server.py`, stdlib, том Health уже на запись): добавить эндпоинт вроде `POST /api/hd/labs-point` с валидацией внутри (повторить `auto_status`, `valid_ref`, `recompute_marker` из `intake.py:172-186, 425-434`). Плюс: нет нового контейнера, действуют `base_hash`, `.versions/`, запись через File Station (DSM) с доставкой в зеркала Drive.
- **B. Вызвать скрипт в hub-notify по образцу `pf_build.py`**: Caddy проксирует `/api/pf/*` в hub-notify с паролем с любого IP, тело JSON/base64, фон + опрос статуса, «Сохранить» отправляет результат через hub-api (`/api/job/save` по `JOB_WHITELIST`, `server.py:421-448`; `pf_build.py:1-40`). Для здоровья нужна новая зона в whitelist и в Caddy (`/api/hd/*` исключён из доверенной LAN-зоны, `Caddyfile.example:120-129`). Чтобы использовать `intake.py` как есть, его надо вынести в библиотечный вид (сейчас у него захардкожены пути Мака `~/Library/CloudStorage/...`, `intake.py:63-64`, и он пишет файлы через `write_atomic` прямо в зеркало).

Проблема, общая для всех пунктов записи в `labs.json`: **появляется второй писатель** (сайт + `intake.py` на Маке). Это ровно класс инцидента 2026-09-02, когда отставшее зеркало Мака затёрло данные на NAS (комментарий в `docker-compose.yml`, блок hub-api; `SKILL.md health-labs`, «Модель хранения»). Лечится так: `labs.json` добавить в `HEALTH_FILES` (чтение с `base_hash`), `intake.py` перед записью перечитывать файл с хешем, бэкапы в `.intake-backups/` уже есть. Если без Claude `intake.py` никто не запускает, то второго писателя де-факто нет.

## 4. Для чего LLM необходим и деградированный режим

| Задача | Почему нужен LLM | Деградированный режим без Claude |
|---|---|---|
| Чтение сканов и фото документов (ЭКГ, УЗИ, осмотр офтальмолога) | OCR + понимание вёрстки + сопоставление названий с маркерами (`references/intake.md:52-61`) | Ручной ввод: форма исследования (есть) + форма точки (a). OCR локально (tesseract) на NAS возможен, но качество на медицинских бланках низкое; без подтверждения человеком не использовать |
| Разбор произвольных PDF с нестандартной вёрсткой, протоколов инструментальных исследований | Извлечение показателей и нормы, разделение «измерение/заключение/параметры проведения» | Положить PDF как файл исследования (d), вписать заключение руками |
| Выбор канонического маркера и категории для нового показателя | Словарь синонимов и правило «не заводить дубль по смыслу» | Выбор из списка в форме; новые id — вручную, с подсказкой поиска по имени |
| Нормы из клинических рекомендаций (`set-ref` + `ref_src`) | Поиск и сверка первоисточника (ASE/EACVI, AHA, ESH/ESC…) | Ввод нормы вручную с текстовой пометкой источника; существующие `ref_src` продолжают показываться |
| Справочник `what/up/down` для новых маркеров (режим B) | Написание корректной физиологической справки | Новых справок не появится; редактор вручную (e); пустая справка страницей допустима |
| Справка по лекарству: действующее вещество, класс, показания, взаимодействия, связь с маркерами (`health-meds`) | Поиск и чтение ГРЛС/DailyMed/SmPC, двойной проход, `confidence` по тирам (`references/sources.md`) | Поля вносятся руками (форма уже есть), `ref_meta` не ставится; проверка взаимодействий между принимаемыми — **недоступна** (сама справка из прошлых прогонов продолжает отображаться) |
| Проверка взаимодействий принимаемых лекарств | Рассуждение над двумя+ инструкциями | Нет замены; максимум — показ записанных `interactions` каждого препарата |
| Отчёты-разборы (`health-report@1`) | Сам текст отчёта пишет Claude в разговоре; скилл только валидирует и кладёт файл | Старые отчёты читаются; новые — владелец пишет или вставляет текст из другого источника (см. п. 4 в разделе 3) |
| Привязка показателей исследования к исследованию (поле `study` в точках) | Определение, что число из протокола — это показатель данного исследования | Форма точки (a) может иметь необязательный выбор исследования |

Деградация без LLM — **постепенная, а не обрыв**: всё уже внесённое продолжает показываться и считаться (динамика, нормы, напоминания, справка). Теряется приток нового: разбор сканов, новые справки, отчёты.

Дополнительный риск: **модель выбирается жёстко.** Оба скилла — Opus-тир, Haiku недопустим (`SKILL.md health-labs:23-26`, `health.md` §1). Заменить Claude на локальную модель для медицинского контента — не рекомендуется без проверки человеком; владельцу в любом случае стоит оставить подтверждение каждой точки.

## 5. Приватность и режим «без ИИ»

Что уже хорошо:
- Данные никогда не лежат в публичной зоне: `/health-data/*` и `/api/hd/*` — только с паролем с любого IP (LAN не доверенный для здоровья). Оболочка страницы публична, данные нет (`Caddyfile.example:176-193`).
- Страница сама не обращается к LLM: ни одного вызова внешнего ИИ-API в `health.html` (fetch только к `../health-data/*`, `../api/hd/*`, `../api/health`).
- Медицинские файлы в GitHub не едут (`build_health_json.py`, комментарий о входе CSV).

Что меняется в режиме «без ИИ» (чек-лист для правки страницы и справки):

| Место | Сейчас | Что сделать |
|---|---|---|
| Подписи полей форм «заполняет скилл» (`health.html:2209-2210`), «Справка не заполнена — действующее вещество…» (`:2023`) | Подсказывают, что справку добавит скилл | В режиме без ИИ: «заполняется вручную / будет заполнено позже»; не терять сами поля |
| Кнопка «? Справка» (`tools/assets/help/health.md`) | Таблица «Хочу… → скажи Claude… (Opus)» | Добавить раздел «Без Claude»: что делается на странице (аптечка, прививки, вес, исследования, и после реализации — ввод анализов), что отложено до возврата Claude. Правило синка: меняется поведение страницы → обновить `health.md` в том же коммите (`CLAUDE.md`, «Справки страниц кабинета»; контракт в `tools/tests/test_pages_contracts.py`) |
| Описание вкладок «Биомаркеры — пишет health-labs» (`health.md` §4) | Источник только скилл | Добавить строку «или вручную на странице» после появления формы (a) |
| Текст ошибок про `Cowork`/`Synology` в `health.md` §5 | «Скилл пишет „нет доступа к Synology“» | Оставить: актуален при возврате Claude |
| `intake-log.json` | Ведётся скриптом | Если файлы вносятся с сайта, лог либо не ведётся, либо страница пишет в него; иначе возврат `/health-labs` покажет как «новые» всё, что внесено руками (`scan` ищет по логу) |

Что должно остаться в любом режиме:
- пароль и закрытый канал данных, `base_hash` с 409, `.versions/` и `.intake-backups/` перед каждой записью;
- единственность «писателя» по файлу или проверка хеша у каждого;
- структурные валидаторы (`validate_health`, plan_check) — это защита от битого файла, а не часть ИИ;
- дисклеймер «справочно, не медицинская рекомендация»;
- явное подтверждение пользователя перед записью чисел анализов (превью «до/после»);
- пометка источника записи (`lab`, `src`, `ref_src`; для ручных — `source: "manual"`), чтобы потом отличать ручной ввод от внесённого Claude и от экспорта.

Когда ничего не сделано: при отключении Claude страница **не ломается**, но хранилище данных перестаёт пополняться только по двум направлениям (`labs.json` и справка). Всё остальное разделом можно вести сегодня.

Деградация постепенная: всё внесённое продолжает показываться; для режима «без ИИ» править подсказки «заполняет скилл» и `tools/assets/help/health.md`, оставив пароль, хеши, превью до записи и дисклеймер.
