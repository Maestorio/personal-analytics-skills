### 1.5 Ручной «черновик поездки» на странице

Сейчас: создавать `trip.yaml` из страницы нельзя. Нет формы, а `trip.yaml` вне whitelist. Но механизм создания в API есть: `save_file` при `base_hash: null` создаёт новый файл, а при существующем отвечает 409 (server.py:937-960). Поездка в UI появляется, как только в `trips/<dir>/` лежит `trip.yaml` (tools/travel.html:1004-1010, `buildMeta` с фолбэком на frontmatter `0_scope.md` и имя директории; STATUS_BADGE `draft` и `progress` уже существуют, travel.html:361-370).

| Вариант | Состав | Размер |
|---|---|---|
| A. Минимум: форма «Новая поездка» (название, даты start/end, город/регион, season, travelers, status `draft`) → `POST /api/save` с `base_hash: null` в `travel-planner/trips/<slug>/trip.yaml` | Форма на travel.html; в server.py новая запись whitelist `^travel-planner/trips/[^/]+/trip\.yaml$` и валидатор (trip-meta@1: обязательные поля, enum статусов, формат дат); slug через транслит | **M** (клиент S + сервер S–M + тест) |
| B. +Редактирование полей существующего `trip.yaml` (статус, даты, заметка) | Тот же whitelist и валидатор; форма-редактор; поддержка `.versions/` уже есть | **M** (+1 день к A) |
| C. +Ручные «заметки поездки» вместо стадий (чеклист, билеты, бронь) в `trip.yaml`/своём `notes.md` | Новая зона записи, новые схемы, чтобы не ломать скилл (скилл читает `trip.yaml` как контракт) | **L** |

Оговорка по риску: `trip.yaml` пишет скилл (контракт `trip-meta@1`, docs/travel-planning). Нужно решить, у кого приоритет при конфликте (скилл читает файл и при ручной правке просто продолжит работу; ручной черновик не должен ломать `determine state по файлам`). Смысл есть: для режима «без ИИ» поездка с датами, местом и статусом видна в хабе («Ближайшая» и счётчик) и работает офлайн; полноценных планов без LLM не будет.
Рекомендация: вариант A (M), только если владельцу реально нужны новые поездки в режиме блокировки.

### 2.2 Ответы

| Вопрос | Ответ |
|---|---|
| (1) Раздел целиком работает без LLM? | **Да.** Скиллов у раздела нет. Вся страница, сервер и валидаторы детерминированы. Единственная ИИ-зависимость — внешний процесс генерации контента. |
| (2) Что от LLM | (а) **Генератор рецептов** — отдельный проект Claude.ai по `docs/food/instruction.md` (кулинарный ассистент, стоп-лист, источники, КБЖУ на порцию, JSON-блок в конце); результат человек кладёт в `Food/recipes/` или вставляет на страницу. (б) **Импорт по ссылке** — на странице нет вообще: импорт принимает только вставленный текст из Claude/Perplexity (tools/food.html:3101-3135, 3289), URL не скачивается. Значит «импорт по ссылке» — это ручной шаг через ИИ-чат. |
| (3) Ручное добавление рецепта | **Форма есть:** кнопка «+ Новый рецепт» (food.html:2035), редактор с названием, кухней, сложностью, типом, ингредиентами, шагами (food.html:2855-2880, `ed-save`). Плюс «↧ Импорт» — вставка md/json-блока и разбор (food.html:2036, 3133). Работает без LLM. Дыра только в удобстве: нет «внести рецепт из фото/сайта», нет автоподсчёта КБЖУ при ручном вводе (КБЖУ считается из каталога; если у продукта нет `nutrition_100g` — заполняется вручную). Закрыть это без LLM можно только формой «вставить URL → разобрать schema.org/Recipe JSON-LD» (многие сайты отдают) — **M** (серверный fetch страницы с whitelist хостов, парс JSON-LD, сопоставление с каталогом, показ на проверку); по произвольным сайтам без LLM нельзя. |

Что отсутствует по смыслу «режима без ИИ»: ничего критичного. Раздел «Еда» — главный кандидат на «остаётся полностью рабочим».

### 3.3 Где жить переключателю и как страницам его читать — снято решением: вариант B, `START.md` §2.1

| Вариант | Плюсы | Минусы | Размер |
|---|---|---|---|
| **A. localStorage `hub-noai` ("1"/отсутствует)** по образцу `hub-theme`: `uiSetNoAi(on)` в ui-kit.js (как `uiSetTheme`, со `ui-noai` событием), кнопка рядом с `uiThemeBtnHTML` в `uiTopHTML`, ранний inline-скрипт в `<head>` ставит `data-noai="1"` на `<html>` до отрисовки. | **B. Файл на сервере** (`Claude-Memory/_hub/settings.json` + запись в whitelist API, чтение страницей через ui-kit при загрузке, кэш в localStorage) | Общий для всех устройств; Claude-скиллы тоже могут его прочитать (стопнуть «режим без ИИ») | Нужен whitelist и валидатор в server.py, контракт и тесты, при отсутствии связи — фолбэк на кэш | **M** |
| **C. Комбо:** A как быстрый слой + B как источник истины (читается при старте, пишется при переключении) | Мгновенно и синхронно между устройствами | Максимальная сложность | **M** |
