# План «Меньше ИИ» — единственный источник порядка работ

**Ветка интеграции: `claude/less-ai`** (от `main` после PR #37). Ветки этапов отходят от неё и вливаются в неё
последовательно, следующая начинается после слияния предыдущей; в `main` — по завершении всего. Документы и
ссылки — по `main`. Задачи с файлами, тестами и приёмкой — `START.md`; обоснования — `README.md` и приложения;
ревизия 09.11 — `REVIEW-2026-11-09.md`. Порядок работ записан **только здесь**; другие файлы ссылаются сюда.

Принцип разделения:

- **Навсегда** — детерминированное изменение, полезное при любом режиме: сайт или скрипт делает то, что раньше
  делала модель, или модель больше не нужна как «курьер» (скопировать фразу → запустить скилл → сохранить).
- **Только режим «без ИИ»** — изменение *поведения*, которое при наличии ИИ было бы хуже: снятие гейта по качеству,
  серые плашки, отказ писателей-«курьеров», ручной ввод там, где модель читает документы лучше.

Принцип хранения (решение владельца 09.11, применять во всех похожих случаях): **один файл — один писатель**;
данные владельца и данные модели лежат в разных файлах, страница и скилл сливают их при чтении. Слияний «сайт
подгружает чужой файл в основной» и переносов «скилл переносит правки сайта» не делаем.

Терминал Mac — запасной путь, не плановый: владелец запускает скрипты руками только когда иначе нельзя (сегодня это
один случай — `PLAN.json` от локальной модели → `intake.py`, по итогам спайка). Всё остальное владельческое идёт с сайта.

Правило гейта писателей (решение ревизии B1): при `ai_mode: off` отказывают писатели, **чей вход — вывод модели**
(`promote_draft.py`, `stamp-report`, `decision_write.py from-report`, `update_index.py`, `build_snapshot.py` из скилла,
`validate_*.py merge` по данным модели, прямой `Write` скиллов). Писатели с **владельческим входом**
(`decision_write.py owner`, `apply_condition.py add/withdraw` с `source: owner`, `intake.py apply` подтверждённого плана,
`zenmoney_csv_backfill.py` + `audit_history.py`, `security_attrs.py set`, `known_splits.py` CLI) работают в обоих режимах
с проверкой свежести зеркала и `author: owner`. Сайт (hub-api, hub-notify) пишет всегда.

**Механика переключения.** Данные и схемы одни в обоих режимах, миграций нет. `on → off`: страницы, hub-notify и
писатели перечитывают флаг; больше ничего. `off → on`: сайт ничего не пересчитывает — показывает список правок за
период (`/api/hub/changes` по `off_since`) и ставит `returned_at`; сверка — первым прогоном скиллов: решения
владельца читаются как обычные, ручные точки `labs.json` помечены `source: manual`, оверлей игр — постоянный слой,
CSV-месяцы сверяются при следующем «закрой месяц». Обязательная проверка — свежесть зеркала Mac (`noai_return.py`),
пока оно отстаёт, скиллы не запускать (`return-to-ai.md`).
