**Актуальность (ревизия 2026-11-09):** §3.6 (клиентский флаг `localStorage`) снят — носитель общий, `START.md` §2.1.

Обложки и метаданные — снято 09.11, обсудить на этапе игр. Номера строк не использовать (`REVIEW` §5); whitelist `Gaming/recommendations` — `REVIEW` S7.

## 0. Главные находки (читать первыми)

1. **Страница «Игры» сегодня пишет ровно одну вещь — просит сервер обновить цены.** Единственный POST в
   `tools/games.html` — `/api/games/eshop-refresh` (`tools/games.html:875`). Редактирования статусов, оценок и заметок нет.
2. **Заявленная в доках кнопка «итог» на странице отсутствует.** Справка (`tools/assets/help/games.md:62`),
   SKILL.md (`skills/game-advisor/SKILL.md:322`), `_shared-references/claude-memory-layout.md:73` и Caddyfile
   (`tools/hosting/Caddyfile.example:30`) говорят, что «итог» правится с веба. В `games.html` нет ни `/api/save`,
   ни `authFetch` кроме цен; `git log -S"api/save" -- tools/games.html` пуст. От фичи остались whitelist
   `Gaming/recommendations/*.md` (`tools/hosting/api/server.py:374`) и тест `test_write_api.py:435-468`. Это либо
   удалённая, либо недоделанная возможность; доки врут. Для владельца полезно: **веб-запись в `Gaming/` уже
   технически разрешена только для подборок, остальное закрыто.**
3. **hub-api — stdlib only, без PyYAML** (`server.py:3`, `cond_save` — «PyYAML здесь нет», `server.py:1950`). Все
   пользовательские данные игр — YAML (taste-profile, watchlist, library_full). Прямая правка YAML из hub-api
   возможна только построчно (как `eshop_lookup.fill`) либо через новый JSON-файл. PyYAML есть только в
   hub-notify (`docker-compose.yml:65`), а он смонтирован на `/srv` read-only.
4. **Расхождение в SKILL.md:** режим КАЛИБРОВКА говорит про веса `genre_weights` (`SKILL.md:189`), но в профиле такого
   ключа нет: веса живут в `mood_clusters.<slug>.weight`. Текст скилла устарел, на дизайн не влияет.

### 3.3. Что нужно по функциям (в варианте A)

Общее: новая зона `/api/gm/*` (`file`, `save`) в `server.py` по образцу `/api/fd/*` (`_zone`, `server.py:3330-3340`),
whitelist `^user-state\.json$` в корне `Gaming/` (отдельный корень не нужен: ROOT уже включает `Gaming/`, но whitelist

## 4. Для чего LLM необходим

| Функция | Почему нужен LLM | Что теряется без него | Критичность для ежедневного использования |
|---|---|---|---|
| Рекомендация под настроение (`SKILL.md:38-76`) | сопоставление запроса с кластерами и латентными осями, поиск новинок по вебу, мостики «понравится, если зашла X», 70/30 разведка, diversity-чек, техно-гейт, отзывы и русская локализация | подбор новых игр; остаётся ручной вишлист и текущий список | высокая (суть скилла), но это эпизодическое использование |
| Калибровка (веса кластеров, `anti_patterns`, `latent_axes`) | интерпретация впечатлений, малый шаг веса, формулировка caveat; ручная правка весов запрещена конвенцией SSOT | веса «замораживаются»; вердикты копятся в оверлее и ждут пакетной калибровки (в репо есть прецедент пакета 41 вердикта) | средняя: профиль меняется медленно; несколько недель без калибровки терпимо |
| Обновление профиля из Exophase/Steam (`SKILL.md:204-215`) | парсит webarchive, сливает, пересчитывает агрегаты кластеров | новые часы и новые игры в `library_full` не появятся; руками вводятся только добавленные игры | низкая–средняя |
| Московские магазины, цены физики (`SKILL.md:217-254`, лестница источников) | WebSearch/Chrome MCP/fetch по каталогам, сверка форматов (картридж/Game-Key), провенанс-гейты | цены Москвы и физические копии; остаются автоцены US eShop | средняя (владельцу важна физика, но покупки не ежедневные) |
| Магазины в поездке (`SKILL.md:256-270`) | поиск и перепроверка свежести точек | нужная точка из `stores-travel.md` остаётся, новые не находятся | низкая |
| Скидочный прогон «что есть интересного» | начинает с watchlist и цен — частично детерминирован | сайт уже показывает «Со скидкой» и шлёт push; теряется только поиск новинок «Новое» | низкая |
| Ретроспектива скилла, подборки, отзывы/HLTB/OpenCritic | аналитика и веб | аналитика и свежие отзывы | низкая |

Оценка: **для повседневного «управлять списком, видеть скидки, отметить прошёл/не зашло» LLM не нужен** — это CRUD по
человеческим полям и уже работающие автоцены. LLM нужен для открытия новых игр, пересчёта вкуса и физических цен в Москве.
При блокировке LLM теряется «нюх» подбора и самообновление профиля, но не рабочий вишлист и не мониторинг скидок.

## 6. Резюме

1. Игры без LLM уже читают все 5 экранов, а сайт сам грузит цены US eShop (08:30 МСК, с NAS из РФ API Nintendo отвечает) и шлёт push о скидках и порогах.
2. Управлять данными страница не умеет: единственный POST — «Обновить цены»; кнопки «итог», заявленной в доках, в `games.html` нет (остались только whitelist подборок и тест).
3. hub-api — stdlib без PyYAML, а все данные игр в YAML; прямое редактирование YAML сайтом хрупко и конфликтует с принципом «единственный писатель — скилл».
4. Рекомендуемый путь: человеческий слой `Gaming/user-state.json` (по образцу зоны «Еда»), страница показывает слияние YAML и оверлея, скилл при следующем запуске подхватывает записи в `watchlist`/`library`.
5. Статусы хочу / на карандаш / не интересно, оценка (5 значений), заметка, пороги цены — дёшево (S–M); «куплена/играю/пройдена» — решение по схеме (в library сегодня нет такого состояния), M.
6. Пороги и nsuid из оверлея надо научить читать `eshop.targets`, иначе цены и push не заметят правок; nsuid по ссылке/slug — перенос `eshop_lookup.py` в контейнер notify, но доступность nintendo.com из РФ не проверена.
7. Обложек и метаданных (HLTB, OpenCritic, русский язык) без LLM в репо нет и открытых API в нём не упомянуто; это вопрос владельцу.
8. LLM необходим для рекомендаций, калибровки весов кластеров, загрузки Exophase/Steam и московских магазинов; для повседневного вишлиста и скидок — не нужен.
9. Придётся обновить: `test_pages_contracts.py` (read-only контракт, enum), `test_write_api.py` (новая зона, сохранить запрет `taste-profile`), `test_site_jobs.py`, `docs/test-registry.md`, справки `games.md`/`hub.md`, SKILL.md, D3-формулировки.
10. Общая оценка режима «без ИИ» для игр: этапы 1–4 примерно M суммарно, переключатель в хабе — не обязателен (достаточно клиентского флага S).
