# Эррата к портфельной части «Кабинет без ИИ» — по состоянию ветки `claude/data-structures`

**Дата:** 2026-11-07. **База сравнения:** отчёт `docs/no-ai-mode/` (README §1, §3 «Портфель», §4, §5, §6, §7; хвосты `02a`/`02b`) написан по `main` на 30.10 (`d8f2721`).
**Объект:** ветка `claude/data-structures`, HEAD `0c90e84` (06.11), 297 коммитов поверх main, 546 файлов. Worktree: `scratchpad/ds`.
**Пути** — от корня worktree, формат `путь:строка`. Читал только код, документы и тесты (не запускал); данных `Claude-Memory/` в репозитории нет.

**Что не проверено.**
(1) Состояние живых данных (сколько решений, какие `review_by`, заполнен ли `security-attrs.json`) — только по планам миграции.
(2) Выложено ли на NAS всё до вьюера 4.4.6: по `docs/investment/TODO.md:192` живой прогон стресса 06.11 шёл на выложенном 4.4.3; 4.4.4–4.4.6 — не знаю.
(3) Переключение на новую БД выполнено 31.10 (`cbbc857` «вьюер 4.1.0 — переключение шага 17»; `decision.md:144-216`), фактическое состояние папки на mount не видел.
(4) Тесты не гонял.

**Общий итог в одной фразе.** Ветка закрыла **пять из моих тринадцати B-пунктов портфеля** (старение гейтов, резолюция условий, пересчёт стресса, веса сценариев, подтверждение сплита) и **сняла главный риск «fail-open после истечения срока»**. Зато появились два новых слабых места, которых я не видел: «fail-closed без выхода» и «бумага без решения не блокируется» (§3). Модель данных стала строже; режим «без ИИ» получил хорошую опору — слова вместо кодов, один компонент «команда для Claude» (`ui-kit.js:2523`), общие модули (а)/(б) — но самого переключателя на ветке нет (`grep` по `hub-noai|AI_MODE` пуст).

## 3. Гейты и старение

### Как устроено
1. Модель пишет решение (поля `verdict`, `target_pct`, `review_by`, `note`); скрипт ставит `recorded_at` и пишет файл (`decision_write.py:1-40`). Срок гейта не хранится: `review_by` null → `recorded_at` + `defaults.review_days` = 60.
2. Модуль (б) на каждое чтение считает статус по правилам (`last_word.py:44-53`): `divested` → `new_position` (первая покупка без решения) → `review_needed` (обзор новее решения с флагом) → *нет решения → статус пуст* → **`review_aging`, если `expires_on < today`** → иначе `verdict_to_gate`.
3. Блокируют докупку статусы `new_position`, `review_needed`, `reviewed_under_review`, `review_aging` (`codelists.json` `gate_to_block`; то же множество, что на main — `rebalance-engine.js:26` там).
4. **Кто вычисляет.** Клиент: `today = dsToday()` — дата МСК по часам устройства (`viewer.js:9456`), передаётся в движок (`viewer.js:9863, :12294`) и в модуль (б) (`:9601-9632`). Python: `last_word.py`; в `gate_aware_sizing.py` дата по умолчанию — `as_of_date` снапшота, не календарная (`:444`); есть `--today`. hub-notify модуль (б) не гоняет (только `held_keys`, `notifier.py:671`).
5. Подпись на экране — слова, не коды: «срок решения вышел дд.мм, откроет разбор» (`viewer.js:7237`), в календаре «истекает срок решения» (`:4800`).

### Работает ли без LLM
**Да, старение происходит само**: ни скилл, ни сервер не нужны, хватает открытой страницы (и офлайн-копии) с датой на устройстве.

### Что блокирует «Сейчас» и чем снимается без ИИ

### Остаётся ли «главный риск»: fail-open после истечения срока
**Нет.** Fail-open исчез: просроченное решение закрывает докупку, статус виден, паритет JS↔Python закреплён тестами. Мои утверждения «клиент и движок срок не применяют» и «статус ставит только скрипт через save-to-library» на ветке неверны.

## 5. `save-to-library`, `promote_draft` и переключатель «без ИИ»

### 5.1 Новый поток приёмки
1. Генератор (7 скиллов) пишет **полный артефакт в `Claude-Memory/_drafts/`**, в чат печатает выжимку (`claude-memory-layout.md:166`; `TODO.md:317` STL-41).
2. Владелец: «сохрани» → `save-to-library` запускает `promote_draft.py --dry-run`, показывает, по «да» — без `--dry-run` (`skills/save-to-library/references/workflow-bcde.md:9, :325, :509` — шаги B1.0/C1.0/D1.0; `skills/save-to-library/SKILL.md:234, :319`; `TODO.md:318` STL-42).
3. Скрипт: найти файлы черновика → собрать целевые (`.yaml` прогноза/сценариев копированием полей из блока Events YAML и шапки `.md`) → валидаторы `assemble_artifact.py` → атомарная запись → при `--replaces` пометить прежнюю версию `superseded` → `update_index.py` (INDEX, `_sync_log.md`) → удалить черновик (`promote_draft.py:1-30`). Тело артефакта через вывод модели не идёт.
4. За моделью остаются решения-флаги: `--replaces`, `--as`, `--force`, `--domain`, `--actual`/`--outcome-resolve`, текст строк INDEX.
5. **Виды, которые приёмка покрывает:** `forecast`, `scenario`, `stress`, `integrated-view`, `monitor-report`, `retro-audit` (`promote_draft.py:51`). **Не покрывает:** обзоры недели, ad-hoc отчёты, решения, условия, справочник бумаг, снапшоты — там модель по-прежнему делает `Write` (с последующим `stamp-report`/`validate-*`) или вызывает скрипты-писатели.

### 5.3 Что это значит для режима «без ИИ»
1. Все эти скрипты **без LLM**, но их входы приходят от LLM. В режиме без ИИ они — «ручной режим в терминале с `--by owner`»: S-добавка к отчёту (список команд для владельца), а не новая функция сайта. Это дешёвый способ закрыть §3 п.1 до формы на сайте.
2. `promote_draft` не пишет ничего, что владелец правит на сайте (план, состояние условий, веса, сплиты). Единственная связка — вид `scenario`: веса сайта привязаны к **имени файла матрицы** (`stress_job.py:266`), а `horizons_changed` сверяет только даты сроков (`:469`), не содержимое матрицы. Замена матрицы тем же именем (`--force`) молча переосмыслит ползунки владельца (оси, полярность). Это единственный повод для проверки в `promote_draft`.
