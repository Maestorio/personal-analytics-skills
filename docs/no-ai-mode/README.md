## 1. Ответ коротко

1. **Сайт уже не зависит от Claude на чтение и на большую часть записи.** Все страницы — статика с
   NAS; `hub-api` и `hub-notify` работают без модели. При исчезновении LLM ничего не ломается:
   показываются последние данные с возрастом.
2. **Три раздела работают без ИИ почти целиком:** Еда (скиллов нет), Деньги на чтение, Здоровье кроме
   внесения анализов и справок. **Портфель** [ds] — существенно больше половины: снапшот, план, доли,
   «Сейчас», живые цены, выплаты, журнал решений, push, **пересчёт стресса, веса сценариев, резолюция
   условий кнопками, старение решений при чтении, подтверждение сплитов** — всё без LLM.
3. **Что принципиально требует LLM:** вердикты и разборы бумаг, построение сценариев и прогнозов
   (не пересчёт), интегрированный синтез, чтение сканов и поиск инструкций в здоровье, рекомендации и
   калибровка вкуса в играх, аудит учёта с суждениями в деньгах, стадии 0–5 путешествий, генератор
   рецептов. Замена — только ручной ввод или заморозка.
4. **Переносимо дёшево (S–M) и даёт основной эффект:** ввод анализов и загрузка документов в
   здоровье; управление вишлистом и статусами в играх; кнопка «Подтверждаю держать» и формы
   определений условий в портфеле; загрузка CSV ZenMoney на сайт; общесайтовый переключатель с
   гейтом для скриптов-писателей.
5. **Главный риск без ИИ в портфеле** [ds]: на ветке он **перевернулся**. На `main` просроченные
   оценки молча *разрешали* докупку (fail-open); на ветке просроченное решение (`review_by`, по умолчанию
   60 дней) *закрывает* докупку при чтении — и без Claude снять блок нечем (fail-closed без выхода), а
   бумага без решения вовсе не блокируется. Это и есть вопрос владельца про «старение в ручном режиме»
   — см. §2 п.3 и §4.
6. **Всё это надо делать, пока Claude есть.** Без него код не развивается; режим «без ИИ» строится
   заранее.

Мнение по предложению владельца (двойная логика «качество + план»): она ложится на существующую модель без
новых сущностей — решение владельца и план уже есть как файлы с единственными писателями; меняется только
то, что истёкший срок перестаёт блокировать. При возврате ИИ советник читает решения владельца наравне со
своими, так что «ручной период» не теряется и не требует миграции.

Что означает «токен» в вопросе 4: у ZenMoney есть официальный API (`api.zenmoney.ru/v8/diff`, OAuth или
персональный токен через сторонний `zerro.app/token`); с ним hub-notify мог бы сам забирать операции по
расписанию. Решение — не использовать; остаётся запасным вариантом (`07` §5).

**C** — LLM необходим (суждение, веб-поиск, чтение документов, MCP). Для C указан деградированный режим.
Отдельно — «в терминале на Mac без ИИ» (скрипты руками): без LLM, но не с телефона (`01` §2).

## 5. Режим «без ИИ» — что он означает на практике

Переключатель — **общесайтовый флаг**, а не другая система: данные и серверные задачи одинаковы в обоих
режимах. Он делает четыре вещи:

1. **Запрещает скриптам и скиллам писать в `Claude-Memory/`** (кроме hub-api и hub-notify — это сам сайт):
   писатели читают флаг через зеркало и отказываются; при включении обратно первым шагом идёт сверка
   правок сайта (оверлей игр, ручные точки анализов, owner-решения).
2. **Убирает обращения к Claude на страницах:** компонент команд для Claude, CTA гейтов, блок «Обновить
   прогнозы и отчёты», разделы справок про фразы и модели.
3. **Меняет семантику свежести и блокировок:** красные плашки и push «просрочено» только для обновляемого
   без ИИ (снапшот, автосрез, план); LLM-файлы — серая пометка «данные от DD.MM»; в портфеле истёкший
   срок решения показывается, но не блокирует докупку (решение 3).
4. **Показывает ручные формы** там, где запись раньше делал LLM: анализы и документы, список и статусы игр,
   «Подтверждаю держать» и определения условий, CSV ZenMoney.
