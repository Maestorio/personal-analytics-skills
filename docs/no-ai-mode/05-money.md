# Раздел «Деньги» (ZenMoney): что работает без LLM, что можно вынести, что требует Claude

**Актуальность (ревизия 2026-11-09):** гейт `zenmoney_csv_backfill.py` — допуск max(1 ₽; 0,05 %); расхождение после правок операций не останавливает, удаления гейт не ловит.
`audit_month.py` уже принимает операции из `backfill.build()` (адаптация к CSV — S–M); B6 и A2 деградируют без `source`, B8 нужны настоящие id.
Прямой API ZenMoney — запасной вариант, не планируется (решение 4): формулировки §3(b), строки «затем проверить API» и «cron-обновление» не действуют.
Политика записи на сайт и проверки до записи — `../zenmoney/csv-checks-research.md`; `money.html` — версия по файлу (сейчас v1.24.3), номера строк заменены якорями; порядок — `PLAN-less-ai.md` §1.4/§3.

Метки: **[репо]** — написано в репозитории (со ссылкой); **[гипотеза]** — моё предположение, надо проверить.

## 0. Главное

- Страница `tools/money.html` — статика: читает 4 JSON с NAS, ничего не пишет, LLM не вызывает. Работает без Claude как есть.
- Расчёт итогов — детерминированный Python (stdlib). LLM в нём — только транспорт и диалог (вызвать MCP, передать JSON скрипту, задать вопрос пользователю).
- Единственная привязка к Claude — ИСТОЧНИК данных: MCP ZenMoney доступен только внутри Claude. В репо **есть рабочий путь без MCP для истории — CSV-выгрузка из приложения** (`tools/zenmoney_csv_backfill.py`), но он ручной и с остаточной зависимостью от MCP (см. §2).
- Прямой API ZenMoney — запасной вариант, не планируется (решение 4); в репо он не реализован (`07-autonomy-local-api.md` §5).


### 2.2 Скрипты на CSV (история без MCP-чтения операций)

| Что | Скрипт | Вход | Выход | Ссылка |
|---|---|---|---|---|
| Пересчёт итогов месяцев + поездок | `tools/zenmoney_csv_backfill.py` | CSV из приложения; `docs/zenmoney/csv/` (курсы, `accounts.json`, `category-flags.json`, `payee-map.json`) | `run-*.json`, `trip-*.json` → затем штатный `audit_history.py spending/trip --write`, `facts` пересчитывается сам | `zenmoney_csv_backfill.py:1-35`; `csv-recompute.md:42-70` |
| Что изменилось между двумя выгрузками (в т.ч. «потеряли тег поездки») | `tools/zenmoney_csv_diff.py` | 2 CSV | отчёт, ничего не пишет | `zenmoney_csv_diff.py:1-20` |
| Словарь «текст банка → место» | `tools/zenmoney_payee_map.py` (`changed/grab/build`) | CSV + **страницы MCP** | `payee-map.json` | `zenmoney_payee_map.py:1-45` |

Особенности (важно для оценки «без LLM»):
- Считает **тем же кодом** `month_stats.compute` и `trip_stats` (`backfill.py:52-54`), поэтому правила идентичны; есть **гейт сверки до рубля** по месяцам, уже записанным через MCP (`backfill.py:23-26`). Это доказано на 81 месяце и 23 поездках (README «Состояние»).
- Курсы валют — ЦБ РФ `XML_daily` напрямую (`backfill.py:167-172`, кеш `rates-cbr.json`); совпадают с курсами ZenMoney (сверка 2026-10-06, `backfill.py:13-15`). Криптовалюты вне ЦБ → `unconverted`.
- **Что CSV НЕ покрывает:** ID операций (разовые ищутся по дата+счёт+сумма, `backfill.py:9-11`); признаки категорий, список счетов «в балансе» — берутся из ранее снятых файлов `category-flags.json`/`accounts.json` (сняты через MCP один раз; при новых счетах/категориях их надо обновлять — [гипотеза: обновление из CSV не автоматизировано, проверить]).
- **Остаточная зависимость от MCP:** колонка «Кому» в CSV — сырой текст банка, а название места знает только MCP (`merchantId → references.merchants`). Без `payee-map.json` в историю попадают тексты банка вместо мест (в 2025-26 так было у 1429 из 2386 трат с местом, `zenmoney_payee_map.py:4-10`). Дозагрузка: 25 окон / 34 вызова MCP против 44 у полной (`csv-recompute.md:55-60`). Т.е. «места» без Claude деградируют (см. §4).
- Рецепт помечен «в Claude Code, не скиллом» (`csv-recompute.md:1-5`); ручные шаги: выгрузка CSV из приложения, копия в `docs/zenmoney/`, проверка diff, гейт, запись. Нет автоматики и нет серверного запуска.
- Аудит учёта (`audit_month.py`: A1–A5, B6/B7, C-проверки, места) из CSV **не строится**: в `history.json` аудиты только за 6 месяцев — «это норма для истории из CSV» (README, таблица данных). Аудит требует `list_transactions` с полями `source`, `hold`, счета и т.д. и категории из MCP [частично гипотеза: конкретно, каких полей CSV не хватает, не проверял].

## 4. Для чего LLM необходим и деградированный режим

| Задача | Почему LLM/человек | Что без LLM |
|---|---|---|
| Аудит учёта с суждениями (что считать проблемой: перевод между своими счетами, дубли категорий, поездка основной категорией) | Модель интерпретирует найденное по `audit.md`, задаёт вопросы | Скрипт `audit_month.py` всё равно даёт числа и классы A1–A5/B/C; без модели — только список без пояснений и без «это норма» диалога (`accept` — тоже через диалог, но может быть CLI) |
| Категоризация незнакомых мест, названия «официальные», `search_merchants` | Режим E/F п.12: «контрагента не придумывать — спрашивать» | Словарь `stmt-places.json` покрывает известное; новое — пользователь руками (таблица) |
| «Что заметно в тратах» | `facts.json` — детерминированные факты (пороги в `history_query.PARAMS`); словесный комментарий — LLM | Факты на «Обзоре» остаются; пропадают только пересказ и объяснения |
| Вопросы по истории («сравни 2023 и 2025 по еде», «600 тыс. — сколько месяцев») | `history_query.py` считает, модель понимает формулировку | Страница уже даёт «Все годы», «к прошлому году», окна категорий — часть вопросов закрыта UI; свободный текст — нет |
| Закрытие месяца целиком (диалог: корректировки, разовые крупные, даты поездки) | Диалог + MCP | (a) может дать `spending.json`/`trips.json` автоматически; ответы «разовая/норма» — форма на странице → `spending-rules.json` [гипотеза, не реализовано]; аудит `history.json` без Claude устаревает |
| Запись в ZenMoney (категории, операции, импорт выписки) | Протокол Режима C, MCP, согласие по пунктам | Нет: писать пользователь вручную в приложении |
| Правка карты `zenmoney-map.md` | `map_edit.py` детерминирован, но решения предлагает модель | Править руками через CLI `map_edit.py` (hash → dry-run → `--write`) |
| Места платежа | словарь строится по страницам MCP | Деградация: места = сырой текст банка из CSV (качество «Где платил», не итоги) |

Деградированный режим «без Claude» = (a) для `spending.json`+`trips.json`+`facts.json` + ручной CLI; аудит учёта и места — застывают на последней записи.

## 6. Резюме (10 строк)

1. `money.html` — чистая статика: читает 4 JSON (`history/spending/trips/facts`) с NAS под паролем, ничего не пишет, LLM не вызывает; без свежих данных показывает последнюю запись.
2. Все числа считают stdlib-скрипты; LLM — только транспорт к MCP и диалог (корректировки, «разовая», «это норма»).
3. Привязка к Claude одна: источник данных — MCP ZenMoney (только внутри Claude).
4. Путь без Claude **есть в репо**: CSV-выгрузка из приложения → `zenmoney_csv_backfill.py` (тот же `month_stats`, курсы ЦБ напрямую, гейт — допуск max(1 ₽; 0,05 %); 81 мес. и 23 поездки пересчитаны) — но вручную и только по ноутбуку.
5. Остаточная зависимость CSV от MCP: названия мест (`payee-map` строится из страниц MCP) и вспомогательные `accounts/category-flags`; без них деградируют «места», не итоги.
6. Прямой API ZenMoney в репо не реализован и не планируется (решение 4); запасной вариант описан в `07-autonomy-local-api.md` §5.
7. Инфраструктура готова: hub-notify уже гоняет без-Claude задачи по cron (eshop, macro, pf_build) с записью через hub-api; Деньги туда пока не подключены.
8. Предложение: S — загрузка CSV на страницу (по образцу `pf_build.py`); S — «сверка выписки» без ZenMoney; порядок и задачи — `PLAN-less-ai.md` §1.4, `START.md` 3.6–3.8.
9. Без Claude не обновляются: аудит учёта (`history.json`), места платежа, запись в ZenMoney, импорт выписок в ZenMoney, словесные «что заметно» и ответы на свободные вопросы.
10. «Режим без ИИ» на странице — замена ~9 подсказок «скажи Claude…» (`money.html`: плашка месяца, пустые состояния, «аудита за … нет», «проверь места платежа») и раздела «Хочу… → говорю Claude» в `money.md`; размер S.
