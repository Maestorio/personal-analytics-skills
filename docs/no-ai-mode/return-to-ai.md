# Возврат к ИИ после режима «без ИИ» — чек-лист

Цель: включить скиллы обратно так, чтобы они **не затёрли** правки, сделанные на сайте, и **увидели** их.
Минимальная работа — пять шагов, около 5 минут; всё тяжёлое делает скрипт `tools/noai_return.py`
(задача 1.4 в `START.md`) и первый прогон каждого скилла.

## Что меняется на сайте в режиме «без ИИ» (и что скиллы должны сверить)

| Что | Где лежит | Кто сверяет при возврате |
|---|---|---|
| Решения владельца по бумагам | `Portfolio/decisions/*.json` (`author: owner`) | советник читает их как обычные решения (`decision_write.py digest`, `last_word`) — ничего дополнительно |
| Условия-напоминания и их состояние | `Portfolio/conditions.yaml` (`source.kind: owner`), `Portfolio/conditions-state.json` | `apply_condition.py` — не трогать отложенные владельцем (задача 1.2); обзор недели видит их через модуль (а) |
| План, веса сценариев, сплиты | `Portfolio/plan.json` + `plan-journal.jsonl`, `scenarios/stress-weights-*.json`, `Portfolio/known-splits.json` | читаются скриптами как SSOT — ничего дополнительно |
| Снапшоты и пересчёты стресса сайта | `Portfolio/snapshots/`, `Portfolio/stress/auto/` | скилл стресса берёт суждения из последнего `stress-*.yaml`, числа — из пересчёта; при желании — новый прогон |
| Оверлей игр | `Gaming/user-state.json` | постоянный слой человеческих полей в обоих режимах; `game-advisor` его читает, переноса в YAML и `deleted: true` нет |
| Ручные точки анализов, файлы исследований, отчёты | `Health/labs.json` (`source: manual`), `Health/studies/`, `Health/reports/` | `health-labs`: `intake.py` перечитывает файл с хешем, ручные точки не трогает и не дублирует (внесение документа на ту же дату и показатель, где есть ручная точка, — КОНФЛИКТ в dry-run, решение за человеком); `set-ref` их не затрагивает; `intake-log` не считает их «новыми». Проверка при возврате: `intake.py apply` (dry-run) на плане с датой ручной точки показывает конфликт |
| Итоги ZenMoney из CSV | `ZenMoney/audit/*.json` (`source: csv`) | `zenmoney-analyst`: при следующем «закрой месяц» по MCP — сверка до рубля с CSV-месяцами (гейт уже есть) |

## Чек-лист

1. **На сайте:** хаб → «Режим» → «Вернуться к ИИ». Окно показывает «что менялось без ИИ» (список выше, по
   `off_since` из `_hub/settings.json`). Подтвердить — hub-api пишет `ai_mode: on`, `returned_at`.
   Если NAS недоступен — не включать: скиллы читают флаг из зеркала, а оно без NAS не обновится.
2. **На Mac:** клиент Synology Drive — «Up to date». Пока он синхронизирует, скиллы не запускать:
   зеркало может быть старее NAS, и скилл прочитает протухшие файлы (инцидент 2026-09-02).
3. **Проверка зеркала — автоматическая:** скрипты-писатели скиллов перед записью сами сверяют зеркало с сайтом
   (`hub_settings.mirror_lag`: файлы, изменённые на NAS за последние 6 часов, против копии Mac; нужны `HUB_URL`/`HUB_AUTH`)
   и отказывают кодом 4 «зеркало отстаёт: N файлов», пока Synology Drive не догонит. Ручная проверка при желании:
   `python3 tools/noai_return.py --root ~/Library/CloudStorage/SynologyDrive-home/Claude-Memory`.
4. **Первые прогоны скиллов** — по одному, в порядке: `game-advisor` (читает оверлей как есть), `health-labs`
   («внеси документы» — он увидит ручные точки), `ru-portfolio-advisor` (обзор недели: решения владельца
   уже в `last_word`), `zenmoney-analyst` («закрой месяц»). Каждый сообщает, что перенёс или учёл.
5. **Контроль:** `python3 skills/revise-memory-remote/scripts/validate_library.py` (сторож целостности) и
   взгляд на хаб — плашки свежести должны вернуться к обычному смыслу (LLM-файлы снова «пора обновить»).

## Чего делать не нужно

- Переносить что-либо руками из `.versions/` — версии там только для отката.
- Перезапускать контейнеры NAS: режим не меняет сервер.
- Повторно выгружать CSV ZenMoney или сделки IntelInvest — они уже учтены.

## Если скилл отказывается писать после возврата

Он прочитал старое зеркало с `ai_mode: off`. Дождаться синхронизации Drive (шаг 2–3) и повторить.
Никогда не обходить отказ флагом `--force`, пока шаг 3 не зелёный.
