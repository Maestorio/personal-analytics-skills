# Плейбук: подготовка репозитория к работе с малыми лимитами токенов

> Переносимая методика. Отработана на репозитории claude_skills при переходе
> Max → Pro (2026-08): стартовый налог сессии упал с 90,8 К до 42,5 К токенов
> (−53%), CLAUDE.md — с 60,6 К до 12,1 К, попутно найдено 30 живых дефектов
> документации. Применяй к любому репозиторию, где работает Claude Code.
> Исследование-обоснование (лимиты, кэш, экономика субагентов) —
> `docs/compactisation.md`.

**Главный принцип:** экономят не «короткие ответы», а снижение ПОСТОЯННОГО
контекстного налога — того, что грузится в каждую сессию, в каждого субагента
и при каждом обновлении кэша. Один и тот же килобайт в CLAUDE.md оплачивается
тысячи раз; килобайт в `docs/` — только когда он реально нужен.

**Ограничение качества:** ничего не удалять — только перемещать. Аннотации,
история дефектов, обоснования решений сохраняются дословно в файлах,
загружаемых по требованию. Проверка «ничего не потеряно» — детерминированная
(сверка списков, диффы), не на глаз.

---

## Шаг 0 — замер (10 минут)

В свежей сессии Claude Code выполнить `/context` и `/usage`, записать:

- Memory files (CLAUDE.md проекта + глобальный + авто-память) — главная цель.
- Skills / MCP — обычно копейки, если грузятся on-demand (проверить!).
- % недельного лимита при текущем объёме работы — умножить на кратность
  перехода (Pro ≈ 1/5 от Max 5x): если получается > 100%, одной оптимизацией
  не обойтись — планировать и вынос рутины (шаг 5), и/или тариф.

Без baseline нельзя принять ни один следующий шаг.

## Шаг 1 — диета CLAUDE.md (наибольший ROI, полдня)

CLAUDE.md загружен всегда и не вытесняется. Целевой размер — ≤ 200–300 строк
/ ~10–12 К токенов (кириллица «весит» в ~2,5 раза больше английского).

**Что ОСТАВИТЬ в корне** (критерий: нарушение стоит дороже, чем постоянная
загрузка правила):

- карту архитектуры: схема потоков данных + таблица «модуль → роль» в 1–2 строки;
- жёсткие правила, действующие всегда (кто куда пишет, порядок запуска,
  запреты, конвенции имён) — по одной строке, без истории;
- команды запуска тестов — по одной строке на тест: `команда  # ярлык (N проверок)`;
- указатели на вынесенное: «полная спека — docs/<файл>».

**Что ВЫНЕСТИ в docs/ (дословно, с заголовком-провенансом «вынесено из
CLAUDE.md <дата>»):**

- аннотации тестов (история дефектов, что закрывает каждый тест) →
  `docs/test-registry.md`;
- полные спецификации архитектурных решений → `docs/<тема>.md`,
  в корне — сводка на 5–10 строк с жёстким ядром;
- карты скриптов/модулей «что где лежит» → отдельный док;
- всё, что дублирует существующие доки, → указатель (СНАЧАЛА grep-проверить,
  что док действительно содержит то же самое).

**Приёмка:** `/context` в свежей сессии — memory files упали в разы; полный
список тестовых команд бит-в-бит совпадает со старым (diff по `^python3`
или аналог); git-история хранит старую версию.

**Побочный эффект (наблюдался дважды):** при выносе вскрываются мёртвые
записи — команды на несуществующие файлы, устаревшие вводные. Чинить сразу.

## Шаг 2 — сторожа против отрастания (час)

Проза «держите файл коротким» забывается; тест — нет. Два переносимых сторожа
(stdlib, без зависимостей; образцы — `tools/tests/test_claude_md_diet.py`
и `tools/tests/test_skill_refs_integrity.py` в claude_skills):

**Сторож бюджета корня:**

```python
# 1) len(CLAUDE.md) <= MAX_BYTES (текущий размер + ~20% запаса);
#    сообщение об ошибке говорит, КУДА выносить, а не просто «слишком большой»
# 2) списки-зеркала синхронны в обе стороны
#    (набор команд в CLAUDE.md == набор в docs/test-registry.md)
# 3) каждая упомянутая команда/файл существует на диске
# 4) строки компакт-списков <= N символов и без строк-аннотаций
#    (длинному место в выносном доке)
```

**Сторож целостности ссылок** (если корень/инструкции ссылаются на файлы,
собираемые или копируемые при деплое): каждое упоминание пути существует
ПОСЛЕ сборки, а не в дереве исходников; запрещены пути, которых в собранном
артефакте не бывает. На введении в claude_skills нашёл 27 дефектов, включая
бандлы, реально уходившие без файлов, на которые ссылались.

Оба регистрируются в общем реестре тестов — сторож, который не гоняют,
не сторож.

## Шаг 3 — модели и делегирование (час)

В похудевший CLAUDE.md — короткая секция:

- **Дефолт сессии — Sonnet**; Opus — точечно (у Opus на Pro отдельный
  недельный счётчик — исполнение на Sonnet его не расходует). Для сложных
  правок `/model opusplan`: Opus планирует, Sonnet исполняет.
- **Делегирование:** субагент перезагружает CLAUDE.md целиком (поэтому шаг 1 —
  до шага 3!). Делегировать, когда шумная работа сворачивается в короткое
  резюме: поиск → Explore на haiku; механические правки по образцу и прогон
  тестов → sonnet-субагент с заранее выданными разрешениями; fan-out ≥3 —
  только на дешёвых моделях. Субагент возвращает резюме — его вывод попадает
  в основной контекст дословно.
- Основная модель оставляет себе архитектуру и правки контрактов.

## Шаг 4 — привычки сессий (бесплатно, с первого дня)

- `/clear` при смене задачи (стоит 0); `/compact` — только продолжая ту же
  задачу и «по-тёплому» (≤5 мин с последнего сообщения).
- Пауза >5 мин ≠ потеря памяти: истекает только серверный кэш, следующее
  сообщение — один «холодный» оборот. Keep-alive-пинги тратят больше,
  чем экономят.
- Связанные правки — одним сообщением; не менять модель/MCP посреди задачи
  (инвалидирует кэш).
- Гонять только затронутые тесты — вывод тестов тоже токены.
- Состояние длинных работ — в файле-артефакте (план/TODO), не в истории чата.

## Шаг 5 — рутина в `claude -p` (на Pro лимит не экономит)

Регулярные детерминированные прогоны (мониторинги, сверки) можно гонять headless
`claude -p "…"` по cron, но на Pro такие запуски тратят тот же лимит подписки:
отдельный SDK-кредит, объявленный на 2026-06, отложен (проверено 2026-10-20,
`api-migration/analysis-2026-10-20.md` §2). Рутину без рассуждений выгоднее
уводить в код без LLM (`api-migration/deterministic-plan.md`).

## Что НЕ работает (проверено исследованием и/или замером)

- **Консолидация скиллов/модулей ради экономии описаний** — описания стоят
  ~60–150 токенов каждое; замер в claude_skills: все 40+ описаний = 5,2 К.
  Слияние ломает роутинг и точность discovery ради копеек.
- **Внешние repo-map/индексы для средних репозиториев** — дублируют
  progressive disclosure, протухают, добавляют слой синхронизации.
- **Keep-alive кэша** — TTL подписки 5 минут, пинги жгут пул.
- **Opus по умолчанию** — сжигает отдельный недельный счётчик на рутине
  без выигрыша в качестве.
- **Массовый перевод доменных текстов на английский** — экономия реальна
  (~2,5×), но риск искажения доменных нюансов при переводе высок; допустимо
  только для нового «машинного» слоя (инструкции, не читаемые человеком),
  с сохранением русских триггер-фраз там, где по ним матчится discovery.
- **Decision-log в шапках часто загружаемых файлов** — наоборот, добавляет
  налог; решениям место в docs/.

## Чек-лист применения к новому репозиторию

1. [ ] `/context` + `/usage` → записать baseline (шаг 0)
2. [ ] Вынести из CLAUDE.md всё, что не «жёсткое правило + команда + карта» (шаг 1)
3. [ ] Приёмка: `/context` упал в разы, списки бит-в-бит (шаг 1)
4. [ ] Сторож бюджета + сторож ссылок, зарегистрированы в тестах (шаг 2)
5. [ ] Секция «модели и делегирование» в корне (шаг 3)
6. [ ] Привычки: /clear, тёплый /compact, батчинг, точечные тесты (шаг 4)
7. [ ] Рутину без рассуждений — в код без LLM; `claude -p` на Pro лимит не экономит (шаг 5)
8. [ ] Через неделю: `/usage` — в какой кап упираетесь? Если в недельный
       «all models» при соблюдении 1–7 — проблема тарифная, не техническая.

**Порядок важен:** 1 → 2 → 3. Делегирование до диеты корня умножает налог
на число субагентов; диета без сторожей отрастает обратно за месяц.
