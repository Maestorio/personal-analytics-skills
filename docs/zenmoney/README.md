# zenmoney-analyst — дев-документация

Точка входа для доработок скилла `skills/zenmoney-analyst/`. Навигатор по темам — `/zenmoney-docs <тема>` (`.claude/skills/zenmoney-docs/`). Установка — как у остальных скиллов (`./pack.sh zenmoney-analyst` → `outputs/zenmoney-analyst.skill`).

## Что делает скилл

Аналитический слой над MCP ZenMoney (контракт v2: 10 инструментов чтения + 2 записи): расходы и доходы по месяцам и категориям, сравнение периодов, запас по времени без дохода, остатки и капитал на прошлые даты, траты на поездку, возвраты, кешбэк и расчёты по общему счёту, плановые платежи, рост цен в одних точках, проверка актуальности MCP. По умолчанию только чтение и арифметика; запись в ZenMoney — Режим C, только по прямой просьбе и согласованному плану. Инвестсоветов не даёт (→ `ru-portfolio-advisor`).

## Зафиксированные решения (2026-09-24)

- ~~**Скилл не пишет в `Claude-Memory`**~~ — устарело: с 2.4.0 пишет `audit/` (`audit_history.py`), с 2.9.0 — строки карты (`map_edit.py`). Карту обновляет пользователь или Claude по прямой просьбе вне скилла; скилл лишь предлагает текст правки.
- **Снапшоты месяцев отложены** (R7 оставлен как схема). (До v2 основной экономией был справочник категорий в карте вместо `get_reference_data`; с v2 названия приходят в `references`.)
- **Два вида итогов:** «как в отчёте» и очищенный (без «Корректировки», инвестиций, доходных категорий-возвратов, возвратов покупок). Всё вычтенное — отдельными строками.
- **«Мой расход» = очищенный расход − сальдо расчётов с партнёром** (её переводы − мои переводы ей за период). Её доля в общей валюте на поездку относится к поездке, а не к месяцу.
- **Уровни запаса (R3):** кеш (`liquid`, включая накопительные) → + валютный кеш (`fx-liquid`, USD/EUR) → + внешний периметр (`external`, зарубежные банки). Общий счёт, остатки валют с поездок, вклады и инвестиции в запас не входят.
- ~~**Поездки** заведены категориями, а не тегами~~ — устарело с 2.2.0: поездка — тег (категория «#Страна’ГГ» в списке категорий), основной категорией — проблема учёта.
- **Язык ответа:** без названий инструментов, полей и кодов рецептов; роли по-русски; периоды длиннее месяца — среднее в месяц, итог периода в скобках.
- **Большие ответы MCP** (справочник ~100 тыс. символов, месяц операций ~60 тыс.) среда сохраняет в файл — считать кодом, а не суммировать в уме.

## Контракт v2 (2026-10-01)

MCP обновился ломающе: `get_reference_data`, `get_transactions`, `get_scheduled_transactions` удалены. Что это дало скиллу (версия 2.0.0):

- **`references` в каждом ответе** — названия счетов, категорий, точек и настройки пользователя; отдельный вызов справочника ради названий не нужен.
- **Фильтры операций** (`accountIds`, `categoryIds`, `tagIds`, `merchantIds`, `comments`, `types`, суммы) — R4 (поездка одним запросом по категории/тегу), R8 (только счета вне баланса), R10 (точки по `merchantId` за все годы), R11 (операции нужной категории). Ловушка: `categoryIds` не включает детей.
- **`get_account_balances`** — остатки на даты с пересчётом по курсу на дату → новый R12 (капитал во времени), R3 точнее.
- **`get_instrument_rates`** — курсы на даты → валютные траты в R4/R8 без «приближения по текущему курсу».
- **Счета:** `title` → `name`, `company` → `institution {name, countryCode}` (эвристика `external` по стране), долги — `a1_…`, `term` в ISO 8601.
- **Запись:** `upsert_categories`, `create_merchant` (у пользователя запрещён правилом доступа на 2026-10-01). Операции и счета править нечем.

Канарейка 2026-10-01 на реальных данных: A1 сошлось на 2026-09 (расходы и доходы), фильтры работают на сервере, остатки на дату пересчитываются по курсу даты, `list_accounts` ≈ 54 тыс. символов уходит в файл.

## Решение о записи в ZenMoney (2026-10-01)

Пользователь может разрешить создание и правку данных, но **каждая правка — строго по согласованию**: снимок «как было», план «было → станет» с точными ID, явное «да» на этот план (одно согласие — один пакет), массовые правки — сначала пробный пакет, перечитывание после записи. Запрет инструмента правилом доступа не обходить. Правила — в `SKILL.md`, Режим C; распространяются на будущие инструменты записи.

## Тонкая карта и запись операций (2026-10-02, версия 2.1.0)

- **Роли счетов — правилами** (`data-schema.md` §4, порядок важен), карта хранит только исключения. На 136 счетах правила расходятся с ролями пользователя у 9 счетов (накопительные с типом «вклад», общий счёт, зарубежный банк без страны, брокерские без слова «брокерский», пустые/просроченные вклады) — они в карте.
- **Новизна счёта** — по реестру первых 8 символов ID; новый или «под вопросом» счёт в запас не входит до решения пользователя. Архивные с остатком в запас не входят никогда.
- **`upsert_transactions` появился** (2026-10-02). Ловушки: `income`/`expense` заменяют обе стороны; `categoryId: null` стирает и теги; `null` в `merchantId`/`comment` стирает значение. Протокол — `write-mode.md`.
- **Решение пользователя:** каждое изменение или добавление в БД подтверждается отдельно — пронумерованный план «было → станет», согласие по пунктам, пилот из одного элемента, ≤ 10 операций в вызове, снимок до и полная сверка после.
- Карта переписана 2026-10-02; прошлая версия сохранена рядом (`zenmoney-map.backup-2026-09-24.md`).
