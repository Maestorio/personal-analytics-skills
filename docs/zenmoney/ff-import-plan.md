# Импорт выписок FF (Freedom Bank KZ) в ZenMoney — решения и план

Дата решения: 2026-10-10. Статус: **этапы 1–4 готовы, запись 2026 выполнена 2026-10-10 (81 запись + проба; сверка остатков объяснена до копейки — см. csv/ff-2026/STATE.md)**; этапы 1–3: (парсер, нормализатор, сопоставление, план исправлений и сборка записи — `parse_ff_statement.py`, `ff_normalize.py`, `stmt_compare.py`, `stmt_propose.py`, 118 проверок); пилот записи в ZenMoney и режимы E/F в `SKILL.md` — следующий шаг, в ZenMoney пока ничего не записано.

## Зачем

ИИ + выписка банка заполняют ZenMoney точнее, чем память. Два режима скилла `zenmoney-analyst`:

- **E — импорт по выписке:** одна или несколько выписок → операции, которых нет в ZenMoney → добавление
  по согласованию (категория, тег поездки, место).
- **F — сверка и корректировки:** сравнить выписку с ZenMoney, найти расхождения, предложить
  исправление (добавить операцию, заменить «Корректировку баланса» реальной операцией, поправить сумму).

Начинаем с FF; другие банки — отдельные парсеры с тем же форматом выхода.

## Что такое FF-выписка (факты, проверены на 8 файлах 2026)

- **PDF с текстовым слоем (mPDF)** — OCR не нужен. Разбор по координатам слов (`pdftotext -bbox`).
- **4 валюты × (текущий + депозитный счёт) = 8 файлов.** Деньги живут на депозите, на текущий
  возвращаются под платёж («Выплата вклада») и остаток уходит обратно («Прием вклада»). Счёт FF в
  ZenMoney = текущий + депозит (подтверждено: остаток FF RUB в ZenMoney = исходящий остаток депозита RUB).
- **Копейки «Прием вклада» — разница между блокировкой и итоговым курсом / округление продаваемой
  валюты, а не проценты.** Проценты — отдельная строка «Выплата процентов по вкладу» (USD 3×0.01, RUB 1.53 за 2026),
  зачисляются на депозит, банк ничего не удерживает (слов «комиссия/налог» в выписках нет).
- **Тандем валют:** покупка в валюте без денег = конвертация из другой валюты + покупка.
  EUR и KZT у пользователя — транзитные (денег там не держат, расходы ведутся в USD/RUB).
- **Место платежа** в строке покупки: `терминал\СТРАНА\ГОРОД\ТОЧКА`. У ~20% покупок банк места не пишет —
  тогда спрашиваем пользователя.
- **Корректировки пользователя** («Корректировка баланса» в комментарии, категория настоящая) бывают
  в 2025 (Аргентина'25, FF USD, апрель), в 2026 на FF их нет → настраиваем на выписках 2025, работаем с 2026.

## Решения

| # | Решение |
|---|---|
| 1 | Обязательны **четыре текущие** выписки (RUB, USD, KZT, EUR). Депозитные — необязательны, нужны для сверки остатка и процентов |
| 2 | Вклад (`Прием/Выплата вклада`) — не операция; проценты — отдельный список, по умолчанию не создаём (добавить, если без них не сходится остаток) |
| 3 | Транзит (EUR, KZT): конвертация + покупка = одна покупка в валюте источника (FIFO по лотам, остаток лота переходит дальше, остаток округления переносится на следующую покупку); возврат + обратная конвертация (частями) = один возврат |
| 4 | Реальные валюты (RUB, USD): обмен = перевод с обеими суммами; пополнение из другого банка = `topup` |
| 5 | Что нельзя собрать однозначно — флаг, ничего не угадываем |
| 6 | Данные из ZenMoney — **MCP, только счета выписок** (`accountIds`); для пополнения из российского банка достаточно перевода в самом FF-счёте (второй счёт приходит в `references`) — сверка ±3 дня, другие банки не грузим |
| 7 | Окно > 200 операций: скилл предупреждает «много токенов, лучше Claude Code»; больше ~1000 — CSV или нарезка по периодам |
| 8 | Запись — только `upsert_transactions`, пачками, каждая с «да»; `originalPayee` + `originalAmount/Instrument`; `delete_transactions` и `upsert_accounts` не используем |
| 10 | **Комиссии и промежуточные счета (решение 2026-10-10):** если деньги шли через счёт, который в ZenMoney не ведётся (Цифра банк), переводы записываются прямо источник → итоговый счёт на полную сумму, **комиссия — отдельная расходная операция** на итоговом счёте (а не разница сумм перевода). Счета ради разового промежуточного хранения не заводятся |
| 11 | Названия мест — официальные; если название двойное/сложное — так, чтобы было понятно, что делать. В `originalPayee` — читаемое имя точки, а не сырая строка банка с кодом терминала (сервер создаёт контрагента по этому тексту) |
| 12 | Контрагента не придумывать: нет названия в выписке или оно неоднозначно — спросить (2026-10-11, «PRO» оказался Perplexity, а не Anthropic). Starbucks — всегда «Кофейни», один контрагент Starbucks |
| 13 | Для FF и BOG доп. источник мест — скриншоты Apple Pay по каждой карте (банк не знает место при оплате Apple Pay); сумма в валюте покупки — проверка. Сумма VND в тексте выписки — в сотых долях (×100) |
| 9 | Рабочая выборка: разработка на январе–марте 2026, проверка на апреле–сентябре; выписки 2025 — для разбора «Корректировок баланса» |

## Конвейер

```
текущ_*.pdf (4) [+ депозит_*.pdf]
  → parse_ff_statement.py      строки + 3 проверки арифметики (blocking)       ← ЭТАП 1, ГОТОВ
  → ff_normalize.py            операции: expense/refund/transfer/topup + флаги  ← ЭТАП 1, ГОТОВ
  → выгрузка ZenMoney (MCP)    счета выписок, окно = период; страницы склеивает merge_pages ← этап 2, ГОТОВ
  → stmt_compare.py              тип+валюта+сумма, дата ±3, допуск 3%; классы ниже    ← этап 2, ГОТОВ
  → предложения                добавить / заменить корректировку / поправить     ← этап 3
  → запись по подтверждению    категория, тег поездки (даты из карты), место     ← этап 4
```

## Классы расхождений (stmt_compare.py)

`matched` · `differs` (ZenMoney выше банка на 1–3% — блокировка по курсу в приложении, не пропуск) · `date_shift` (сумма до копейки,
дата на недели иначе) · `merged` (одна сумма ZenMoney = несколько покупок банка того же места) · `partial_transfer` (совпала одна сторона перевода) ·
`topup_currency` (банк зачислил USD, в ZenMoney пополнение внесено в RUB — подразумеваемый курс) · `missing_in_zen` (кандидат на добавление) ·
`missing_in_bank` (+ `adjustment` для «Корректировок баланса»).

## Результат на реальных данных (2026, 8 файлов)

Все 8 выписок проходят проверки парсера. Нормализатор: 74 покупки, 1 возврат, 7 переводов между валютами,
10 пополнений из других банков; сверка остатка текущий + депозит: RUB 0.00, USD 0.00 (с учётом процентов).
Флагов только «банк не указал место» (16). Цепочки собраны: EUR (две покупки 39.87 и 37.46 USD, возврат 36.80 USD), KZT (подписки по ~3.1 USD).
