# План: режим «Аудит учёта» и статистика качества (zenmoney-analyst)

Статус: решения согласованы 2026-10-05. Этапы 1–2 сделаны (2.3.0 — `audit_month.py`, `references/audit.md`; 2.4.0 — `audit_history.py`, история в `ZenMoney/audit/`, первая запись 2026-09). Этап 3 (страница) — бриф и промпт для Claude Design готовы: `docs/zenmoney/money-page-brief.md`.

## Принципы

- **Числа считает скрипт** (`scripts/audit_month.py` над сохранёнными ответами MCP), модель только объясняет и предлагает правки. Иначе месяцы несопоставимы.
- **Хранение опционально.** Есть доступ к `Claude-Memory/ZenMoney/audit/` — читать историю и писать итог; нет доступа — аудит работает полностью, метрики, требующие истории, помечены «нет истории», итог отдаётся файлом для ручного сохранения.
- Хранится состояние **на дату аудита**, прошлые записи не пересчитываются (ZenMoney меняется задним числом).
- Операции на страницу и в хранилище не выносятся — только агрегаты; исправления делаются в приложении или через Режим C.

## Чек-листы

**A. Искажают итоги** (ежемесячно)
1. Перевод между ведущимися своими счетами записан расходом и доходом (пара на одну сумму, ±1 день).
2. «Корректировки»: число, сумма, доля в расходах; отдельно в поездках.
3. Операции без категории.
4. Проект в основной категории вместо тега — сигнал + варианты переноса в тег.
5. Возможные дубли (дата, счёт, сумма, точка) — вопрос, не вердикт.

(Холд старше N дней — решено не делать.)

**B. Полнота учёта** (ежемесячно)
6. Синхронизируемый счёт молчит: счета, у которых были операции `source: plugin` за 90 дней, но нет ни одной за последние 7 дней. Счета без синхронизации не проверяются.
7. Траты по счетам вне баланса (R8).
8. Новые счета вне реестра карты.

**C. Структура категорий** (раз в квартал и в большом аудите)
9. Дубли по смыслу и опечатки.
10. Категории, созданные за период.
11. Категории без операций 12+ месяцев (ни основной категорией, ни тегом) + дата последней операции. Кандидаты — из выгрузки за 12 месяцев; дата — `list_transactions` по `categoryIds` и по `tagIds`, `order: desc`, `limit: 1`.
12. Поездка закончилась больше 30 дней назад, а категория-тег не убрана в «Путешествия». Конец поездки — из карты; нет в карте → дата последней операции с тегом.

**D. Информационно** (не проблема)
13. Запись в родителя при подходящем ребёнке.
14. Пустое место платежа у любой операции; место платежа — сервис банка.

Месячный аудит — A + B за месяц. Большой — A–D за 12 месяцев.

## Статистика качества

| Метрика | Требует истории |
|---|---|
| Доля «Корректировок» в расходах, % | нет (тренд — да) |
| Доля чистых операций — по числу и по сумме (по модулю) | нет |
| Замечания по типам: число и ₽ | нет |
| Доля исправленного с прошлого аудита | да |
| Открытые замечания по возрасту (<1 мес / 1–3 / >3) | да |
| Тренд 6–12 месяцев | да |

## Хранение (`Claude-Memory/ZenMoney/audit/`)

- `history.json` — по записи на месяц, только агрегаты, схема `zenmoney-audit@1`.
- `accepted.json` — принятые исключения (ID операции, тип, причина, дата), чтобы не спрашивать повторно.
- Запись — только скриптом-валидатором; **узкое исключение из D3 согласовано** (как у `portfolio-coherence-audit`): только `ZenMoney/audit/`. Карта остаётся только для чтения.
- **Суммы трат хранить можно** (решение R7 «снапшоты месяцев не используются» отменено): итоги и суммы по категориям, **без привязки к счетам, точкам и операциям**. Только под паролем.

## Статистика месяца (решение 2026-10-05, реализовано в 2.5.0)

«Закрой месяц» = аудит + статистика одной командой. Считать по операциям (не по отчёту). В `spending.json` хранятся итоги, категории, поездки и **топ мест платежа** (решение пользователя — для поиска закономерностей); без счетов и отдельных операций. Пересчёт июль–сентябрь 2026 — отдельно, позже.

## Страница «Деньги» (решение 2026-10-05)

Независимая страница `tools/money.html`, на неё ведёт отдельная карточка в хабе. Данные — `/ZenMoney/*`, под паролем. Две вкладки, обе только агрегаты:
- **«Качество учёта»** — метрики аудита из `history.json`.
- **«Траты»** — итоги месяца против среднего за 3 месяца (расход и доход очищенные, топ категорий). Источник — отдельный отчёт «закрытие месяца» (R1 + R2), не аудит. Хранение сумм согласовано (см. «Хранение»).

Промпт для Claude Design — после этапа 2.
