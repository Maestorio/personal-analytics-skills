# Пересчёт истории из CSV-выгрузки — рецепт для Claude Code

Команда пользователя: «`/zenmoney-docs пересчитай историю (места) из csv <файл>`» или просто
«пересчитай историю из CSV». Делается **в Claude Code**, не скиллом и не через MCP: скрипт
пересчитывает 81+ месяц и все поездки за минуты, итоги сверяются до рубля. Источник правок —
**ZenMoney** (места, категории, теги правит пользователь в приложении); CSV руками не править:
следующая выгрузка вернёт старое.

Политика записи на сайт и проверки до записи — `csv-checks-research.md`.

Где что лежит:

| Что | Где |
|---|---|
| выгрузки CSV | `docs/zenmoney/source/` (в `.gitignore`; никогда `git add -A docs`) |
| вспомогательные файлы | `docs/zenmoney/csv/` (курсы, `trip-ids.json`, `accounts.json`, `category-flags.json`) |
| словарь мест | `docs/zenmoney/csv/payee-map.json` (текст банка → место), страницы MCP для него — `docs/zenmoney/csv/payee-pages/` |
| история | `~/Library/CloudStorage/SynologyDrive-home/Claude-Memory/ZenMoney/audit/` (`spending.json`, `trips.json`, `facts.json`) |
| последняя записанная выгрузка | README, раздел «Состояние…», строка «Последняя записанная выгрузка» |
| черновики прогона | scratchpad сессии (не в репозиторий) |

Интерпретатор — `~/.pyenv/versions/3.12.9/bin/python3` (`PY` ниже), `R` — корень репозитория,
`A` — папка `audit/`, `S` — scratchpad.

## Шаги

1. **Файл.** Новая выгрузка обычно в `~/Downloads/` — скопировать в `docs/zenmoney/`, проверить
   `git check-ignore -q docs/zenmoney/<файл>` (должен быть проигнорирован). Synology смонтирован
   (`ls $A`), иначе стоп.
2. **Что изменилось** (только чтение):
   `$PY tools/zenmoney_csv_diff.py --old docs/zenmoney/<последняя записанная> --new docs/zenmoney/<новая>`.
   - **«потеряли тег поездки» ≠ 0 → стоп.** Показать пользователю дату, сумму, место, какой тег
     был; он возвращает теги в приложении и делает новую выгрузку. (2026-10-07: правка места
     сбросила тег у 4 операций; одну потом вернули не на ту поездку — сверять по датам поездки.)
   - **«Кому» в diff — не повод для вопросов:** в CSV там сырой текст банка или пусто (место снято/от плагина), а в ZenMoney место нормальное; это закрывает словарь (шаг 3). Подозрительны категории, суммы, даты, теги и исчезнувшие операции (удалённый дубль объясняет «гейт не пройден» по поездке: гейт считает правки, не удаления).
   - Изменения мест и категорий — показать коротко; подозрительные (место явно другого рода,
     доставка пиццы → супермаркет) — назвать датой и суммой, решает пользователь.
3. **Словарь мест.** CSV «Кому» — сырой текст банка, если место поставил плагин банка
   («PRODUKTY ERMOLINO» вместо «Ермолино»); без словаря на странице окажутся тексты банка.
   Словарь **обновлять при каждом пересчёте**: правка места в приложении «Кому» в CSV часто не
   меняет (у места от банка там текст банка — «AV AZBUKAVKUSA» до и после совмещения), но всегда
   меняет `changedDate` операции. Поэтому подгружаются только изменённые дни:
   - `$PY tools/zenmoney_payee_map.py changed --old docs/zenmoney/<последняя записанная> --new docs/zenmoney/<новая>`
     → окна дат (по странице на окно). Запомнить время (UTC) перед первым вызовом;
   - на каждое окно — `list_transactions` с его `from`/`to`, `types: ["expense","income"]`, `limit 200`
     (если `nextCursor` не `null` — дочитать по курсору). Ответы ничем не сохранять вручную;
   - `$PY tools/zenmoney_payee_map.py grab --session <журнал сессии .jsonl> --after <время> --out docs/zenmoney/csv/payee-pages --prefix u<дата>`
     — все ответы, и сохранённые средой в tool-results, и пришедшие прямо в контекст (их
     иначе пришлось бы перепечатывать). Журнал — `~/.claude/projects/<проект>/<id сессии>.jsonl`
     (id — в пути scratchpad). Файлы `u…` читаются после `p…`: у операции побеждает свежая версия;
   - `$PY tools/zenmoney_payee_map.py build --csv docs/zenmoney/<новая> --pages docs/zenmoney/csv/payee-pages --out docs/zenmoney/csv/payee-map.json`;
     «нет в MCP» и «неоднозначно» — единицы; сотни → не та выгрузка или не все окна.

   Сколько стоит: правки по всей истории (совмещение мест 2026-10-07: 134 операции в 124 днях) —
   34 вызова против 44 у полной загрузки; правки за месяц-два — несколько вызовов.
   **Полная загрузка** (`from` 2020-01-01, `to` сегодня, по `nextCursor` до `null`, ~44 страницы;
   старую папку — в `payee-pages.<дата>`, `grab --prefix p`) — если окон больше ~40, если
   пользователь **переименовывал** места (переименование подхватится, только если в окнах есть
   хоть одна операция этого места) или если словаря нет.

4. **Сухой прогон** в scratchpad:
   `$PY tools/zenmoney_csv_backfill.py --csv docs/zenmoney/<новая> --prev-csv docs/zenmoney/<последняя записанная> --data docs/zenmoney/csv --audit $A --from 2020-01 --trips --out $S/runs`.
   - Строка «Гейт сверки: пройден» обязательна; строка «Словарь мест: …» — дата сборки и
     период страниц (нет словаря — «! словаря мест нет»: стоп, шаг 3).
   - Проверка мест: все места прогона — названия из справочника ZenMoney (`references.merchants`
     страниц); текст банка, которого нет в справочнике, — операция вне страниц или после сборки.
   - «~ расходится: N операций изменено…» у месяцев — нормально (пользователь правил).
   - У **поездок** «~ записано X: … изменено» — итог поездки поменялся: выяснить, почему (обычно
     слетел или сменился тег) — до записи.
   - Месяцы с другими **итогами** (не только места/категории) — найти операцию и объяснить.
5. **Копия до записи:** `cp -p $A/{spending,trips,facts}.json` → `*.before-<что>-<дата>`.
6. **Запись на копии** (`cp $A/*.json $S/copy/`), циклом:
   `for f in $S/runs/run-*.json; do $PY skills/zenmoney-analyst/scripts/audit_history.py spending --run $f --spending $S/copy/spending.json --write; done`,
   `for f in $S/runs/trip-*.json; do … trip --run $f --trips $S/copy/trips.json --date <сегодня> --write; done`.
   Сравнить с живыми: число месяцев, какие `totals` изменились (должны быть объяснимы).
7. **Запись по-настоящему** — те же циклы с `--spending $A/spending.json` / `--trips $A/trips.json`.
   `facts.json` пересчитывается сам. Проверить: `spending.json` = копии из шага 6 (у `trips.json`
   может отличаться порядок поездок — сравнивать по содержимому).
8. **После:** обновить в README строку «Последняя записанная выгрузка»; страница «Деньги»
   подхватит данные сама (деплой не нужен). Коммитить нечего, кроме README — **CSV не коммитить**.
9. **Доложить:** что изменилось в итогах (обычно ничего), какие поездки и почему, где копии.

## Проверка мест за период (по просьбе)

CSV «Кому» — сырой текст банка или имя места; одно название у **двух разных мест** в CSV не видно
(словарь мест это не лечит: он переносит в историю ровно то, что в ZenMoney).
Поэтому проверка мест — только по MCP: `list_transactions` (траты, `limit 200`, страницы в
`docs/zenmoney/csv/places-<период>/`) → `audit_month.py places --month <последний> --as-of <дата> --window-from <начало> --tx <страницы> --accepted $A/accepted.json`.
Список для пользователя — файлом `Claude-Memory/ZenMoney/places-todo-<период>.md` (галочки).
Большой ответ MCP сохраняется в файл сам; маленький (последняя страница) приходит в контекст —
его надо записать в файл, иначе он выпадет из проверки.
