## 1. Что сломано

Функция `compute_fixed_point_target` считает неподвижную точку акционной корзины:

```
T* = F / (1 − S)
```

где `F` — сумма в неподвижных за цикл тикерах, `S` — сумма целевых весов открытых тикеров.

Спека делит класс на четыре категории и исключает `Selling` из обеих величин:

> Тикер с активным сигналом «продать»/«сократить» — отдельный поток, не часть `F`: он уменьшается, а не остаётся неподвижным. Исключается и из `F`, и из `S` до вызова формулы.

**Дефект:** категория `Selling` не различает полный выход и срез до плановой доли. При срезе позиция уменьшается **частично**, а остаток остаётся неподвижным и стоит ровно на плановом весе — то есть по определению самой спеки это `Dormant`, часть `F`. Исключая позицию целиком, движок выбрасывает из `F` неподвижные деньги и занижает `T*`.

Обоснование в спеке («он уменьшается») верно только для продаваемого куска.

## 2. Величина ошибки

Реальный случай, снапшот `portfolio-2026-08-21.json`, NAV без ИИС-3 = 385 555 950 ₽.

SBERP: позиция 11 030 634 ₽ (8,61% корзины), решение — срезать до плановых 8,0%. То есть продать ~20–29 тыс ₽ и **оставить ~380–388 тыс ₽ на плане**.

Два прогона `gate_aware_sizing.py --open X5,MBNK,LSNGP`:

| Классификация SBERP | T\* | % NAV | Докупка |
|---|---:|---:|---:|
| `--selling SBERP` (текущее поведение) | 39 671 559 ₽ | 30,87% | 651 411 ₽ |
| без исключения (SBERP целиком в `F`) | 43 897 851 ₽ | 34,16% | 1 200 834 ₽ |
| **корректно (SBERP как `Open` с w=8%)** | **43 688 925 ₽** | **34,00%** | **1 173 672 ₽** |

Ошибка текущего поведения: `T*` занижен на **12 052 098 ₽**, докупка — в **1,8 раза**.

**Направление ошибки противоречит цели механизма.** T\* существует, чтобы открытые бумаги не выходили за свой cap относительно реальной книги. Занижение T\* даёт обратный перекос: открытые бумаги остаются **ниже** целевых относительных весов. В разобранном случае LSNGP стоит 1,64% при плане 3,0% — крупнейшее внутреннее отклонение корзины, и заниженный потолок продлевает его.

## 3. Второй дефект, исчезающий автоматически

Цель среза («TRIM до 8,0% L2») считалась от `L2_cur` — текущей стоимости корзины. Покупки считались от `T*`. Один и тот же плановый вес 8% меряется двумя разными знаменателями в одном плане, причём `L2_cur` — это вариант A, явно отвергнутый спекой для покупок («база сама занижена → недобор класса маскируется»).

При правке из раздела 4 отдельного исправления не требуется: если trim-to-target попадает в `Open`, его цель по построению равна `w_i × T*`, как и у покупок.

## 4. Изменения

### 4.1 `references/stocks-methodology.md` — §«Из чего состоит `F`»

Заменить таблицу категорий на пять строк и добавить дискриминатор.

| Категория | Определение | В `F`? | В `S`? |
|---|---|---|---|
| **Blocked** | таргет не достигнут, активный gate/`no_buy` — купить нельзя | да | нет |
| **Dormant** | таргет достигнут (гистерезис Rule 3) либо нет триггера на пересмотр | да | нет |
| **Open** | есть разрыв к таргету, гейта нет — можно двигать | нет | да (`w_i`) |
| **Rebalancing** (новое) | **срез до определённой плановой доли**; после исполнения позиция стоит на `w_i` | нет | **да (`w_i`)** |
| **Selling** | полный выход либо выход траншами без определённой целевой доли | нет | нет |

**Дискриминатор `Rebalancing` vs `Selling`** — один вопрос: *определён ли для позиции целевой вес после сокращения, и равен ли он её плановой доле?*

- да → `Rebalancing`: позиция входит в `S` со своим `w_i`, `target_i = w_i × T*`, `buy_rub` выходит отрицательным и равен сумме среза;
- нет (цель 0, либо «выходим траншами», либо цель не задана) → `Selling`: как сейчас, вне `F` и вне `S`.

Добавить абзац-обоснование:

> Обоснование исключения `Selling` («он уменьшается, а не остаётся неподвижным») распространяется только на продаваемую часть позиции. При срезе до плановой доли остаток неподвижен и стоит на таргете — это `Dormant` по определению выше. Исключать его из `F` значит занижать `T*` и удерживать открытые бумаги ниже их относительных весов, то есть получать тот же дисбаланс корзины, ради предотвращения которого механизм и введён.

Также обновить строку про инвариант: сейчас написано `L2_cur < T* < T_full` — при наличии `Rebalancing` неравенство сохраняется, но проверить формулировку на случай, когда суммарный срез велик.

### 4.3 `scripts/gate_aware_sizing.py`

**CLI.** Добавить `--trim TICKER[=weight_pct][,...]` рядом с существующими `--open` / `--selling` / `--blocked`. Синтаксис веса — как у `--open` (`TICKER=6.0`); без явного веса берётся `planned_share_pct` из снапшота, как для `--open`.

**Классификатор** (сейчас ~строка 266–346, функция классификации). Приоритет при пересечении ручных множеств сейчас `Selling > Open > остальное`. Новый приоритет: **`Selling > Rebalancing > Open > остальное`**. Тикер, попавший и в `--trim`, и в `--selling`, считается `Selling` (полный выход старше частичного) — и это должно давать warning, а не молчаливый выбор.

Вернуть пятый ключ в словаре классификации: `{"open": [...], "blocked": [...], "dormant": [...], "selling": [...], "rebalancing": [...]}`.

**Расчёт.** `Rebalancing` участвует в `S` наравне с `Open`. Проще всего: собрать объединённый список `sized = open + rebalancing`, посчитать `S = Σ w_i` по нему, `F` — по `blocked + dormant`, и считать `target_i = w_i × T*`, `delta_i = target_i − current_i` для всех элементов `sized`. Знак `delta_i` и определяет направление; отдельной ветки для тримов в арифметике быть не должно.

Переименовать в выдаче `buy_rub` → `delta_rub` **нельзя** без проверки потребителей (см. 4.5). Оставить `buy_rub`, разрешив отрицательные значения, и добавить рядом поле `direction: "buy" | "trim"`.

**Округление по лотам.** `compute_lots(buy_rub, quote)` (~строка 449) сейчас делает `floor(buy_rub / lot_rub)` — «чтобы не переплатить». Для отрицательной величины `floor` даёт перерезание по модулю, что случайно совпадает с нужным поведением, но полагаться на это нельзя. Сделать явно:

- `delta > 0` (покупка) → `floor(|delta| / lot_rub)` — недокупить лучше, чем выйти за cap;
- `delta < 0` (срез) → `ceil(|delta| / lot_rub)` — **дорезать лучше, чем недорезать**: недорезав, остаёшься выше cap, а именно этого механизм и не должен допускать.

`remainder` считать со знаком, соответствующим направлению.

**Отчётный блок** (`build_report_block`, ~строка 483; фильтр `buy > 0` около строки 570). Снять фильтр, рендерить обе стороны разными формулировками: «докупить ≈ N лот.» / «срезать ≈ N лот.». Существующий хвост «Лоты — оценка по последней цене, точное количество считает IntelInvest» сохранить.

Контракт вывода из `references/output-templates.md` §«Как называть базу докупки» не меняется: наружу по-прежнему идут **база докупки** и **остаток, закрытый для покупок гейтами**, без `T*`, `F`, `S` и вывода формулы.

**Новое: пост-трейд проверка.** После округления по лотам фактические доли отличаются от `w_i × T*`. Добавить в JSON-выход и в отчётный блок:

- `weight_after_pct` по каждому тикеру из `sized`;
- флаг `cap_breach_after_rounding: [TICKER, ...]` — **только вклад округления**: `вес_после_округления − вес_при_идеальном_исполнении` больше 0,25 пп;
- флаг `structural_cap_offset: [TICKER, ...]` — отклонение при идеальном исполнении, `вес_идеальный − w_i` больше 0,25 пп. Ненулевой только в ветке `t_full_no_gates` (цели от полного плана класса, книга ниже него) и в отчёт идёт ОДНОЙ строкой, а не пофамильно. **Поправка ревью 26.08.2026:** без этого разделения флаг срабатывал на 100% тикеров при полностью отсутствующих котировках, то есть когда округлять было нечего.

**Новое: сведение по деньгам.** Добавить блок:

```
покупки:            Σ delta_i > 0
выручка от тримов:  Σ |delta_i| < 0
--extra-cash-from-sales
кэш (из снапшота)
→ дефицит / остаток
```

Дефицит — не ошибка, а информация: он означает, что цикл нужно исполнять частями.

### 4.4 Guard на вырожденность — **обязательно проверить**

Существующий guard: при `(1 − S) < 0.01` расчёт не досчитывается, fallback на `T_full` + флаг на ручную проверку. Это правильное поведение, ломать нельзя.

Перевод тримов в `S` **повышает `S`** — в разобранном случае с 0,13 до 0,21. При нескольких одновременных тримах крупных позиций `S` может подойти к порогу там, где раньше не подходил. Требуется:

- тест на срабатывание guard'а при `S → 1` с участием `Rebalancing` (см. 5.5);
- в сообщении guard'а перечислять, какие тикеры дали вклад в `S`, с разбивкой `open` / `rebalancing` — иначе причина отказа непонятна.

## 5. Тест-кейсы (критерий приёмки)

Числа получены на реальном снапшоте и перепроверены вручную. Все — NAV без ИИС-3 = 385 555 950 ₽, план класса 40% = `T_full` 51 407 460 ₽.

### 5.1 Регрессия: поведение без тримов не меняется

`--open X5,MBNK,LSNGP --selling SBERP` (SBERP как полный выход) →
`T* = 39 671 559 ₽`, `base_pct_nav = 30,87`, `S = 0,13`, докупка 651 411 ₽ (X5 26 886 · MBNK 26 895 · LSNGP 163 359).

Это текущее поведение. После правки при том же вызове должно получиться **то же самое**.

### 5.2 Основной кейс: trim-to-target

`--open X5,MBNK,LSNGP --trim SBERP=8.0` →

- `S = 0,21`
- `F = 34 514 253 ₽`
- `T* = 43 688 925 ₽`, `base_pct_nav = 34,00`
- `SBERP`: target 1 165 038, current 1 225 626, **delta −60 588**, `direction: "trim"`
- `X5`: target 873 780, current 766 545, delta +107 235
- `MBNK`: target 582 519, current 502 062, delta +80 457
- `LSNGP`: target 436 890, current 233 358, delta +203 532
- сумма покупок 391 224, выручка от трима 60 588, нетто +330 636

Допуск: ±2 ₽ на округления.

### 5.3 Вес по умолчанию

`--trim SBERP` без явного веса должен взять `planned_share_pct` SBERP из снапшота (8,0) и дать результат, идентичный 5.2.

### 5.4 Полная продажа остаётся полной продажей

`--selling SBERP` и `--trim SBERP` должны давать **разные** `T*` (13 223 853 против 14 562 975). Если совпали — правка не применилась либо `--trim` молча деградировал в `--selling`.

Тикер в обоих списках → `Selling` + warning в `warnings[]`.

### 5.5 Guard на вырожденность

Синтетический вход, где `open + rebalancing` в сумме дают `S ≥ 0,99`: расчёт **не досчитывается**, `base_source` указывает на fallback, в `warnings[]` есть запись с разбивкой вклада в `S` по категориям. Числа не выдумываются.

### 5.6 Лотность и направление округления

С `--quotes` (выход `moex_quotes.py --json`):

- для покупки количество лотов таково, что `lots × lot_rub ≤ delta` (не больше);
- для трима — `lots × lot_rub ≥ |delta|` (не меньше);
- при отсутствии `price` или `lot_size` в котировке — `lots = None` и запись `lots_unavailable:TICKER` в `warnings[]` (существующее поведение, сохранить).

### 5.7 Пост-трейд веса

Вклад округления по лотам ни по одному тикеру из `sized` не превышает 0,25 пп; при превышении — тикер в `cap_breach_after_rounding`. Структурное отклонение базы от пост-трейд книги в этот флаг НЕ попадает — оно уходит в `structural_cap_offset` (см. 4.3). Контрольный кейс: прогон в ветке `t_full_no_gates` без `--quotes` обязан давать `cap_breach_after_rounding: []`.

## 6. Вне задачи A

Не делать в правке раздела 4 (см. также задачу B в разделе 8):

- **Автоклассификацию тримов.** `--trim` — только ручной флаг. Автоматически выводить «это трим, а не продажа» из `advisor_verdict: TRIM` заманчиво, но вердикт TRIM не несёт целевой доли, а дискриминатор требует именно её. Отдельная задача.

  > **Закрыто 27.08.2026 подсказкой, а не автоклассификацией.** Запрет остаётся в силе:
  > `--trim` — по-прежнему ручной флаг, классификация автоматически не меняется. Но в
  > снапшоте нашёлся сигнал, который целевую долю НЕСЁТ: `user_plan: BALANCE` («привести к
  > плану») вместе с `planned_share_pct` — на нём дискриминатор §4.1 выполним, в отличие от
  > `advisor_verdict: TRIM`. Поэтому добавлена подсказка `trim_candidate_hint:<TICKER>`:
  > тикер помечен BALANCE, стоит выше плана и не передан в `--trim`/`--selling`. Порог —
  > не гистерезис Rule 3: флаг решает не размер среза, а попадёт ли ВСЯ позиция в `S` или
  > останется в `F`, поэтому цена ошибки зависит от размера позиции. Кейс 21.08.2026:
  > перевес SBERP 0,61 пп (внутри гистерезиса), позиция 11 030 634 ₽, занижение базы
  > 12 052 098 ₽ — гистерезисный порог промолчал бы ровно там, где нужен.
- **Лимиты концентрации** — вынесены в отдельную задачу C (раздел 9). Секторная часть дополнительно требует починки поля `sector` в снапшоте (45,57% корзины имеют `sector: null`, категории дублируются) — это задача `portfolio-data-loader`, не этого скрипта.
- **Правило кэша** (`ожидаемый_кэш = 4% × NAV + (T_full − T*)`, тревога односторонняя). Живёт в методологии и в отчётах, не в этом скрипте.

  > **Записано 27.08.2026.** Проверка показала, что в методологии правила не было — спека
  > ссылалась на него как на существующее. Внесено в `stocks-methodology.md`
  > §«Сколько кэша считать нормальным, пока часть класса под гейтами», с раскрытием
  > односторонности: тревога только на ПРЕВЫШЕНИЕ ожидаемого (деньги не работают и гейтами
  > это уже не объясняется); кэш ниже ожидаемого — рабочее состояние, а не аномалия,
  > симметричная тревога давала бы ложное срабатывание на каждом цикле с докупками.
- **Переименование `buy_rub` → `delta_rub`.** Ломает потребителей ради косметики.
- **Правило неразворота** — вынесено в отдельную задачу B (раздел 8). Реализуется ПОСЛЕ задачи A и опирается на её отрицательные `buy_rub`.

## 8. Задача B — правило неразворота (после задачи A)

Отдельная задача. Реализуется только после того, как задача A принята: она опирается на существование отрицательных `buy_rub` и на категорию `Rebalancing`.

### 8.1 Проблема

`T*` растёт при снятии каждого гейта, а цель бумаги равна `w_i × T*`. Значит бумага, срезанная в раннем цикле, в позднем цикле формально оказывается недобранной — и механическое применение расчёта предписывает выкупить только что проданное. Симметрично: при появлении нового гейта `T*` падает, и недавно докупленная бумага формально оказывается в перевесе.

На горизонте плана (обычно 3–6 месяцев) такой разворот — чистые потери: комиссии обеих сделок, НДФЛ 13/15% с реализованной при срезе прибыли и обнуление трёхлетнего срока ЛДВ по вновь купленному лоту. Экспозиция при этом не меняется.

Реальный пример (снапшот 21.08.2026): SBERP режется в цикле 1 до `8% × 14 137 734 = 10 179 162 ₽`; в цикле 3 цель того же тикера — `8% × 14 562 975 = 10 485 342 ₽`, в граничном состоянии (открыты MOEX и RENI) — 10 799 082 ₽. Формальный «недобор» 206 640 ₽.

В этом конкретном случае разворота не происходит, потому что 206 640 ₽ = 0,48 пп корзины, а гистерезис Rule 3 равен 1 пп. **Но защита здесь случайная, а не спроектированная** — при большем скачке `T*` (одновременное снятие нескольких крупных гейтов) порог будет пробит.

### 8.2 Требуемое поведение

**B1. Проверка диапазона цели.** Новый режим: по списку обозримых состояний цикла посчитать цель каждой бумаги в каждом состоянии и вернуть диапазон.

Вход — список состояний, каждое задаётся набором открытых тикеров с весами. Форма CLI на усмотрение реализующего; разумный вариант — `--cycles FILE.json` со списком вида `[{"label": "C1", "open": {"SBERP": 8.0}}, {"label": "C2", "open": {"SBERP": 8.0, "MBNK": 4.0}}, ...]`.

Выход по каждому тикеру: `target_min`, `target_max`, `target_by_cycle`, `current_rub`.

**B2. Флаг разворота.** Для каждой бумаги, по которой в текущем цикле предписано действие, проверить: попадает ли `current_rub` **после** исполнения действия в интервал, из которого какое-то последующее состояние потребует движения в обратную сторону **сверх гистерезиса**.

```
после_действия = target_текущего_цикла
разворот, если существует состояние k такое, что
    знак(target_k − после_действия) ≠ знак(target_текущего − current_rub)
    И |target_k − после_действия| > hysteresis_pp × sleeve
```

`hysteresis_pp` — 1,0 по умолчанию, из Rule 3; вынести параметром.

При обнаружении — `reversal_risk: [{ticker, cycle, amount_rub, deviation_pp}]` в JSON и явная строка в отчётном блоке. **Это предупреждение, а не блокировка:** решение о том, отложить сделку или исполнить, принимает владелец.

**B3. Фиксация направления.** Ввести признак «по бумаге уже была сделка в текущем горизонте». Источник — на усмотрение реализующего (простейший вариант: `--acted TICKER[,...]`, более правильный — вывод из `conditions.yaml` history или из сделок снапшота). Бумага с этим признаком принудительно классифицируется как `Dormant` до конца горизонта, независимо от арифметического разрыва.

Снятие признака — только по существенному основанию, которое в скрипт не зашивается: смена фундаментального вердикта, вердикт разбора Mode 4, срабатывание условия, нарушение лимита концентрации. То есть снятие делается человеком через явный флаг, а не автоматически.

### 8.3 Методология

В `references/stocks-methodology.md` добавить подраздел «Правило неразворота» после §«Из чего состоит `F`»: формулировка правила, три уровня защиты (гистерезис Rule 3 → фиксация направления на горизонт → обязательная проверка диапазона перед сделкой), требование не дробить сделку при возможной смене направления внутри горизонта.

В `references/output-templates.md` — строка проверки на разворот в шаблоне, где называется база докупки: план обязан показывать диапазон цели по обозримым циклам, а не только цель текущего цикла.

### 8.4 Тест-кейсы задачи B

Снапшот `portfolio-2026-08-21.json`, гистерезис 1,0 пп, корзина 42 697 026 ₽.

**B-T1. Диапазон целей.** Состояния C1 `{SBERP:8}` · C2 `{SBERP:8, MBNK:4}` · C3 `{SBERP:8, MBNK:4, X5:6, LSNGP:3}` · C4 `{+MOEX:8}` · C5 `{+MOEX:8, RENI:12}` дают базы **14 137 734 / 14 209 833 / 14 562 975 / 14 623 626 / 44 996 175 ₽** и цели SBERP **1 131 018 / 1 136 787 / 1 165 038 / 1 169 889 / 10 799 082 ₽**. Допуск ±2 ₽.

**B-T2. Разворота нет (текущий случай).** Действие «срезать SBERP до 1 131 018» при состояниях C1–C5: максимальное последующее отклонение `1 199 898 − 1 131 018 = 206 640 ₽ = 0,48 пп < 1,0 пп` → `reversal_risk` **пустой**.

**B-T3. Разворот обнаруживается.** Тот же вход с `hysteresis_pp = 0,4` → SBERP попадает в `reversal_risk` с `amount_rub ≈ 68 880`, `deviation_pp ≈ 0,48`, `cycle = "C5"`.

**B-T4. Монотонные покупки не помечаются.** MBNK (568 392 → 599 949), X5 (873 780 → 899 922), LSNGP (436 890 → 449 961) растут по циклам монотонно → в `reversal_risk` не попадают ни при каком гистерезисе.

**B-T5. Фиксация направления.** С `--acted SBERP` тикер уходит в `dormant` даже при явном `--open SBERP=8.0`, и в `warnings[]` появляется запись с причиной.

### 8.5 На что смотреть ревьюеру задачи B

1. **Знак в B2.** Легко ошибиться и пометить разворотом обычное продолжение той же покупки в следующем цикле. Тест B-T4 ровно про это.
2. **Гистерезис как параметр, а не константа.** Тест B-T3 не пройдёт, если 1,0 пп зашит.
3. **B3 не должен снимать признак автоматически.** Любая автоматика здесь — это ровно тот разворот, который правило запрещает.
4. **`reversal_risk` — предупреждение, не блокировка.** Скрипт не должен отказываться считать при непустом флаге.

## 9. Задача C — лимиты концентрации (независима от A и B)

Отдельная задача, с A и B не связана — можно делать параллельно.

### 9.1 Что требуется

Ввести проверку лимитов концентрации акционной книги. **Лимиты — не константы в коде, а конфигурация с именованными исключениями.**

Действующие значения (решение владельца 21.08.2026):

| Лимит | Значение |
|---|---|
| Один эмитент, по умолчанию | 15% акционной книги |
| SBER + SBERP (именованное исключение) | 20% |
| Сектор | 35% (принят, активируется после починки `sector`) |

### 9.2 Ключевые правила

**Группировка эмитента.** Обыкновенные и привилегированные акции одного эмитента считаются одной позицией. Группы задаются конфигом, а не эвристикой по тикеру: `{"SBER": ["SBER", "SBERP"]}`. Правило «тикер + P» встречается, но не универсально, и на нём нельзя строить риск-лимит.

**Знаменатель — фактическая корзина (`L2_cur`), а НЕ `T*`.** Это принципиально и противоположно тому, как считаются цели. Цели размещения — от базы `T*` (куда книга идёт); лимиты — от факта (какой риск несётся сегодня). Обоснование то же, по которому в §4.1 отвергнут вариант B: риск реализуется на фактически удерживаемой позиции. Реализующему: не «унифицировать» знаменатели — это регрессия.

**Именованное исключение — запись, а не число.** Структура: эмитент, значение, обоснование (текст), дата пересмотра. Исключение с истёкшей датой пересмотра **не применяется** и даёт warning: проверка идёт по лимиту по умолчанию. Исключение без даты пересмотра конфиг принимать не должен — это молчаливая отмена лимита.

**Реакция на нарушение — срез до лимита, а не до планового веса.** Величина: `current − limit × L2_cur` по группе эмитента. Нарушение лимита — существенное основание в терминах правила неразворота (задача B, §8.2 B3), поэтому оно снимает признак «сделка уже была в горизонте», если тот стоит.

**Секторный лимит активируется отдельным флагом** и обязан отказываться считать, если доля позиций с `sector = null` превышает порог (предлагаю 5% книги). Считать секторный лимит по данным, где почти половина корзины без сектора, хуже, чем не считать вовсе.

### 9.3 Выход

В JSON и в отчётный блок:

- `concentration.by_issuer`: по каждой группе — `value_rub`, `share_pct`, `limit_pct`, `limit_source: "default" | "exception:<id>"`, `headroom_pp`, `breach: bool`, `trim_to_limit_rub`;
- `concentration.by_sector`: то же по кластерам, либо `{"status": "disabled", "reason": "sector_coverage_below_threshold", "null_share_pct": 45.57}`;
- `warnings[]`: `concentration_breach:<группа>`, `exception_expired:<id>`, `sector_limit_disabled`.

Взаимодействие с сайзингом: при нарушении лимита бумага не может быть в `Open` на докупку — это блокирующее условие сильнее арифметического разрыва.

### 9.4 Тест-кейсы задачи C

Снапшот `portfolio-2026-08-21.json`, корзина 42 697 026 ₽.

**C-T1. Группировка и исключение.** `SBER + SBERP = 24 849 288 ₽ = 19,40%`, `limit_pct = 20`, `limit_source = "exception:sber"`, `headroom_pp ≈ 0,60`, `breach = false`. Допуск ±0,01 пп.

**C-T2. Лимит по умолчанию.** Ближайший к порогу из прочих — RENI `13 801 752 ₽ = 10,77%`, `limit_pct = 15`, `limit_source = "default"`, `breach = false`. Ни одна из двадцати групп не в нарушении.

**C-T3. Исключение снято.** Тот же вход без записи исключения → SBER+SBERP проверяется по 15%, `breach = true`, `trim_to_limit_rub ≈ 626 178`.

**C-T4. Истёкшее исключение.** Запись с `review_date` в прошлом → применяется 15%, `breach = true`, в `warnings[]` есть `exception_expired:sber`.

**C-T5. Секторный лимит отключён.** На текущем снапшоте `by_sector.status = "disabled"` с `null_share_pct ≈ 45,57`. Финансовый кластер (20 480 553 ₽ = 47,97% при 35%) **не** должен считаться на этих данных.

**C-T6. Знаменатель.** Доли считаются от `L2_cur = 14 232 342`, не от `T*`. Проверка: при `--open` любого состава `share_pct` по SBER+SBERP не меняется.

### 9.5 На что смотреть ревьюеру задачи C

1. **Знаменатель.** Самая вероятная ошибка — посчитать лимиты от `T*` «для единообразия». Тест C-T6.
2. **Группировка из конфига, а не по суффиксу `P`.** Эвристика сломается на первом же исключении.
3. **Истёкшее исключение обязано деградировать к лимиту по умолчанию**, а не игнорироваться (C-T4).
4. **Секторный лимит на грязных данных не считается вовсе** (C-T5) — «посчитать по тому, что есть» здесь означает выдать уверенное неверное число.

### 10.2 Разделение `cap_breach_after_rounding` (ревью реализации)

Отклонение факта от плана раскладывается на два слагаемых с разными причинами:
`structural_pp = вес_идеальный − w_i` (база не равна пост-трейд книге) и
`rounding_pp = вес_после_округления − вес_идеальный` (лотность). Смешивать нельзя: на живом
прогоне 21.08.2026 в ветке `t_full_no_gates` **без котировок вообще** флаг срабатывал на всех
четырёх тикерах (X5 +0,81 пп, MBNK +0,54, LSNGP +0,40, SBERP +1,08) — то есть когда округлять
было нечего. Предупреждение, срабатывающее на 100% случаев, — шум, из-за которого пропускают
настоящее нарушение.

`cap_breach_after_rounding` реагирует только на `rounding_pp`; структурное отклонение уходит в
`structural_cap_offset` и в отчёт одной пояснительной строкой. Побочно это делает видимой цену
варианта B: в ветке без гейтов цели считаются от полного плана класса, и пока класс недобран,
открытые бумаги действительно занимают долю выше плановой относительно реальной книги — ровно
то, о чём предупреждает `stocks-methodology.md` §«Три варианта денежной базы».

### 10.3 Поправка к задаче B (§8.2 B3) — правило неразворота направленное

§8.2 B3 требует переводить бумагу с признаком «сделка была» в `Dormant` **независимо** от
арифметического разрыва, то есть замораживать в обе стороны. **Это отменяется.** Запрещается
не движение, а разворот:

- Признак направленный: `--acted SBERP=trim`, `--acted MBNK=buy`.
- **Движение в ту же сторону разрешено.** Срезали → можно срезать ещё; докупали → можно
  докупать ещё. Ни повторной комиссии на круг, ни НДФЛ с выкупа, ни обнуления ЛДВ здесь нет.
- **Подавляется только обратное движение.** Тикер, по которому арифметика требует
  развернуться, уходит в `Dormant` с warning'ом — и, раз он больше не двигается, его деньги
  возвращаются в `F`, а база пересчитывается.
- **Срочная продажа проходит всегда:** `--selling` (полный выход) признаку `--acted` не
  подчиняется — приоритет `Selling` и так старше всех.

**Итеративность.** Направление известно только после расчёта `T*`, а перевод тикера в `F`
меняет `T*`. Расчёт сходится: перевод «покупаемого» тикера в `F` строго уменьшает `T*`
(из `c < w·T*`, что и означает «предписана покупка», следует `(F+c)/(1−S+w) < F/(1−S)`), а
множество подвижных тикеров каждый проход строго сжимается — значит не более `|sized|`
итераций. Зацикливание невозможно, но счётчик итераций и warning при недостижении
неподвижной точки обязательны.

### 10.3а Правило «на плане» — в обоих режимах (28.10.2026) — **отменено 11.11, см. §10.7**

Решение владельца: замороженная перевешенная бумага считается стоящей на плане не только в авто-режиме «Сейчас», но и в ручном режиме советника (`--open`/`--trim`): `compute_sizing`, `apply_acted_guard`, `run_sizing` — `frozen_on_plan=True` по умолчанию (CLI-флага для старой арифметики нет; параметр оставлен для тестов-контрастов). Причина: разбор бумаги и сайт называли разные базы одного и того же портфеля. В `report_block` при непустом `frozen_at_plan` — строка «Замороженные бумаги выше плана считаются стоящими на плане и базу не раздувают: …». ### 10.6 Решения владельца 11.11.2026 (2) — каскад одним расчётом, непрерывная база, неразворот, горизонт дат, пауза от покупки

1. **Каскад — весь за один расчёт, в обе стороны** (`run_auto` / `runAuto`). Коридор меряется от книги, поэтому после
   исполнения «Сейчас» доли соседей сдвигаются: срез худеет книгу (соседи выше коридора), докупка растит (соседи ниже).
   Расчёт итерируется: сделки → идеальное исполнение в модели (цели, без лотов) → доли от книги после исполнения →
   переклассификация (выше коридора — срез при «привести к плану», ниже — докупка, если открыта) → снова, пока набор
   торгуемых бумаг не перестанет меняться. Бумага, раз попавшая в сделки, в них остаётся (после исполнения она на плане,
   коридор её не выбрасывает); «держать», «ждать», заблокированные — не торгуются. Итоговый набор пересчитывается от книги
   сейчас (неторгуемые подписываются по своим сегодняшним долям). Предел — число бумаг + 1 проход; набор только растёт,
   поэтому колебания наборов нет, но база может выродиться (открытое ≈ весь класс) — тогда результат первого прохода и
   `cascade.converged = false` (сайт показывает предупреждение). Поле результата — `cascade {iterations, converged,
   added}`, у строки — `cascade: true` для бумаг, попавших в сделки из-за сдвига долей. Докупаемая бумага, у которой цель
   ниже текущей (база меньше её рублей), не торгуется и уходит в F своими рублями — иначе книга после исполнения ≠ база.
   Ручной режим (`--open/--trim`) каскада не делает: набор бумаг называет аналитик; правило неразворота `--acted` не
   затронуто. **§10.3а (перевешенная заморозка «на плане») не выровнен на итерацию:** критерий остаётся против книги ДО
   сделок. Выравнивание против книги очередной итерации даёт ту же цепочку, что §10.3а уже отверг (срез худеет книгу →
   новые «на плане» → база ниже → новые срезы). Цена решения: при непустом «на плане» книга после исполнения больше базы на
   перевес таких бумаг, и повторный расчёт после исполнения может дать сделки — это противоречие правила «на плане»
   инварианту «база = книга после исполнения» (§10.5), решать владельцу (вариант — отменить «на плане» в пользу
   инварианта). На живых данных 11.11 «на плане» пусто.
2. **Непрерывная база.** Ветка «блокировок нет → база = план класса» убрана: база = F / (1 − S) при любом составе F
   (заблокированные и спящие — «держать», бумаги в коридоре — одинаково своими текущими рублями), предел — план класса
   (`fixed_point_capped`). Это и есть «книга после исполнения + деньги до плана класса только в бумаги, которые реально
   докупаются, и только до их плановой доли базы»; без открытых к докупке база = книга после исполнения. План класса
   (`t_full_no_gates`) — только когда в F ничего нет (всё движется к плану). Снятие последней блокировки базу не прыгает:
   бумага переходит из F в S (меняя базу на свой вклад) или остаётся в F (база не меняется). Живые 11.11: снятие всех
   блокировок по очереди (OZON/YDEX/GMKN/DATA, RENI/NVTK/LSNGP/PRMD/PLZL, LENT) — база 43 312 788 ₽ на каждом шаге (раньше
   на последнем — 53 170 488 ₽, +1,1 млн). Цена: недобор «держать» и коридора и нераспределённая доля плана теперь
   не размещаются и без блокировок — они видны в разложении разрыва (п.4). Ограничение формулы: при Σ плановых долей
   < 100 % и «в F ничего нет» книга после исполнения = S × план класса < базы (нераспределённая доля как невидимая
   замороженная бумага); на живых данных недостижимо. Ручной режим считает той же формулой.
3. **Ручной режим классифицирует как авто.** `classify_stocks` для бумаг вне `--open/--trim/--selling`: причины
   блокировки = `_merge_stop_reason(_blocking_reasons, _auto_stop_condition)`, без них — лимит эмитента
   (`concentration_breach:<группа>`, «после среза до лимита концентрации»). Ручная база = `run_auto` на тех же входах
   (`TestManualClassifiesLikeAuto`, фикстура аудита manual_cf).
4. **Разрыв «план − база» — тремя слагаемыми.** При fixed_point (1 − S_eff)·(план − база) = Σ_blocked(w·план − c) +
   Σ_dormant(w·план − c) + нераспределённая доля·план; поля `gap_gated_rub` (недобор заблокированных до своей доли
   плана), `gap_in_corridor_rub` (недобор спящих — «держать», в коридоре; со знаком), `gap_unallocated_rub` (Σ плановых
   долей < 100 %), каждое на (1 − S_eff). Сумма = `blocked_gap_rub` (оставлено для совместимости — весь разрыв). При
   пределе и «в F ничего нет» — нули. Норма кэша советника (`compute_cash_buffer`) берёт только `gap_gated_rub`. Живые
   11.11: 9 857 691 = 1 495 629 + 1 242 120 + 548 148.
5. **Пауза докупки — от первой покупки после решения** (модуль (б), правило 7): конец = дата первой покупки по ключу с
   датой ≥ даты решения BUY/ADD + 21 день; покупки нет — паузы нет. Покупки — `buys_at` (все увеличения количества по
   истории снапшотов), без него — `last_buy_at` (последняя покупка; при одной покупке после решения — она же первая;
   при нескольких пауза длиннее — безопасная сторона). Покупка в день решения считается сделанной по нему (дни снапшотов,
   порядок внутри дня неизвестен). Источник: `decisions_read.trade_times` (советник — история снапшотов рядом с
   `--snapshot`, `security_digest` — снапшоты корня), во вьюере — `dsLastTradeAt`.
6. **Неразворот 14 дней в «Сейчас» (мягкий)** — `defaults.no_reversal_days`. Докупку бумаги, проданной меньше 14 дней
   назад, и срез купленной не предлагаем: строка `reason: no_reversal:<до>`, `unblock_by: <до>`, `no_reversal {until,
   trade: sell|buy, trade_at}`; недобранная — blocked (место в F), перевешенная — dormant. Сделки — по истории снапшотов
   (`last_sell_at` / `last_buy_at`). Снимает событие позже дня сделки: новое решение по ключу (любой источник) или правка
   плана бумаги (`plan_changed_at` — строки журнала плана `stocks.<ключ>.user_plan|plan_pct`; статус исполнения и
   заметки не считаются); событие в день сделки не снимает (решение, по которому сделка, обычно того же дня). Цена не
   снимает. Ручной режим: правило мягкое — разворот в пределах 14 дней допустим только с названным событием.
7. **Горизонт известных дат 7 дней — только для СРЕЗОВ** (`defaults.known_dates_horizon_days`). Недобранная (вне коридора)
   заблокированная бумага, у которой блокировка снимается в известную дату ≤ сегодня + 7 и на эту дату вся картина гейта
   открыта (модуль (б) с today = дата снятия — нет истёкшего срока решения, «наблюдать», «нужен разбор», другой паузы; все
   условия, действующие на ту дату, сняты), для базы срезов считается открытой: `base_trim_rub` (срезы — от неё), докупки
   — от обычной базы, сама бумага сегодня не покупается. Снимаемое: конец паузы докупки, конец IPO-паузы, ожидающее
   условие с триггером «дата», ценовое условие с началом окна (`not_before`), если текущая цена уже за порогом («если цена
   удержится»). Не снимаемое: гейт (срок решения закрывает), отчёт/событие (исход неизвестен), цена без даты, слово
   плана, лимит эмитента. Поля: результат — `horizon` (тикеры), `base_trim_rub`; строка — `opens_on`,
