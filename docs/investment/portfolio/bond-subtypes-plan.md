**Не сломалось.** `_rows_to_dicts` строит словари по заголовку, а не по индексам,

**Молча деградировало — вот настоящая проблема:**

| # | Что | Следствие |
|---|---|---|
| **A** | `metrics.bonds_value_by_type*` группирует только по `Тип`: `{USD, EUR, CNY, ОФЗ: 4 778 730, КОРП: 4 648 734}` | Факт по подтипам не считается вообще. План стал 9-корзинным, факт остался 5-корзинным → **сопоставление план↔факт на уровне подтипа невозможно** |

Дополнительно вскрылись три **уже существовавших** дефекта, которые это изменение
делает нетерпимыми:

- **D. `balance_summary.bonds_value_by_type_excl_iis` в снапшоте отсутствует.**

### 4.2 Лестница рейтингов → подтип КОРП

Национальная шкала (Эксперт РА / АКРА / НКР / НРА), от старшего к младшему:

```
AAA > AA+ > AA > AA- > A+ > A > A- > BBB+ > BBB > BBB- > BB+ > BB > BB- > B+ > B > B-
```

| Подтип | Диапазон | Формулировка владельца |
|---|---|---|
| `AA+` | `AA-` … `AAA` | «всё, что хотя бы AA-» |
| `A` | `A-` … `A+` | «A-, A, A+» |
| `B+` | `B-` … `BBB+` | «всё, что B- и выше» (т.е. ниже `A-`) |

> ⚠️ **Имена корзин ≠ рейтинги.** Корзина `AA+` содержит `AAA`; корзина `B+`
> содержит `BBB+`. Метка — не порог сверху, а ярлык корзины. Любой, кто
> «починит» это по интуиции, сломает разбор. Проверка по живому файлу:
> `AA+` → {AA, AAA, AA-}, `A` → {A, A-, A+}, `B+` → {BB, BB+, BBB-, BBB, BBB+}.

Ниже `B-` — корзины нет: флаг `bond_rating_below_ladder`.

### 4.4 Обратная совместимость

Снапшоты до 2026-08-18 несут `goals_bonds_breakdown` со **старым** ключом
`Рейтинг` и 6 корзинами (`КОРП/AAA`, `КОРП/BBB`). Парсер обязан принимать оба
имени колонки в таблице «План по Облигациям» (`Подтип` приоритетно, `Рейтинг` —
legacy) и нормализовать в производный ключ, **сохраняя исходную строку как есть**.
Мигрировать старые снапшоты не нужно — они read-only исторические.

### 4.5 Корзина выводится, а не вводится (решение владельца 2026-10-28)

Корзина облигации выводится из данных Мосбиржи и рейтинга; руками задаётся только исключение.
Правило вывода (`scripts/bond_bucket.py`, загрузчик):

| Условие (по порядку) | Корзина | `bucket_source` |
|---|---|---|
| валюта номинала (`FACEUNIT`) ≠ RUB | `USD` / `EUR` / `CNY` | `iss` |
| эмитент Минфин РФ (`ISSUENAME` «облигации федерального займа») + переменный купон | `ОФЗ/Флоат` | `iss` |
| эмитент Минфин РФ, иначе | `ОФЗ/>10` при ≥10 лет от даты снапшота до `MATDATE`, иначе `ОФЗ/<10` | `iss` |
| прочее корпоративное | `КОРП/<корзина по лестнице §4.2>` | `rating` |
| иностранный суверен / регион (`TYPE ofz_bond` без фразы про ОФЗ, напр. Казахстан-11) | вывести нельзя — только вручную | — |

- **Источник рейтинга КОРП** (по приоритету): `per_bond[ISIN].rating` последнего обзора облигаций не
  позднее даты снапшота → `plan.bonds[ISIN].rating` (запасной, пока в обзоре рейтинга нет) → нет рейтинга: подтип пуст, флаг `bond_rating_missing`;
  рейтинг ниже `B-` — `bond_rating_below_ladder`. Рейтинг меняется только при новом релизе агентства.
- **Атрибуты Мосбиржи** (`Portfolio/security-types.json`, запись по SECID, поле `bond`): `sectype`, `typename`,
  `matdate`, `faceunit` (SUR→RUB), `facevalue`, `is_floater`, `issuer_type` (`ofz | gov_other | corp`).
  Признак флоатера — слова «переменным купон» / «плавающ» / «ОФЗ-ПК» в `ISSUENAME`/`NAME`: проверяем по тому же
  ответу ISS; корпоративный флоатер без этих слов так не виден (его корзину задаёт рейтинг). Запись справочника
  без блока `bond` дозапрашивается один раз (сеть — только сборка на сайте, как у типов бумаг).
- **Ручная корзина** — запись `plan.bonds[ISIN]` с `manual: true` и `reason`; перебивает вывод
  (`bucket_source: "manual"`, `bucket_reason: "вручную: …"`). Остальные записи `plan.bonds` — режим «вывод».
- **Переходный режим:** итоговая корзина (`plan_bucket_key`) в снапшоте остаётся по плану; если выведенная
  (`bucket_derived`) отличается — флаг `bond_bucket_changed` (было → стало) и `bucket_source: "plan"`, решает владелец.
  Плановой корзины нет — берётся выведенная. Нет справочника или блока `bond` — всё по плану (`bucket_source: "plan"`).
  `bonds_plan_vs_fact` считается по итоговому ключу.
- **Поля holding'а:** `plan_bucket_key` (итоговый), `bucket_source` (`iss | rating | manual | plan`),
  `bucket_derived`, `bucket_reason` («ОФЗ, до погашения 12,3 г.», «КОРП, рейтинг AA- (АКРА, 12.09.2026)»,
  «валюта номинала USD», «вручную: …»). Сводка по снапшоту — `bond_bucket_check {changes, missing, derived,
  attrs_missing}`.
- **Рейтинг в обзоре облигаций:** `per_bond[ISIN].rating {value, agency, date, source}` — необязательное;
  `value` из лестницы §4.2 или «нет рейтинга», `agency` ∈ АКРА · Эксперт РА · НКР · НРА, `date` — YYYY-MM-DD.
  Заготовка обзора переносит прошлое значение, режим 2 обновляет его только при новом релизе агентства.
- **Средняя цена покупки облигации** (по сделкам, отдельно основной счёт и ИИС-3, WACC как у фондов и акций:
  продажа среднюю не меняет, докупка сдвигает): `avg_price_pct` — % номинала без НКД и комиссии; `avg_cost_rub` —
  ₽ за бумагу без НКД (сделка в валюте — по курсу ЦБ на дату сделки); `avg_includes_accint` — true, если в сделке
  нет цены/номинала и взята сумма с НКД (тогда `avg_price_pct` null); `avg_cost_source` — `trades`, а у ИИС-3 без
  новой выгрузки — `carried` (из прошлого снапшота при том же количестве). Выгрузка основного счёта содержит и сделки
  ИИС-3, поэтому они вычитаются из неё по ключу тикер · операция · дата · количество · цена.

    тестом. При нехватке любого входа проверка молча пропускается.

## 6. Порядок исполнения и распределение

Строго последовательно по волнам: RPA/PSS/STL читают контракт, который создаёт PDL.

| Волна | Пакет | Кому | Почему так |
|---|---|---|---|
| 1 | PDL-1…7 (код) | субагент Sonnet #1 | Ядро контракта, один файловый кластер |
| 1 | PDL-10 (тесты) | тот же агент, после кода | Тест пишется против свежего кода |
| 2 | RPA-13…15, PSS-12…14 (код) | субагент Sonnet #2 | Оба — потребители `plan_subtype`, общий контракт |
| 2 | RPA-8…12, RPA-16 (доки скилла) | субагент Sonnet #3 | Чистый текст, не конфликтует с #2 |
| 3 | STL-7…9 | субагент Sonnet #4 | Зависит от финального имени полей |
| 3 | PDL-8, PDL-9, DOC-1…5 | субагент Sonnet #5 | Документация — после того как код устоялся |
| 4 | Проверка | основная модель | См. §7 |

Волны 2 и 3 — внутри волны агенты параллельны, между волнами — барьер.
Согласно `feedback_agent_model_tiering`: fan-out ≥3 — только Sonnet, и выдать
разрешения на `Bash`/`Edit`/`Write` заранее, иначе агенты будут дёргать
подтверждение на каждый файл.

**Каждому агенту в промпт обязательно:**
- ссылка на этот файл + §4 (контракт) целиком, без пересказа;
- `python3` сломан → `~/.pyenv/versions/3.12.9/bin/python3`;
- имя файла с NBSP: `examples/Общий баланс\xa0— копия 4.numbers`, открывать через
  `glob.glob('examples/*.numbers')`, прямой путь строкой не работает;
- вернуть **резюме**, а не диффы.
