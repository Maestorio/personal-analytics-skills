**Статус:** ✅ закрыт 2026-10-30 — вьюер 4.0.0, итоговая сверка — §5b. Ниже — история работ.

**Было:** 2026-10-27 — решения владельца по §5 приняты, этап 1 в работе (этап 5 плана
`tools/design-reference/viewer-rethink-plan.md`, инвентарь — его §4). Источник для сверки колонок — «Общий баланс — копия 4.numbers»
(iCloud, 26.10.2026): листы «Общий баланс · Акции · Облигации · Импорт Акции · Импорт облигации · Ребаланс · Invest Era». Заготовка и история вопроса — `TODO-numbers-exit.md` (пункты 1–8 оттуда входят сюда).

## 1. Цель и границы

Сегодня план портфеля (доли по бумагам и классам, статусы KEEP/BALANCE/WAIT, заметки IE/AI, корзины облигаций, «Действие»
по облигации, цели IE) живёт в `Общий баланс.numbers`; загрузчик (`parse_portfolio.py`) читает его вместе с выгрузкой
IntelInvest. Цель: IntelInvest даёт сделки и позиции, **наш сервис — план**; Numbers не нужен. Не цель: заменить IntelInvest,
менять формат снапшота для потребителей (поля `ie_actual.per_ticker`, `ie_model`, план корзин — те же).

Требования владельца (13.10, 26.10): правка долей и статусов с сайта (карточка «Мой план», «Доли и цели»), два сценария ввода
модели IE (импорт webarchive с diff и комментариями причин · правка одной доли окном), экспорт для офлайн-проверки и обратный
импорт, один писатель файла плана с `base_hash` и журналом «кто/когда/было → стало/почему», переходный период с чтением обоих
источников и показом расхождений.

## 3. Архитектура

### 3.1 Схема `plan.json` v1 (`schema_version: plan@1.0`) — контракт этапа 1

Все значения — ровно те, что сегодня даёт `parse_portfolio.py` из Numbers (конвертер `numbers_to_plan.py` — чистое
переложение `portfolio.json → plan.json`, без интерпретации). Единицы — как отдаёт парсер: `classes`, `matrix`, `bond_buckets` —
доли единицы (0.4), `stocks.*_pct` и `ie_model` — проценты (10.0); имя поля говорит о единице (`share` против `_pct`). Ключи бумаг — тикер (акции) и ISIN (облигации), как в снапшоте.

| Ключ | Откуда в `portfolio.json` | Содержимое |
|---|---|---|
| `schema_version`, `generated_at`, `updated_at`, `updated_by` | — | `plan@1.0`; дата разбора; кто писал (`numbers_to_plan.py` на этапе 1, `hub-api` с этапа 2) |
| `source` | метаданные | `{kind: numbers, file, extraction_date}`; с этапа 2 — `{kind: site}` |
| `classes[]` | `goals.overall` | `{class: Акции, share: 0.4}` × 5 классов (Акции · Облигация · Золото · Другое · Кеш) |
| `matrix[]` | `goals.matrix` | `{currency: RUB, class: Акция, share: 0.4}` — только план (факт считает загрузчик) |
| `bond_buckets[]` | `goals.bonds_breakdown` без итоговой строки | `{key: "ОФЗ/>10", type: ОФЗ, subtype: ">10", share: 0.3}` — 9 корзин |
| `stocks{T}` | `ie_actual.per_ticker` (нормализован парсером) | `{plan_pct, user_plan, user_status, note_ie, note_ai, ie_new_pct, ie_old_pct}`; только тикеры, где хоть что-то задано (27.10: 24, из них с `plan_pct` — 20). `user_plan` — коды `USER_PLAN_RU`; `user_status` с сайта — коды `USER_STATUS_RU` (DONE/DEFERRED/ORDER/NOTED: сделал / отложил / поставил заявку / запомнил, решение 27.10), старый текст из Numbers остаётся как есть |
| `ie_model` | `ie_model` | как есть: `extraction_date`, `model_total_pct`, `positions[]`; с этапа 3 (27.10) — `cash_pct`/`cash_ticker` (строка «Кэш LQDT» модельной страницы), у позиций из общего портфеля IE `active_in_model: false` (потенциалы без доли) и ключи `industry`, `target_price_rub`, `target_price_lt_rub`; `extraction_date` — дата последнего импорта webarchive |
| `ie_history[]` | — (этап 3, только сайт) | только дописывание: `{ts, date, ticker, was, now, reason, source: site\|webarchive}` на каждое изменение доли IE — «доля IE с <дата>, было N %» в карточке, таблице и окне; в сверке с Numbers не участвует |
| `bonds{ISIN}` | `bonds[]` | `{name, type, subtype, rating, action, iis_qty}` — только активные (`Всего` > 0) или с заполненными полями |
| `manual_positions[]` | `other_positions` | `{type: "USD - Другое", name: TGLD, value_rub}` — на этапе 5 останется только FINAMAR (решение §5.5) |

Обратное преобразование `plan_to_portfolio_fragments(plan)` возвращает те же куски в форме `portfolio.json`
(`goals`, `ie_model`, `ie_actual`, `other_positions`, типизацию `bonds[]`), чтобы `assemble_snapshot.py` с этапа 6 собирал
снапшот без Numbers теми же ветками кода. На этапе 1 оно же даёт сверку: `plan_diff` = расхождения между кусками из Numbers
и кусками из `plan.json` (список `{path, numbers, plan}`), снапшот получает блок `plan_check {source, plan_file, plan_updated_at,
n_diff, diff[]}`, `checks.py` — предупреждение `plan_mismatch` при `n_diff > 0`.


### 3.2 Этап 4 — контракт (27.10.2026 вечер): классы, матрица, корзины, облигации, фонды

Факты из сверки матрицы Numbers (лист «Планы», 26.10) со снапшотом: «Кеш RUB» = деньги брокерского счёта + TMON + TPAY ·
«Акция RUB» = акции без замороженных (замороженные US вне матрицы) · «Облигация <валюта>» = облигации по валюте номинала
(+ TLCB в USD) · «Другое USD» = TGLD · «Другое RUB» = Рентал ПРО + FINAMAR · ИИС-3 вне матрицы (своя строка «ИИС»);
сумма ячеек = `total_current_rub_excl_iis`. Корзины облигаций загрузчик уже считает по holdings (`_build_bonds_plan_vs_fact`),
фонды-члены валютных корзин берёт из «Таблицы 1» — с этапа 4 их место занимает карта фондов плана.

**Данные (plan.json, аддитивно):**
- `funds{T}` — `{class, currency, in_rebalance, bucket, note}`: `class` ∈ Кеш · Акции · Облигация · Золото · Другое, `currency` ∈
  RUB · USD · EUR · CNY, `bucket` — любой из девяти ключей корзин или null, `in_rebalance` — участвует ли в
  балансировке. Стартовая карта владельца: TMON, LQDT, TPAY (владелец 27.10: как в Numbers — кеш) → Кеш RUB · TGLD → Золото USD ·
  TLCB → Облигация USD, корзина USD · XXXXXX (Рентал ПРО) → Другое RUB · SBGB → Облигация RUB, `in_rebalance: false` (только ИИС-3)
  · FINAMAR → Другое RUB, `in_rebalance: false`. Фонд со стоимостью > 0 без записи — «не отнесён» (загрузчик: флаг `fund_unmapped`,
  вьюер — подсветка).
- `classes[]`, `matrix[]`, `bond_buckets[]` — как в §3.1; матрица получает строку `USD/Золото` (вместо «Другое USD» — владелец
  27.10), строки с нулевой долей остаются. `bonds{ISIN}` — `type`, `subtype`, `rating`, `action` (текст ≤200), `iis_qty`.
  `manual_positions[]` — после этапа 4 только FINAMAR (`value_rub` вручную), остальные строки «Таблицы 1» заменяет карта фондов.

**API (`PLAN_PATH_RULES`, через тот же `POST /api/pv/plan/set` пакетом):** `classes.<Класс>.share` и `matrix.<CUR>/<Класс>.share`
(доли единицы 0..1; класс и валюта — из словарей, строки создаются по ключу), `bond_buckets.<ключ>.share` (0..1; 9 ключей),
`bonds.<ISIN>.(type|subtype|rating|action|iis_qty)` (тип/подтип — из словаря корзин, запись создаётся), `funds.<T>.(class|currency|
in_rebalance|bucket|note)`, `manual_positions.<type>/<name>.value_rub`. Элементы списков адресуются ключом (класс; валюта/класс;
ключ корзины; тип/имя) — общий сеттер для словарных и ключевых путей; журнал — те же пути. Сумма долей классов и корзин ≠ 100 %
сервер **не** запрещает (окно предупреждает), иначе нельзя править по одному полю.

**Загрузчик (`assemble_snapshot --plan`):** факт по классам и матрице считается из holdings + `cash` + карты фондов →
`balance_summary.class_plan_vs_fact[]` `{class, target_pct, target_rub, actual_rub, actual_pct, delta_pp, delta_rub}` и
`matrix_plan_vs_fact[]` `{currency, class, …}` (база — без ИИС-3, как у корзин); корзины: фонды-члены — из карты (`bucket`),
«Таблица 1» — запасной путь, пока Numbers главный. Паритет с матрицей Numbers (`goals.matrix[].Сейчас`) на одном дне —
тест `test_class_breakdown.py` с допуском по дате цен; расхождение по ячейке ≥ 1 % — флаг `class_fact_mismatch`.

**Вьюер (3.71+):** «Доли и цели» → карточки «Цели по классам» (план · факт % · факт ₽ · отклонение; карандаш → окно всех пяти
долей с контролем суммы), «Валюта × класс» (то же окном), «Фонды» (фонд · класс · валюта · стоимость · доля · в балансировке;
класс и валюта — списками в строке, «не отнесён» подсвечен); «Облигации» → у таблицы план ↔ факт карандаш → окно девяти корзин;
карточка облигации → «Мой план»: корзина списком и «Действие» текстом; **карточка фонда** (новый вид карточки: состав класса,
стоимость, доля, цена и история по снапшотам, XIRR из `per_instrument_xirr`, «Мой план» = карта). Телефон — окна одной
колонкой, списки компактные. Режим балансировки с фондами («Сейчас» по классам и корзинам: куда сколько ₽ — не лоты) — подэтап
4d после паритета факта; «когда TMON, а когда LQDT» — задача советника.

**Порядок:** 4a сервер (пути и сеттер, тесты) ∥ 4b загрузчик (факт по классам, паритет) → 4c вьюер (карточки, окна, карточка
фонда) → 4d балансировка с фондами. Версию вьюера поднимать последним шагом (кэш).

**4d — сделано 3.77 (28.10):** база «Общие доли» на «Долях и целях» (первая в сегменте баз): плитки (база без ИИС-3, вне коридора, кеш всего, свободно сверх плана кеша), «Цели по классам» с карточкой «Что перевести» под ними, «Цели по облигациям», журнал плана. «Что перевести» — деньги, не лоты, отдельно по классам и по корзинам облигаций: строки выше плана больше чем на коридор (±1 п.п.) — источники (излишек = факт ₽ − план × база), строки ниже плана больше чем на коридор — приёмники (недобор); сумма перевода `S = min(Σизлишков, Σнедоборов)`; в разделе два списка: «Отдать» (−`S × излишек_i/Σизлишков`) и «Получить» (+`S × недобор_j/Σнедоборов`), итог «перевести S»; пар «из X в Y» нет; округление до рубля, меньше 1 000 ₽ не показывается; нет источника — «пополнение или сокращение другого класса». Только во вьюере, без зеркала в Python (решение §5 п.17). Закрытые вопросы: строка ИИС-3 отдельно — нет; фонды с `in_rebalance: false` — факт класса из снапшота берётся загрузчиком как есть, в «Что перевести» пометка «FINAMAR и фонды вне балансировки в факте классов учтены загрузчиком; их не трогаем».

- **Файл:** `Claude-Memory/Portfolio/plan.json` (`schema_version: plan@1.0`, `updated_at`, `updated_by`, разделы из §2).
  Один писатель — `hub-api` `/api/pv/plan*` (зона `/api/pv/*`: пароль с любого IP, Caddy без изменений; `/api/pf/*` занят
  hub-notify — сборкой снапшота; исключение D3 по образцу `Food/` и `ZenMoney/zenmoney-map.md`; строка в
  `_shared-references/claude-memory-layout.md`). Журнал — `Portfolio/plan-journal.jsonl` (только дописывание: `ts, who, path,
  was, now, reason`); копии прежних версий — `.versions/` как у `/api/job/save`.
- **API (NAS, `tools/hosting/api/server.py`):** `GET /api/pv/plan` (файл + `hash`), `POST /api/pv/plan/set`
  (`{path, value, reason, base_hash}` — одно поле за раз; `base_hash` не сошёлся → 409 и свежий файл; разрешённые пути —
  `PLAN_PATH_RULES`, этап 2: `stocks.<T>.(plan_pct|user_plan|user_status|note_ie|note_ai)`), `GET /api/pv/plan/journal?limit=N`,
  `POST /api/pv/plan/ie-import` (этап 3, 27.10: тело `{name, b64, tickers}` — webarchive Safari или голый HTML, лимит 16 МБ; разбор по заголовкам
  колонок → `{kind: model|general, positions[], cash_pct, diff[{ticker, status: changed|new|removed|same, share{was,now}, fields{…}}], ignored[]}`, без записи),
  `POST /api/pv/plan/ie-set` (единственный писатель полей IE: `{base_hash, source: site|webarchive, extraction_date, cash_pct, changes[{ticker, share_pct?, note_ie?, reason, position?}]}`
  — смена доли пишет `ie_old_pct`/`ie_new_pct`, позицию модели, строку `ie_history` и одну строку журнала `stocks.T.ie_new_pct`; позиция — журнал `ie_model.positions.T`
  с объектами «было/стало»; `set` поля IE не принимает),
  `GET /api/pv/plan/export?fmt=xlsx|json`, `POST /api/pv/plan/import` (обратный путь из экспорта с diff и подтверждением).
  Разбор webarchive — stdlib (`plistlib` + `html.parser`), проверен 26.10 на обеих страницах IE.
- **Загрузчик** (`parse_portfolio.py` → `assemble_snapshot.py`): флаг `--plan plan.json`; переходный период — оба источника,
  снапшот получает `plan_source: numbers|plan.json|both` и `plan_diff[]` (расхождения по полям); `checks.py` — предупреждение
  при расхождении. Серверная сборка (`pf_build.py`) передаёт `--plan` всегда (у сайта Numbers нет).
- **Вьюер:** «Доли и цели» и карточка — кнопки «изменить» оживают (сейчас `disabled` с подсказкой про §4); окна стопкой
  (`uiModalHTML`, как «к прошлому году» в «Деньгах»); после записи — перерисовка от `plan.json`, колонка «Сейчас» считается от
  нового плана живым движком (`rebalance-engine.js`). Плашка «План менялся» в условиях уже читает `context.plan_pct` (3.57.0).
- **Советник и стресс:** не трогаются — читают снапшот.

### 3.3 Этап 5 — контракт (27.10.2026): экспорт и импорт плана

- **Форматы.** Экспорт — JSON (байты `plan.json` как есть, заголовок `X-Plan-Hash`) и XLSX (только просмотр). Импорт — только
  JSON. CSV не делается (решение владельца).
- **Листы XLSX** (русские заголовки, числа числами, доли — в процентах): «Акции» (тикер · план, % · план словом · статус ·
  доля IE, % · была доля IE, % · заметка IE · моя заметка), «Классы», «Матрица», «Корзины», «Облигации» (ISIN · название · тип ·
  подтип · рейтинг · действие · количество на ИИС), «Фонды», «Ручные позиции», «Модель IE» (шапка: дата модели, дата общего
  портфеля, кэш; ниже позиции), «История IE» (`ie_history[]` построчно).
- **Импорт.** `schema_version` строго `plan@1.0`; неизвестные верхние ключи и поля — отказ; поля проверяются теми же правилами,
  что `set`; до записи считается diff (по ключам строк списков, допуск чисел 1e-9) и показывается в окне; запись требует
  причину (на сайте) и `base_hash`; пустой diff ничего не пишет. В журнале — одна строка `kind: "import"`.
- **Что не импортируется / не сравнивается:** `generated_at`, `updated_at`, `updated_by`, `source` (служебные; после импорта
  `updated_by: hub-api`); XLSX в обратную сторону; порядок строк списков.

### 3.4 Этап 6 — контракт (28.10.2026)

Сделки без баланса + `plan.json` собираются штатно: план главный сам (флаг `--plan-primary` нужен только при наличии Numbers — переключение балансного режима остаётся решением §5.6). Из плана: цели классов, матрица, корзины, типизация облигаций (`bonds` по ISIN, количество на ИИС-3 план не перезаписывает), модель и доли IE, стоимость FINAMAR (`manual_positions`; биржевые фонды и бумаги — цены MOEX, п. 5 решений); факт IE (доля реальная, дельта), колонки формул листа («Сейчас», «Планы», «План сумма», …) и `ie_summary` считает загрузчик из holdings. Из прошлого снапшота переносится лишь то, чего нет ни в плане, ни в сделках, ни в котировках: позиции ИИС-3 (сделок счёта нет), дрейф кеша без факта владельца, названия и номинал без котировки, облигации вне `plan.bonds`, цена внебиржевой без плана. Без `plan.json` — прежнее поведение (всё из прошлого снапшота) с флагом `no_plan_for_trades_mode`. Паритет: `build_snapshot.py` сверяет сборку без баланса со снапшотом того же дня с балансом (`parity`, законные различия — `parity-known-diffs-nobalance.yaml`; стоимость FINAMAR, позиции, класс/матрица факта — не известные), расхождения не блокируют. Переключение балансного режима Numbers → план (`--plan-primary` по умолчанию) — только после месяца и не меньше трёх сборок с `parity.diverged == 0`.
