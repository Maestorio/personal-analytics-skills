## 1. Монитор различает «ревью просрочено» и «горизонт прошёл»

**Проблема.** Монитор для прогноза с прошедшим горизонтом пишет «ревью просрочено» и предлагает «обнови». Пример: `usd-rub-sept-2026` (горизонт 01.09.2026, курс ЦБ 86,38 при центре 85–90 — сбылся) — обновлять нечего, нужно закрыть с исходом, чтобы исход попал в калибровку.

**Что сделать.**
- `skills/forecast-monitor/SKILL.md` + шаблон отчёта: новая категория `horizon_passed` (отдельно от `review_overdue`). Признак — `forecast.horizon` (или последний горизонт сетки) < даты прогона. Фраза действия: «Закрой прогноз <тема>: на <дата горизонта> <факт>, прогноз <центр/диапазон> — сбылся | не сбылся», при паре «прогноз + сценарии» — закрыть обе записи одной фразой. Факт монитор уже ищет в сети («Проверено в сети»).
- Валидатор отчёта монитора (save-to-library, `validate_monitor_report`) — категория в перечне.
- Закрытие с исходом — вход save-to-library «Закрой прогноз» (`references/close-forecast.md`), фраза монитора ведёт в него.
- Вьюер: у `horizon_passed` метка «горизонт прошёл» и другая подсказка; в «Сделано» уходит после закрытия (status resolved/superseded).

## 2. Вьюер не путает «прогноз» и «сценарии» одной темы

**Проблема.** По одной теме бывает пара файлов: прогноз (`forecasts/<тема>-ДАТА`) и сценарная матрица (`scenarios/scenario-<тема>-ДАТА`). Монитор ссылается на один из них, и фраза «Обнови сценарии …» читается как «а почему не прогноз». В строке сценарной матрицы подпись «прогноз от 30.04» (3.109), хотя это сценарии.

**Что сделать.**
- На «Действиях» предупреждения по одной теме (прогноз и сценарии) — одна строка; под названием «прогноз от ДД.ММ · сценарии от ДД.ММ», окно открывает оба файла вкладками «Прогноз · Сценарии».
- Подпись по виду файла: «сценарии от ДД.ММ», а не «прогноз от».
- Фраза для Claude — по причине (п. 1): «обнови прогноз» / «обнови сценарии» / «закрой с исходом»; если у темы есть оба файла и обновлять надо оба — две фразы.
- Метка роли (3.111) — общая для пары.
- **Плашка роли в заголовке строки** (владелец 29.10: «чтобы сразу было видно, самостоятельный прогноз или часть комплекса»): рядом с плашкой важности (HIGH) — тег ui-kit «в стресс-тесте» (акцентный) или «самостоятельный» (приглушённый), у пары «прогноз + сценарии» — один тег; подробная метка («входит в стресс-тест от 04.10 · фактор: ставка ЦБ (по названию) · есть новее») остаётся строкой ниже. Тот же тег — в шапке окна прогноза. Фильтр на «Действиях» не нужен.
- Тест: кликом по «Действиям» на живых парах (`usd-rub-sept-2026`, `brent-dec-2026`, `ai-capex`).

## 3. Окна документов стопкой

**Проблема.** Окно «Gate» (и любой документ) и окно отчёта — одно окно сайта (`#modal`, слой 300). Карточка, открытая поверх документа, встаёт на слой 320. Отчёт из такой карточки открывается в том же `#modal` — под карточкой: его не видно, а «Gate» подменён. То же в цепочке «отчёт → карточка → другой отчёт».

**Что сделать (выбран вариант «стопка», владелец 29.10).**
- Документы — стопкой, как карточки (`uiStack*` ui-kit): каждый документ, открытый поверх карточки, — новое окно выше неё; «← К бумаге», Esc и клик по фону закрывают только верхнее окно с анимацией ухода; под ним — карточка, под ней — исходный документ («Gate», отчёт, список «Мои репорты»).
- Глубина стопки — без искусственного предела, но листание карточек ← → внутри стопки работает только в верхней карточке.
- Тест по реальному пути: «Gate» → бумага → «Отчёты» → отчёт → «← К бумаге» → Esc → видно «Gate»; и «Мои репорты» → отчёт → чип бумаги → отчёт из карточки → назад по цепочке.
- Справка 04-tabs (сгиб «карточка бумаги»): одна фраза про возврат по цепочке.
