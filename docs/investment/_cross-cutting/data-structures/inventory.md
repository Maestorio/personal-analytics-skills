### 0.1 TL;DR

1. **Вывод разбора бумаги не существует как поле.** Из Mode 4 структурно выходит только директива гейта
   (`new_status`, дата, причина прозой); вердикт, целевая доля, триггеры пересмотра и срок остаются текстом раздела
   «Рекомендация». Mode 3 и Mode 8 не выдают по бумаге ничего машинного, кроме пакетных директив гейта.
   Валидатора отчётов `reports/` в save-to-library нет, frontmatter проверяет модель. [AK] Нет структуры отчетов этих режимов. так как сначала не предполагалось их сохранение. Потом добавили, но назвали режим сохранения другое с минимальными требованиями к форматированию
2. **«Последнего слова» по бумаге нет ни в одной базе**, а три слоя говорят на разных словарях: гейт
   (`reviewed_*`), вердикт обзора (`HOLD/TRIM/...`), план владельца (`KEEP/BALANCE/...`). Вьюер собирает статус из
   пяти источников по типу источника; сравнение по дате есть только в заплатке 3.114 для гейта и отчёта.
3. **Времени суток в реестрах нет вообще:** 0 из 28 записей гейтов, 0 из 155 событий истории гейтов, 0 из 31
   событий условий, хотя код пишет поля с 28.10. `created_at` отчёта — оценка модели (GMKN: 17:40 при записи
   файла 17:34). Порядок событий внутри дня восстанавливается только по mtime файлов. [AK] Время появилось недавно. И то записалось скриптом в отчеты, и не во все
4. **Производные (`securities/`, журнал решений) пересобираются только при сохранении снапшота:** задержка от
   3 часов до 4,5 суток. Индекс `securities/` при этом **не читает никто** — ни вьюер, ни уведомитель, ни скиллы;
   раскладка хранилища утверждает обратное. [AK] Проверить надо, что никто не использует. Ну не просто так же добавили его без дальнейшего использования (хотя это и возможно)
5. **Условия — самое слабое звено операционного цикла:** срабатывание по дате фиксируется только при записи
   обзора (MDMG: 7 дней), сработавшие условия удаляются следующим обзором вместе с историей, «следующее действие»
   после исполнения — проза, движок «Сейчас» сработавшие условия игнорирует. [AK] Я иногда могу не сразу отработать условие. К примеру, если есть требование отчета, а отчетность еще не вышла. или я был занят для проверки и продажи бумаги. Поэтому это нормально, что действие за срабатыванием условия не сразу происходит (или отсутствие действия, как вместо среза NVTK было решено сделать анализ бумаги с последующим сохранением в портфеле)
6. **Главный класс реальных ошибок за 60 дней — копии без синхронизации (K3), не парсеры (K10):** из 50 случаев
   K3 — 12 основных и 18 с пересечениями, K10 — 2 и 4. Парсеры — структурный риск: почти каждый выбор источника во
   вьюере и в выжимке советника опирается на свободный текст (`mode` — 28 написаний, 7 форм директив гейта).
7. **Прогнозы:** дата и версия прогноза теряются на шаге «прогноз → макровход» (остаётся тема и дата спота); стресс
   на `forecasts/` не ссылается; обзор акций на стресс не ссылается полем; обзор облигаций и стресс стоят на разных
   бандлах; `stale_flags.yaml` никем не читается машинно; категория `horizon_passed` монитором не ставится. [AK] Да, мы это обнаружили, когда пытались в действиях просто хотя бы отобразить, какой прогноз часть macro-forecast-chain,  а какой индивидуальный. Надо бы как-то связать. При этом, если прогноз в середине цепочти чуть-чуть меняется (заменяется на новый), то надо как-то будет внутрь цепочки новый вставить. Надо подумать про это.
