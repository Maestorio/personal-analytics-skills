## Почему этот прогноз

Критерий §3.1: «входит в действующий стресс-тест (stress-2026-10-04) И по нему монитор давал предупреждение за 60 дней».
- Входит в стресс: `macro-chain/macro-scenarios-2026-10-04.yaml` → `factors.brent_price` (бумага `source_forecast: 'brent'`), стресс 10-04 → `macro_input: macro-scenarios-2026-10-04.yaml`, `baseline_spot.brent_price`, фактор `brent` в `factor_definitions`.
- Монитор: 3 предупреждения `factor_breach` по теме `brent-price` (28.08, 03.09, 08.10; severity HIGH) + каскад `stale_flags.yaml` (usdrub-rate, 08.10).
- Бонус выбора: прогноз **пересобран после** стресса (10-08 09:48 против стресса 10-04 13:56) — виден чистый случай «в стрессе версия не последняя». Кандидаты «ставка ЦБ» (`cbr-rate-2026-2027-2026-09-17`, пробой HIGH только 26.10) и USD/RUB (только `event_window` 28.08 и flag-каскад) дают более короткую цепочку.

## Где по пути теряется дата прогноза

1. **Прогноз → макро-вход.** Контракт «у каждого фактора `source_files`» (`macro-forecast-chain/SKILL.md:725`, `scripts/check_source_files.py`) введён 29.10 (коммит 55ba1f62); во всех бандлах 08-15…10-04 `source_files` нет (grep: 0). Реально: `factors.brent_price.source_forecast = 'brent'` (тема) и `fact_anchor.as_of` (дата спота). Файл и версия прогноза — только в прозе (`macro-scenarios-2026-10-04.yaml`, строка 833).
2. **Макро-вход → стресс.** В стрессе от прогноза остаются: `macro_input` (имя файла бандла = дата сборки), `baseline_spot` без дат, `scenario_matrix_ref`; в `caveats` — «идентично бандлу 09-17» (проза). Ссылок на `forecasts/*.yaml` в стрессе нет. Свежесть стресса всюду считается по `stress.date` (`stress_digest.py:696-699`, лестница 30/60 дн — только Mode 3 и 8), поэтому устаревшая внутри версия прогноза скрыта.
3. **Стресс → обзор недели.** В обзоре акций нет поля-ссылки на стресс (`macro_input: null` в 10-16/26/28); упоминания «Stress h12 EV…» — в тексте `advisor_verdict_basis` (7 вхождений «стресс» в обзоре 28.10). Обзор облигаций ссылается на бандл 09-17, а не на 10-04 (разные версии в одном цикле).
4. **Монитор → стресс/обзор.** Предупреждение несёт `target_file` и `detected_at`, но вернуться к «входит ли в действующий стресс» монитор не умеет: в `freshness_audit` стресс — просто файл с возрастом. Связь «прогноз ⊂ стресс» восстанавливает только вьюер (`viewer.js:3341-3367` `stressInputs()`: по теме и дате ≤ даты сборки, метка «по названию»).
5. **Монитор → `stale_flags`.** Флаг — две темы и серьёзность, без файлов, версий, ссылки на отчёт; «флаг сохранить» решается прозой в `caveats`. По SKILL (Шаг 6b) файл должен перезаписываться каждым запуском, фактически — не перезаписывался с 10-08 (3 запуска).
6. **Обновление прогноза не идёт вниз.** 10-08 09:48 прогноз Brent пересобран; стресс 10-04, бандл 10-04, интегрированный вид 10-04 остаются; «есть новее» показывает только вьюер (`stressRoleOf`, `viewer.js:3369-3391`) по сравнению дат в именах файлов.
7. **Время.** `generated_at` монитора 10-26 (21:40Z = 00:40 МСК 26.10) и v2 (11:25Z = 14:25 МСК) позже mtime файлов (00:34 и 14:17); `created_at` отчётов тоже расходится с mtime (GMKN: +6 мин). Внутри дня порядок «монитор → пересбор → обзор» надёжно восстанавливается только по mtime.
