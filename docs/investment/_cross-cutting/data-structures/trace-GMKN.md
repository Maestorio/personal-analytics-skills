## Где цепочка рвётся (данные)

1. **Вердикт разбора — проза, не поле.** Решение «держать на плане, добор закрыт» и три триггера «срезать» (цена металла, гайденс, налог) лежат только в теле отчёта (разд. «Выводы / Action items»). Машинно у отчёта: `fm.tickers`, `kind/mode` и блок `gate_review_update` (статус гейта + `reason` прозой + `cooldown_weeks/valid_days`). Условий по GMKN в `conditions.yaml` нет (0 строк с ticker=GMKN) — триггеры среза не заведены. Класс K2/K10/K12.
2. **Последнее слово обзора устарело на момент 29.10 17:30.** Последняя запись по GMKN в `weekly-reviews` — обзор 28.10 (mtime 12:08): `advisor_verdict=HOLD`, `gate_status_snapshot=reviewed_keep@02.10/mode_4`. Копию гейта в обзоре никто не обновляет после записи реестра (K3); нет поля «после этого обзора был разбор/смена гейта» (K1).
3. **Время есть не везде и расходится.** `gate-reviews.yaml` — только `set_date`/`history.date`, `set_time`/`history.time` отсутствуют, хотя код с 28.10 19:15 их пишет (эта запись 29.10 сделана без них — какая копия скилла исполнялась, не проверено). Порядок внутри 29.10 восстанавливается только по mtime: гейт 17:30:47 → файл отчёта 17:34 → `created_at` в отчёте 17:40 (на 6 мин позже файла). Метки в именах `.backups` (1733, 1742) на 3–8 мин впереди mtime. Класс K6.
4. **Производный индекс отстаёт.** `securities/GMKN.json` пересобирается только со сборкой снапшота (`built_at 2026-10-30T15:07:29+03:00`); по плану §0 после 29.10 11:00 разбора в нём не было; версий индекса нет (`securities/` без `.versions`) — что именно показывал индекс между 29.10 17:34 и 30.10 12:26, восстановить нельзя (не проверено). Класс K4.
5. **План-доля.** План живёт в `plan.json` (сайт) и `plan-journal.jsonl` (журнал только с 27.10 08:20 UTC). По GMKN в журнале: 27.10 запись `ie_model.positions.GMKN` целиком; 28.10 13:09 МСК `user_plan` KEEP→BALANCE→KEEP за 10 секунд, `reason=null`.
