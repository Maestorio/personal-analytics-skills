# Открытость системы и портфолио

## Стоит ли делать систему открытой?

### Что имеет смысл открыть

**Инфраструктурный слой** — наиболее ценная часть для сообщества:

- Фреймворк скиллов: структура `SKILL.md`, механика `pack.sh`, соглашения по именованию и транспорту
- Python-скрипты без доменной специфики — по сути standalone CLI-утилиты с хорошим покрытием тестами:
  - `weighted_consensus.py` — агрегация прогнозов с весами доверия
  - `monitor_alerts.py` — детерминированный движок алертов с каскадированием
  - `retro_metrics.py` — матрица оценки качества прогноза
  - `coverage_report.py` — age × horizon coverage с автоматической рекомендацией режима
  - `sync_planner.py` — агрегация + diff + eviction для синхронизации памяти
  - `assemble_artifact.py` — schema validation перед записью в библиотеку
- Архитектурный шаблон: data-pipeline с детерминированными скриптами + LLM-оркестрацией

### Что не стоит открывать сразу

- `ru-portfolio-advisor`, `portfolio-data-loader` — специфика MOEX и российского рынка, узкая аудитория
- Пути к `Claude-Memory`, структуры личных данных — приватная инфраструктура
- Скиллы с жёсткой привязкой к личным источникам (конкретные аналитики, каналы)

### Почему это интересно сообществу

Реальный интерес представляет **архитектурный паттерн**:

> LLM как оркестратор + детерминированные Python-скрипты как исполнители + файловая БД с версионированием и audit trail

Этот паттерн редко оформлен в полноценную рабочую систему. Большинство публичных примеров — либо игрушечные демо, либо монолитные агенты без разделения ответственности. Здесь:

- Чёткое разграничение: что считает LLM, что считает скрипт
- Идемпотентность: каждый скилл воспроизводим при тех же входных данных
- Schema validation на входе в хранилище
- Версионированные артефакты с frontmatter
- Каскадирование состояния (stale_flags) между скиллами

### Практический путь к открытию

1. README на английском с архитектурной диаграммой (`docs/investment/_cross-cutting/skill-system-map.html`)
2. Выделить общие скрипты в отдельный пакет (`skill-utils` или аналог)
3. Написать 1–2 статьи: _"How I built a personal forecasting OS with Claude Code"_ — Medium/Substack даёт органический охват среди AI-инженеров
4. Добавить пустые шаблоны скиллов, чтобы другие могли форкнуть и адаптировать

## Портфолио и применимость

### Что демонстрирует эта система

| Навык | Как проявлен в системе |
|---|---|
| **Агентный system design** | 16 скиллов с явными контрактами (inputs/outputs), DAG-зависимости, правило D3 (единственная точка записи) |
| **LLM + детерминированный код** | Чёткое разграничение: LLM парсит и оркестрирует, Python считает числа |
| **Data engineering** | Pipeline: raw files → JSON snapshot → stress YAML → integrated view; schema versioning |
| **Domain knowledge** | Quantitative investing: XIRR/TWR, YTM, портфельный стресс-тест, форвардное качество бумаги |
| **Тестирование** | 400+ unit-тестов на детерминированную логику (числа, алерты, валидация) |
| **Документирование** | CLAUDE.md, SKILL.md, shared-references, эта диаграмма |

### Где конкретно пригодится

**AI/LLM-инженер в финтех или инвестиционной компании**
Ровно этот стек: агенты + финансовые данные + audit trail. Таких кандидатов мало — большинство знают либо finance, либо AI, но не умеют их соединять на уровне production-системы.

**AI Product Manager**
Редкий случай, когда PM сам построил и понимает агентную систему изнутри. Это принципиально меняет качество постановки задач инженерам.

**Технический консультант / фриланс**
Работающий прецедент: "Построю вам персональную AI-систему для [вашей задачи]". Финансовый аналитик, исследователь, журналист-расследователь, частный инвестор — у каждого есть аналог этой задачи.

**Собственный продукт**
Ядро готово: транспортный слой, YAML-хранилище, скиллы как плагины, механизм упаковки. Следующий шаг — UI или API поверх этого.

### Как оформить для показа

Минимальный набор для портфолио:

```
README.md (EN)          ← архитектура в 5 абзацах + диаграмма
docs/investment/_cross-cutting/skill-system-map.html  ← живой граф (уже есть)
CLAUDE.md               ← технические детали
tests/                  ← доказательство, что это работает
```

Опционально — пост с заголовком вида:

> _"I built a 16-skill AI system that manages my investment portfolio and tracks my forecasting accuracy over time"_

Такой заголовок точно читают в AI-сообществе, потому что сочетает конкретику (16 скиллов, инвестиции, ретроспектива) с нетривиальным результатом.

### Навык, который стоит сформулировать явно

Умение **декомпозировать сложную аналитическую задачу в граф скиллов** — это отдельная компетенция, которой пока нет устоявшегося названия. Близкие термины: agentic system design, LLM orchestration architecture, AI workflow engineering. Этот навык будет только дорожать по мере того, как агентные системы входят в mainstream.
