**Дата: 2026-10-20.** Рабочий документ для локальных сессий Claude Code (Mac с примонтированным
Synology). Архитектура и обоснования — [`deterministic-plan.md`](deterministic-plan.md); здесь —
нарезка на PR, файлы, тесты и критерии приёмки. Задача — [`docs/TODO.md` → API-1](../TODO.md#api-1).

## Рамки (решения владельца 2026-10-20)

- **Numbers остаётся.** Работаем в текущем подходе: `Общий баланс.numbers` + выгрузки IntelInvest.
  Этап 3 плана (уход от Numbers) отложен, к нему не готовимся.
- Портфель: оркестратор → проверки → теневая сверка 2–4 прогона → только потом веб и переключение скилла.
- eShop: загрузка цен **раз в сутки в 08:30 МСК** (окно 8–9) с сохранением на диск + кнопка
  **«Обновить цены»** на `games.html`. Скилл доверяет файлу цен **24 ч**.
- Веб-загрузка портфеля — через вьюер, в контейнере `hub-api` подпроцессом. Баланс на вебе — **xlsx-экспорт
  из Numbers** (`parse_portfolio.py` его уже принимает): `numbers-parser` в контейнер не тянем.

## Общие правила для каждого PR

- `python3 tools/run_tests.py` без фильтров — зелёный перед пушем.
- Новый тест — блок в `docs/test-registry.md` (аннотация `# …` + строка `python3 …`).
- Сеть в тестах — только записанные фикстуры (`tests/fixtures/`), живых запросов нет.
- Меняется поведение скилла или страницы → справка страницы в том же коммите (корневой `CLAUDE.md`,
  «Справки страниц кабинета»). Портфель — **оба зеркала**: `tools/viewer-help.md` и
  `docs/investment/portfolio-workflow-guide.md`.
- Запись в `Claude-Memory` со стороны NAS — только через `hub-api` (File Station; инцидент 2026-09-02).
- Перед правкой загрузчика — блоки его тестов в реестре и таблица «Технические особенности» в SKILL.md.

### PR-2. Оркестратор `build_snapshot.py` (A.1)

- **Файл:** `skills/portfolio-data-loader/scripts/build_snapshot.py`.
- Вызывает существующие скрипты в нынешнем порядке, внутрь расчётов не лезет.
  `merge_cross_currency_positions` / `apply_known_splits` снаружи по-прежнему не вызывать.
- CLI: `--trades`, `--balance`, `--iis-trades` (опц.), `--memory`, `--out`, `--replay <bundle>`, `--commit`,
  `--rebaseline-cash`.
- Логика, которую сейчас держит модель:
  - режим по набору файлов (полный / returns-only / holdings-only);
  - поиск прошлого снапшота, `sector-overrides.yaml`, последней выгрузки ИИС-3;
  - сеть: повтор → `--no-moex` / `--cbr-offline` с флагом;
  - `build-summary.json`: позиции, XIRR, флаги, **решения владельца** (`cash_drift_changed`,
    `iis_returns_mismatch`, `iis_composition_changed`).
- `--replay`: ответы MOEX и ЦБ берутся из пакета, сеть не трогается.
- `--commit`: снапшот на место + `decision_journal_update.py`. Без флага — сухой прогон в `--out`.
- Попутно: убрать устаревший `scipy` из `pip install` в Шаге 3 SKILL.md.
- **Тест:** `tests/test_build_snapshot.py`:
  - выбор режима по набору файлов;
  - фолбэки сети (мок) дают свои флаги;
  - `--replay` даёт тот же снапшот, что ручная цепочка на тех же входах;
  - идемпотентность: два прогона → одинаковый JSON без служебных полей;
  - без `--commit` в `--memory` ничего не пишется.
- **Готово, когда:** на реальных файлах последнего прогона снапшот совпадает с сохранённым
  (сверка — вручную до PR-4 или сразу PR-4).

### PR-7. Проверка источника (B1, руками, до кода)

С Mac или NAS:

```bash
curl -s "https://api.ec.nintendo.com/v1/price?country=US&lang=en&ids=<nsuid>" | python3 -m json.tool
```

Записать в этот бриф: формат ответа, сколько id принимает запрос, ответ на неизвестный id, нужен ли
User-Agent. Ответ сохранить фикстурой для тестов. Не работает → eShop откладывается.

**✅ Сделано 2026-10-21 с Mac** (фикстуры — `tools/tests/fixtures/eshop/`):
- Ответ: `{"country":"US","prices":[…]}`; на игру — `title_id` (число), `sales_status`
  (`onsale` / `not_found`), `regular_price` {`amount` "$14.99", `currency`, `raw_value` "14.99"};
  при скидке — `discount_price` с тем же и `start_datetime` / `end_datetime` (UTC, ISO).
  Цены — строками, разбирать `raw_value`. Поле `gold_point` не нужно.
- Неизвестный nsuid → `sales_status: not_found` без цены; мусорный id → пустой `prices`.
- Лимит — **50 id в запросе**; 51 → HTTP 400 `{"error":{"code":4004,"message":"Bad request: Over ids limit number"}}`.
- User-Agent не нужен.
- Пример скидок 21.10: Undertale `70010000009921` $14.99 → $9.89 до 01.11; Skyrim Anniversary Edition
  `70070000015127` $59.99 → $29.99 до 01.11; Red Dead Redemption `70010000058660` $49.99 → $24.99 до 07.11.
  Префикс `7007…` у Skyrim — не опечатка: nsuid бывают не только `7001…`.
- **nsuid находится без LLM:** страница `https://www.nintendo.com/us/store/products/<slug>/` несёт в
  `<script id="__NEXT_DATA__">` объект с `urlKey == slug` и полем `nsuid`. На странице десятки nsuid
  (похожие игры) — брать только объект с совпадающим `urlKey`. Публичный поиск Algolia
  (`store_game_en_us`) закрыт — 403. Значит, B2 (заполнение `nsuid_us`) может делать скрипт по ссылке
  на игру, а скилл — только находить ссылку.
- Издание для Switch 2 — **отдельный товар со своим nsuid**: «Red Dead Redemption: Nintendo Switch™ 2
  Edition» — `70010000112715`, slug `red-dead-redemption-nintendo-switch-2-edition-switch-2` (у изданий
  Switch 2 slug кончается на `-switch-2`). Обычная версия — `70010000058660`. В названии из магазина
  бывает хвостовой пробел — при сохранении `strip()`.
- **Название и проверка существования** (решение 2026-10-21): скилл находит ссылку на страницу US eShop,
  скрипт `eshop_lookup.py <ссылка>` берёт из `__NEXT_DATA__` nsuid, официальное название и платформу.
  В watchlist: `title` (как называет владелец), `store_title` (как в магазине), `nsuid_us`. Страницы нет →
  запись без цены с пометкой «нет в US eShop». Ежедневная загрузка помечает `not_found`.
- **Бандлы:** цена — ровно по сохранённому nsuid (бандл со своим nsuid работает, Skyrim `7007…`).
  Поиск «дешевле в составе бандла» и DLC — не в ежедневном скрипте, а в скилле с поиском.
