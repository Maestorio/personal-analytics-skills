# Format firewall — нормализация и валидация артефактов travel-planning

Опорный документ. Описывает: (1) что уже есть для контроля формата MD-артефактов,
(2) каталог реальных дрейфов (по прогонам Китай + Страна Б-новый), (3) целевую
архитектуру «normalize → validate-gate», (4) per-stage план правок.

Создан 2026-06-08 по итогам ревизии прогонов `регион_a_2027` и
`страна_б_2026-09-новый`. Связано: `travel-planning-methodology.md`, `architecture.md`,
`changelog.md`.

---

## 1. Принцип

Дешевле гарантировать **чистый выход** каждой стадии, чем делать N потребителей
терпимыми ко всем вариациям входа. Ответственность — на продюсере (стадия,
породившая MD). «Строгий продюсер» вместо «терпимый консьюмер».

**Нормализатор — детерминированный (REGEX), НЕ LLM.** LLM-нормализация меняет
контент → нарушает «polish ≠ writing» / «никаких скрытых ИИ-решений», стоит
токенов, недетерминирована. Все реальные дрейфы (см. §3) — механические,
адресуемые regex. Остаточные семантические случаи чинит **модель в петле**
(она и есть LLM), получив громкий сигнал валидатора.

## 2. Что уже есть (инвентаризация слоёв)

| Слой | Инструмент | Тип | Покрытие |
|---|---|---|---|
| L1 Канон формата | `references/stageN/stageN-output-spec.md` | спека | все 0–6 ✅ |
| L2 Self-check генерации | Pre-emit чек-листы в `references/` (LLM) | ручной | все (разной строгости) |
| L2b check_format | `scripts/check_format.py` | скрипт | все 0–6 ✅ (пресеты 0/1/2 + `frontmatter_integrity` на всех) |
| L3 Export-sanity | `scripts/export/polish_check.py` | скрипт | все 0–6 ✅ (source↔polished diff) |
| L4 Parse-толерантность | regex в `parser.py` + `stageN.py` | скрипт | все (дырявая) |
| L5 Контент-гейт | `validate_longlist` (0, hard), `_check_parse_completeness` (3, **soft**) | скрипт | только 0, 3 |
| L6 Drift-тест | `tests/test_format_contract.py` | CI | все 0–6 ✅ |
| **L-NORM Нормализатор** | **нет** | — | **отсутствует** |

**Тройная работа (overlaps):**
- Делиметр `-----`→`---`: `check_format` *проверяет* (3–6), модель *чинит* в polish, скрипт *не чинит*, 0/1/2 не проверяются.
- Счётчики: `check_format` (raw) + `_check_parse_completeness` Stage 3 (parsed) + Pre-emit (модель) — три механизма.
- Один Stage 1 DR-MD парсят **ТРИ** независимых пути с разными регэкспами: `parse_dr_cards.py` (для Stage 2), `stage1.py` (export), `stage3.py load_author_lookup` (export). Bug C — прямое следствие.

**Двуязычные таксоны (русификация Фаза 1, v0.55).** Парсеры экспорта таксонов
(категории авторов/POI, роли регионов, тональности) принимают ярлыки
**на обоих языках** через `scripts/taxonomy.py` (`pattern()` для регулярки +
`canon()` сразу после матча → внутри кода только канонические EN-ключи). Это
не нормализатор контента и не L-NORM: язык таксона на приёме не считается
дрейфом. Источник переводов — `scripts/data/taxonomy.json` (SSOT); согласованность
ключей словаря с константами скриптов и двуязычность `pattern()` покрывает ось
taxonomy в `test_format_contract.py` (L6). **С Фазы 2b (v0.72) `.md`-артефакт
эмитится с RU-ярлыками в теле и EN-ключами в YAML** (§7); двуязычие парсеров
остаётся навсегда — легаси-поездки и выход DR несут EN.

**Гейт эмита (Р5).** Валидация — в момент ЭМИТА `.md` стадией (normalize → check_format),
не при импорте на экспорт. `check_format.frontmatter_parse` прогоняет
нормализованный frontmatter через тот же `parser.parse_yaml`, что и потребитель:
его warnings → FAIL (ловит непарсимый YAML/block-скаляры на продюсере). Валидный
YAML (flush/flow-списки) чинится на стороне парсера, а не запретом в гейте.
`polish_check` применяет ту же делимитер/CRLF-нормализацию и выбирает профиль по
лидирующей цифре `stage` (чужой профиль допусков — источник ложных вердиктов).

**Stage 1 структура (D6) — три РАЗНЫХ формата за два прогона:**
- KLT (фикстура): `## КАРТОЧКА N` / `### Карточка N`.
- Китай: `## КАРТОЧКА N` (H2, **плоско, без регионов**).
- Страна Б: `**КАРТОЧКА 01**` (bold-абзац, **не заголовок**) под `### РЕГИОН N — Name` (H3, em-dash).

Export ждёт `## РЕГИОН N:` (H2, двоеточие) + `### Карточка N` — не совпадает ни с одним.
→ **Решение пользователя (2026-06-08): на Stage 1/2 регионы не группировать.** Регион — свойство POI (Stage 3). Stage 1 export: карточки списком, покрытые регионы — строкой на карточке (из суффикса/контекста). Stage 2 — без регионов вообще.

**Чисто (дрейфов нет):**
- **Stage 4** — `_VARIANT_RE` уже матчит и `## Variant A —` (лат.), и `## Вариант A:` (кир.); `## Решение` пусто (корректно); `$`-цены экранированы.
- **Stage 5** — делиметр `---` ок; маркеры `📍🏨🎯💰⚠️` на месте; `todo_verification_items=22` == 22 чекбокса в `## TODO` (check_format скоупит секцию верно); все 9 секций на месте.
- **Stage 6** — файлов в прогонах нет; парсер механический (координаты), низкий риск.

Вывод: **дрейф сконцентрирован в Stage 0–3**, ровно там, где и были баги. Stage 4–6 робастны.

## 4. Целевая архитектура

```
ГЕНЕРАЦИЯ стадии (модель пишет MD):
  → normalize.py  (детерм. механика: делиметр, 1.→seq, лейблы, скобки)   🆕
  → check_format  (HARD-гейт; расширить на 0,1,2; влить контент-гейты)    🔁
  → fail → модель чинит остаток в петле → re-run
  → save канонический MD

EXPORT (MD → PDF/DOCX):
  → normalize.py (защитно, для легаси-файлов)                             🆕
  → polish (LLM — ТОЛЬКО видимый язык; формат-фиксы убрать)               🔁
  → polish_check (source↔polished diff)                                   ✅ как есть
  → render (парсеры доверяют канону; толерантность ужать)                 🔁
```

Кто что делает после слияния:
- **`normalize.py`** (новое ядро) — механика D1–D5, D7. Идемпотентно, контент не трогает. Правила **per-stage** (схемы полей разные!).
- **`check_format`** — единственный hard-валидатор; +пресеты 0/1/2; поглотить `validate_longlist` и `_check_parse_completeness`.
- **`polish_check`** — оставить (своя задача).
- **Pre-emit (LLM)** — страховка; тяжёлое на скрипты.
- **Парсеры** — толерантность ужать; 3 парсера Stage 1 свести на один канон.

1. Схемы полей разные: Stage 1 карточка = 20 полей; Stage 3 POI = 6 полей. `1.→seq` применять **только к полям стадии**, не к нумерованным спискам в прозе Stage 5.

## 6. Фазы

- **Фаза 0** (останавливает потерю данных): Stage 3 фиксы D3/D4/D5 + `_check_parse_completeness` soft→hard; Stage 1 де-регионизация + card-finder + строка покрытия; export-modes.md (Stage 2).
- **Фаза 1** (firewall как система): ✅ `normalize.py` (D1, $, tidy) + ✅ check_format
  пресеты 0/1/2 (`longlist_count`/`reports_count`) + ✅ инвокация в gen-флоу
  (Stage 0 §6.7 Класс H, Stage 1 §4.5 доп-сверка, Stage 2 перед save).

Фиксы Фазы 0 *становятся* первыми правилами `normalize.py` — работа не пропадает.

### Нормализатор — на ВСЕХ стадиях 0–6 (не только где были баги)

Требование (2026-06-08): `normalize.py` применяется к **каждой** стадии 0–6,
а не точечно. Логика — для облегчения и стабильности: даже у робастных Stage
4–6 единый прогон нормализатора (делиметр `-----`→`---`, `$`-escape, кавычки)
снимает с модели ручную работу в polish и убирает целый класс будущих
дрейфов до того, как они станут багами. Структура:
- **Универсальные правила** (все стадии): делиметр, `$`-escape, типографика.
- **Per-stage правила** (только своя стадия): D3 (`1.`→seq для полей Stage 1/3),
  D4 (скобки POI Stage 3), D5 (лейблы Stage 1), card-finder (Stage 1) и т.п. —
  применяются по `stage` из YAML, чтобы не задеть чужой формат (напр.
  нумерованные списки в прозе Stage 5).

## 7. Термины и русификация: `taxonomy.json` как SSOT

Единый источник истины для **всех отображаемых ярлыков** таксономии и видимых
англицизмов экспорта — `scripts/data/taxonomy.json` (+ доступ `scripts/taxonomy.py`).

**Канон body-слоя сменился в Фазе 2b (v0.72): ключ — в YAML, ярлык — в теле.**

| Слой | Язык | Кто отвечает |
|---|---|---|
| YAML frontmatter, JSON-контракты скриптов, payload | **EN-ключ** (`category: HIGH`, `strong_confirmed: 4`, `role: core`, `tempo: balanced`) | машинный слой, не меняется никогда |
| Тело `.md` — **таксоны** | **RU-ярлык** (ВЫСОКАЯ, СКРЫТАЯ ЖЕМЧУЖИНА, Ядро) | эмит модели по спеке; ярлык **копируется вербатим** из `category_label` / `cluster_category_label` / `severity_label` output'а скриптов, не переводится моделью |
| Тело `.md` — **якоря парсинга** | **EN** (`## Longlist`, `#### Cluster:`, `**Combined with:**`, `SIGNAL:`, `C1 style 8→2.0`) | не переводятся; рендер печатает русские подписи сам |
| Рендер (обе ветки) | **RU** через `taxonomy.label()` / `short_label()` | никаких захардкоженных EN-ярлыков или RU-дублей в рендерерах |

**Парсеры остаются двуязычными навсегда** — не «на переходный период»: старые
поездки несут EN-ярлыки в теле, а DR (Stage 1) недисциплинирован и пишет стили
по-английски независимо от просьбы в промте. Язык таксона на приёме — **не
дрейф формата**.

**Правило батча (ловушка B6, реальный кейс v0.72).** Перевод ярлыка в спеке и
двуязычие матчера — **одна правка, один батч**. Иначе секция тихо пропадает из
экспорта (`_ROLE_HEADING_RE`, `_TEMPO_H2_PREFIX`) либо, хуже, гейт молча
становится no-op (`check_format.check_longlist_count` матчит `^##\s+Longlist` и
на переименованной секции вернёт `[]`, а не FAIL). Ось «спека ↔ реальный матчер»
проверяется тестом (`test_format_contract`), а не считается очевидной — та же
логика, что и «словарь мёртв, если рендерер его не зовёт» ниже.
Применяется в **обеих** ветках рендера (`stages/` reportlab/DOCX и
`stages_html/` HTML); при этом `stages_html/*` — **не** зеркала парсеров: они
переиспользуют `extract_content` из `stages/*`, парсер на стадию один.

| Группа | Где показывается |
|---|---|

| `poi_category` / `poi_category_badge` | Stage 3 бейджи POI (ЖЕМЧУЖИНА…), coverage-заголовки |

| `region_role_group` (Ядро поездки/Поддержка…) | Stage 0 заголовки групп ролей |
| `similarity_component` + `ru_short` (самост.…) | Stage 2 лейблы метров (узкие колонки) |

**Свободный текст vs enum (Фаза 2a).** Часть видимого EN приходит не таксоном,
а прозой: DR пишет «Стиль путешествия: backpacker / mid-range independent с
гидом», модель — «**Tempo:** balanced». Для них в `taxonomy.py` два движка:

| Механизм | Где подменяет | Зачем отдельно |
|---|---|---|
| `localize_terms(group, text)` | везде в тексте | составные значения DR: длинные термины раньше коротких, разделители `_`/`-`/пробел взаимозаменяемы |
| `localize_labels(group, text)` | только перед `:` (`**Tempo:**`) | короткие слова-метки (`Country`, `Math`) в свободной фразе значат не то же самое — иначе «cross-country» → «cross-Страны» |

Оба идемпотентны и не трогают незнакомое → на артефактах Фазы 2b (эмит уже
русский) просто не срабатывают, а на легаси и на выходе DR продолжают работать.
**Граница механизма:** там, где подмена ломает грамматику («balanced с лёгким
slow-уклоном» → «размеренный-уклоном») или бьёт по именам собственным
(`Luxury Suites` в поле «Размещение»), — не подменяем; это чинится эмитом
(сделано в 2b: спека Stage 0 просит русскую формулировку темпа, спека Stage 1 —
русский сегмент размещения с сохранением имён отелей).

**Легенда RU=EN.** Т.к. `.md` остаётся EN, видимый вывод — RU, читателю нужна
карта обратно: `taxonomy.legend(*groups)` → строка «ВЫСОКАЯ = HIGH · …», в HTML
оформляется `html_lib.legend_line()` (Stage 2 → `author_category`; Stage 3 →
`poi_category, author_category`).

**Англицизмы** (не таксоны, а токены контента: `all-in`, `cost rank`, `Variant`,
`multi-region`, `scarce`/`abundant` в прозе warnings…) русифицируются
`html_lib.ru_anglicisms()` — точечный проход к видимому тексту перед
`md()`/`mdb()` (URL/код не трогает). Составные формы — своим правилом раньше
одиночного слова («scarce-режим» → «скудный режим», не «скудный-режим»).
Русификатор подключён к прозе Stage 2 (2a) и Stage 3 warnings/контекст (2c) в
обеих ветках — словарь мёртв, если рендерер его не зовёт. `no_translate`:
`POI`, `Deep Research` (+ `open-jaw` — устоявшийся авиатермин, оставлен как есть).

**Правило при добавлении термина.** Новый видимый ярлык/категория —
**сначала в `taxonomy.json`**, затем рендерер зовёт
`label()`/`short_label()`/`localize_terms()`/`localize_labels()`. Хардкодить
RU-строку в рендерере нельзя: так уже дважды заводились параллельные словари
(`_localize_distribution_term` в stage1 и `_trip_format_display` в stage0 —
последний тихо печатал EN на обложке; оба убраны в Фазе 2a).

Единственное исключение — **англицизмы контента** (`all-in`, `Variant`,
`reading list`): они живут списком regex'ов `html_lib._RU_ANGLICISMS`, потому
что это не термины таксономии, а правила подмены с флагами регистра
(`In-trip` / `in-trip` — разные правила ради заглавной в начале фразы).
Миграция этого списка в `taxonomy.json` не сделана — при желании это отдельная
задача, не блокирующая 2b.

**Словарь мёртв, если рендерер его не зовёт.** Реальный баг Фазы 2a: запись
`score → балл` существовала, но проза Stage 2 шла мимо `ru_anglicisms` в обеих
ветках — русификатор звался только из баннера интерактивного HTML. Поэтому ось
«рендерер реально зовёт словарь» проверяется тестом
(`test_html_export::test_ru_anglicisms`), а не считается очевидной. Дрейф ловится в обе стороны: `test_taxonomy.py` (ключи ↔ ярлыки),
`test_format_contract.py::test_taxonomy_consumers_axis` (группа ↔ потребитель
в `stages_html`), smoke `test_html_export.py` (битая группа → ValueError).
