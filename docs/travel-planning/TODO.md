  строгая граница безопасности, две оси дублирования, 3 части output-spec,

- **Решение по объёму.** Делаем **только R2a**. R2b (схлопывание копий до одного
  рантайм-канона) — отложен, см. п. 3b. Сравнение «R2a vs R2a+R2b с валидацией»:
  R2b не снижает риск, а перемещает его из CI в рантайм + требует калибровки,
  которую сейчас не платим; R2a даёт почти всю ценность за строго-нулевой риск.
- **Триггер.** Делать можно в любой момент (Волна 1 ревью: аддитивно, выход не
  меняется). Прецедент частичного расщепления: polish-промты в
  `stageN-polish-prompt.md`.
- **Источник.** Аудит структуры скилла, R1/R2 + §0 + §3
  (`docs/travel-planning/plans/travel-planning-structure-review-2026-06-04.md`).

### 3b. R2b — схлопывание копий до одного рантайм-канона (отложен)
- **Что.** После R2a убрать избыточные in-context копии формата, оставив один
  канон, который продюсер и потребители **читают в рантайме** (варианты:
  dual-read `process`+`output-spec`; manifest, импортируемый парсерами; или
  минимальный — инлайн-пример → указатель). Тогда и часть 3 спеки (известные
  дрейфы) начинает активно доходить до consumer-стадии на прогоне.
- **Почему отложен.** Меняет токен-поток → меняет распределение выхода →
  обязателен golden-прогон (Страна Б+Страна В) на каждый затронутый артефакт.
  Вносит новый рантайм-режим отказа («модель не загрузила канон», ×каждый
  потребитель). При активной слепой калибровке сбрасывает golden-базу. Прежний
  вердикт «R2 = худший ROI» относился именно к этой части.
- **Когда это надо править (триггеры — любой достаточен):**
  - **T1.** drift-тест R2a начал **часто** ловить расхождения копий → человек не
    тянет синхронизацию N копий, дешевле схлопнуть до одной.
  - **T2.** Формат-дрейф **воспроизвёлся в реальном прогоне вопреки** drift-тесту
    → симптоматической защиты мало, нужен корневой фикс (одна копия).
  - **T3.** Появилась дешёвая авто-проверка качества выхода стадии **ИЛИ** ты
    готов разово прогнать golden Страна Б+Страна В (тогда гейт перестаёт быть
    дорогим).
  - **T4.** Число копий на артефакт выросло так, что drift-тест ненадёжно их
    перечисляет.
  - **T5.** Понадобилась активная рантайм-помощь потребителю «известными
    дрейфами» (часть 3 спеки доходит до стадии только при R2b-wiring).
- **Предусловие.** Скилл **не** в активной слепой калибровке (R2b сбрасывает
  golden-базу). Делать **per-artifact**, за golden-прогоном, с коммит-чекпойнтом
  для отката; R2a-слой при откате сохраняется.
- **Источник.** Аудит R2 (R2b-трактовка); сравнение и решение «не сейчас» —
  обсуждение 2026-06-04; план — `plans/r2-split-plan.md` §0, §9.
