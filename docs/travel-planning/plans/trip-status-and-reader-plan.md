## 1. Поездка или возможная поездка (решения владельца 2026-10-03)

Признак один — **точные даты** (`start` + `end` в `trip.yaml`); отдельного поля
«возможная/точная» нет и не будет (второй признак разошёлся бы с первым).
Исключение — поездка, объявленная готовой (`status: ready`) с известным месяцем:
это поездка с точностью до месяца.

| Что известно | Вид | До | Во время | После |
|---|---|---|---|---|
| `start` + `end` | **поездка** | «через 12 дн» · «завтра» · «сегодня старт» | «идёт · день 3 из 10» | «прошла» → архив со дня после `end` |
| `status: ready` + месяц | **поездка (месяц)** | «в следующем месяце» · «через N мес» | «в этом месяце» | «прошла» → архив после конца месяца |
| месяц, статус не `ready` | **возможная** | «Октябрь 2026 · даты не определены» + метка «возможная», без отсчёта | то же | архив «срок прошёл, дат нет» (не «состоялась») |
| только год | **идея** | «Идея · 2027», без «в этом/следующем году» (в т.ч. при `ready`) | то же | архив «срок прошёл, дат нет» |
| ничего | — | как сейчас | — | — |

- Явный `status: done` → «состоялась» всегда (как сейчас).
- Битые даты (`end < start`, один ключ, не ISO) → как будто дат нет;
  `check_format` предупреждает.
- **«Ближайшая»** (сводка `travel.html`, «Моя ближайшая» на хабе) — только
  поездки (первые две строки таблицы). Нет таких — «Точных дат пока нет ·
  ближайшая идея — X, октябрь 2026».
- `check_format`: `status: ready` + только год (или ничего) — предупреждение.
- Сортировка внутри месяца — по `start`, если есть.
- Подсказка при наведении на статус без точных дат: «точных дат нет — по
  сезону из trip.yaml».

## 2. Скилл `travel-planning`: ключи `start`/`end` в `trip.yaml`

Перед правкой — `docs/travel-planning/CLAUDE.md` и `format-firewall.md`.

- `references/storage-and-naming.md` §2.3 — два **необязательных** плоских ключа:
  `start: 2026-10-14`, `end: 2026-10-23` (ISO, без кавычек). Оба или ни одного;
  `end ≥ start`. Заполняются, когда даты дней определены (стадия 5). Без них
  карточка валидна — это и есть «поездка без точных дат».
- `scripts/check_format.py::check_trip_meta` — формат, пара, порядок; месяц
  `start` согласован с `season` (предупреждение, не блок: поездку могли сдвинуть).
- `references/stage5/stage5-final.md` (и output-spec, если там шаблон
  `trip.yaml`) — при принятии финального плана выдать `trip.yaml` с `start`/`end`
  = первый и последний датированный день, вместе со `status: ready`. Даты дней
  без года или без чисел → ключей нет (уровень B).
- **Новый скрипт `scripts/trip_dates.py`** — для уже существующих поездок:
  читает `5_*.md`, достаёт даты дней тем же правилом, что `_day_date`
  (`(DD.MM`), год — из `trip_id`/`season`, **с переходом через Новый год**
  (декабрь → январь следующего года); печатает строки `start:`/`end:` для
  вставки. В хранилище не пишет (manual save — принцип скилла). Нет дат →
  сообщает «точных дат нет, остаётся сезон».
- Синхронизация документации (обязательные 4 места из dev-гайда):
  `SKILL.md` (жизненный цикл `trip.yaml`), `STAGES.md`, `changelog.md`,
  справка `tools/assets/help/travel.md`.
- Тесты: `tests/test_check_format.py` (новые случаи: пара, порядок, формат,
  без дат — валидно), новый `tests/test_trip_dates.py` (обычная поездка,
  переход через год, нет дат, дни без чисел).

## 3. Общая функция статуса — `uiTripWhen` в ui-kit

Статус нужен двум страницам (`travel.html` и `hub.html`), у хаба уже своя копия
разбора сезона — значит, функция одна, в `ui-kit.js` (ui-kit 1.8.0):

- `uiTripWhen({start, end, season, status}, today)` →
  `{ kind: "trip"|"trip-month"|"possible"|"idea"|"none", phase: "before"|"during"|"after"|null,
     label, title, sortKey, archived, archivedLabel, nearest }` (вход: `start`, `end`, `season`, `status`).
- `today` — параметр (для тестов), по умолчанию локальная дата.
- `hub.html`: снять свои `seasonKey`/`seasonDisp`, «Моя ближайшая» — по
  `uiTripWhen` (ближайшая — минимальный `sortKey` среди не прошедших).
- Тест: node-прогон функции на фиксированной «сегодня» — все 4 уровня × 3 фазы,
  битые даты, переход через месяц/год (в `test_pages_contracts.py`, как
  `uiMarkdown`).

## 4. `travel.html`

1. Разбор `trip.yaml` — читать `start`/`end` рядом с `season`.
2. Карточка поездки — строка статуса рядом с сезоном (`label` + `title`).

5. Шапка окна просмотра — статус рядом с названием стадии (`#vw-stage`):
   виден на любой стадии, включая 0–3 и md-режим.
6. md-режим стадий и профили — `uiReaderHTML`/`uiReaderMount` вместо
   локальных `mdRender`/`mdInline` (удалить), `toc: "auto"`, акцент `--c-4`.
7. **Кнопка «Сегодня» в md-режиме** — только если: уровень A, фаза «во время»,

   `opts.bar` (HTML-кнопки в нижней полосе) — правка ui-kit 1.8.0.
   Иначе кнопки нет, остаётся статус в шапке.
8. HTML-стадии **не трогать**: у TNAV свои «До старта»/«Сегодня» по `data-date`.
