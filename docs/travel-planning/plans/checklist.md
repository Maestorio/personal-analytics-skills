# Golden-чеклист — Волна 1b + 2 (спека-emphasis) + русификация 2b

Что проверить **после реального LLM-прогона**, прежде чем считать
валидированными: спека-emphasis-части Волны 1b+2 (changelog v0.46, Stage 5/6)
и русификацию эмита Фазы 2b (changelog v0.72, Stage 0–4 — секция в конце).

Контекст: эти правки меняют **выход модели** (правлены рантайм-`.md`:
`stage5-final.md`, `stage5-polish-prompt.md`, `stage6-final.md`). Детерминированные
тесты их не ловят — нужен прогон. Render/код-части (D-воздух, G4-titler) уже
проверены тестами + визуально, в этом чеклисте они только для регресс-сверки.

---

## Как прогонять

Два калибровочных кейса (одинаковые входы → сравнение с прошлым выходом):

1. **Страна Б, сентябрь–октябрь 2023** (`страна_б_2023-09`) — outcome mediocre.
2. **Страна А, март 2024** (`страна_а_2024-03`) — есть прошлый прогон для diff.

Прогон: профиль + Stage 0 → 1 → 2 → 3 → 4 → 5 → 6 → Export PDF. Сверять
**Stage 5 `.md`**, **Stage 6 `.md`** и **финальный PDF** против пунктов ниже.

**Базовый регресс (не должно сломаться):** старый `5_vX` без новых маркеров
рендерится как раньше; набор иконок дня и 9 секций не изменились;
`format_contract` зелёный.

## G4 — establishing-фраза региона (`описание`)

- [ ] В Stage 5 `.md` маркеры `[[регион: …]]` у **первого дня каждого региона**
      несут поле `описание:` (≤ ~120 символов).
- [ ] `описание` — **не новый контент**: формулировка выводится из уже
      имеющихся дней / поля `главное`, без новых фактов, дат, имён.
- [ ] В PDF establishing-фраза рендерится **курсивом под названием региона**,
      над строкой «дни X–Y · даты · ночи · база».
- [ ] Повторный регион (возврат в Сеул) — `описание` уместно или отсутствует
      (не дублирует первое вхождение слово-в-слово).
- [ ] **Backward-compat:** если модель не дала `описание` — плашка региона
      рендерится без неё, без ошибки.

❌ Провал: `описание` пересказывает дни / содержит выдуманный факт / длиннее
строки и переносится на 3+ строки / ломает titler.

## G5 — структурный бокс исключений «Чего больше нет в маршруте»

- [ ] Подсекция в `## Контекст…` присутствует, **когда есть значимые
      отбрасывания** (регион/якорный POI, который читатель ожидал бы) —
      не только при явном блоке Stage 4.
- [ ] Каждый пункт — строго `- {Место/регион/POI} — {причина, 1–2 фразы}`
      (тире ` — ` с пробелами).
- [ ] В PDF у фронта (после обложки/карты) бокс отрендерен **таблицей
      «Место | Причина исключения»** (т.е. парсер поделил по ` — `, не свалил
      весь пункт в одну колонку).
- [ ] Причины **правдивы** (логистика / темп / сезон / тег «не интересно» /
      компромисс варианта), не выдуманы.
- [ ] 3–7 пунктов; при отсутствии значимых отбрасываний подсекция **опущена**.

❌ Провал: пункт без ` — ` → одна колонка; выдуманная причина; бокс есть, а
отбрасываний нет (вода).

## SYS-2/G2 — fact-SSOT (Шапка S5 ↔ досье S6)

- [ ] **Шапка Stage 5** несёт booking-critical факты *одной строкой*: визовый
      режим (безвиз/e-visa/срок паспорта), FX, перелёт. Без глубокого
      справочного слоя.
- [ ] Прививки / денге / высота / этикет / экстренные контакты / SIM — **НЕ в
      Шапке**, а только в **досье Stage 6**.
- [ ] Один факт **не дублируется** в Шапке и досье с **расходящимися**
      деталями. Если визовый режим есть в обоих — Шапка кратко, досье
      развёрнуто и согласованно.
- [ ] При расхождении досье = авторитет (актуализировано web search на финал).
- [ ] **Самодостаточность S5:** без Stage 6 Шапки достаточно, чтобы
      действовать (booking-critical не «уехало» целиком в досье).

❌ Провал: виза в Шапке = «безвиз 60 дней», в досье = «нужна e-visa» (или
наоборот); прививки расписаны и в Шапке, и в досье.

## MET-3 — profile-fit аудит (Класс H Pre-emit)

Сверять Stage 5 против **профиля группы** (`## Темп`, `## Частота смены
локаций`, `## Физическая форма`, `## Ядро интересов`, `группа_архетип`):

- [ ] **Темп:** нет пачки перегруженных дней подряд (3+ якорных POI + длинный
      переезд) при профиле «медленный/умеренный» + старший архетип.
- [ ] **Ранние подъёмы:** число «рассветных» дней умеренно; нет двух подряд
      для медленного/старшего профиля без флага.
- [ ] **Частота смены локаций:** фактические ночи-на-базу не противоречат
      профилю (профиль «3–5 ночей» → не цепочка one-night-stand'ов).
- [ ] **Фото-профиль:** если фотография в `## Ядро интересов` — золотой час /
      рассвет-закат у ключевых видовых точек учтён.
- [ ] **Интересы / анти-интересы:** якорные POI тянутся к ядру интересов;
      регионов/POI из «не интересно» нет.
- [ ] Каждое выявленное несоответствие → **либо поправлено в плане, либо
      строка в `warnings:`** (не молчаливый пропуск).

❌ Провал: явный mismatch (напр. рассветная точка в полдень при фото-профиле)
без правки и без `warnings`.

### Калибровочная привязка
- **Страна А** (mediocre-зоны прошлого прогона): аудит должен **поднять флаги** на
  местах, которые в реальности разочаровали (темп/ранние подъёмы).
- **Страна В-юг** (successful): аудит **не должен** навязать нерелевантные
  регионы (Bariloche / El Bolsón / Puerto Madryn) и не ломать удачный темп.

## Русификация 2b — эмит `.md` по-русски (v0.72; приёмка Фазы 2b)

Канон: **ключ — в YAML, ярлык — в теле**. Проверять на новых артефактах
Stage 0–4 обоих кейсов (Stage 5/6 русификация не правилась — там базовый регресс).

- [ ] **YAML-шапки — EN без изменений**: `category: HIGH`, `counts:
      STRONG_CONFIRMED`, `role: core`, `aggregation_mode`, `tempo: balanced` —
      ни одного русского значения в YAML.
- [ ] **Таксоны в теле — русские ярлыки**: заголовки POI
      `[**СИЛЬНОЕ ПОДТВЕРЖДЕНИЕ**]`, счётчики `2. ВЫСОКАЯ: N (…)`,
      reading list «Обязательные (ВЫСОКАЯ)» / «ОСОБЫЙ СИГНАЛ», роли регионов
      Stage 0 по-русски, «Спорные решения» Stage 4.
- [ ] **Ярлык скопирован вербатим** из `category_label` /
      `cluster_category_label` / `severity_label` JSON'а скриптов — нет
      самодельных форм («ПОДТВЕРЖДЁН», «ВЫСОКОЕ» и т.п. → fail).
- [ ] **Stage 0**: секция темпа с русским заголовком и лидами
      («Темп:/Страны:/Расчёт:»), формулировка темпа русская (не «balanced с
      лёгким slow-уклоном»), scope-формат в прозе русским, в прозе —
      display_name группы (машинный id только в YAML).
- [ ] **Stage 1 (DR)**: поле СТИЛЬ и «Размещение» — по-русски (имена отелей
      сохранены латиницей); если DR всё же дал EN — рендер-страховка 2a
      русифицирует, это NOT fail эмита, но зафиксировать частоту.
- [ ] **Warnings Stage 2/3** — русская проза, без ссылок на внутренние файлы
      скилла («см. stage3-poi.md §6.5» → fail).
- [ ] **Якоря остались EN дословно** (решение 2c): `## Longlist`,
      `## Honest assessment`, `**Cluster:**`, `SIGNAL:`, `(HIGH-авторов: N)`,
      abundant/scarce в blockquote режима, компонентные строки `C1 style 8→2.0`.
      Переведённый якорь = fail (секция выпадет из экспорта/гейтов).
- [ ] **`check_format` проходит** на каждом новом артефакте (счётчики
      longlist/poi/todo не сломаны русским телом).
- [ ] **Экспорт собирается** (HTML+PDF) на новых артефактах; в видимом выводе
      нет смешанного EN (кроме легенды RU=EN и no_translate: POI, Deep
      Research, open-jaw).
