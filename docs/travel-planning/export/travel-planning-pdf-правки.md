# Инструкция по правкам travel-planning skill: PDF-экспорт, навигация, оформление

## Контекст

Калибровочный прогон скилла на 19-дневном маршруте по Южной Страна А (Stage 5, Reconstructive) выявил блокирующие дефекты экспорта PDF и зоны улучшения структуры. Этот документ — checklist правок для Claude Code, сгруппированный по приоритетам.

---

## Раздел 1. Критичные дефекты экспорта (P0)

### 1.1 Шрифт без CJK fallback

**Проблема.** Страна А названия в скобках (경복궁, 창덕궁, 아바이마을) рендерятся пустыми квадратами. Без хангыля поиск точки в Naver Maps / KakaoMap невозможен — операционная ценность плана падает до нуля.

**Что сделать:**
- В template PDF-стадии указать font-family с fallback-цепочкой: основной шрифт → `Noto Sans CJK KR` → системный fallback.
- Использовать `Noto Sans CJK` (свободный) или `Apple SD Gothic Neo` (системный macOS).
- Применить для всех Asian-направлений (Япония, Китай, Страна А, Страна Б, Страна Г, Страна Г) — не только Страна А.

### 1.2 Эмодзи не рендерятся

**Проблема.** Флаг 🇰🇷, иконки 📍 ✈ ⚠ — пустые квадраты в финальном PDF.

**Что сделать (вариант A — рекомендуется):**
- Убрать все эмодзи из template.
- Заменить на Unicode-геометрию: ■ ▶ ▲ ⚑ ★ ➤ — эти глифы есть в любом sans-шрифте, проблем рендеринга нет.

**Что сделать (вариант B — для перспективы):**
- Подключить `Noto Color Emoji` или `Twemoji` при PDF-сборке. Решает проблему универсально, но добавляет зависимость.

### 1.3 PDF outline через H1/H2

**Проблема.** Outline-панель в Preview / Acrobat пустая — нет навигации по разделам. При 19-дневном маршруте это критично.

**Что сделать:**
- Установить семантические heading-уровни (не визуальные плашки):
  - H1 = разделы документа: «Сводка», «Маршрут по дням», «Бюджет», «Логистика», «Приложения»
  - H1 = каждый регион: «Сеул (прилёт)», «Сораксан», «Кёнджу», «Пусан», «Чонджу», «Сеул (финал)»
  - H2 = каждый день внутри региона
- Визуальные плашки с заливкой должны обрамлять текст с heading-семантикой, а не заменять её.

**Проверка:** после генерации открыть PDF в Preview → cmd+opt+3 (Show Table of Contents). Outline должен быть полностью наполнен. Если пусто — скилл рендерит визуальные плашки без semantic heading.

## Раздел 2. Структурные блоки (P1)

### 2.1 Сводная таблица регионов

**Положение:** После титульного блока и параметров маршрута, перед разделом «Маршрут по дням».

**Колонки:**
- Регион
- Дни
- Даты
- Ночи
- Главное
- Бюджет региона

**Важно:**
- Каждый номер дня — гиперссылка на якорь `#dayN`.
- В диапазонах номера кликабельны по отдельности: `3–4–5`, не `3–5`. Пользователь должен иметь возможность ткнуть в конкретный день.
- Колонку «База» НЕ включать — отель может меняться, пользователь выбирает сам. Достаточно города-якоря в самой нижней строке шапки дня.
- Бюджет региона — без жилья и межгорода (они идут отдельно в сводной бюджетной таблице).

### 2.2 Titler региона

**Положение:** Перед днём переезда в регион. Не перед первым полным днём пребывания. День переезда (сборы → автобус → заселение → ужин в новом городе) логически принадлежит новому региону, бюджет дня — Сораксанский, не Сеульский.

**Структура:**

```
РЕГИОН N ИЗ 5
Сораксан
Дни 3–5 · 28–30.03 · 3 ночи · Сокчо

• Главное: Ульсанбави (день 4)
• Буфер: день 5 — погодный (snow line ~700 м в конце марта)
• Бронь заранее: express bus накануне
• Риск: метель → fallback Соннянса
• Бюджет региона: ~₩200 000 (без жилья и межгорода)
```

**Важно:**
- НЕТ строки «База» (отель) — только город-якорь в верхней строке.
- Прогресс-метка «Регион N из 5» сверху мелким — помогает понимать положение в маршруте.
- Ссылки на дни внутри буллетов (день 4, день 5) — кликабельные якоря.
- Buffer-дни должны иметь прописанные сценарии (если погода ОК → X; если буря → Y).

### 2.3 Региональный контекст в шапке дня

**Что сделать:** каждая шапка дня несёт caption-метку с названием региона.

**Формат:**

```
СОРАКСАН   ← caption, мелким с трекингом, цветом региона
День 3 — 28.03 Чт                    ~₩35 000–50 000
                                      ~7 200–10 200 ₽
```

**Зачем:** при открытии PDF в произвольной точке (или при пролистывании посередине) пользователь сразу видит регион. Дополнительно: автоматически попадает в PDF-outline корректно (H1=регион, H2=день).

### 2.4 Индекс бронирований с дедлайнами

**Положение:** В начале документа, сразу после сводной таблицы регионов. Отдельный раздел/лист.

**Формат:**

| Что бронировать | Дедлайн | Где | День |
|-----------------|---------|-----|------|
| Хувон, таймслот | за 6 дней онлайн | english.cdg.go.kr | [2](#day2) |
| Express bus Сеул→Сокчо | накануне | kobus.co.kr | [3](#day3) |
| Канатка Сораксан | в день, утром | на месте | [4](#day4) |

Зачем: бронирования с дедлайнами и информационные блоки сейчас лежат вперемешку. Этот индекс — pre-trip checklist одной страницей.

### 2.5 Индекс warnings (опционально)

**Положение:** Приложение в конце документа.

Список всех жёлтых блоков с указанием дня. Используется как финальный pre-trip checklist.

## Раздел 3. Цветовое оформление (P2)

### 3.1 Цветовое кодирование регионов

**Что сделать:** 5 регионов = 5 неярких акцентов. Не для заливки всего блока, а как тонкий маркер.

**Палитра (для Страна А; для других направлений — аналогичный принцип):**

| Регион | Цвет | Семантика |
|--------|------|-----------|
| Сеул | тёмно-синий (текущий) | столица |
| Сораксан | приглушённо-зелёный | горы |
| Кёнджу | терракот | древняя столица |
| Пусан | серо-голубой | море |
| Чонджу | охра | традиционный, ремёсла |

**Где применять (только в одном элементе на блок, не везде):**
- Тонкая вертикальная полоса слева от плашки дня (3–4px).
- Цвет caption-метки «РЕГИОН» в шапке дня.
- Цвет вертикальной полосы titler-блока региона.
- НЕ заливать всю плашку или фон страницы — будет рябить.

### 3.2 Существующие визуальные дефекты

**Плашка дня (тёмно-синяя):** сейчас сплошная заливка через 19 повторов перегружает документ. Уменьшить высоту, оставить акцент только на номере дня и дате. Можно вообще убрать заливку, оставив только нижнюю/левую цветную границу.

**Бюджет дня (правый угол шапки):** сейчас жёлто-зелёный на тёмно-синем — низкий контраст. Заменить:
- Основная сумма (₩): белый bold
- Конвертация (₽): белый regular, opacity 0.7, на 2px меньше

**Жёлтые warning-блоки:** снизить насыщенность жёлтого на 15–20%. Сейчас на странице с двумя днями и двумя warnings они визуально конкурируют с заголовком дня. Должны быть заметнее текста, но тише заголовка.

### 3.3 Типографика

- Шрифт основной: что есть сейчас (san-serif).
- Страна А названия в скобках: серым, на 2px меньше основного текста — scannable, но не отвлекают.
- Caption-метки регионов: 11px, letter-spacing ~1.5px, цвет региона.
- Иерархия размеров: H1 региона = 22px / H2 дня = 18px / body = 14–16px.

### 3.4 Запреты

- Не добавлять иконки-эмодзи в заголовки — тот же шрифтовой провал, что с CJK.
- Не делать колонки в основном теле документа — A4-печать и мобильное чтение ломаются.
- Не вставлять декоративные разделители между блоками внутри дня — воздуха достаточно, линии шумят.

## Раздел 4. Гиперссылки

### 4.1 Якоря

- Каждый день — id `dayN`, где N = порядковый номер (1, 2, ... 19).
- Каждый регион — id `region-{slug}` (например, `region-seoraksan`).
- Titler региона имеет собственный id `titler-{slug}` или совпадает с id дня переезда.

### 4.2 Что куда ссылается

- Из сводной таблицы регионов → к каждому дню (через номер дня).
- Из titler региона → к дням внутри региона (через ссылки в буллетах: «день 4», «день 5»).
- Из индекса бронирований → к соответствующему дню.
- Из каждого дня → обратная ссылка «↑ К сводной таблице» в самом конце дня (мелким, отдельной строкой).

### 4.3 Технический чекинг

- Pandoc: синтаксис `[текст](#anchor)` + `{#anchor}` после заголовка работает из коробки. Флаг `--toc` опционален (для печатного содержания).
- Word/docx: «закладки + перекрёстные ссылки». Конвертер должен сохранять interactive hyperlinks при экспорте в PDF.
- Проверка: после сборки PDF открыть в Preview, кликнуть 3–4 случайные ссылки из сводной таблицы и titler. Якоря должны срабатывать, скролл — попадать в правильный день.

## Раздел 5. Эргономика плана (P2-P3)

### 5.1 Тег «можно пропустить, если»

Для дней с плотной программой (4+ пунктов) добавить пометку у каждого второстепенного пункта: «можно пропустить при усталости / плохой погоде / задержке предыдущего пункта». Снимает решения на месте, когда мозг уже занят.

Пример: День 2 (Сеул, дворцы) — 4 пункта в 6–7 часов. Помечать второстепенные: «Букчон Ханок Виллидж — можно пропустить, если устал от Кёнбоккуна».

### 5.2 Buffer-логика обязательна

В дни-буферы (как день 5 — Сораксан) явно прописывать сценарии:
- Если погода ОК → план A (Ульсанбави / Соннянса)
- Если буря → план B (отдых, городская лагуна, рынок)
- Если канатка закрыта → план C

Buffer без сценариев = потерянный день.

### 5.3 Связка между днями

В titler региона: явная фраза-якорь «Базируемся в [город], дни N–M, выезды радиальные». Снимает домысливание структуры (сейчас приходится прокручивать дневник и собирать самому).

## Чеклист валидации

После применения правок проверить:

- [ ] PDF outline (Preview → cmd+opt+3) наполнен всеми H1 и H2
- [ ] Хангыль в скобках читается
- [ ] Эмодзи либо рендерятся корректно, либо заменены на Unicode-геометрию
- [ ] Каждая ссылка из сводной таблицы ведёт к нужному дню
- [ ] Каждая ссылка из titler региона ведёт к нужному дню
- [ ] Обратная ссылка «↑ К сводной» в конце каждого дня ведёт на таблицу
- [ ] Колонка «База» отсутствует в сводной таблице и в titler региона
- [ ] Titler региона стоит перед днём переезда, не после
- [ ] Region caption есть в шапке каждого дня
- [ ] Цветовая полоса региона применена (и только в одном элементе на блок)
- [ ] Бюджет дня читается белым на тёмном фоне без потери контраста
- [ ] Жёлтые warning не конкурируют по весу с заголовком дня
- [ ] Buffer-дни имеют прописанные сценарии план A / B / C

## Приоритеты внедрения

**P0 — без этого экспорт операционно непригоден:**
1. CJK font fallback
2. Emoji fix (вариант A — замена на Unicode-геометрию)
3. PDF outline через H1/H2

**P1 — структурная ценность:**
4. Сводная таблица регионов с гиперссылками (без колонки «База»)
5. Titler региона перед днём переезда (без строки «База»)
6. Region caption в шапке каждого дня
7. Индекс бронирований с дедлайнами

**P2 — эргономика и оформление:**
8. Цветовое кодирование регионов (тонкие маркеры)
9. Обратные ссылки «↑ К сводной таблице» с каждого дня
10. Исправление контраста бюджета и насыщенности warnings
11. Buffer-сценарии план A/B/C

**P3 — улучшения второго уровня:**
12. Тег «можно пропустить»
13. Индекс всех warnings отдельным приложением
14. Связки-якоря между днями в titler региона

## Применимость

Большинство правок (Разделы 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 4) — универсальны для любого направления, не специфичны для Страна А. Раздел 3.1 (цветовая палитра) — пример для Страна А; для других направлений принцип тот же (5 регионов = 5 акцентов), палитра подбирается под географию.

Калибровочный документ (Страна А 19 дней) использовать как референс при тестировании правок: если после изменений он выглядит лучше — катить на остальные направления.
