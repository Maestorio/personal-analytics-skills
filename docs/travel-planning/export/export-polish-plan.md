## 2. P1 — видимые баги (приоритет)

### P1-1. Дубль подписи «Программа. Программа»

- **Корень.** Билдер сам добавляет метку-лид `f"{marker.label}."`
  (`stage5.py:1078`). Тело дня в md начинается с `**Программа** (текст)`.
  Дедуп `_BOLD_LABEL_RE` (`stage5.py:1043`) ловит только голую
  `**Label:**$` (с двоеточием, без текста после) — `**Программа** (...)`
  не матчит, поэтому ведущее слово не срезается → «Программа. Программа …».
- **Тип.** Python (билдер владеет инжектом метки — он же владеет
  дедупом; это страховка, не утечка в прозу из D3).
- **Правка.** В `_render_marker` (`stage5.py:1066–1079`): после получения
  `first_line` срезать **ведущий bold-токен, равный `marker.label`**
  (case-insensitive), с любым хвостом после него. Т.е.
  `**Программа** (день лёгкий…)` → `(день лёгкий…)`, рендер даёт
  «**Программа.** (день лёгкий…)». Реализовать как отдельный helper
  `_strip_leading_label(text, label)` рядом с `_BOLD_LABEL_RE`, покрыть
  всеми пятью метками (Локация/Отель/Программа/Бюджет/Риски — последняя
  идёт через `warning_box`, но проверить и её путь).
- **Тест.** `tests/test_export_stage5.py`: фикстура дня с
  `🎯 **Программа** (…)` → в выводе метка не дублируется; и обратный
  кейс `🎯 (…)` без слова — метка добавляется ровно один раз.

### P1-2. Сырые значения тегов в прозе

- **Корень.** Теги `можно`/`пропуск`/`не интересно` лежат **сырыми**
  (в backticks) уже в `5_final_plan_v1.md` и `4_variants_v1.md`
  (раздел «Чего больше нет в маршруте», `reason:` вариантов). Python
  прокидывает их корректно. В `stage5-polish-prompt.md` и
  `stage4-polish-prompt.md` **нет** правила переформулировки.
- **Тип.** Polish-промт (D3).
- **Правка.** Добавить трансформацию в **оба** промта
  (`stage5-polish-prompt.md`, `stage4-polish-prompt.md`):
  таблица тег → человеческая формулировка, например
  `обязательно` → «обязательный регион»,
  `можно` → «оставлен опциональным»,
  `не интересно` → «помечен как неинтересный»,
  `пропуск` → «слот осознанно пропущен»,
  `can_pool` → «можно объединить с соседним».
  Инструкция: не подставлять raw-значение тега в предложение,
  переписать фразу целиком (грамматическое согласование), не оставлять
  backticks. Добавить в чек-лист промта строку «не осталось raw-тегов в
  прозе».
- **Замечание по D3.** Поскольку договорились без Python-страховки —
  в `polish_check.py` стоит добавить **только детект** (не правку):
  warning, если в polished-выводе встречаются ` `можно`/`пропуск`/
  `не интересно` ` в backticks. Это не дублирует маппинг, а ловит
  недовычитку. Опционально (см. §6).
- **Тест.** Не автоматизируется на уровне Python (это LLM-шаг); проверка
  — ручной прогон polish на страна А фикстуре + детект в `polish_check`.

### P1-3. Перенос числа валюты внутри ячейки

- **Корень.** Таблица «Регионы маршрута» рендерит `g.budget`
  (`stage5.py:918`). Два источника значения:
  (1) computed `_region_budget_range` (`stage5.py:833`) — `_fmt_amount`
  ставит nbsp **в разрядах**, но вокруг en-dash `–` nbsp **нет**;
  (2) **сырое поле маркера** `[[регион: … | бюджет: ~₩75 000–110 000]]`
  с обычными пробелами (когда у дней нет 💰-маркера с диапазоном) —
  именно отсюда страна А разрыв «110 ⏎ 000».
- **Тип.** Python (билдер/данные).
- **Правка.**
  1. Helper `_nbsp_budget(s: str) -> str` рядом с `_fmt_amount`:
     обычные пробелы между цифрами → ` `; вокруг `–`/`-` в диапазоне
     цифр → ` – ` (или `–` без пробелов, но с nbsp,
     чтобы не рвалось). Применять к ячейке бюджета на рендере
     (`stage5.py:918`) **независимо от источника** — покрывает оба пути.
  2. В `_region_budget_range` (`stage5.py:833`) сразу строить через
     `_nbsp_budget` или вручную nbsp вокруг en-dash.
  3. Чуть расширить колонку «Бюджет» (`stage5.py:903/906`: 17%→19%,
     20%→22%) — компенсировать за счёт «Главное».
- **Тест.** `tests/test_export_stage5.py`: бюджет-строка с обычными
  пробелами на входе → в ячейке только nbsp (` `), нет обычных
  пробелов между цифрами и вокруг тире.
