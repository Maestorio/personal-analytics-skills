# Stage 4 PDF Export — план дизайна

**Статус:** РЕАЛИЗОВАНО (2026-05-29). Код — `scripts/export/stages/stage4.py`,
polish-промт — `references/stages/stage4-polish-prompt.md`, тесты —
`tests/test_export_stage4.py` (67 проверок, зелёные; включая legacy-формат
страна_г_1, cover-хелперы, дедуп контекста, линкификацию «Вариант X» и
collapse одинаковых старта/финиша). Расхождения с планом и правки по
фидбэку — см. «Заметки реализации» в конце.
**Опирается на:** `skills/travel-planning/references/export/pdf-visual-language.md`
(§9 — набросок маппинга Stage 4; §1–§8 — общий визуальный язык и API
`pdf_lib`) и образец реализации `scripts/export/stages/stage5.py`.

**Контекст решения (changelog export-design.md, 2026-05-28):** Stage 4 —
**PDF read-only витрина** сравнения вариантов. Пользователь открывает PDF
с 2–3 вариантами, сравнивает, выбирает один **в чате** (не в файле).
Round-trip DOCX для Stage 4 отменён.

**Источник контента (пример для калибровки):**
`docs/travel-planning/страна Б/4_variants.md` (Страна В-юг, 3 варианта) —
эталонная структура секций.

## 1. Базовые решения

| Параметр | Значение | Почему |
|---|---|---|
| Ориентация | **Portrait A4** | Landscape только у Stage 0. Stage 4 — плотный текст + таблицы дней. |
| Получатель | **только `self`** | Варианты — внутренний инструмент выбора. Для `parents` показываем уже финал Stage 5. |
| Редактируемость | **read-only** | Решение делается в чате. Никаких form fields. |
| Имя файла | `{trip_id}_варианты_v{N}.pdf` | напр. `страна_в_юг_2025-03_варианты_v1.pdf`. Версия — из исходного `4_variants_v{N}.md`. |
| Цвет вариантов | `REGION_PALETTE[0/1/2]` | A=синий, B=зелёный, C=терракот. Та же палитра, что регионы Stage 5. |

Реализация — новый `scripts/export/stages/stage4.py` на тех же
`pdf_lib`-блоках. Никаких новых цветов/шрифтов/таблиц «с нуля»
(правило `pdf-visual-language.md §8`).

## 2. Структура документа

```
1. ОБЛОЖКА                          ← page 1
2. Контекст + Предупреждения        ← page break
3. Сводная сравнительная таблица    (двунаправленные ссылки ↔ варианты)
4. Приоритеты POI (свёрнуто)        ← компактная сводка, не полные таблицы
5. ВАРИАНТЫ                         ← parent в outline (level 0)
     • Вариант A                    ← section_bar, цвет[0], outline level 1
     • Вариант B                    ← цвет[1], level 1
     • Вариант C                    ← цвет[2], level 1
6. Honest assessment                ← section_bar, page break — конец документа
```

**Отклонение от md-порядка:** сравнительная таблица поднята **наверх**
(после контекста), а не оставлена перед Honest assessment. Причина —
это «карта» для чтения: читатель сначала видит оси сравнения, потом
ныряет в каждый вариант. Полная таблица (все оси) рендерится **один
раз** сверху, внизу не дублируется.

**Блок «Решение» из md НЕ рендерится** ни при каком состоянии (заполнен
он или пуст). Выбор фиксируется в чате. Honest assessment — последняя
секция документа.

## 3. Постранично

### 3.1. Обложка

- `cover_title`: «{Страна} · {N} ночей · сравнение вариантов»
  (человекочитаемо, без `trip_id` / `stage` / жаргона).
- `cover_subtitle`: «Рекомендованный сбалансированный — Вариант A»
  (из YAML `recommended_balanced`).
- `key_params_table`: Длительность · Сезон · Регионы (стрелками) · Темп ·
  Бюджет-таргет словами · По каким осям сравниваем.

### 3.2. Контекст + предупреждения (page break)

- `## Контекст для следующих стадий` → параграфы через `info_box`
  (спокойная заметка, не риск).
- блок `warnings:` из YAML → `warning_box` (amber). Для `self`
  сохраняем все (включая бюджетные и tag_parse). Жаргон чистится
  polish-шагом, содержание остаётся.

### 3.3. Сводная сравнительная таблица (`data_table`)

- строки = оси (Культурное наполнение, Физнагрузка, Погодные риски,
  Логистика, Соответствие профилю/сезону, Бюджет, Уникальный риск,
  Окна погоды для главной цели, Нетипичные точки…);
- колонки = A / B / C;
- **имена вариантов в шапке = ссылки** `[Вариант A](#variant-a)` на их
  секции (двунаправленность — см. §5);
- бюджетные ячейки с ⚠️: эмодзи вырезается → заменяем на `(!)` или
  amber-текст.

### 3.4. Приоритеты POI — свёрнуто

Полные таблицы `MUST / MEDIUM / CONDITIONAL / Мягкие / EXCLUDE / Synergy`
из md **НЕ рендерим**. Вместо них компактная сводка:

- `section_bar` «Приоритеты POI»;
- `info_box` с 1 строкой логики: «Пользовательский комментарий
  перекрывает методологическую категорию Stage 3»;
- короткая сводка по корзинам, по одной строке (`definition_list`):
  - **Обязательно (MUST):** N POI — перечислить имена через запятую;
  - **Условно (CONDITIONAL):** имена + в каких вариантах;
  - **Исключено:** N POI (без перечисления причин — детали в md).

Цель свёртки: дать понять «что точно внутри / что под вопросом», не
вываливая всю методологическую кухню. Полные таблицы остаются в
исходном `4_variants.md` для тех, кому нужно.

### 3.5. Варианты (parent outline level 0)

Каждый вариант — `section_bar` с цветом `REGION_PALETTE[i]`,
`anchor_slug=variant-{a|b|c}`, `outline_level=1`. Анатомия — §4.

### 3.6. Honest assessment (page break)

- `section_bar` «Честная оценка»;
- bold-рекомендации и абзацы «когда выбирать B / C» — параграфы;
- «Бюджетная сводка — важно» → `warning_box`;
- «Развилка в комментариях пользователя» → `info_box`;
- секция закрывает документ.

## 4. Анатомия блока одного варианта

| Блок md | Компонент `pdf_lib` |
|---|---|
| `⚠️ Бюджет: …` (превышение + источники + альтернативы) | `warning_box` (amber) — структурный риск варианта |
| `Распределение ночей: …` | короткий `para` / `definition_list` (1 строка) |
| `### Маршрут по дням` (таблица День/Локация/Содержание) | `data_table` (тёмный header, зебра) |
| `### Что включает из агрегации` | `bullet_list`; категории (**STRONG CONFIRMED** и т.п.) — bold |
| └ строка `⚠ RED FLAG …` | вложенный `warning_box`, не обычный bullet |
| `### Что осознанно отбрасывает` | `bullet_list` |
| `### Логистика между точками` | `bullet_list`; `**Самые сложные звенья**` — bold-лид |
| `### Ключевые риски` | `bullet_list` с bold-именем риска (не каждый в box — иначе визуальный шум) |
| `### Кому подходит лучше / хуже` | `bullet_list`; `✅/❌` → `✓`/`✗` (см. §5) |
| `**Бюджет:** ~… тыс ₽` | `definition_list` |
| (хвост блока) | back-link **`↑ К сравнению`** на сводную таблицу |

## 5. Навигация и подводные камни рендера

**Outline (закладки):** «Варианты» level 0 → A/B/C level 1 (вложенно);
остальные H2 — level 0. Панель открывается автоматически
(`showOutline`).

**Двунаправленные ссылки (требование пользователя):**
- сверху: имена вариантов в сводной таблице → секции вариантов
  (`[Вариант A](#variant-a)`);
- снизу: в хвосте каждого варианта — `↑ К сравнению` на якорь сводной
  таблицы.

Destination'ы — только через `afterFlowable`/anchored-механизм
(`pdf-visual-language.md §8 п.3`), не через `<a name>` в ячейке таблицы.

**Эмодзи (критично, §3/§8 визуального языка):** `📍🏨💰⚠️✅❌🇦🇷`
шрифтом не рендерятся и вырезаются. Значимые маркеры заменяем на
Unicode-геометрию, которую тянет DejaVu:
- `⚠️` в заголовке бюджета → семантику несёт сам `warning_box`,
  текст-маркер не нужен;
- `✅ / ❌` в «кому подходит» → **`✓` (зелёный) / `✗` (красный)** —
  работа polish-шага или рендера; иначе строки теряют маркер;
- `🇦🇷` и прочие флаги — убрать.

**Числа/валюту парсить валюта-агностично** (₽/$/€/₫/…), с учётом
разделителей тысяч.

## 6. Polish-шаг (`stage4-polish-prompt.md`)

По аналогии со `stage5-polish-prompt.md`, flow
`polish → sanity (polish_check.py) → render`:

- убрать pipeline-жаргон: `aggregation_mode: scarce`, «Stage 3/4»,
  ярлыки `over_20+`/`over_10_20` → человекочитаемо («превышение ~+32%»);
- категории `STRONG CONFIRMED / LOW SIGNAL / OUTLIER TRC` для `self`
  смягчить, но смысл сохранить (объясняет, почему POI там, где он есть);
- человекочитаемые заголовки вариантов уже есть в md — не трогать;
- `✅/❌ → ✓/✗`, снять флаги-эмодзи;
- никакого `trip_id` / `chosen_variant` / `## Решение` в человеко-facing
  выводе.

## Заметки реализации (2026-05-29)

Что отклонилось/уточнилось при кодировании относительно плана выше:

- **Ссылки в сводной таблице.** Имена вариантов в шапке таблицы сделать
  кликабельными нельзя: фон шапки = `primary`, цвет ссылки = `primary`
  → ссылка слилась бы. Решение: отдельная видимая навигационная строка
  «Подробнее по вариантам: Вариант A · B · C» под заголовком сравнения
  (ссылки на `#variant-N`). Back-link `↑ К сравнению` в хвосте каждого
  варианта — как в плане.
- **Цвет плашки варианта.** Потребовал добавить параметр `bg_color` в
  `pdf_lib.section_bar` (backward-compatible, default = section_bar_bg).
  Варианты красятся `REGION_PALETTE[0/1/2]`.
- **Priority pool свёрнут** в `info_box` (лид) + `definition_list`:
  «Обязательно» и «Условно» — с именами POI (колонка после `#`),
  «Средний / Мягкие / Исключено» — счётчиком позиций.
- **Бюджетный блок варианта** (`⚠️ **Бюджет:** …`) рендерится в amber
  `warning_box` (детект по лид-маркеру ⚠ в `render_md_body`).
- **Слаги вариантов** — по индексу (`variant-1/2/3`), ASCII-safe независимо
  от алфавита метки (A/B/C или А/Б/В).
- **honest assessment** рендерится generic-renderer'ом как проза; отдельный
  warning_box для «Бюджетной сводки» не делался (можно добавить позже).
- **render_md_body** — собственный компактный markdown-renderer Stage 4
  (не импорт private-функций stage5): держит модуль независимым.
- **Два формата заголовков.** Экстрактор понимает и новый формат
  («Вариант A: …» + «Сравнительная таблица»), и старый («Variant A — …»
  + «Сравнение», встречается в страна_г_1). Незнакомые содержательные H2
  (CONTESTED, «Что не вошло …») рендерятся generic-passthrough'ом;
  pipeline-шум (Tags resolution, Trip parameters, Следующий шаг) подавлен.

## Правки по фидбэку (2026-05-29, после ревью страна_г_1)

- **Колонки сравнения** «Variant A/B/C» → «Вариант A/B/C» (`_ru_variant_label`
  на строке-заголовке таблицы).
- **Оглавление:** убрана родительская «Варианты маршрута»; варианты —
  секции верхнего уровня (outline level 0). Добавлен пункт «Обзор»
  (якорь на обложку) для быстрого прыжка в начало; в outline он показан
  кратким «Обзор», а не полным заголовком.
- **Русификация заголовков секций:** `CONTESTED → Спорные`,
  английское `variant → вариант` (`_normalize_heading` на extras).
- **Таблица параметров поездки на обложке** (через polish-маркер
  `[[поездка: …]]` + скрипт): строки «Кто едет / Маршрут / Старт-финиш /
  Длительность / Сезон / Темп / Вариантов / Бюджет-ориентир». Маршрут,
  сезон, темп имеют fallback-инференцию из trip_id/контекста, если маркера
  нет; «Кто едет» — только из маркера (берётся из профиля).
- **Заголовок обложки** (`_cover_title`): pipeline-H1 («Stage 4 … —
  Варианты маршрута: trip_id») заменяется на «{регионы} · {N} ночей ·
  сравнение вариантов»; чистый H1 (после polish) остаётся как есть.
- **Без дублей таблица ↔ заголовок ↔ контекст** (2-й раунд ревью):
  регионы — только в заголовке (строка «Маршрут» из таблицы убрана);
  длительность/сезон/темп — только в таблице (из заголовка убраны);
  `_strip_dup_context` вырезает из прозы контекста вводные **Key:**-пункты
  (Поездка/Темп/Маршрут/Длительность/Сезон/Бюджет/Группа), оставляя
  содержательное (ограничения, теги, развилки). Polish T1 обновлён —
  заголовок без «N ночей».
- **Граница:** инлайновые упоминания «Variant»/«CONTESTED» и параметров
  внутри содержательной прозы (напр. «18 ночей не закрывают оба») рендер
  НЕ переписывает (риск порчи смысла) — это работа polish-шага.
  Русифицируются/дедуплицируются только заголовки, колонки и вводные
  param-пункты.
