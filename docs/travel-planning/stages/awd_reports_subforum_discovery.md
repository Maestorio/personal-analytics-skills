Памятка для `fetch_awd.py` (`scripts/`) и Stage 1 скилла `travel-planning`
(`references/stage1/stage1-dr-prompt.md`, §7.2.1 B1).

Проблема, диагноз, обобщённый метод и готовые патчи. Кейс — Китай, но логика
страно-независимая.

> **✅ Реализовано (2026-06-08).** Патчи §5 (`score_reports_subforum`,
> `_report_ratio`, `pick_reports_subforum` + замена выбора в `discover_reports`,
> вывод `[выбран: score, score=N]`) и §6 (скилл `stage1-dr-prompt.md` §7.2.1) в
> коде. Скоринг доработан против памятки: `виз`/`шоп`/`ресторан` в минус-списке
> (закрыты «Визовый»/«Шопинг»/«рестораны»), тай-брейк — только внутри топ-кластера.
> Проверено живьём на 7 странах: Китай f=247, Япония f=308, Страна А f=1110, shared
> Страна В f=439 / Непал f=341 / ЮАР f=673, слабый Марокко f=641 — все верно, без
> падений. Офлайн-регресс: `tests/test_fetch_awd.py` (24 проверки, фикстуры
> снятых subforum'ов).

## TL;DR

- На awd.ru у каждой страны несколько дочерних subforum'ов. Реальные
  травелоги (отчёты с фото) и планировочные ветки («помогите с маршрутом»)
  лежат в **разных** subforum'ах.
- Текущий `discover_reports()` выбирает subforum по совпадению `отчёт|отзыв`
  в названии и берёт **первый** (`report_children[0]`). Для Китая первым
  идёт **f=911 «Маршруты … советы, планирование и отзывы»** (планирование,
  балласт), хотя нужен **f=247 «Отзывы о поездках … впечатления, отчёты и
  фото»** (травелоги).
- Слово **«отзыв» — слабый/неоднозначный сигнал** (есть и в планировочной,
  и в травелог-ветке). Различают их **«отчёт/впечатления/фото/рассказ/
  дневник»** (травелог) vs **«маршрут/планирование/советы/вопросы»**
  (планирование).
- Фикс: **скоринг** дочерних subforum'ов по словам в названии + опциональная
  **эмпирическая проверка** (доля отчётных заголовков на первой странице).

## 1. Проблема — почему `discover_reports` промахивается

Текущая логика (`fetch_awd.py`, функция `discover_reports`):

```python
report_kw = re.compile(r'отчёт|отчет|отзыв', re.IGNORECASE)
report_children = [c for c in children if report_kw.search(c['name'])]
if not report_children:
    raise ValueError(...)
reports = report_children[0]          # ← берёт ПЕРВЫЙ совпавший
```

Два дефекта:

1. **`report_children[0]`** — берёт первый child в порядке вёрстки страницы,
   а не лучший по смыслу.
2. **`отзыв` ловит планировочную ветку.** На awd.ru названия subforum'ов
   «маркетинговые» и длинные: и планировочная, и травелог-ветка содержат
   «отзывы». Поэтому фильтр `отчёт|отзыв` пропускает обе, а `[0]` отдаёт ту,
   что выше в списке.

Для Китая (родитель f=138) список детей в порядке вёрстки:

| Поряд. | f | Название | Тип |
|---|---|---|---|
| 1 | 244 | Общие вопросы о Китае — подготовка и организация поездки | планирование |
| … | 251 | Деньги и обмен валюты | инфо |
| … | 1425 | Сотовая связь и мобильный интернет | инфо |
| … | 1668 | Что посмотреть — достопримечательности | инфо/POI |
| … | 1715 | Хайнань и острова | регион |
| **6** | **911** | **Маршруты по Китаю — советы, планирование и отзывы** | **планирование** ← брался |
| … | 246 | Транспорт | инфо |
| … | 249 | Виза и транзит | инфо |
| … | 1716 | Таможня | инфо |
| **10** | **247** | **Отзывы о поездках — впечатления, отчёты и фото** | **травелоги** ← нужен |
| … | 248 | Отели | инфо |
| … | 1717 | Медицина | инфо |
| … | 250 | Шоппинг и рестораны | инфо |

`report_children` = [f=911, f=247] (оба содержат «отзыв»), `[0]` = **f=911**.
Результат: discovery возвращал планировочный subforum, где ~90% веток —
«Прошу помощи», «Покритикуйте маршрут», «Вопросы по маршруту». Реальные
отчёты — в f=247 (524 темы-травелога).

## 2. Как я нашёл f=247 в этот раз (фактические шаги)

1. **`--discover-reports` дал f=911** и его планировочные темы → триаж
   ~11 веток показал, что почти все они планировочные (первый пост в
   будущем времени: «хочу поехать», «прошу советов», «подскажите»).
   Вывод: subforum выбран неверно.

2. **Прочитал ВСЕХ детей родительского forum'а Китая (f=138)** напрямую:

   ```python
   import fetch_awd
   html = fetch_awd.fetch_awd('https://forum.awd.ru/viewforum.php?f=138')
   for k in fetch_awd._child_subforums(html):
       print(k['f'], k['name'])
   ```

   В списке сразу видно **f=247 «Отзывы о поездках в Китай — впечатления,
   отчёты и фото путешественников»** — название явно травелог-ветки
   («впечатления, отчёты, фото»), в отличие от f=911 («советы,
   планирование»).

3. **Проверил f=247 через `--list-topics 247 --pages 4`** → 524 темы,
   заголовки — реальные отчёты («Пара сеньоров в Китае в октябре 2025»,
   «Такой разный Китай с юга на север», «Пекин-Пинъяо-Датун. Май 2019»).
   Это и есть «подсветка отчётов».

4. **Внутри f=247 всё равно триажировал по первому посту** (отчёт vs
   изредка проскакивающий вопрос) — см. §4.

Узкое место, которое стоило времени: шаг 2 (прочитать всех детей и выбрать
по смыслу) пришлось делать руками, потому что `discover_reports` его не
делает. Это и автоматизируем.

## 3. Обобщённый метод — скоринг subforum'а (страно-независимо)

Не «первый по `отчёт|отзыв`», а **выбор по сумме баллов названия**.

### 3.1 Сигнальные слова

**Травелог (положительные):**
- `отчёт` / `отчет` (+3)
- `впечатлен` (+2), `рассказ` (+2), `фото` (+2), `дневник` (+2)
- `путешеств` (+1)

**Планирование/инфо (отрицательные):**
- `маршрут` (−3), `планирован` (−3), `вопрос` (−3)
- `совет` (−2), `подготовк` (−2), `организац` (−2)
- `виза` / `транспорт` / `отел` / `деньги` / `связь` / `таможн` /
  `медицин` / `шоппинг` (−3 каждый — это чисто инфо-ветки)
- `достоприм` (−1)

**Неоднозначное:**
- `отзыв` (+1) — слабый сигнал; есть и там, и там. Не должен решать
  исход в одиночку.

Выбираем child с **максимальным баллом > 0**. Для Китая:
- f=247: `отзыв`(+1) + `впечатлен`(+2) + `отчёт`(+3) + `фото`(+2) = **+8**
- f=911: `маршрут`(−3) + `совет`(−2) + `планирован`(−3) + `отзыв`(+1) = **−7**

→ уверенно f=247.

### 3.2 Граничные случаи

- **Нет ни одного child с баллом > 0** (страна без выделенной травелог-ветки)
  → fallback на сам country forum, если у него есть свои темы (как в текущем
  коде: `own_topics_count >= 10`), иначе — честный `ValueError` с перечнем
  детей, чтобы человек выбрал руками.
- **Ничья / близкие баллы** (две похожие ветки) → перейти к эмпирической
  проверке §4.2 (доля отчётных заголовков).

## 4. Эмпирическая проверка и триаж тем

Скоринг названия — дёшево и обычно достаточно. Где нужна надёжность —
сэмплировать заголовки.

### 4.1 Отчёт vs вопрос по ЗАГОЛОВКУ темы

**Признаки отчёта:**
- список регионов через тире/стрелки с датами: `Пекин-Сиань-Шанхай … (октябрь 2024)`
- слова `отчёт`, `дневник`, `как мы`, `впечатления`, `за N дней`, `вернулись`,
  `съездили`, `побывали`
- прошедшее/завершённое время

**Признаки вопроса/планирования (отбрасывать):**
- `помогите`, `подскажите`, `прошу помощи`, `вопрос(ы)`, `критику`,
  `покритикуйте`, `оптимизация маршрута`, `планиру`, `?` в конце
- «Маршрут … на N недель в {будущий месяц}»

### 4.2 Report-ratio первой страницы (для выбора между двумя subforum'ами)

```text
ratio = (кол-во отчётных заголовков) / (всего тем на стр. 1)
```
Травелог-ветка даёт ratio ≫ планировочной. Берём subforum с большим ratio.

### 4.3 Триаж ВНУТРИ выбранного subforum'а (всё равно нужен)

Даже в f=247 изредка попадают вопросы, а отчётные заголовки врут
(«Путешествие по маршруту …: советы» оказалось планированием — t=437001/2).
**Финальный фильтр — по первому посту:** прошедшее время и личный опыт →
отчёт; «хочу/прошу/планирую» → балласт. Не доверять только заголовку.

## 5. Патч для `fetch_awd.py`

Добавить функцию-скоринг и поправить выбор в `discover_reports`.

```python
# --- NEW: скоринг дочернего subforum'а как травелог-ветки ---
_REPORTS_POS = {
    "отчёт": 3, "отчет": 3, "впечатлен": 2, "рассказ": 2,
    "фото": 2, "дневник": 2, "путешеств": 1,
}
_REPORTS_NEG = {
    "маршрут": -3, "планирован": -3, "вопрос": -3, "совет": -2,
    "подготовк": -2, "организац": -2, "виза": -3, "транспорт": -3,
    "отел": -3, "деньги": -3, "связь": -3, "таможн": -3,
    "медицин": -3, "шоппинг": -3, "достоприм": -1,
}

def score_reports_subforum(name):
    """Балл «это ветка отчётов, а не планирования/инфо». >0 — кандидат."""
    n = name.lower()
    score = 0
    for k, v in _REPORTS_POS.items():
        if k in n:
            score += v
    for k, v in _REPORTS_NEG.items():
        if k in n:
            score += v
    if "отзыв" in n:          # слабый неоднозначный сигнал
        score += 1
    return score


def _report_ratio(f_id):
    """Доля отчётных заголовков на первой странице (для тай-брейка)."""
    topics = list_topics(f_id, pages=1)
    if not topics:
        return 0.0
    q = re.compile(r"помог|подскаж|прош|вопрос|критик|планир|оптимиз|\?$",
                   re.IGNORECASE)
    rep = re.compile(r"отчёт|отчет|дневник|как мы|вернул|съезди|побыва|"
                     r"впечатл|за \d+ дн|\d{4}", re.IGNORECASE)
    good = sum(1 for t in topics
               if rep.search(t["title"]) and not q.search(t["title"]))
    return good / len(topics)
```

В `discover_reports`, заменить блок выбора reports-subforum:

```python
    if own_topics_count >= 10:
        reports = country
    else:
        # БЫЛО: report_children[0]
        # СТАЛО: скоринг по названию, при ничьей — report_ratio
        scored = [(c, score_reports_subforum(c["name"])) for c in children]
        cands = sorted([(c, s) for c, s in scored if s > 0],
                       key=lambda cs: cs[1], reverse=True)
        if not cands:
            raise ValueError(
                f"У subforum '{country['name']}' (f={country['f']}) нет "
                f"травелог-ветки по скорингу. Дочерние: "
                + ", ".join(f"f={c['f']} '{c['name']}'" for c in children[:8]))
        # тай-брейк, если топ-2 близки (разница ≤1 балла)
        if len(cands) > 1 and cands[0][1] - cands[1][1] <= 1:
            cands.sort(key=lambda cs: _report_ratio(cs[0]["f"]), reverse=True)
        reports = cands[0][0]
```

Опционально — флаг прозрачности: печатать выбранный subforum и его балл в JSON
(`"reports_forum": {"f":..., "name":..., "score":...}`), чтобы было видно, на
каком основании выбрано.

### 5.1 Тест после патча

```bash
python3 fetch_awd.py --discover-reports китай --pages 1 --json | \
  python3 -c "import json,sys; d=json.load(sys.stdin); print(d['reports_forum'])"
# ожидаем f=247, не f=911
```

Регресс-проверка на других странах (где `discover_reports` уже работал):
прогнать `--discover-reports страна Б`, `--discover-reports страна В` — балл
не должен «увести» от корректной ветки. Если у страны только одна
report-ветка, скоринг её и вернёт (единственный кандидат с score>0).

## 7. Чек-лист «найти ветку отчётов страны на awd.ru» (вручную, если без патча)

1. `--discover-reports <страна>` → если темы выглядят как «помогите/прошу/
   вопрос» — subforum выбран неверно, не останавливаться на нём.
2. Прочитать ВСЕХ детей родительского forum'а:
   `fetch_awd._child_subforums(fetch_awd.fetch_awd('https://forum.awd.ru/viewforum.php?f=<country_f>'))`.
3. Выбрать child с `отчёт/впечатления/фото/рассказ/дневник` в названии (НЕ
   «маршрут/планирование/советы»).
4. `--list-topics <f> --pages 3-4` → убедиться, что заголовки — отчёты.
5. Внутри — триаж по первому посту (прошедшее время vs «хочу поехать»).
