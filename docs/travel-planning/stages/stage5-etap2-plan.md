## 1. Граница Stage 5 / Stage 6

**Правило решения:** *нужно, чтобы ВЫБРАТЬ маршрут или ЗАБРОНИРОВАТЬ → Stage 5;
пост-решение/финиш, считается ОДИН раз → Stage 6.*

- **Stage 5 = прочный каркас**, с которым уже можно ехать: маршрут, дни,
  переезды, отели (план, с TODO-ценой), бюджет, риски, day-fill. Итерируется
  (4_v2/5_v2/…/5_vX). Producing-модель: Opus + Thinking + high.
- **Stage 6 = идеал**, один раз после устаканивания 5_vX: поглощает его и доводит.
  Producing-модель: Sonnet (retrieval/компиляция/мёрж) + детерминированная карта.
  **Переживает iteration loop** (зависит от устаканенного маршрута, не от тегов).

### Раскладка пунктов

| | Stage 5 (каркас) | Stage 6 (идеал) |
|---|---|---|
| Маршрут/дни/переезды(план)/бюджет/риски | ✓ | — |
| #8 happy/contingency · #12 рационал · #13 источник POI · #14 тезис | ✓ | — |
| TODO-**верификация цен** (нужно, чтобы бронировать) | ✓ | — |
| Отели/переезды | план (выбор + TODO-цена) | финал (подтверждённые) |
| **Карты** (координаты персистятся в артефакте 6) | — | ✓ #7 |
| **Досье**: визы/медицина/прививки/страховка/этикет/упаковка/экстренное | — | ✓ #9 |
| Гастрономия | — | ✓ (enrichment) |
| **Enrichment по запросу**: рестораны/онсэны/кофе/история региона | — | ✓ |

### Бронь — может идти в ОБЕ стадии (клариф пользователя)
Бронь = новый входной факт-ограничение.
- **Структурная** (отель далеко/окраина; переезд фиксирует плечо) → подаётся
  **в Stage 5** → новый 5_vX перепланирует вокруг факта. ⇒ блоки отеля/переезда
  Stage 5 имеют представление «забронировано» (убрать TODO-цену, реальное
  расположение, перекроить день).
- **Косметическая** (номер/подтверждение, маршрут не меняется) → **Stage 6**.
- Workflow: 5_vX (готов) → [бронь] → если структурная, назад в 5 (новый vX);
  иначе сразу 6. Повторно гонять 5 ради косметики не нужно.

### Backward-compat на вход (жёсткое требование)
Новая итерация из СТАРОГО 5_v{N} не должна падать:
- mode-detection — по упорядоченному списку регионов (устойчив к формату);
- новые секции/маркеры Этапа-2 — **опциональны на входе** (отсутствие ≠ ошибка),
  новая итерация их дописывает;
- `check_format` валидирует ВЫХОД (новый vN+1), не вход.
Правило репозитория: смена схемы → миграция ИЛИ backward-compat; берём 2-е.

## 3. Фазы

### Фаза A — Stage 5 route-уточнения (2B) ← не зависит от Stage 6
Producing-спека §6.3 + полиш + экспорт-рендер, **всё input-backward-compatible**:
- #8 ⚠️ как короткий указатель (деталь — в риск-секции);
- #12 тонкий «почему» в дне, глубокий — наружу (рендер уже выносит в приложение);
- #13 строка-источник для якорных POI (из пула Stage 3);
- #14 тезис маршрута на обложке;
- #15 маркер «погодный риск»; **booking-режим отеля/переезда** (план/забронировано)
  — общий с Stage 6 контракт маркера брони.
- Маркеры дня структурно те же (📍🏨🎯💰⚠️) → format_contract держится; golden обяз.

### Фаза B — Stage 6 (новая стадия) ← дизайн через `/travel-stage-builder`
Артефакт `6_*.md` (имя — на дизайне), Sonnet. Состав:
- **Ядро (детерминированно/всегда):**
  - **Карты (#7):** координаты резолвятся двухтиерно и **персистятся в артефакте 6**
    (таблица регион/точка → `lat,lon` + `source: gazetteer|model`, ревьюабельно —
    согласовано). Tier-1 — газетир Natural Earth (скрипт); Tier-2 — модель для
    ненайденных. Рендерер — универсальный из прототипа, кормится из артефакта 6.
  - **Досье (#9):** визы/медицина/прививки/страховка/этикет/упаковка/экстренное.
  - **Инкорпорация брони (#16, косметическая):** реальные билеты/номера/статусы.
- **Enrichment (только по явному запросу):** история региона/города, конкретные
  точки/рестораны/онсэны/кофе. Не делается само — иначе Stage 6 безграничен.
- Профиль-бокс (#11) — route-independent → здесь (или мелким блоком на обложке 5).

### Геобандл (общий ассет, шаг 1 — частично готов build-скрипт)

## 5. Решения
- **Граница 5/6 — согласовано** (см. §1).
- **Бронь — в обе стадии**, по структурности (§1).
- **Backward-compat на вход — обязателен** (§1).
