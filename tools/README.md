# tools/ — Personal Hub: страницы, хостинг, данные

Веб-часть кабинета: страницы, конфиги NAS и обслуживающие скрипты.

## Что где

| Путь | Что это |
|---|---|
| `*.html`, `assets/` (справка вьюера — `assets/help/viewer/`) | **Страницы кабинета.** Лежат в корне намеренно: так репозиторий зеркалит боевой адрес — `tools/hub.html` здесь = `/tools/hub.html` на сервере. |
| `assets/help/*.md` | **Справки страниц** (кнопка «? Справка», компонент в `assets/ui-kit.js`): hub/travel/games/health — что сказать Claude, какая модель, откуда данные. Едут на NAS вместе с `assets/`. Правило синхронизации со скиллами — корневой `CLAUDE.md`, «Справки страниц кабинета». |
| `hosting/` | **Всё, что живёт на NAS**: `Caddyfile` (+`.example`), `docker-compose.yml`, `api/server.py` (write-API sidecar), `SYNOLOGY-SETUP.md`. |
| `design-reference/` | Дизайн-система, макеты Claude Design, планы (`*-plan.md`). |
| `tests/` | Контракт-тесты страниц, write-API и зон Caddy. |
| `deploy.zsh` | Выкладка. Точка входа — держится в корне. |
| `_archive/` | Отработавшие одноразовые скрипты (миграция Claude-Memory 2026-05). Не запускать; лежат ради истории. |

## Как выкладывать

```bash
zsh tools/deploy.zsh
```

Скрипт кладёт **только страницы/ассеты** на Synology, довозит конфиги NAS в
`Claude-Memory/_nas/`, а затем **опрашивает боевой сервер** и печатает готовую
команду, если на NAS что-то устарело. Файлы из `hosting/` он положить на место
не может — они лежат вне дерева Synology Drive, поэтому финальный `cp` делается
на самом NAS (команду скрипт выдаёт).

Все файлы здоровья (`labs.json`, `biomarkers-info.json`, `meds.json`,
`vaccinations.json`, `vitals.json`, `studies.json`) deploy **не трогает**: их
мастер — только на Synology, их пишут напрямую страница и скиллы
`health-labs`/`health-meds`, копия с Мака затёрла бы правки.

## Тесты

```bash
python3 tools/tests/test_pages_contracts.py    # страницы ↔ контракты данных
python3 tools/tests/test_write_api.py          # sidecar: whitelist, схемы, 409
python3 tools/tests/test_caddy_zones.py        # зоны на НАСТОЯЩЕМ caddy (нужен brew install caddy)
python3 skills/health-labs/scripts/build_health_json.py --selftest   # конвертер labs — владелец health-labs
```

Правило версий: правишь страницу — подними её версию в футере, иначе браузеры
держат старый файл по тому же ключу кэша.

**Минор — счётчик, а не десятичная дробь: за 1.9 идёт 1.10, потом 1.11.**
Мелкие правки набегают часто, и упереться в «девятку» нельзя. Мажорную цифру
двигаем только за существенное — редизайн, смена модели данных, — а не потому,
что «1.10 некрасиво выглядит» (реальная причина ошибочного health 2.0 →
переименован в 1.10). Прецедент в репозитории уже был: вьюер ходил
2.6.9 → 2.6.10.

Версии нигде не сравниваются программно — они печатаются в футере, а в кэш-
бастере (`?v=…`) участвуют строкой. Поэтому «1.10 < 1.9» при строковом
сравнении ничего не ломает. **Если появится сравнение версий — сравнивать
по числам покомпонентно, не строкой.**
