## Целевая модель доступа — 3 уровня (зафиксирована пользователем 2026-07-13)

| Уровень | Кто | Что может |
|---|---|---|
| **1 — пароль** | ввёл пароль (спрашивается ТОЛЬКО при входе в Портфель, позже — Здоровье) | всё |
| **2 — доверенная сеть** | LAN или личный VPN (по IP) | просмотр всего публичного + правки travel Stage 3–4 (и «итог» игр) |
| **3 — все остальные** | любой IP | видят все путешествия и игры; правки запрещены; парольных окон НЕ возникает |

План реализует все три уровня: §§1–2 — уровни 2–3 (шаринг + гость без
попапов), §3 — уровень 1 честно «пароль с ЛЮБОГО IP = все функции»
(добавлено по решению пользователя 2026-07-13): единый токен на origin,
edit-слой travel и games принимают пароль наравне с доверенным IP.
Чтение портфеля под паролем уже работает (форма вьюера v2.8.1).

## Решения пользователя (2026-07-13)

1. **Шаринг без авторизации**: ссылка `travel.html?trip=<dir>` открывает одну
   карточку поездки. Весь `/travel-planner/*` остаётся публичным (как сейчас).
   Приватность = «не раскрывать адрес» — осознанно принято; настоящий
   контроль доступа (токены) — в будущем (Приложение A).
2. **Правки travel (edit-слой Stage 3/4, «итог» игр) — только LAN + личный
   VPN.** Это УЖЕ работает через `@api_trusted` в Caddy (доверенные IP — без
   пароля). Парольный вход в правки с чужих IP считаем ненужным → фетчи к
   `/api` без кредов с чужих IP должны получать тихий 403 (см. §2) — иначе у
   получателя ссылки внутри Stage-3 HTML выскочит нативный диалог пароля.

## 1. `tools/travel.html` (v1.3 → v1.4)

**Share-режим** — `?trip=<dir>` в URL (dir = имя директории поездки):
- после загрузки трипов отфильтровать до одного: сравнение имён с
  `.normalize("NFC")` с обеих сторон (гоча macOS NFD — «й» из двух кодпоинтов,
  см. память project_personal_hub_plan «Ловушки JSON-листинга»);
- рендер: одна карточка, раскрытая (`open`), НЕ archive-стиль даже для архивных
  (полная шапка читабельнее для гостя); скрыть: фильтры «Кто едет», сводку
  `#summary`, группы-заголовки, кнопку «Поделиться» (см. ниже);
  крошку «← Хаб» можно оставить (хаб публичный) или заменить на нейтральную
  подпись — на вкус реализатора;
- всё остальное работает как есть без правок: панель просмотра стадий,
  PDF/DOCX-ссылки, профили путешественников (публичны), cache-buster;
- `?trip=` не найден → плашка «Поездка не найдена — возможно, ссылка устарела»
  (в стиле существующей «Нет связи с данными»);
- футер: бамп версии до v1.4 (правило версий страниц).

**Кнопка «Поделиться»** (только в обычном режиме, не в share):
- на карточке поездки; ВАЖНО: клик внутри `<summary>` сворачивает
  `<details>` — либо `preventDefault/stopPropagation` (паттерн `.who-name` в
  делегировании `#groups`), либо разместить в `card-body` рядом с «Финальный
  план» (проще);
- действие: `navigator.clipboard.writeText(location.origin + location.pathname
  + "?trip=" + encodeURIComponent(dir))` → фидбек «Скопировано ✓» на 1.5 сек
  (паттерн `#vw-copy`);
- никакого API/сервера — чисто клиентская ссылка, работает с любым доменом.

## 2. Caddyfile — одно правило (тихий 403 для api-фетчей без кредов)

> Править синхронно `tools/Caddyfile` (реальный, не в git) и
> `tools/Caddyfile.example`. Накат: копия на NAS
> `/volume1/docker/portfolio-viewer/` + `docker restart portfolio-viewer`.

Проблема: экспорт Stage 3 содержит edit-слой, который пингует `/api/health`
с любой страницы, где открыт (в т.ч. в iframe у получателя ссылки). С чужого
IP сейчас это `basic_auth` → 401 + `WWW-Authenticate` → **нативный диалог
пароля у гостя** (та же механика, что замораживала вкладку вьюера, см. память
viewer-auth-protection-space-bug).

Фикс — в `route` ПОСЛЕ `reverse_proxy @api_trusted`, ДО `basic_auth
@api_untrusted`:

```caddy
# Фетчи к /api без креденшалов с недоверенных IP → 403 БЕЗ попапа:
# edit-слой Stage-3 HTML у гостя тихо остаётся статичной витриной.
# Политика: правки travel/games — ТОЛЬКО с доверенных IP (LAN + VPN).
@api_fetch_noauth {
    path /api/*
    header Sec-Fetch-Dest empty
    not header Authorization *
}
respond @api_fetch_noauth 403
```

Следствие (задокументировать в шапке Caddyfile): парольный вход в правки с
чужого IP через попап больше не работает — и это соответствует политике
(редактируют только доверенные IP). `basic_auth @api_untrusted` остаётся как
страховка для запросов с явным `Authorization`.

Edit-слой при 403 штатно деградирует в статику (проверять не надо — это его
существующая ветка «нет API → витрина»).

## 3. Уровень 1 с любого IP: единый токен `hub-auth` (пароль = все функции)

Серверная часть уже готова: 403-правило §2 матчит только запросы БЕЗ
`Authorization`; запрос с заголовком проходит в `basic_auth @api_untrusted` и
валидируется. Caddy дополнительно не трогаем. Нужны клиентские правки:

1. **Единый ключ токена на origin** — `localStorage["hub-auth"]`
   (= btoa("hubuser:" + пароль), как `piv-auth`):
   - форма входа вьюера (v2.8.1 → v2.9.0) пишет токен в `hub-auth`
     (localStorage) вместо `piv-auth` (sessionStorage); `authFetch` читает
     оттуда; появляется кнопка **«Выйти»** в шапке вьюера (чистит токен) —
     localStorage переживает закрытие браузера, без выхода токен живёт долго;
   - механика заголовков БЕЗ изменений: явный `Authorization` +
     `credentials:'omit'` (обязателен — гасит нативный диалог на 401).
2. **Edit-слой Stage 3/4** (правка скилла `travel-planning`,
   `scripts/export/stages_html/` — JS edit-слоя в шаблоне HTML-экспорта):
   ко всем вызовам `/api/health|file|save` прикладывать
   `Authorization: Basic <hub-auth>` (если ключ есть) + `credentials:'omit'`.
   Итоговая логика доступа: доверенный IP → работает без токена (как сейчас);
   чужой IP + токен → работает по паролю; чужой IP без токена → 403 → статика.
   Вход — один раз через форму вьюера (отдельную форму на travel не городим;
   если токена нет — edit-слой просто остаётся витриной, как у гостя).
   После правки: прогнать тесты travel (`test_html_export.py` — контракт
   JS-конфига edit-слоя не дрейфует от добавления заголовка, но проверить),
   перегенерировать существующие Stage-3 HTML-экспорты
   (`export.py --stage 3 --trip <id> --travel-root <Synology> --format html`;
   сейчас такой один — Китай), переупаковать скилл (`/pack`).
3. **games.html** («итог:» в подборках): тот же заголовок из `hub-auth` на
   POST `/api/save` (+ `credentials:'omit'`); бамп версии страницы.
4. **Self-host chart.js и js-yaml во вьюере** (безопасность токена):
   `hub-auth` в localStorage читается любым скриптом origin'а, а
   `portfolio-integrated-viewer.html` грузит chart.js (jsdelivr) и js-yaml
   (cdnjs) с CDN — компрометация CDN = утечка пароля. Скопировать обе
   библиотеки в `tools/assets/` (js-yaml там уже лежит — games.html им
   пользуется) и переключить `<script src>` вьюера на локальные копии
   с `?v=`-кеш-бастером. hub/travel/games уже полностью self-host.

## 4. Приёмка

1. Владелец (LAN/VPN): travel.html как раньше + кнопка «Поделиться» копирует
   ссылку; edit-слой Stage 3/4 работает (`/api/health` → 200 без пароля,
   токен не нужен).
2. Гость (чужой IP, любой браузер): по ссылке `?trip=` видит одну карточку,
   все стадии смотрятся/скачиваются, профили открываются; НИ ОДНОГО диалога
   пароля, в т.ч. внутри Stage-3 HTML (edit-слой = статика).
3. Гость, стерев `?trip=`, видит полный индекс — известное следствие решения
   «без авторизации» (зафиксировано, не баг).
4. `travel.html` без параметра — поведение не изменилось (регрессия недопустима).
5. **Уровень 1 (чужой IP + пароль)**: вход через форму вьюера → портфель
   грузится; затем travel Stage-3 HTML — edit-слой АКТИВЕН (правки
   сохраняются), games «итог:» работает. «Выйти» во вьюере → edit-слой на
   travel снова статика. Эмуляция чужого IP при проверке из LAN:
   `curl -H "X-Forwarded-For: 8.8.8.8"` (для страниц — реальный внешний IP
   или выключенный VPN… включённый VPN и есть чужой-для-LAN, но он доверенный;
   тестировать с мобильного интернета).
6. Диалог пароля НИГДЕ не нативный: неверный пароль в форме вьюера → встроенная
   ошибка (не заморозка вкладки — регрессия v2.8.1 недопустима).
