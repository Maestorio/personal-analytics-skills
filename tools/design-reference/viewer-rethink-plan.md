## 0. Что выяснено (аудит 26.10.2026, вьюер 3.5x, обзор акций 26.10, YDEX и Атомэнпр08)

### 0.1 Карточка акции, подвкладка «Главное» — семь блоков про одно решение

| Блок на карточке | Откуда данные | Что не так |
|---|---|---|
| Обоснование вердикта | `per_stock[t].advisor_verdict_basis` (YAML) | Один абзац без структуры: вес, L2, IR-новости, гейт-коды, id условия, «Уверенность 0,5» — всё подряд. В MD тот же текст разбит на «Что произошло / Макро-привязка / Рекомендация» маркерами и читается |
| Что проверить до действия · HIGH | `verification_priority` + `verification_check` (пусто) | Блок с заглушкой «пунктов нет — приоритет по совокупности». Шум: приоритет без содержания |
| Отложенные условия | `conditions.yaml` (`ydex-q3-ifrs-guidance`) | Правильная механика, но `on_trigger.action` — прозаический абзац с развилкой (а)(б)(в)(г) ДОБОР / СРЕЗ / иначе. Читать как таблицу «если → то» невозможно |
| Ограничения | `advisor_verdict_constraints` — **производное** от того же условия (`derived: true`) | Строка «решение владельца · до 2026-11-30 · после — HOLD» — это то же условие, пересказанное кодами типа. Для читателя — пустой блок, который «что-то требует» |
| Фундаментальная оценка (гейт) | `gate-reviews.yaml` | Статус словами + подсказка — хорошо. Но «Причина» повторяет обоснование вердикта и условие третий раз |
| Мой план | `ie_actual.user_plan` (Numbers) | «KEEP» голым кодом; план-доля уже в плитке «Вес» |
| Позиция / Модель IE / Обзор (правая колонка) | снапшот | Нормально; «Уверенность 50 %» и «Дата обзора» дублируют метки шапки |

Итог: решение по YDEX («держать 9 %, ждать МСФО 3К до 30.11, потом либо добор до 10 %, либо срез до 7 %»)
пересказано четыре раза четырьмя словарями. Нужен **один блок «Решение»**, остальное — свёрнуто или убрано.

### 0.2 Остальные подвкладки

- **Доходность** — понятна (разложение ожидания, дивиденды наперёд, цена по снапшотам с «моей средней» и «целью IE»).
- **Риски** — первым блоком идёт `fundamental_score_basis`, а это по факту **сводка новостей недели** (цены, IR-релиз, кто снял
  рекомендацию) + 13 ссылок-источников. Дальше беты и сценарный профиль. Рисков как таковых (что может сломать тезис) нет —
  они лежат в катализаторах с `downside_pct`.
- **Катализаторы** — 7 штук с вероятностью/эффектом/окном: внутренняя арифметика ожидания (EV). Для человека ценность —
  только список «что может двинуть бумагу», без чисел.
- **История** — таблица дата / вердикт / фундаментал / див.% по 26 обзорам. Полезна, но это только обзоры: нет смен гейта,
  создания и срабатывания условий, сделок владельца, цены и веса в те даты.

### 0.3 Карточка облигации

То же самое плюс два отдельных дефекта: обоснование — `<pre class="raw">` с кодами («manual constraint, разовое»,
«своп в КОРП/А», «Re-entry»); блок ограничений — старая жёлтая плашка `renderConstraintBlock` с английскими
подписями («Тип: manual», «Re-entry», «confidence 70%»), не переведённая на ui-kit (в §1 TODO_design её не было в списке).

### 0.4 Термины, протекающие в текст для человека

`L2`, `review_needed` / `reviewed_under_review`, `Mode 4` (частично уже «разбор бумаги (Mode 4)»), id условий
(`ydex-q3-ifrs-guidance`), `manual`, `derived`, `Re-entry`, `confidence`, `KEEP`, `HOLD_TO_MAT`, `n=4 ⚡L1`,
«Уверенность 0,5». Для гейтов словарь уже есть (`_shared-references/gate_status_ru.py`), для остального — нет.

### 0.5 Данные: что есть и чего нет

- Есть в YAML/снапшоте/реестрах: вердикт, уверенность, обоснование (абзац), фундаментал + источники, дивиденды,
  катализаторы, беты, сценарный профиль, условия с историей, гейт с историей, план/статус/заметки из Numbers,
  IE old→new, цена и вес по 35 снапшотам.
- **Нет в YAML**: недельное «Что произошло / Макро-привязка / Рекомендация» по бумаге. Его пишет модель в `changes.md`,
  `render_weekly_md.py` (RPA-33) вклеивает в MD, а в YAML остаётся только `advisor_verdict_basis`. Поэтому карточка
  не может показать то, что читается в MD. Это главная причина «MD понятен, карточка — нет».
- Условия: развилка решения — только прозой в `on_trigger.action`.

### 0.6 Snowball и другие системы — что взять

Snowball ([карточка SBER](https://snowball-income.com/public/asset/SBER.MCX.RUB)): цена, P/E, EPS, капитализация,
дивдоходность, график с линией «средняя в портфеле», блок «в моих портфелях» (средняя, прибыль, выплаты, доля),
вкладки «Дивиденды», «Финансовые показатели», ИИ-инсайт по отчётности (по подписке). Ребалансировка — по категориям
с целевыми % (наши «Доли и цели» уже богаче: гейты, условия, лоты). Карточка Snowball — **страница рынка**, не страница
решения; тезиса, условий и истории решений там нет. Берём только приём: шапка одним экраном «цена · моя средняя ·
прибыль · доля», остальное у нас уже есть или отвергнуто (§1 TODO_design, 2026-10-12).

Образец структуры решения по бумаге — шаблоны «thesis tracker» ([Anthropic financial-services](https://mcpservers.org/id/agent-skills/anthropic/financial-services/thesis-tracker),
[Vibe-Trading](https://tessl.io/registry/skills/github/HKUDS/Vibe-Trading/thesis-tracker), [Trader Memory Core](https://skillselion.com/skills/tradermonty/claude-trading-skills/trader-memory-core)):
тезис из нескольких опор → falsifiable-допущения и «красные линии» (что опровергнет тезис) → журнал обновлений (новый факт
усиливает/ослабляет опору, действие, уверенность) → квартальный пересмотр. У нас всё это есть по частям: опоры = обоснование,
красные линии = условия и гейт, журнал = история обзоров + история условий/гейта. Карточка должна их так и показывать.
Готовых потребительских приложений с таким контуром поиск не дал ([Sharesight](https://www.sharesight.com/blog/how-to-get-the-most-out-of-sharesights-performance-tracking-features)
и аналоги — учёт и отчётность; русские «дневники инвестора» — [учёт операций в 1С](https://infostart.ru/public/2601441/),
[советы вести дневник](https://finratings.kz/news/9435-kak-vesti-dnevnik-investora-chtoby-sdelki-stali-pribylnymi-sovety-opytnogo-investora/amp)).

## 1. Целевая карточка бумаги

### 1.1 Принципы

1. **Одна карточка — одно решение.** На «Главном» решение написано один раз: что делаю, почему, чего жду, что тогда.
2. **Текст для человека.** Коды (L2, статусы, id, Mode N) — только в подсказках `(i)`; в тексте — слова из общего словаря.
3. **Производное не показывать дважды.** Ограничение, порождённое условием (`derived: true`), не рисуется отдельным блоком.
4. **Пустой блок не рисуется.** «Что проверить» без пунктов, «Ограничения» без ограничений — убираются, а не заменяются заглушкой.
5. **Числа — только с единицей и датой.** «Уверенность 0,5» → «уверенность средняя (50 %)»; суммы — «по снапшоту 23.10».
6. **История — это журнал решений по бумаге**, а не таблица обзоров.

- **Правка плана и доли IE** (замечание владельца по макету, 26.10): у блоков «Мой план» и «Модель IE» кнопка «изменить →» стоит
  справа от заголовка группы, в той же строке — отдельной строки не занимает (вход в сценарии §4: правка плана, правка одной доли IE с комментарием).
- **Лоты, не штуки** (замечание владельца по макету 26.10): где расчёт идёт лотами (развилка условий, колонка «Сейчас»), показывать
  лоты («15 лотов»); количество в позиции и в таблицах — в две строки: крупно «129 лотов», под ним бледно «1 шт. в лоте · 129 шт.»
  (вариант принят как самый читаемый в узкой колонке; если лотность у всех бумаг одна — выносить в заголовок колонки).
  **Облигации — штуками, без лотов** (владелец 26.10).
  Подпись под развилкой — одной строкой: «доли заданы разбором дд.мм; суммы и лоты — по актуальной цене; база — X млн ₽».
- **Блок «Модель IE»** (замечание владельца по макету, 26.10): «было X%» показывать только при изменении цели; бумаги нет в модели —
  строка «нет в IE» вместо прочерков; есть — потенциал IE. Свежесть: модель моложе 2 месяцев — «актуальна»; старше —
  подпись «пересобери модель IE с сайта» с датой (порог 2 мес, при 3+ — выделять как устаревшую; порог уточнить).
  Изменилась доля IE и к изменению есть комментарий причины (`user_note_ie`, после ухода от Numbers — журнал импорта) — строка
  «было X% → Y%: причина…»; комментария нет — про изменение ничего не выводится. «Мой план»: статус и заметка показываются только
  когда заполнены — пустых строк «не задан» / «нет» не бывает (замечание владельца 26.10).
- «Фундаментальная оценка» (гейт) схлопывается в одну строку в «Почему» + подсказка; полный блок — по клику (окно Gate уже есть).
- «Что проверить до действия» — только если есть пункты; приоритет HIGH без пунктов → слово «проверка перед сделкой обязательна» в строке решения.
- Метки шапки: у каждой метки-статуса («проверка перед сделкой», «гейт: на пересмотре», значки у вердикта) — пояснение при наведении и по касанию на телефоне (`.ui-info` с меткой вместо кружка-(i)), плюс легенда в справке (замечание владельца по макету 26.10).

**Про «переосмыслить БД» (вопрос владельца 26.10).** Сегодня хранилище — файлы-артефакты по неделям (YAML + MD),
реестры (`conditions.yaml`, `gate-reviews.yaml`) и снапшоты JSON; это правильная форма для записи (один писатель на файл,
история — отдельными файлами, D3). Неудобна она для чтения «по бумаге»: вьюер грузит в браузер ~45 отчётов и 35 снапшотов
и разбирает YAML на лету, уведомитель на NAS читает те же файлы. Менять формат записи не стоит (26 обзоров, тесты, скиллы);
стоит добавить **производный слой чтения** — индекс по бумаге (F), который пересобирается детерминированно из артефактов.
Тогда карточка и таймлайн читают один файл, уведомитель — тоже, а старые артефакты остаются источником истины. Решение по F —
открыто (§6).

Переписывать `save-to-library` не нужно: формат отчётов (MD) не меняется, YAML расширяется необязательными полями,
валидаторы — аддитивно. Это снимает вопрос «отображать и старый, и новый вид»: старое читается fallback'ом.

### 7.1 Где сегодня одно и то же показано несколько раз

### 7.2 Принцип

Раздел отвечает на один вопрос, и ответ живёт в одном месте; остальные разделы **ссылаются**, не пересказывают:

- **«Сегодня»** — *что изменилось и сколько у меня*: плитки (портфель, доходность, «Требует внимания», купоны 12 мес),
  устаревшее — одной строкой со ссылкой на «Действия», окно катализаторов. **Без** списков вердиктов и условий
  (они — «Действия»).
- **«Действия»** — *что решить и что сказать Claude*: единственный список решений (условия, вердикты, устаревшее), все
  кнопки-команды. Остаётся как есть (3.52.0), плюс забирает «Ждут решения» с «Сегодня» (на «Сегодня» — счётчик).
- **«Акции» / «Облигации» / «ИИС-3»** — *что у меня есть и что про это думает советник*: таблицы с вердиктами
  (информация, не список дел), карточка — решение по бумаге. Пара `HOLD → TRIM` в таблице остаётся (это состояние бумаги).
- **«Доли и цели»** — *расстояние до плана*: колонка «Сейчас» остаётся арифметикой, но строка бумаги с активным вердиктом
  BUY/TRIM/SELL получает ссылку «советник: …» в «Действия» (а не второй ответ).
- **«Выплаты»** — *деньги по датам* (с переключателем счетов).
- **«Динамика» · «Стресс» · «Макро» · «Изменения» · Ещё (Интеграционный · Прогнозы)** — *контекст*: без изменений.
