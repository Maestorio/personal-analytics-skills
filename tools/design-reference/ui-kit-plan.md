# План унификации UI-компонентов Personal Hub в общий `ui-kit`

Проектный SSOT работы по выносу общего UI пяти страниц кабинета
(`tools/{hub,travel,games,food,health}.html`) в `tools/assets/ui-kit.{css,js}`
по образцу `viewer.{css,js}` (версия через `?v=`). Ведётся на ветке
`ui-kit-unification`. Детальная карта дрейфа по элементам — `ui-kit-audit.md`
рядом. (Личная рабочая копия была в `~/.claude/plans/distributed-skipping-pillow.md`;
этот файл — проектный SSOT, при расхождении верить ему.)

## Порядок исполнения (выбран пользователем 2026-07-21)

1. **Фаза 3 — auth/refresh** (Войти/Выйти + Обновить), включая health. ✅ сделано+задеплоено
2. **Ярус 1 — «чистая метла»** (шрифты + токены + `plural` + `.spin`) ✅ сделано+задеплоено
3. **Ярус 2 — вынос после сведения** (кнопки/чипы/топбар + переписывание food-хрома) ← следующая
4. **Ярус 3 — архитектурный пересмотр** (поля форм + модалки)

> Порядок отличается от «окупаемость↓/риск↑» (там Ярус 1 шёл бы первым) —
> сознательный выбор: сперва довести уже начатое поведенческое (auth/refresh),
> потом дешёвая метла.

## Открытые пункты (на конец дня 2026-07-21)

- **Слияние в `main`** — вся работа на ветке `ui-kit-unification` (22 коммита от
  `main`), в `main` НЕ влита. Ждёт решения владельца.
- **Хрупкость внешних токенов** — Ярус 1 вынес токены/шрифты во внешний
  `ui-kit.css`; страницы перестали быть самодостаточными. Реальная поломка в этот
  день: hub/travel не грузили `ui-kit.css` → белый фон, нет темы/рамок. Опция
  отката, если хрупкость не устроит: вернуть токены инлайн на страницы, оставив в
  ui-kit только шрифты/компоненты. Решение за владельцем.
- **Ярусы 2–3** — не начаты. Карта дрейфа и стоимость — `ui-kit-audit.md`.
- **Урок (зафиксирован тестом)**: вставка `<link>` через `.replace("<style>", …)`
  била по ПЕРВОМУ `<style>` — а он был словом ВНУТРИ head-комментария hub/travel,
  и ссылка ушла в комментарий (страница грузилась голой). Подстроковый тест это
  пропускал; усилен — ищет `<link>` вне комментариев.

## Технический инвариант всех фаз

Две одноимённые функции в двух `<script>` НЕ дают ошибку — молча побеждает
загруженная последней (инлайн). При переносе функции в `ui-kit.js` **обязательно
удалять** старое определение на странице, а не только дописывать `<script src>`.
Каждая фаза это тестирует drift-гардом «нет локальной копии».

## Фаза 3 — auth/refresh (✅ сделано)

Единственная фаза, меняющая **видимое** поведение → обязателен ручной браузер-тест
(Python-тесты его не покрывают). Пользователь заранее одобрил скоуп: чинить hub-баг,
дать food кнопку «Выйти», унифицировать «Обновить»; **health включён** в унификацию.

### 3a — общие хелперы в `ui-kit.js` (v1.2.0)

`authToken()`, `clearAuthToken()`, `loginUrl(why)`, `authBtnHTML({why, prefix})`
(**один** элемент-тернарник Войти/Выйти), `uiRefresh(btn)`, `uiLogout(btn)`.
Единый делегированный `document.addEventListener("click", …)`, реагирующий на
`data-act="refresh"`/`data-act="logout"` **только у кнопок с `data-cache-prefix`**
(дискриминатор — чтобы сосуществовать с доменными `data-act`-диспетчерами food/health
без задвоения; food/health-refresh без префикса остаются за своими обработчиками).

**Четыре расхождения, которые общий хелпер ОБЯЗАН учесть** (иначе тихая регрессия hub;
Python-тесты не поймают):

1. **`loginUrl(why)` несёт per-page параметр** — hub `why=hub`, health `why=health`.
   `why` берётся с кнопки (`data-login-why`/аргумент), НЕ хардкодится.
2. **`uiRefresh(btn)` читает `data-cache-prefix`**: чистит `<prefix>-cache:` +
   ставит `<prefix>-cb` + `<prefix>-last-refresh` (последний пишет только hub —
   на games/travel безвреден, ставить всегда).
3. **`uiLogout(btn)` тоже читает `data-cache-prefix`** и ОБЯЗАН, кроме
   `clearAuthToken()`+reload, чистить `<prefix>-cache:` и пытаться
   `removeItem("piv-seen")` — иначе hub-сводка «зависает» после выхода
   (комментарий в hub.html:754 это фиксирует). Наивный `clearAuthToken(); reload()`
   регрессирует hub.
4. **Имя сброса токена разошлось**: hub `clearToken()`, health `clearAuthToken()`.
   Канон — `clearAuthToken()`; при переезде hub переписать вызов в его логаут-обработчике.

### 3b — перевод страниц (по коммиту на страницу)

- **hub**: refresh id-listener → `data-act="refresh" data-cache-prefix="hub"`, удалить
  императивный обработчик; пару `#btn-login`/`#btn-logout` (`hidden`, источник бага
  гонки видимости) → один `authBtnHTML({why:"hub",prefix:"hub"})`; удалить локальные
  `clearToken`/`authToken`/`loginUrl`.
- **travel/games**: refresh → `data-act="refresh" data-cache-prefix="travel|games"`,
  удалить императивный обработчик. Войти/Выйти НЕ добавлять (публичны без пароля —
  архитектурное решение Caddy).
- **food**: добавить `authBtnHTML({why:"food",prefix:"food"})` в топбар (сейчас логаута
  нет вовсе — подтверждённое расширение). refresh НЕ трогать (свой SPA-перерендер).
  Проверить, что food-диспетчер `data-act` graceful на `act="logout"` (нет ветки → no-op).
- **health** (включён по решению пользователя): перевести на общие `authBtnHTML`/
  `loginUrl`/`uiLogout`, удалить локальные копии; аккуратно убрать logout-ветку из
  health-диспетчера и дать health-логаут-кнопке `data-cache-prefix="health"`; health-
  re-render зовёт общий `authBtnHTML`. refresh health — свой (без префикса).

Тема (`data-act="theme"`) в этот заход НЕ унифицируется (у hub/travel/games и food/health
принципиально разный механизм перерисовки лейбла).

**Тесты 3b**: «Обновить везде `data-act`, не id-listener»; «hub не содержит двух
login/logout-узлов»; «нет локальных `authToken()`/`loginUrl()`». **Ручной браузер-тест
обязателен**: hub логин/логаут (одна кнопка в любой момент), food «Выйти», health
логин/логаут, на всех — «Обновить» чистит свой, а не чужой префикс кеша.
