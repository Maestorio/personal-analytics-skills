# Personal Hub — бриф для Claude Design

Пошаговая инструкция + готовые промты для дизайна хаба личных данных
(хаб · путешествия · игры; здоровье — фаза 3, экраны дорисуем в этот же проект).

**Согласованность обеспечивается дизайн-системой + тремя якорями:**

0. **Design-system проект уже создан и наполнен** (Claude Code, 2026-07-09):
   «Personal Hub — Design System», id `ce39a64b-3261-4269-936f-d41bec1e5db6`.
   Внутри: канонические токены (`tokens/viewer-tokens.css`) + 6 карточек-превью
   (цвета/типографика/кнопки/карточки/полосы данных, каждая в обеих темах).
   Источник — репозиторий: бандл `personal-hub-ds/`, генератор
   `gen_personal_hub_ds.py` (перегенерация при изменении токенов → повторный
   push через DesignSync).
1. База — токены портфельного вьюера (`design-tokens-extracted.css`): тёплый
   «бумажный» фон, Spectral для заголовков, Golos Text для UI, обе темы.
2. Акцент каждого домена берётся ИЗ существующей категориальной палитры
   `--c-1…--c-6`, а не придумывается: инвестиции — бирюза `--c-1`, путешествия —
   терракота `--c-4`, игры — слива `--c-5`, здоровье (позже) — зелёный `--c-3`.
   Палитра уже сбалансирована между собой и в обеих темах → «вырви глаз» исключён.
3. Общая грамматика: одна шапка, одни карточки, одни радиусы/тени/отступы.
   Домены различаются акцентным цветом и характером контента, не каркасом.

## Шаг 0 — что такое проект в Claude Design

Claude Design (https://claude.ai/design) — отдельный продукт: ты описываешь
экраны текстом, Claude рисует интерактивные страницы, ты итерируешь репликами
(«карточки теснее», «заголовок крупнее»). **Проект** — контейнер с набором
экранов и общей дизайн-системой; все экраны проекта автоматически наследуют
одни шрифты/цвета/компоненты. Именно поэтому делаем ОДИН проект на все домены.
Так был сделан портфельный вьюер (проект `a58f3b10-…`) — его не трогаем.

## Шаг 3 — Промт №2: раздел «Путешествия» (индекс поездок)

> Отправь после того, как хаб устроит по духу.


## Шаг 5 — как итерировать (чек-лист)

- Смотри каждый экран в **обеих темах и на mobile** до перехода к следующему.
- Правки проси конкретикой: «карточку архива приглушить сильнее», «полосы
  кластеров тоньше», «терракоты слишком много — оставить только в бейджах».
- Если Claude Design начинает уводить в «маркетинговый» стиль (hero-блоки,
  градиенты, огромные заголовки) — верни фразой «вернись к editorial-характеру
  токенов, это личный инструмент, не лендинг».
- Ничего страшного, если контент местами упростится — при порте я подключу
  реальные данные; важен каркас, типографика, состояния.

## Приложение — план внедрения после дизайна (для Claude Code)

- **Фаза 1**: порт хаба + travel-индекса. Travel-индекс читает листинг
  `travel-planner/trips/` через Caddy JSON-браузинг (`Accept: application/json`)
  либо через генерируемый манифест `trips-manifest.json` — решить при порте.
  Caddyfile: исключить `/travel*`, `/games*` и хаб из `basic_auth @external`
  (решение: travel/игры — без аутентификации, портфель — как был).
- **Фаза 2**: games-вьюер; конвертер `taste-profile.yaml` + `library_full.yaml`
  → `games-data.json` (мини-скрипт, запускается при обновлении профиля).
- **Фаза 3**: health — данные НЕ переносятся в Claude-Memory (Google-синк!);
  отдельный volume в docker-compose вне Google-синхронизации, только
  LAN/приватная зона. Перед дашбордом: дожать парсер (75 непропарсенных
  анализов, см. `parser_tuning_recommendations.md`) + health-data-loader
  CSV → валидированный JSON. Экраны дорисовываются в этот же Design-проект
  (акцент --c-3).
