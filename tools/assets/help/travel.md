# Справка: раздел «Путешествия»

Раздел ведёт **один скилл — `/travel-planning`**. Он проводит поездку через
стадии 0–6; каждая стадия — отдельная сессия со своей моделью и своим файлом.
Ключевые решения (скоуп, выбор варианта) — за тобой: скилл даёт альтернативы
и тредофы, а не «лучший ответ».

Страница показывает то, что лежит в `Claude-Memory/travel-planner/`:
карточки поездок (`trips/<поездка>/trip.yaml`), экспорты стадий и профили.

---

## 1. Стадии: что сказать → что получишь → модель

| # | Стадия | Что сказать Claude | Результат | Модель |
|---|---|---|---|---|
| P | Профиль группы | «создай / обнови профиль путешественников» | `profiles/<id>.md` | Sonnet |
| 0 | Регионы | «новая поездка: <куда>, <сколько ночей>, <сезон>, профиль <id>» | `0_scope.md` + `trip.yaml` | **Opus + thinking** |
| 1 | Промт для Deep Research | «Stage 1 для <поездки>» | промт; DR запускаешь сам в отдельной сессии → `1_dr_reports.md` | Sonnet (довыборка — Sonnet + thinking) |
| 2 | Похожие авторы | «Stage 2 для <поездки>» | `2_similarity.md` — оценка авторов 0–10 | **Opus** |
| 3 | Места (POI) | «Stage 3 для <поездки>» | `3_poi_pool.md` — места по 6 категориям | **Opus** (thinking — только на базе >60 мест) |
| 4 | Варианты маршрута | «Stage 4 для <поездки>» | `4_variants.md` — 2–3 варианта с тредофами | **Opus** (+ thinking на больших поездках) |
| 5 | Финальный план | «Stage 5 для <поездки>» | `5_final_plan.md` — дни, отели, транспорт, бюджет | правки — Sonnet + thinking; с нуля — **Opus + thinking** |
| 6 | Финиш: карта + досье | «Stage 6 для <поездки>» | `6_final_v<N>.md` — координаты, визы/медицина/связь, бронь | Sonnet + thinking |
| E | Экспорт | «экспортируй Stage N <поездки> [для <кого>]» | HTML (по умолчанию), PDF/DOCX по запросу | Sonnet |

**Модели — тир, а не поколение:** «Opus» = текущий Opus, «Sonnet» =
текущий Sonnet (версию бери в переключателе моделей). **Haiku и Sonnet без thinking на стадиях 2–5 не годятся** — срезают
углы (скилл сам проверяет модель и остановится). В обычном чате на Sonnet
кнопка «Continue» после сбоя фильтра запускает Haiku — лучше начать новый чат.

## 2. Что делаешь ты между стадиями

- **После 0** — заполни блок `## Решение` в `0_scope.md` (какой пакет регионов).
- **После 1** — прогони DR-промт в отдельной сессии Deep Research, сохрани
  результат как `1_dr_reports.md`.
- **После 3** — проставь теги и «Комментарий пользователя» у интересных мест
  (можно прямо в HTML-экспорте Stage 3 — кнопка «Сохранить»).
- **После 4** — выбери вариант в `## Решение`, при желании — комментарии к
  вариантам (тоже можно в HTML Stage 4).
- **После 5** — когда маршрут устаканился, запускай Stage 6.

Скилл **не сохраняет файлы сам** — выдаёт markdown в чат, сохраняешь ты
(исключение — Cowork с подключённым Synology). Не уверен, где остановился —
назови поездку, скилл сам определит состояние по файлам.

---

## 3. Экспорт (режим E)

- **По умолчанию — HTML** для любой стадии 0–6: self-contained страница в
  дизайн-системе кабинета; открывается прямо из карточки поездки.
- **PDF / DOCX — только по явной просьбе** («в PDF», «в Word»). DOCX — для
  Stage 3 (офлайн-заполнение тегов с обратным импортом). Stage 6 в PDF — дорожный
  документ с картой, номерами страниц и приложениями.
- **Stage 3 и Stage 4 в HTML — редактируемые**, если открыты с NAS: правки
  (теги, комментарии) пишутся обратно в исходный `.md`. Экспортируй Stage 3
  прямо в папку поездки — иначе сохранение не сработает.
- Экспорт лежит рядом с исходником: `<стадия>_<краткое_имя>_<дата>.<ext>`.
- Экспорт делает двухслойно: модель полирует формулировки → скрипт сверяет,
  что числа и разделы не потерялись → рендер. Можно указать получателя
  (партнёр, семья, друзья) — поменяется тон, не содержание.

## 4. Статусы поездки на странице

Статус берётся из `trip.yaml`, его обновляет скилл:
`planning` → черновик / в проработке, `ready` — план принят (к поездке готов),
`done` — состоялась (архив), `superseded` — вытеснена другой проработкой.

**Когда поездка** (строка под названием, сводка «Ближайшая», «Моя ближайшая»
на хабе) зависит от того, что известно о датах:

| Что в `trip.yaml` | Что видно | После срока |
|---|---|---|
| точные даты `start` / `end` | «через 12 дн», «идёт · день 3 из 10» | «прошла» → архив на следующий день |
| `ready` + месяц в `season` | «в следующем месяце», «в этом месяце» | «прошла» → архив после конца месяца |
| месяц, статус не `ready` | «возможная · даты не определены» | «срок прошёл» (не «состоялась») |
| только год | «идея» | «срок прошёл» |

**Мои / для близких.** Поездка «моя», если я есть в `travelers` (один или с кем-то), иначе — «для близких» (например, родители). Счётчики — в сводке вверху и на хабе. В «Ближайшую» попадают только мои поездки (первые две строки таблицы); возможные поездки
и идеи — отдельной оговоркой «точных дат нет». Даты ставит Stage 5 вместе с
финальным планом. Для плана, принятого раньше, скажи Claude «достань даты из
плана <поездка>» — скрипт `trip_dates.py` выдаст строки `start:`/`end:`, их
вставляешь в `trip.yaml` сам. В md-режиме идущей поездки есть кнопка
«Сегодня» — прыжок к сегодняшнему дню.

Ссылка «поделиться» (`?trip=<поездка>`) открывает одну поездку без входа —
для тех, с кем едешь.

## 5. Правила, которые стоит помнить

- **Цены — всегда TODO**, пока не проверены на агрегаторе: у ИИ устойчивое
  занижение цен отелей в разы.
- **Профиль поменялся** после старта поездки — скилл предупредит, но старые
  стадии сам не пересчитывает.
- **Без связи** — список поездок и стадии 3–6 (кроме архива) из копии на телефоне: HTML, где он есть,
  иначе MD; PDF и печатные копии — только при связи. Комментарии, теги, варианты и чекбоксы подготовки,
  сделанные без связи, сохраняются на телефоне и сами уходят в MD, когда связь появится (справка хаба §4).
- Подробная шпаргалка по стадиям — `skills/travel-planning/STAGES.md`.
